# UI 任务提示词与验收记录

与 [开发工作流](development-workflow.md) 和 [本地任务跟踪](issue-tracker.md) 配套使用。按任务范围选用以下模板；用户已明确授权的范围和差异不重复请求审批。

前端控件测试/检查、点击验证、交互走查、视觉空间/布局/无响应诊断等同义提示，以及影响前端交互或布局的开发后验收，默认读取并应用[前端控件与视觉空间诊断规范](frontend-control-audit.md)。开发任务即使未重复写“检查”也应填写下列控件验收项；整页或全控件请求按完整登记，局部修改按影响面。范围排除记录用户依据，不能将一次“窄屏不修复”沿用为后续默认规则。

派发前将模板中的 `【…】` 替换为实际内容，填完参考、范围、责任人、适用门槛和预期结果；没有的内容明确写“无”并说明必要依据。占位符、待补截图和实现者自述均不能作为完成证据。建议将视觉契约、验收记录和截图放在 `.scratch/<feature-slug>/`，任务票仍放在该目录的 `issues/` 下。

状态统一为 `PASS`、`FAIL`、`NOT VERIFIED`、`NOT APPLICABLE`。未执行或证据不足用 `NOT VERIFIED`；只有要求确实不适用于本次范围时才用 `NOT APPLICABLE`，并记录依据。纯文档任务不强制浏览器或数据库验收；无写入任务不强制数据库写入验证，但仍须验证适用的导航、状态联动等端到端路径。不能以“不适用”跳过已承诺的视觉还原或核心保存行为。

## 1. 实现任务提示词

```text
目标：【用户可观察的结果及任务票路径】。
规格与参考：【文字规格路径、原稿路径/来源、visual-contract.md 路径】。
没有用户原稿时，按已记录的界面需求及现有视觉规范验收，可引用现有界面截图；
记录适用依据，不将无原稿本身当成视觉验收阻塞。
授权差异：【逐项记录用户已允许的差异及依据；没有则写无】。
允许修改：【精确文件范围】；禁止项：【数据、文件及行为边界】。
输入/输出接口：【数据来源、事件、组件或 API 契约】。
实现负责人：【姓名/代理】；整页视觉负责人：【姓名/代理】；
跨组件/API/持久化接线负责人：【姓名/代理及接口范围】。
依赖：【必须先完成的任务及可验收结果】。不得再派代理或扩大范围。

视觉契约（引用的契约必须已填完）：
- 原稿像素尺寸：【宽×高 px】；参考 CSS 视口：【宽×高 CSS px】；
  浏览器缩放：【值】；设备像素比：【值或未知及限制】。
  原图像素宽度不等于实际 CSS 视口；不得直接据此设置响应式断点。
- 布局/比例/首屏重心：【侧栏、顶栏、主区顺序、卡片、图表、表格】。
- 密度与层级：【行高、间距、字体、颜色、主次信息和控件】。
- 数据与交互状态：【代表性完整/部分/空数据、选中、hover、浮层等适用项】。
- 对照宽度：【参考视口、宽桌面、关键断点两侧、窄屏及选择依据】。
先装配一屏代表性数据，由整页负责人核对，再扩展其余模块。
业务字段调整只按授权差异处理，不自动意味着可改变布局或密度。

核心状态链：【真实数据读取→选中准确对象→用户操作→实际保存→重新读取
→返回列表即时变化→刷新后仍保留】。写入验证使用显式指定的独立数据库。
失败/取消预期：【原状态保持及错误反馈】。无写入时说明写入项不适用依据，
并列明仍适用的端到端路径：【导航、状态联动及最终用户可见结果】。
不得用回调成功、注入 props、mock 保存或重渲染 fixture 冒充持久化闭环。

验证要求：【行为测试命令、浏览器路径、渲染截图与预期】。
控件检查（默认适用前端开发）：【触发依据；完整/局部范围及上下游；
控件/选项/动态实例登记路径与分母；负责实际操作和空间对照的人】。
按 frontend-control-audit.md 填写真实操作验证表与问题表，覆盖点击前中后、
展开/选中/空态等适用状态、实际作用域、布局预算、返回/刷新；
逐项说明用户排除与未测项，不用测试数量代替控件覆盖或通过率。
报告位置：【路径】。分别报告实现及功能正确性、端到端行为、视觉还原三道门槛结果，附证据。
有写入时，端到端行为包含真实持久化闭环。
未直接看到渲染结果就写视觉 NOT VERIFIED。待其他负责人接线的工作明确列出，
不得算成本票闭环；交接后由协调者验收集成结果。
```

## 2. 独立视觉审查提示词

```text
你未参与所审 UI 的实现；若参与过，报告角色冲突，不能自签独立视觉 PASS。
输入：【原稿路径、visual-contract.md、授权差异、当前页面 URL、截图路径】。
待审版本/运行位置：【提交或工作区变更标识、worktree、端口、截图时间】。

直接打开参考图与实际渲染截图，不以实现报告、测试数量、DOM/CSS 阅读替代看图。
有用户原稿时以原稿为准；无用户原稿时以已记录的界面需求及现有视觉规范验收，
可引用现有界面截图，逐项记录规格依据及渲染观察。
比较条件必须可比：相同 CSS 视口宽度、相同浏览器缩放、对应数据和交互状态；
同时记录原图像素尺寸、CSS 视口、DPR 和裁切范围，不把截图像素当 CSS 宽度。
原稿没有可确认的视口/缩放信息时记录推定依据和限制，不声称精确等同比较。
核对参考视口、宽桌面、关键断点两侧、窄屏，以及契约要求的关键交互状态。
逐项核对本次授权排除的状态/视口并保留来源；排除不记 PASS，
未获排除的必需检查仍适用。按控件诊断规范核对点击前中后空间变化、
舞台/详情槽/下游区块位置、长文及空态预算，不以静态截图无溢出代替状态对照。

逐项比较布局比例、主区顺序、首屏层级、信息密度、字体颜色、控件、图表与表格。
每条差距记录：原稿/规格预期、实际观察、参考/渲染截图位置、影响和严重性、修复负责人。
主区顺序错误、首屏重心明显偏离、桌面主布局退化、核心信息遮挡或非预期滚动、
表格过度展开等主要差距必须逐项处理，不能用其他维度的高分或总分抵消。
授权差异单列依据；修复后检查新的渲染证据并记录复核结果。

输出视觉结论 PASS / FAIL / NOT VERIFIED，并列出未检查的视口和状态。
PASS 需要所要求的比较已完成且无未解决的阻断差距；看到了不符合要求就记 FAIL；
任务指定原稿却取不到、取不到渲染图、无法直接看图或证据不完整时如实记
NOT VERIFIED；无用户原稿本身不阻塞按已记录规格完成视觉验收。
仅静态审查必须标为静态审查。报告能力限制并交回协调者，不新增审批流程。
报告路径：【acceptance.md 或独立视觉审查记录路径】。
```

## 3. 协调者放行提示词

```text
核验本次范围与验收记录：【任务票、视觉契约、acceptance.md、实现和审查报告】。
亲自核对实际变更和适用的核心浏览器路径，不仅转述实现者的完成声明。
分别给出功能正确性、端到端行为、视觉还原三项结论及证据；不适用项说明范围依据。
端到端行为在有写入时包含真实持久化闭环；无写入仍须核验适用的导航、状态联动。

确认每项证据证明了什么：静态审查、组件测试、实际浏览器操作、真实数据库读写、
渲染对照各有边界；鼠标、键盘、模拟触控、实际触屏、组件合成事件分别记录，
不得互相冒充。未测不勾选。
写入链必须覆盖准确对象、实际保存、返回即时变化、刷新保留及失败/取消保持旧值；
核实隔离数据库、显式 TRADEREVIEW_DB_PATH、原始数据未变证据。
视觉 PASS 须有未参与所审 UI 实现者直接看图的审查证据，且重大差距已修复并复核。
确保截图和验证对应最终版本；后续修改影响的结果需要重验。
核对 frontend-control-audit.md 的触发与范围记录、完整控件清单或局部影响面、
动态/条件出现控件与选项、实际操作验证表、空间对照和问题表。
分别核实覆盖率分子/分母与通过率，未测或失效证据不计已覆盖；
真实点击失败仍记 FAIL，范围排除有用户依据且不记通过。
开发后无显式“检查”提示不免除该验收；局部通过不宣称整个前端100%。

发现 FAIL 则交回负责人修复；缺证据保留 NOT VERIFIED，不因测试通过数量改成 PASS。
适用的核心门槛未通过时只交付阶段结果，明确差距和负责人，不宣称整页完成。
完成 UI 交付时核验最终预览服务仍运行，并在真实浏览器新鲜检查最终 URL；
当前聊天提供可点击 URL、分项验证结果、限制、启动/重启方式及工作流链接。
纯文档等非 UI 交付按实际范围验证，不人为增加预览门槛。
```

## 5. 前端控件检查 / 诊断提示词

该模板用于相关语义检查请求，也作为前端开发后的默认验收入口。登记表、问题表、空间对照表及修复方案模板统一使用[控件诊断规范](frontend-control-audit.md)，无需在此复制另一套字段。

```text
先读取 docs/agents/frontend-control-audit.md 及本次规格、视觉契约和 DESIGN-COVERAGE.md。
触发依据：【用户检查请求/前端开发后；用户当前目标】。
待验版本与环境：【worktree、提交/未提交指纹、真实 URL、服务、数据库、数据和过滤状态】。
范围：【整页全部可点击控件/局部变更及上下游；状态/选项/动态数据边界】；
排除：【逐项用户依据；无则写无】；对照视口：【CSS宽高、缩放、DPR、断点与适用设备】。
负责人：【真实操作、整页空间一致性、状态/持久化闭环、独立视觉审查及集成负责人】。

先建立控件登记，实际点击所有范围内项与必需状态；展开/条件出现/选项/图点不漏记。
保存点击前中后结果、空间尺寸和滚动偏移，检查作用域、身份、可见反馈及上下游。
有写入时仅在显式隔离库验证真实保存→返回→reload，核对原始业务数据未变。
记录视觉跳动、错位/遮挡/密度、无响应/错误结果及设计待补问题，区分工具限制。
按规范输出验证表、覆盖率、通过率、问题表及空间对照；修复只按已授权范围推进。
已授权修复先写状态与尺寸方案，再复验反例和独立视觉；保留失败与失效证据。
报告位置：【路径】。最终分别给功能、状态链、视觉结论及未验证/排除项。
UI 交付按现行流程提供仍运行且真实浏览器新鲜检查的预览 URL 与启动方法。
```
