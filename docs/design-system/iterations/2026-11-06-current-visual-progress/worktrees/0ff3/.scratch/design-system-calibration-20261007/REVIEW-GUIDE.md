## 推荐设计与取舍

保留暗色基底、React/CSS Module/Lucide、现有盈亏配置和真实图表组件。参考 TradingView 的是工具分组与图表主工作面，不把未经测量的 TradingView 像素值当标准。

首页用范围、资产数值、单币历史和复盘入口建立顺序。复盘让图表占据主工作面，完整判断与补充在流内对照，不把首页方案 B 的比例迁入复盘。长中文增加行高，接受必要的纵向滚动；价格、币种、判断和补记不为排版删减。大额数值与说明拉开层级，图标视觉尺寸与触摸命中区分别约束。

只有一个推荐方向。“同内容样式基线”是当前组件规则在固定内容上的对照，不是当前业务首页完整的修改前截图，也不是第二套审美候选。

## 评审操作清单

以下是待在真实浏览器执行的清单，**不是已经通过的操作证据**。

1. 在首页比较两种样式，先看能否快速识别范围、日期、金额和入口；再看较窄窗口是否需要缩小字才能读完。
2. 进入复盘。初始 S1 为 D69，已知买入和 D68 减仓，持仓 400 股；不应出现未来退出事实。检查阶段与行情/成交双截止是否足够清楚。
3. 选择原判断，完整阅读原文；选择当前补记，对照形成阶段与图中锚点。检查选中与真实键盘焦点是否各自清楚。旧阶段形成的补记在后续阶段只读，新观察另记在当前阶段。
4. 点击“下一根”。图中必须出现下一根完成 K，Tooltip、摘要、数据说明与图层都使用同一可知边界，成交不暗中提前推进。
5. 展开 S2，再回到 S0。未来 K、成交、结果补记和未来价格轴不能留在早期视图；已经见过后续后形成的新补记需保留知情来源。
6. 在手工移动/缩放后的同一阶段切换样式。数据、全文、阶段、图表范围保持一致，才可比较密度和阅读感受。

你只需判断四件事：第一眼的焦点是否正确、信息密度是否舒适、长中文是否读得顺、动作含义是否清楚。字号、圆角、图标与间距由实现者按画面校准。
