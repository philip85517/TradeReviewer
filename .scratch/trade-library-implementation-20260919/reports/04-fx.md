# Ticket 04 — 手动刷新汇率与持久化快照

## 交付范围

已实现独立的 FX 快照垂直切片，文件范围为：

- `app/lib/fx/contracts.ts`：公开 `FxSnapshot`、响应和校验类型。
- `app/lib/fx/provider.ts`：ECB/Frankfurter provider 请求、方向归一化、完整性校验及整段请求体超时。
- `app/lib/fx/storage.ts`：使用既有 `app_settings` JSON KV 表保存单行完整快照，并通过 SQLite 事务原子替换。
- `app/lib/fx/service.ts`：手动刷新、失败缓存回退和并发刷新代次保护。
- `app/lib/fx/client.ts`：浏览器端 GET/POST 客户端。
- `app/api/fx/route.ts`：`GET /api/fx` 只读快照；`POST /api/fx` 才允许 provider 请求。
- `app/components/library/fx-rates-control.tsx`：可注入客户端的小型展示/刷新控件，并通过 `onSnapshotChange` 将同一快照交给交易库汇总层。

刷新得到的汇率口径为“1 单位原币对应多少人民币”：CNY 固定为 `1`，HKD 和 USD 来自 provider 的 CNY-base 报价倒数。快照同时记录来源、provider 数据日期、最近一次成功保存时间、最近尝试时间、`fresh`/`cached` 状态及失败原因。

## 来源核实

采用 Frankfurter v2 的 provider-pinned ECB endpoint：

`https://api.frankfurter.dev/v2/providers/ecb/rates?base=CNY&quotes=HKD,USD`

Frankfurter 官方文档说明其公共 API 无需 API key，并支持通过 `providers=ecb` 或 provider 路由固定数据源；其最新汇率按最近工作日返回，而不是实时交易报价：[Frankfurter 官方文档](https://frankfurter.dev/)。ECB 官方参考汇率框架说明参考汇率每日设置并发布，且覆盖 USD、HKD、CNY：[ECB reference-rate framework](https://www.ecb.europa.eu/stats/pdf/exchange/Frameworkfortheeuroforeignexchangereferencerates.lv.pdf)。ECB 当前汇率页面提供官方参考汇率及 XML/CSV 下载入口：[ECB euro foreign exchange reference rates](https://www.ecb.europa.eu/stats/policy_and_exchange_rates/euro_reference_exchange_rates/html/index.en.html)。

provider 请求只携带固定的货币查询参数，不带交易 ID、成交、账户或任何交易数据库字段。进入交易库时只请求本地 `GET /api/fx`；外部 provider 请求只发生在用户点击刷新后触发的 `POST /api/fx`。

## 缓存与失败行为

- 成功刷新构建一个包含 CNY/HKD/USD 的完整快照后，一次事务写入 `app_settings` 的 `fx.rates.snapshot.v1` 行。
- 缺失、重复、空行、不同日期、非有限或非正汇率都会被拒绝，不会替换旧快照。
- provider 失败或返回非法数据时，旧完整快照继续保留，状态改为 `cached`，保留原 `fetchedAt` 和汇率日期，并记录 `lastAttemptedAt`/`lastError`。
- 没有历史快照时返回 `unavailable`，控件显示“暂无法折算”，不会填充 0。
- 请求 deadline 覆盖 headers、JSON body 读取和解析，默认 10 秒；超时会 abort provider request。
- 同一 SQLite 数据库上的重叠刷新使用 generation guard，较早请求不会以晚启动请求的结果覆盖当前快照。

## 限制

ECB/Frankfurter 是每日工作日参考汇率，适合本需求的人民币展示和比较，不是实时交易报价。快照只在手动刷新时更新；provider 暂时不可用时继续使用并明确标记的旧快照。代次保护覆盖当前 Node 进程内的并发调用，SQLite 写入本身仍由事务保证单行原子性。
