# 一次性实验结果（2026-10-29）

**在固定合成数据中，预先准备并保存轻量交易行和常用摘要，减少了后续读取与编码成本；仅缩小响应仍保留重复全表准备成本。** 代价是准备耗时、额外存储、更新失效和恢复责任。第三轮20,000笔的首次准备782.22ms、状态更新后重建820.84ms；第二轮同一场景曾测得1,108.18ms，说明不能承诺准备总能在一秒内完成。

这是CLI合成实验，**不能证明正式页面变快、产品链路达标、真实导入或财务规则通过，也不构成完整MVP验收**。Wayfinder `03-mvp` 的依赖和HITL判断不由本实验关闭。

## 环境与方法

代码基点 `8c8c66c715be46e1e8a53d61d02b82f4fa13b22c`；最终脚本SHA256 `eaeac44724a44124114494aeb7723da13a655f66c4ccdfe85b76db5212dae31c`。原始记录时间 `2026-10-28T16:38:16.851Z`。Intel i5-1038NG7 2.00GHz、8逻辑CPU、16GiB，Darwin24.3.0 x64，固定Node26.0.0／SQLite3.53.0，暴露GC。

每条读取路线9次，p50/p95为nearest-rank，**9次时p95就是最大样本，不是置信区间**。同一合成库和操作系统warm缓存，固定路线顺序，无随机打散、独占负载或HTTP。计时包含SQLite／计算、JSON编码、本地Node JSON解析；GC在单次读取计时前运行。结果不能代表真正冷缓存或浏览器首次访问。

每组3个虚构账户；第一页8笔成交，全范围1,867／20,000笔、236／1,200标的。先筛选再计数、排序和分页；成交日期倒序＋唯一成交ID正序。每笔带3,264字节重复合成padding。**字节量是本地未压缩UTF-8 JSON，既无HTTP压缩，也不复刻产品来源沿革或34.33MB真实响应**。1,867／236仅接近既有诊断记录规模，绝非同数据baseline。

## 第三轮正确性与故障证据

两组各15项检查PASS，另有2个新进程持久化读PASS；共72个读取样本。1,867笔全范围234页；20,000笔2,500页；旧日期新增后1,868笔234页／20,001笔2,501页。账户分别逐页核对，原始SQL完整ID列表与实际所有页相等、无重复；独立JS谓词／reducer交叉检查SQL范围与摘要。

|场景|实际结果|
|---|---|
|跨账户、同日、全页、搜索、期间、显式空账户集合|完整计数与稳定ID一致；页大小8→17不改摘要；精确benchmark组合也逐页对照|
|全量与窄响应等价|剥除fullSource后整份full envelope与窄响应deepEqual；窄响应与准备响应deepEqual|
|金额依据缺失|初始缺失110／1,177笔，事实保留；金额null＋unknown；已知小计单列，完整金额不冒充0|
|第一页后合成新增2010年成交|旧游标拒绝VERSION_CHANGED，未准备读报PREPARED_STALE，重建后完整含新增|
|发布失败注入|回滚后**全体旧prepared行＋所有摘要＋发布指针**稳定digest与失败前完全相同，旧版本仍拒绝冒充当前|
|合成review状态、rule版本变化|各版本独立失效，旧游标拒绝，重建后状态与摘要持久化一致|
|游标改变账户或页大小|拒绝CURSOR_SCOPE_CHANGED|
|详情引用|原始合成证据ID、持久化引用及SHA256一致|
|新Node进程|默认范围第一页响应及版本的摘要校验值等于关闭前；插桩prepare函数调用计数实测0（只统计本实验函数）|

首次运行在执行期间修改脚本，父子进程schema不一致导致FAIL；第二轮原有14项自测PASS但独立复核发现验证覆盖与硬编码计数缺口。第三轮一次性补齐后完整PASS；首轮失败、第二轮原值与hash全部保留于[运行历史](RUN-HISTORY.md)。不做第四轮，不再修改最终脚本。

## 结论与未验证
