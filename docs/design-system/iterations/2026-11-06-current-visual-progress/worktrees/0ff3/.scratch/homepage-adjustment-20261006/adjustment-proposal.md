# 首页交互视觉调整草案

日期：2026-10-06 · 状态：候选方案，供设计决策；尚未形成批准的视觉规格，未实施页面改动。

本草案基于[首页交互视觉评审](../../artifacts/design-report/TradeReview-首页交互视觉评审.docx)。当前按“覆盖全部 8 项问题、保留深色风格”整理；这是规划假设，用户尚未单独确认范围选项。对应的权威决策记录为[首页交互视觉调整决策地图](issues/00-homepage-adjustment-map.md)。

## 1. 调整目标与既定边界

建议把首页的阅读顺序收敛为：**确认账户范围 → 看可信金额 → 看变化与缺口 → 进入需要处理的持仓或复盘**。读数的可信范围应贴着金额；复杂证据按需展开；更新在后台进行，用户可以继续操作。

用户已经确认的要求直接保留：展示已知部分、异步补齐完整估值、更新过程有动态状态、保留手工触发按钮。这些不作为本轮待重新批准的选项。

既有业务契约继续有效：

- 金额按币种、指标、估值时点和账户范围计算。市值覆盖与盈亏覆盖分别统计；缺成本不妨碍可信市值，却可能使盈亏不可用。未知不等于零，小计不等于完整值。
- 当前持仓时点、持仓历史观察期间、选中的历史时点、复盘统计期间是不同状态。选择历史日期不改变当前持仓，不把复盘统计期间强行联动到持仓。
- 实盘与模拟范围、模拟账户和已批准的账户合并规则不变；报表折算继续标注汇率时点。原币不能直接求和，不能把最新汇率折算称为历史真实折算。
- 已确认空头可以保留负净市值；持仓方向未知不能从负数量猜测。含空头的分布比例以**持仓总敞口（市值绝对值之和）**为分母，不以多空相抵后的净市值作分母。
- 同一范围、同一目标币种、同一份 FX 快照且时点不回退的兼容旧快照才可沿用。范围、币种或 FX 快照改变，以及时间回退，均不能用旧图冒充新结果；仅同为“最新汇率”口径仍不足以复用。
- 不改原始交易；不新增行情供应商、财务算法或首页二级路由。本轮交付设计方案，后续实现另按已批准契约拆分。

## 2. 推荐的首页结构

保留现有左导航和单一“我的交易室”页标题，将改动集中在现有内容区。推荐延续当前“持仓照看在前”的阅读路径，并把待复盘的轻量入口前移；具体模块顺序仍待决策。

| 位置 / 草案元素 | 内容与交互 | 设计目的 |
| --- | --- | --- |
| 顶部现有页头 · H01 | 页标题、性质、账户范围、报告计价；搜索与附加筛选可收起，启用项在收起后仍有可移除标签 | 让筛选范围常见，减少首屏控件堆叠；复用现有页头，不叠加一层导航 |
| 页头内任务入口 · H02 | `待复盘 · 实时数量`，进入现有待办区域；零项显示“当前范围暂无待复盘”；加载中或数量未知不得显示为零。直接“继续复盘”只在能准确识别该回合的已保存进度时提供 | 将下一步行动前移；通知数量与待复盘数量分开 |
| 持仓摘要 · H03 | 4 项摘要：市值、未实现盈亏、当日盈亏、持仓数；金额、币种、覆盖和时点成组排版 | 首先回答持有什么、能确认多少、缺什么 |
| 主区左侧 · H04 | 持仓趋势；指标、期间、币种、粒度分行分组；默认选中一个币种 | 给图形稳定阅读空间，减少工具栏相互竞争 |
| 主区右侧 · H05/H06 | 资产分布或金额替代视图；下方一条数据问题摘要，打开问题详情 | 主区高度不被原始诊断撑长，保持缺口可见 |
| 主区之后 · H07 | 当前／历史持仓明细，标题明确日期；查看标的进入既有回合上下文 | 图表发现异常后可以定位具体仓位 |
| 后续复盘区 · H08 | 已完成交易统计、日历和待复盘列表；保留完整分析，压缩分页 | 轻入口前移，完整分析仍在原有单页路径中 |

桌面候选布局：

```text
既有左导航 │ 我的交易室                         待复盘 · N
           │ 性质 / 账户 / 报告计价    搜索 / 筛选
           │ 已启用筛选标签（有筛选时显示）
           │ 持仓照看          更新状态 · 更新估值 / 取消
           │ 市值        未实现盈亏       当日盈亏      持仓数
           │ ┌───────────────────┬───────────┐
           │ │ 持仓趋势          │ 资产分布   │
           │ │ 指标 / 期间       │ 或金额列表 │
           │ │ 币种 / 粒度       │           │
           │ │ 图形 + 时点详情   │ 数据问题摘要│
           │ └───────────────────┴───────────┘
           │ 持仓明细 → 复盘统计 → 待复盘列表
```

比较过的方向：只修文案和颜色，不能解决右栏诊断占比与窄屏筛选过长；彻底改为多页或多标签首页，会扩大导航和返回状态成本。推荐在现有单页内调整。9 月已验收规格曾要求绩效在前，当前页面已是持仓在前；本草案把顺序差异显式交给[首页阅读路径与复盘入口](issues/02-reading-path.md)，不把当前实现或旧顺序当成新的用户批准。

## 3. 金额与币种表达

对应评审 P1-01、P1-02；由[金额可信范围与币种阅读方式](issues/01-value-and-currency.md)确定最终呈现。

| 数据状态 | 推荐主表达 | 紧邻说明与动作 |
| --- | --- | --- |
| 完整 | `持仓市值`；含空头时使用既有净市值语义 | 币种 + 金额；本币种覆盖 n/n；估值时点 |
| 部分 | **已知市值小计**；盈亏使用**已知未实现盈亏小计** | `CNY 覆盖 6/7 · 1 个仓位待核对`；可查看缺口 |
| 全缺失 | `暂不可用` | `覆盖 0/n`、首要原因、可用动作；不用 0.00 替代 |
| 更新中 | 保留对应的完整／部分／缺失状态 | 更新状态附着显示；数据可信状态与更新阶段分别表达 |

上例的 6/7 只用于说明排版，不能硬编码为业务数据。估值时点使用本地可读格式并注明时区，完整时间与来源可在详情查看；行情截止仍按各市场最近已完成交易日，不把参考估值称为实时行情。多币种摘要每个币种独占一行，币种与金额不可拆开；全组合覆盖作为独立摘要，并明确“全组合”标签。不要把某个币种的 6/7 放在全卡 7/8 的说明位置。

报告曾建议“可估值净市值小计”；这里改用领域词表已有的“已知市值小计”，避免引入同义词。成本小计、当日盈亏和收益率各自遵守有效条件，不能沿用市值的可用状态。

币种候选视觉映射：CNY 青绿 + 圆点，HKD 紫 + 菱形，USD 蓝 + 方形。它是待原型校验的映射方向，最终颜色值须在深色背景上验证；涨跌红绿继续遵循用户偏好。颜色、标记和币种文字共同识别系列；实线／虚线专门表示完整性，不再兼任币种编码。

推荐原币图默认展示一个币种：保留用户在当前有效范围内的选择；没有有效选择时按稳定顺序 CNY → HKD → USD 选首个存在的币种，并明确选中项。不按金额大小自动切换。跨币比较用共享时间轴的独立面板，不把不同面值塞进同一数值轴。报告计价模式仍保留其既定折算口径；图内币种切换只是呈现选择，不隐式改变全局账户／币种筛选。最终默认选择规则留待该决策票确认。

## 4. 分布与数据问题

对应 P1-03、P2-05；由[分布替代视图与问题详情](issues/03-distribution-and-diagnostics.md)确定。

**比例有效时**才显示分布图，并在标题旁写清当前币种和分母；含空头时呈现“持仓总敞口分布”，净市值作为独立金额。分类覆盖、数量方向、价格及分母必须符合既定模型。完整且有效的空头不是自动禁用分布的原因。

**比例无效时**移除装饰性的整圈灰环，换成可读内容：已知市值小计 → 分类金额列表 → 估值覆盖 → 缺口摘要。部分估值不显示“整组合占比”；估值覆盖条只按可估值仓位数表达，清楚标作“估值覆盖”，不模拟资产分配。零分母、方向待核对、全缺失分别给对应说明。

问题摘要建议最多展示三类主因和“查看全部问题”，每类显示受影响仓位／记录数。候选分组为缺失行情、持仓或成本待核对、记录属性待确认；最终按实际诊断数据映射。一个仓位可以有多个原因，分类计数不能相加冒充唯一仓位数。

详情建议在独立抽屉中呈现：桌面侧边、窄屏全屏；首页仍只有一个主滚动区，不在卡片中嵌套多层滚动。详情结构为“问题解释 → 受影响对象 → 可执行动作 → 原始证据”。原始 ID、供应商规则、逐笔记录留在最后一级，并提供搜索／分段查看。缺失行情对应重试估值；数量、成本、方向、记录属性问题指向现有数据管理／质量流程，不用下载行情冒充修复。关闭后回到原触发点，Esc 与键盘焦点可恢复。

参考现金、今日卖出回款保留独立业务含义。参考现金的记录属性问题在详情可完整追溯；首页不重复展开相同的上千条原因。现有约 176px 原因滚动容器本身并非故障，本次改善的是重复内容、行动路径和视觉占比。

## 5. 趋势、日期与密度

对应 P2-04、P2-06；由[趋势密度与日期联动](issues/04-trend-and-dates.md)确定。

推荐控制顺序：标题和指标 → 观察期间 → 图内币种与采样粒度 → 图形 → 时点详情。将“历史持仓日期”改为能说明动作的“查看某日持仓”；显示选中日期，并提供返回当前持仓。近 1 月的既有语义是本自然月，建议直接显示“本月”，避免被理解为滚动 30 天。

候选自动粒度：跨度 ≤ 92 天用日、93–730 天用周、更长用月；显示“自动 · 周”等实际粒度，并允许手工选择日／周／月。阈值和偏好保留规则需要原型确认。周／月代表区间末可用快照，明确显示实际快照日期，**不把市值求和**。

完整为实线，部分为虚线，完全不可用留空；成员集合或可信状态改变时保留断点。稀疏单点可见可选，全缺失仍能看见原因。密度处理不能连接原本不连续的段；如一个采样段内出现缺失或状态边界，保留边界点或断开，并在详情解释。

| 用户操作 | 保持不变 | 可观察结果 |
| --- | --- | --- |
| 改持仓观察期间 | 当前持仓时点、复盘统计期间 | 新区间生效；旧区间快照不得冒充新区间 |
| 图上选择某日 | 观察区间、当前持仓基准、复盘统计期间 | 时点详情与历史持仓日期一致；退出选择可返回当前 |
| 改日／周／月 | 区间和全局范围 | 改快照密度，不累加市值，不移动日期范围 |
| 自定义日期应用／取消 | 取消或无效时保留原范围 | 错误贴字段，显式应用才更改 |
| 切图内币种 | 账户筛选、复盘统计期间 | 只变可视系列；不能把旧币种值标成新币种 |
| 进入复盘再返回 | 按已批准的返回规则恢复 | 范围、列表页、回合上下文、滚动位置恢复 |

原评审中日期选择与 End 键因工具超时未验证，不作为已确认产品故障。后续验收需要实际操作日期控件、左右键、Home／End、Esc、鼠标与触摸，并分别记录。

## 6. 异步更新的动态反馈

对应 P2-04 与用户已确认要求；[后台更新反馈与恢复](issues/05-update-feedback.md)只决策呈现细节，不重新讨论是否自动补齐。

在“持仓照看”标题行保留一个任务状态源，同时保留图内历史计算状态。行情下载与历史计算是不同子阶段：只有真实有关联的任务才组合展示，不把所有局部计算强行标为全局行情任务。旧数据时点、最近成功时间、当前任务阶段分别显示。

| 阶段 | 建议反馈 | 动作与数据保持 |
| --- | --- | --- |
| 等待锁／排队 | `等待行情更新 · 当前可继续查看`，真实原因可展开 | 普通筛选与浏览可用；手工入口并入现有任务，不新建重复任务 |
| 下载 | 小型转动图标 + `正在补齐行情 · 已处理 x/y 个标的` | 仅已知总量才画确定进度；已处理数不称成功数；可取消 |
| 重新计算 | `正在计算持仓历史`，无总量用不定进度 | 兼容旧图带“上次快照”与时点；不兼容则显示相应加载／空状态 |
| 完成 | 短暂完成反馈 + 最近成功时间 | 金额与覆盖一并更新，完成动效后静止 |
| 部分完成 | `已更新可用行情，仍有 n 项待处理` | 已取得的有效数据保留；按原因指向重试或核对 |
| 失败／取消／中断 | 明确结果与简短原因 | 不丢有效缓存；手工重试可见；重新载入识别中断而非假装成功 |

动效候选：图标转动或轻量进度条、完成时约 200ms 的状态过渡。金额不滚动计数、不全卡闪烁、不全屏遮罩。开启减少动态效果时使用静态图标与阶段文字，状态消息使用低打扰的可访问播报。进度未知不能制造百分比。

沿用既有调度与去重规则：稳定范围 × 各市场最近已完成交易 session 中，每个候选标的自动尝试一次；历史计算后新发现的候选仍可加入，并非每个浏览器会话只发一次任务。失败不无限重试；自动与手工共用锁、合并和预算；仅补齐当前组合及所选历史需要的标的。页顶全局消息与本区状态若描述同一任务，应保持一致并避免重复，其他任务不被误隐藏。

## 7. 视觉与响应式契约候选

对应 P2-06、P2-07；最终尺寸与状态板由[整页视觉与验收契约](issues/06-visual-contract.md)确认。原报告截图是问题证据，并非要原样复刻的目标设计。

| 项目 | 既定基线 / 候选目标 |
| --- | --- |
| 风格 | 保留深色、现有左导航、单一页标题、用户涨跌色偏好；减少重复边框与多层卡片包裹 |
| 字体 | 既定正文和控件 ≥ 14px，辅助文字／坐标 ≥ 12px；金额等宽数字；金额与币种成组。金额与单位价格精度不同，不把 ETF 价格一律截成两位 |
| 交互面积 | 主要交互 ≥ 44px；密度通过合并重复控件和渐进展开改善，不靠缩小字号与点击区 |
| 桌面 | 候选内容内边距 24px、区块间距 16–24px；趋势／分布约 2:1。1280×720 默认折叠态必须展示核心摘要及至少 120px 的真实趋势绘图区 |
| 列切换 | 候选内容宽度不足 900px 时主区转单列；以内容区可用宽度判断，不能只看窗口宽度 |
| 390×844 | 页头显示性质／账户／计价摘要及筛选入口；低频选项折叠，激活条件仍可见。摘要优先两列，趋势紧随其后，分布与明细在下；目标首屏露出 ≥ 120px 趋势，须原型验证而非压缩字号达成 |
| 320px 边界 | 无整页横向溢出；空间不足时金额项改一列。长账户名截断可查看全文；不拆分符号、币种与金额；月历沿用窄屏日期列表 |
| 焦点与对比 | 选中、悬停和焦点分开；文字、形状辅助颜色。最终色值实测文本／控件对比度；不能因颜色“看起来够亮”就记为通过 |

响应式规则不隐藏金额覆盖、日期或错误。手工更新入口在窄屏仍可触达；低频控件折叠后当前选择可恢复。一个主页面滚动；表格必要的局部横向滚动保持明确边界。

## 8. 推进次序与验收

当前阶段先形成设计决策，不下发实现任务。所有 8 项评审问题已映射至[设计覆盖矩阵](DESIGN-COVERAGE.md)，未验证项明确保留。

| 后续阶段 | 要解决的用户体验 | 进入下一阶段的依据 |
| --- | --- | --- |
| 设计决策 | 金额／币种、首页顺序、问题详情、趋势日期、更新反馈 | 对应决策票保留真实用户结论；不能由代理代答 |
| 状态原型与目标视觉 | 同组数据下完整／部分／缺失／更新／失败，桌面与窄屏 | 确认目标画面、尺寸、默认状态和授权偏差；与已批准契约逐项核对 |
| 第一条实现旅程 | 看见已知小计 → 查看缺口 → 异步更新 → 看到新金额与覆盖 | 真实页面接受端到端数据更新和安全旧快照；再扩展依赖其状态的界面 |
| 趋势与分布整合 | 期间／币种／日期切换 → 定位历史仓位 → 返回 | 断点、比例条件、日期独立性及返回状态分别通过 |
| 复盘与整页接受 | 上部入口 → 准确回合 → 保存 → 返回 → 刷新 | 隔离数据库证明实际持久化；独立审阅者比较同状态截图 |

将来实现时，整页视觉一致性由协调者 `/root` 负责；完整数据／持久化链路也由 `/root` 负责最终接受。按项目流程把实施交给有明确写入边界的实现代理，并在派发前指定每个实现切片的负责人。

验收分开记录：功能与财务口径、完整旅程与数据持久化、同状态视觉对比、可访问性。视口至少包括 1440×1000、1280×720、390×844、320px 边界；保存对照前后同数据、同日期、同导航状态。鼠标、键盘、模拟触摸、物理触摸证据分别记录。真实图形可读性不能由 DOM 或 HTTP 成功代替。

本次为文档规划：未修改应用，未启动写入测试；产品功能、视觉实现和持久化验收均 **NOT VERIFIED**。日期选择、End 键、屏幕阅读器、物理触摸、缩放、减少动态效果、最终对比度及手工更新／取消的旧报告验证缺口继续保留，后续补验。
