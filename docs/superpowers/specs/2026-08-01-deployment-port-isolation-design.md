# 部署端口隔离设计

## 背景

TradeReview 当前默认将宿主机端口 `3000` 映射到容器端口 `3000`。该端口常被本地开发服务占用，导致首次部署在 Compose 启动阶段失败，且错误信息只显示端口已分配。

## 目标

- 将 TradeReview 的宿主机默认端口改为专用的 `4317`。
- 保持容器内部端口 `3000` 不变，避免修改应用运行时和健康检查逻辑。
- 让新部署、当前部署目录、文档和测试使用同一个默认端口。
- 在没有现有 TradeReview release 的首次部署前检查端口；若端口已被占用，提前给出包含 `APP_PORT` 修改建议的明确错误。

## 方案

### 端口分层

`APP_PORT` 代表宿主机端口，默认值为 `4317`；Compose 继续把它映射到容器的 `3000` 端口。Compose 的容器环境变量 `PORT=3000` 和容器内健康检查 URL `127.0.0.1:3000` 保持不变。

### 配置同步

- 更新 `deploy/config/.env.example` 和 Compose 的宿主机端口回退值。
- 更新部署文档和 README 中的默认访问地址。
- 将当前 `/Users/zhoulin/projects/TradeReview/config/.env` 的 `APP_PORT` 从 `3000` 改为 `4317`。部署流程继续保留用户后续手工配置的端口，不在每次部署时覆盖已有 `.env`。

### 部署前检查

当目标尚无 active release 时，部署脚本读取目标 `.env` 中的 `APP_BIND` 和 `APP_PORT`，尝试临时监听该地址和端口后立即释放。监听失败且错误为端口占用时，部署以可操作的错误退出；已有 release 的更新部署跳过该检查，以允许 Compose 重建当前 TradeReview 容器。

## 错误处理

- `APP_PORT` 必须是 `1` 到 `65535` 的整数。
- 端口被占用时报告 `APP_BIND:APP_PORT`，并提示修改目标配置后重试。
- 非端口占用的监听错误原样包装为部署前检查失败。
- 检查失败发生在 release 接受前，不改变当前 release、数据库或运行时控制面文件。

## 测试

- 清单测试确认默认宿主机端口为 `4317`，容器内部仍为 `3000`。
- 端口可用时部署前检查通过。
- 端口被占用时检查返回可读错误，且不会调用 Compose。
- 完整部署测试、类型检查和 lint 继续通过。

## 非目标

- 不自动停止或重配置其他软件/容器。
- 不改变用户已自定义且已存在的 `APP_PORT`。
- 不改变容器内部监听端口或公网反向代理配置。
