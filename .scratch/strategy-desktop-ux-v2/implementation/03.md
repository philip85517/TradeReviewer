## Implemented

- Kept `RunningDraft` and the original required `RunningPrototype` props compatible. Added optional `experimentName`, `sourceExposure`, `onProgress`, `onDerive`, and `openResultsRequest` props. Shared exports are `RuntimeProgress`, `SourceExposure`, `PortfolioId`, and `PortfolioIdentity` in `running-model.ts`.
- `RuntimeProgress` reports the current status, M (`knownDate`), V (`viewDate`), optional exposure source/time, and independent `completed` state. The completed flag stays true when M is at the end even if V is being reviewed. `onDerive(progress)` stops playback and preserves the original runtime instance; the config drawer shows the inherited source-chain boundary without advancing the derived run.
- The global portfolio selector uses stable IDs that are separate from strategy IDs and names. The two configured strategy portfolios each have their own ledger, principal, holdings, and events while sharing the same calendar and V/M. Four explicitly labeled synthetic display samples are available from the all-combinations menu; each has a unique ID and independent scaled principal, while reusing only an existing EMA or quality calculation template. They do not claim to add strategy packages.
- Selecting a portfolio leaves V/M and chart mode unchanged, clears event details and selected-holding emphasis, and recalculates every visible portfolio surface from that portfolio's ledger. The price-symbol selector retains all synthetic symbols so EMA C can remain visible after switching to quality; a clear “当前组合未持有此标的” message identifies that state. Event drawer provides a direct close-and-focus-to-tabs path.
- Portfolio tabs implement Left/Right/Home/End selection and roving focus. The “更多组合” menu lists current portfolios and all synthetic additions, supports Arrow/Home/End/Escape, and reveals all four display samples. Tab and drawer-title DOM IDs include a React `useId` instance prefix so multiple retained experiment workbenches do not collide.
- The workbench now consumes the named `ResultsPrototype` component. A stage result opens from the current V, stops playback, and leaves M/ledger unchanged. The completion action is “查看回测结果”; playback and speed controls are hidden at the end, and T0 explains that no analyzable range exists yet. `openResultsRequest` from the experiment list either reopens the existing result entry when its portfolio/M/V source still matches, or starts a new entry at the current V after process progress changes.
- Results are retained hidden in the same mounted instance. Ordinary return restores the source portfolio, V/M, chart mode/symbol, holding selection, and saved viewport. Selecting a result event navigates to its process date/symbol and opens event detail; “返回来源结果” restores the prior process context and returns to the same result `entryId`, preserving result cursor/filter/scroll. Explicit process advance or normal date review leaves that event-return chain.
- Result cursor movement beyond the entry V reports exposure only; it does not advance M or execute trades. Exposure date is the maximum of result R, current M, and any prior exposure date, so recording an earlier R never reduces the farthest-known boundary.
- The T0 portfolio snapshot now uses the actual input date (`draft.date.slice(0, 10)`) while the market chart keeps its last complete daily bar as the cutoff. Thus an intraday Monday T0 can be shown as Monday on the net-value chart while the K-line's most recent known bar stays Friday. The default Friday 16:00 baseline is unchanged.
- Global keyboard playback is disabled whenever the results page is visible. A synchronous result-view ref and the process root's native `hidden` state both guard the document key handler, and `advance` checks the ref as a final state boundary. The playback timer also checks the result-view state, so a queued timeout cannot advance M after entering results.
