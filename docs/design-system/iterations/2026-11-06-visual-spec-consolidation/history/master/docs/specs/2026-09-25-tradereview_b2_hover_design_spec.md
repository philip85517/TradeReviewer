# TradeReview 首页修正版设计说明（B2）

## 1. 版本说明
本设计稿基于此前选定的**第二套方案**进行一次定向修正。

本次修正的唯一核心目标：

> 在“持仓总览”图表中，明确展示 hover 交互能力，确保用户把鼠标移动到曲线时，能够看到对应时点的盈亏信息。

因此，本次改动不是重新设计整页，而是在保留第二套方案整体结构与视觉风格的前提下，对**持仓图表交互表达**进行强化。

---

## 2. 设计目标
### 2.1 业务目标
用户进入“我的交易室”首页后，第一优先任务是照看当前持仓。

因此首页的第一个主图，不应该只是“有一条曲线”，而必须能够回答：
- 当前持仓组合在某个时间点的总市值是多少？
- 那个时间点的未实现盈亏是多少？
- 盈亏率是多少？
- 当日浮动如何？

### 2.2 交互目标
用户鼠标移动到曲线时，应立即理解：
- 自己正在查看哪个时间点
- 那个点对应的收益状态
- 图表是可读、可交互、可用于判断的，而不是纯装饰

---

## 3. 页面结构（保持不变）
首页仍然维持两段式结构：

### 第一工作区：持仓照看
包含：
1. KPI 指标卡
2. 持仓总览图
3. 资产分布图
4. 持仓明细表

### 第二工作区：历史交易与复盘
包含：
1. 已完成交易摘要
2. 已完成交易表现图
3. 盈亏贡献分解
4. 盈亏日历
5. 待复盘交易列表

---

## 4. 本次修正点

## 4.1 修正对象
模块：`持仓总览`

此前问题：
- 图表表现了趋势，但没有明确展示用户 hover 之后能看到什么
- 盈亏信息没有被清楚挂接到曲线交互中
- 用户无法从静态稿中判断该图是否真正支持“看时点盈亏”

本次修正后：
- 增加 hover 状态
- 增加垂直参考线
- 增加高亮数据点
- 增加 tooltip 浮层
- tooltip 内明确展示盈亏相关信息

---

## 4.2 Hover 交互定义
当鼠标进入“持仓总览”图表区域时：

### 状态变化
1. 曲线上出现一个被吸附的高亮点
2. 当前 x 轴对应位置出现一条垂直参考线
3. 浮出 tooltip

### Tooltip 内容
tooltip 必须至少包含以下字段：
1. 日期
2. 总市值
3. 未实现盈亏
4. 未实现盈亏率
5. 当日盈亏

### 视觉规则
- 正收益：绿色 / 青绿色
- 负收益：红色
- 文案采用深色浮层中的高对比文本
- tooltip 尺寸适中，不遮挡主要走势信息
- tooltip 与参考线、高亮点视觉联动

---

## 4.3 信息优先级
tooltip 内部推荐层级：

### 第一层（最重要）
- 未实现盈亏金额

### 第二层
- 日期
- 总市值
- 未实现盈亏率

### 第三层
- 当日盈亏

原因：
对于交易者来说，查看 hover 的第一诉求是“这个时间点赚了还是亏了多少”；
总市值与盈亏率用于辅助判断；当日盈亏则用于补充短期波动信息。

---

## 5. 视觉设计原则

## 5.1 保持第二套方案的专业工作台特征
- 深色背景
- 蓝青色主视觉
- 高密度但不压迫的信息组织
- 强调卡片化与图表化

## 5.2 不做无关重设计
本次修正不应改变：
- 页面整体布局
- 右侧资产分布结构
- 下方持仓表结构
- 历史交易与复盘区结构

这样做的原因是：
本轮目标是修正交互表达，而不是重开一轮整体视觉方案比稿。

---

## 6. 图表交互规范

## 6.1 默认状态
- 不显示 tooltip
- 不显示参考线
- 折线保持正常视觉状态

## 6.2 Hover 状态
- 显示高亮点
- 显示垂直参考线
- 显示 tooltip
- tooltip 随鼠标移动更新

## 6.3 Mouse leave
- tooltip 消失
- 高亮点消失
- 参考线消失

## 6.4 切换后的行为
当用户切换以下条件时，hover 状态应重置：
- 时间范围（近1月 / 近3月 / 今年 / 全部）
- 粒度（日 / 周 / 月）
- 实盘 / 模拟盘
- 账户范围

避免出现：
- tooltip 停留在旧日期
- 实盘 hover 信息残留到模拟盘
- 周/月切换后仍显示日级别内容

---

## 7. 数据口径建议
为了让 hover 信息具备一致性，建议口径如下：

### 总市值
该时点组合持仓市值总和

### 未实现盈亏
该时点持仓组合相对持仓成本的未实现盈亏

### 未实现盈亏率
未实现盈亏 / 持仓成本

### 当日盈亏
该时点相对上一统计点的变化，或当日估值变化

### 粒度说明
- 日：按日收盘或日终估值
- 周：按周末或周最后一个交易日估值
- 月：按月末或月最后一个交易日估值

---

## 8. 为什么这是改进
本次修正后的改进价值主要体现在三点：

### 8.1 图表从“展示趋势”升级为“支持判断”
用户不仅能看走势，还能读取关键时点的盈亏结果。

### 8.2 首屏更符合“持仓照看”任务
持仓图表本来就是首屏主视觉，补足 hover 盈亏后，用户能真正用它管理仓位，而不是只把它当作背景趋势图。

### 8.3 静态稿更能准确传达未来产品行为
在设计评审阶段，团队可以直接理解：
- 图表支持交互
- hover 是有效的
- 盈亏是首要显示信息

---

## 9. 验收标准
修正版视觉稿应满足：

1. 一眼可见这是第二套方案的延续，而非完全换版
2. 持仓总览图中明显存在 hover 状态
3. hover 时能明确看到：
   - 日期
   - 总市值
   - 未实现盈亏
   - 未实现盈亏率
   - 当日盈亏
4. 盈亏数字具备正负语义色
5. tooltip 与图表视觉体系一致
6. 页面整体仍保持专业、克制、可实现的金融产品风格
