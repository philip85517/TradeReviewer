文档 1.0 · 复盘页视觉规范

复盘页视觉规范 V1.0

2026-10-23 论述结构修订 · 复盘工作区 · 设计提案

复盘工作区要帮助用户还原“当时知道什么、据此作了什么判断、执行后发生了什么”。本版以主图为观察中心，用阶段侧栏承载计划与评价，用明确的时间边界隔开当时信息与后续结果，让观察、记录和核对能够在同一工作区内连续完成。

这份规范先解释为什么这样组织复盘，再规定各区域如何呈现和协作。第一至三章确定设计方向、空间结构与视觉语言；第四至七章沿着判断、回放、记录、保存的过程说明状态与数据；第八、九章处理设备适配及导出、返回；第十章给出元素追踪与验收依据。规则表用于落实前文的决定，画板用于展示对应状态，引用资料用于追溯既有约束。

范围仅限复盘工作区，首页、历史列表和交易库内部页面不在本轮改版范围。本版交付视觉方案与可实施的状态契约，新增布局与信息编排仍为待审阅的设计提案；旧版已确认的三阶段、数据边界、原始成交只读和回合完成规则继续有效。画板使用合成数据，图内控件是静态示意，不能作为真实行情回放、数据库保存或导出已经实现的证据。

一、依据、目标与设计取舍

本版选择“主图持续可见、侧栏随阶段组织”的工作方式。目标是让用户在记录判断时仍能看到依据，在回看结果时仍能区分原计划与实际执行。视觉优化围绕这条复盘过程展开，已有的阶段、记录和数据约束构成方案边界。

设计目标如何转化为布局选择

工作区需要同时解决四件事：观察与编辑期间保留主图；分别说明行情截止、成交截止和记录归属；让每个阶段首先呈现适用字段；区分草稿保存、快照留存和正式完成。后续布局、颜色和状态规则都服务于这些目标。

因此，本版保留主图与阶段侧栏，并将身份、时间和动作放在稳定位置。全屏图表加覆盖抽屉会遮挡价格轴，三阶段纵向表单会压缩主图，均不采用。侧栏和次要内容可以收起，以换取观察空间，但完整字段、历史记录和工具入口必须继续可达。

下面的调整集中于信息位置和展开顺序。每项调整同时列出需要保留的约束，便于评审时区分视觉优化与业务变更。

二、工作区结构与空间预算

工作区的空间分配首先保障看图与编辑能够并行。身份、时间、输入和回放动作各有固定区域，用户切换阶段或处理异常时，可以继续找到原来的观察位置。布局为此采用紧凑的常驻栏位，把主要面积留给主图与当前阶段侧栏。

先划分职责，再分配尺寸

从上到下依次是身份与阶段顶栏、可知截止与来源行、主图和阶段侧栏、底部回放条。左侧沿用应用导航；主图内的工具列和价格轴分别占位。默认焦点位于图表观察区，编辑计划后留在该字段，避免中断输入。

阶段侧栏承载当前任务，记录列表打开时替换同一位置的内容，并提供“返回当前阶段”。关闭列表只返回阶段视图。这个安排减少多个详情区同时展开的占用；迁移旧底部详情时，必须逐项保留功能，不能以移动容器为由删减记录能力。

画板按100%尺寸表达空间关系。应用导航只用于说明可用宽度，其页面内容与交互不属于本次改版。

状态变化时保持观察位置

空间稳定的重点是避免界面反馈打断判断。悬停只改变表面，不改变边框厚度或盒尺寸；加载保留主图和侧栏槽位；字段错误使用就近说明行，并由侧栏内部滚动承接。保存错误通过既定入口提示，详细恢复操作留在侧栏。

侧栏开合可以改变图表宽度，但不能隐式执行fitContent、推进时间、改变价格范围或让标签进入侧栏。记录列表滚动和阶段切换不推动底部回放条。空间如何变化与观察到了哪个时点应分别管理，后者按第五章的时间契约恢复。

三、公共视觉与复盘专用语义

复盘视觉需要让用户迅速分清操作、计划、成交与结果。公共控件沿用全站语言，复盘对象再通过文字、形状和线型补充含义。这样既能保持跨页面的一致性，也能避免把按钮选中、K线涨跌和财务盈亏误读为同一件事。

先分清语义，再应用颜色

当前阶段、选择态和焦点使用公共蓝色；计划使用带名称的琥珀虚线；实际成交使用菱形并标注“买入/减仓/清仓”；判断使用蓝色Text及连接线。财务盈亏同时给出正负号和币种。买卖方向、计划和净盈亏必须由内容与形态共同说明，颜色只承担辅助识别。

K线继续尊重用户的 colorScheme：默认青涨红跌 #26A69A/#EF5350，其他已保存方案照旧。工作区统一财务和控件颜色时，不替换用户图表配色。

用文字和尺寸建立阅读层级

证券身份、阶段标题、当前字段和辅助说明按阅读任务分层。界面采用系统无衬线中文后备，数字启用tabular-nums，以保持数值对齐；不将整页中文设为等宽字体。若产品继续加载Geist，承接既有字体变量，不新增字体下载依赖。

证券身份使用18/24px，侧栏标题16/24px，正文、输入和按钮14/20px，辅助文字与坐标轴12/16px。Text默认14px，并保留用户原有12/14/16/18/24/32px样式。工作区不使用28px绩效卡作为常驻主视觉，以免结果摘要抢占观察空间。

公共规则的引用边界

共享控件的完整状态和取值以V2.5视觉基础及控件状态手册为单一来源。本章负责说明它们在复盘中的用途；通用样式发生变更时，应先核对公共来源，再更新这份映射。

四、三阶段信息层级

三阶段分别回答“入场前如何计划”“持仓时如何判断”和“结果出现后如何评价”。侧栏随问题变化，主图始终保留观察依据。信息层级的取舍是先呈现当时可知、当前可编辑的内容，再展开来源和全量记录，防止后续结果干扰早期判断。

入场前：先形成计划，再核对风险

入场前默认打开计划侧栏。字段按方向/币种语境、计划入场、初始止损与目标、规模输入、资金基数与来源、派生风险排列。资金详情默认折叠，摘要保留“参考资金”及金额；展开后可查看币种、时点和手填/可信快照来源。

规模提供数量、金额、仓位比例三种模式，一次只有一个主输入，切换时换算且不偷偷归零。计划用于帮助判断，因此缺计划仍可看图和推进，不为凑齐R而强迫填写虚构数字。有效多头满足止损<入场<目标，空头相反；无效值就近解释，且不绘制计划线。

主图只显示首次入场前已完成的行情，真实买入菱形、退出、最终盈亏、已平仓状态及未来范围均不出现。画面标明“复盘补记”；此前已看过结果时显示“已看后续后补记”，切回早期仍保留这一来源。

持仓过程：判断变化与初始计划分别留存

持仓阶段优先给主图留出观察空间，因此侧栏默认收起。用户展开后，依次看到当前已知仓位与成交、只读初始计划和计划修订入口。图上的Text承载判断正文，侧栏不要求重复录入同一份心态记录。

普通逐根推进保持Text的记录归属，只有“下一决策”等明确选择才改变记录对象。新判断可以继承旧标注，历史快照保留原文；调整计划需新增带时点和原因的修订，不能覆盖初始风险基准。此阶段不展示最终执行评分或未揭示的退出结果。

事后复盘：对照事实，逐次评价退出

用户主动展开结果后进入事后阶段，侧栏默认打开。先以摘要给出原计划与风险基准、实际成交及结果，再提供退出决策选择、是否提前、原因和执行符合度。全量成交和评价标签可以继续展开，评价输入应在核心区域可达，不能排在几屏只读摘要之后。

每次减仓、清仓都有独立评价，选择项显示日期、动作、数量和价格。“是否提前”提供是/否/不确定；未填写为“未评价”，不自动归为“否”。原因与执行符合度分别填写：原因包括计划内分批、结构失效、风险收缩、情绪影响、资金需求、其他，“其他”需说明；符合度包括按计划、偏离、无原计划、未评价。系统不能凭盈利替用户判断执行对错。

原计划与真实成交使用只读行及来源标识。切换退出决策前保留本地草稿，再加载目标决策数据，避免评价串值。

特殊进入状态：说明观察和成果的边界

未平仓回合可以主动查看截至当前可用行情的事后观察，但需标明“尚未平仓”。已实现部分与持仓浮动分别呈现，不给出最终回合净额和最终R。

已完成成果进入时，显示成果版本及“查看成果/继续编辑”的语境。“重新开始回放”作为明确的次级动作，只把游标和视野重置到约定起点，保留已看后续来源、快照、原计划与正式成果。

五、回放、时间与未来信息契约

回放要让用户相信当前画面只包含该时点允许知道的信息，同时能够找回当时的记录。为此，行情、成交和记录分别管理，再在动作发生时同步呈现。推进一根K线不应自动把判断归到另一笔决策，回看早期也不能抹去用户已经看过结果的事实。

用三个边界描述当前观察状态

M表示行情可知截止，X表示成交可知截止，D表示当前记录归属。M与X分别保存，D不能只由当前K线推导。阶段、M、X、所选决策或快照及相应画面应一次更新；侧栏、工具菜单和焦点保持为独立界面状态。

这一拆分允许用户持续观察而不被迫频繁留存，也允许同一K线内的多笔决策独立访问。代价是每个动作都必须明确影响哪些状态，不能用一个泛化的“跳转”覆盖推进、回看、预览和恢复。

从整幅画面限制未来信息

未来信息边界覆盖K线、摘要、tooltip、交易提示和坐标轴。未来区不绘制淡化K线，不利用未来高低点定轴，也不显示未来成交提示。切换周期时，只能呈现新周期中已完成且可知的K线，不能因此展示未完成的当日全量行情。

用户主动展开结果或完整历史后，应保留来源类型与时间；回到早期仍带有“已看后续”的语境。隐藏未来画面与记录用户已知经历是两项同时成立的要求。

让推进、暂停与末尾都可感知

播放默认每秒一根。编辑Text、输入数字或中文IME组词期间暂停播放，并屏蔽回放快捷键，防止输入造成意外推进。每次前进都必须使新增K线或目标成交进入可见主图，包括越过原观察窗口的情况。

到达末尾后，下一根与播放禁用，并就近显示“已到最后可用行情”；若仍有可定位决策，单独说明可用动作。缺行情时显示原因和重试入口，不绘制零值曲线。验收应直接看到新增内容，不能只检查游标文字是否变化。

六、Text、记录与结构化字段

记录需要同时保留判断正文、发生语境和可计算的数据。Text负责表达判断，记录列表负责找回决策与版本，结构化字段负责计算和核对。三者分工后，用户可以顺着图表阅读，也可以回到具体对象继续编辑，并追溯数值来源。

Text承载判断，锚点保留上下文

图上默认展开一张短卡，最多同时展开两张，以减少对行情的遮挡。长文先显示摘要及明确的展开动作，全文仍可编辑。锚点可以是时间/价格或归一化画布位置；拖移只改变位置，不改变记录归属，并优先避开当前K线和价格轴。

按T再点击图表进入编辑。Enter用于换行时不触发播放，Esc取消当前编辑时按既有保存规则保留可恢复内容。文字显示记录对象及来源；从后期回到早期补记，继续保留“已看后续”标识。

后续编辑生成修订，历史快照引用原修订。Text、计划数值、评价和标签分别结构化保存，图片只承担展示，不能替代这些可追溯对象。

记录列表组织对象与版本

记录列表按三阶段归组，但组内仍能访问每笔加仓、减仓、清仓及多个快照。侧栏行至少显示决策身份、观察时点、快照版本/次数和补记来源，帮助用户在选择前判断自己将打开什么。

当前选中与正在编辑采用不同状态。编辑已有快照时显示“更新此快照”和“返回工作图”；删除保留原撤销入口，重新排序不能改变稳定身份。阶段代表图用于呈现阶段成果，全部记录列表用于查找过程，两者在迁移到侧栏后仍需分别保留。

数值先说明口径，再呈现结果

金额显示原币，价格精度遵守证券报价单位。留空字段保存为null，不渲染为0、false或“否”；缺资金时比例待计算，缺费用时净额和净R待核算，无效方向或零风险不计算R。摘要可用万/亿并允许查看全值，输入和复制保留完整精度，长数值不能靠缩字隐藏。

实际R使用冻结的初始风险基准，事后修改止损不能改变分母。留存计划时应同时冻结风险基准，保证后续评价与当时承担的风险一致。

七、保存、异常与完成

用户需要知道当前编辑是否安全、哪个版本可以追溯、整轮复盘是否已正式完成。这三种承诺分别由草稿保存、快照留存和完成动作承担。异常处理首先保留输入和观察点，再提供恢复路径；反馈应清楚，但不能把主图挤出视口。

三种动作承担不同承诺

自动保存保护连续编辑，留存快照冻结某个时点的证据，完成回合产生满足既有条件的正式成果。界面应使用明确名称和真实状态，让用户能够判断当前成果处于哪一步。

动作/状态 用户看到什么 必须真实发生什么

留存当前快照 当前记录新增可追溯版本 冻结图、Text、计划/评价/成交/指标引用组合

先保留本地内容，再处理失败与冲突

保存状态必须来自真实请求，服务端确认后才显示“已保存”，不能用定时动画模拟成功。保存失败时保留输入与当前观察点并提供重试。顶栏维持稳定状态入口，详细恢复操作放在侧栏。

版本冲突时，先保留本地内容，再提供比较和显式重新载入。重新载入前说明将替换当前未保存输入；取消继续保留本地，确认后字段、派生数值及保存状态同步至服务器版本，随后可继续编辑保存。行情重试与重新载入复盘文档各有目标，应分别命名。

八、响应式、触控与键盘

设备适配要延续“看图时能记录”的工作方式。可用宽度不足时，工作区改变区域排列，保留趋势和当前输入的联系；交互尺寸与文字可读性继续优先。触控和键盘规则则保证不同输入方式都能到达、识别并退出当前操作。

空间不足时改为上下布局

工作区宽度不足1102px时采用上图下表单。编辑态顶部趋势区默认220px，允许在200–240px内按实际视口分配；保留价格轴以及当前、入场、止损、目标价格的语境，下方表单独立滚动。

这一安排用纵向空间承接字段，避免把图表和表单同时压窄。工具保留选择、Text和更多，其余工具仍从更多进入；缩小设备不能删减能力。触控命中至少44px，同样适用于宽屏触控设备。

用容器与输入环境核对适配

布局判断依据工作区容器，导航展开和软件键盘出现都需要重新考虑可用空间。下表是对照场景，其中软件键盘按visual viewport保留当前字段和趋势上下文。

键盘顺序与焦点恢复

Tab依次经过顶栏、阶段、工具、当前侧栏和回放。图标提供名称，选中状态提供aria-pressed/current语义，保存反馈使用适当的live region。Esc只关闭当前菜单或编辑层，并将焦点送回触发点，不级联退出整个工作区。

输入字段、IME和Text编辑拦截回放快捷键，避免输入与播放争抢按键。支持减弱动效，即使关闭动画也应能理解状态变化。

设计预期与设备证据分别记录

窄屏画板表达空间与操作预期。正式实现时，应分别记录鼠标、键盘、模拟触控和物理触控证据，软件键盘需要真机检查，不能用静态稿或模拟触控替代。

九、导出与返回边界

导出和返回是复盘工作区向外移交结果与上下文的两个出口。导出需要保留判断所依据的时点与版本，返回需要保留用户从哪里来以及当前编辑是否安全。两者都应延续工作区内的状态含义，避免离开当前画面后丢失证据或误解保存状态。

导出围绕三阶段组织成果

导出使用现有对话框模式，以三张已留存阶段图和一张总结表构成主要叙事，默认16:9。额外决策进入附录，不能因四页结构而被删掉。三张图尽量采用相同周期与观察窗口，便于对照计划、过程和结果。

可比性服从原始观察边界

统一构图不能改变早期知道的信息。导出保留轴、已揭示行情、Text、计划和成交，移除绘图工具、录入侧栏、回放条与焦点框；不得用最终高低价重算早期轴。旧快照无法同窗时，保留原构图并注明范围差异。

缺少阶段时直接显示缺失，不从最终图伪造早期图；存在未留存修改时提示“导出不含当前未留存编辑”。图片支持高分辨率，PPTX中文字与总结表可编辑，不承诺K线逐点编辑。既有Markdown+图片方式继续可用，导出失败不改数据，导出成功也不自动完成回合。

返回时恢复来源与编辑语境

返回原回合集时携带回合/练习身份，恢复所选行、筛选、排序、页码、滚动与焦点。来源失效时回到来源容器标题并解释原因，让用户仍能理解当前所在位置。

离开时若保存尚未完成，提供等待、重试或明确保留本地草稿的路径，不能用虚假“已保存”消除离开阻碍。以上规定的是工作区与来源页面之间的交接合同，不改变首页或历史列表布局。

十、元素映射与交付验收

验收需要分别回答“设计是否完整”和“产品是否按设计运行”。本版用元素映射追踪原需求，用独立门槛约束后续实施，让视觉调整中的每项能力都有去处，也让静态设计证据保持清楚的适用范围。
