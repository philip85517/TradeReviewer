# QA 单元测试编写规范

本规范用于交易导入、持仓回放和收益计算相关测试。目标是让测试能够发现“原始数据解析成功，但业务含义错误”的问题，而不只验证页面能渲染或记录数量不为零。

## 1. 测试要覆盖正确的 seam

一个导入规则至少拆成以下三层验证：

| 层级 | 必须验证 | 典型反例 |
| --- | --- | --- |
| PDF 行解析 | 字段、方向、费用、余额、来源行是否准确 | 缺失余额被当成 0；卖出数量符号错位 |
| 持仓重建 | 期初/期末快照与成交变动是否一致 | 首行卖出被当成空头开仓；快照重复累加 |
| 交易回放/收益 | 方向、剩余数量、平仓状态、收益可用性 | 负向库存被展示为真实空头；无成本仍计算收益 |

只测 dispatcher 的“识别成功”不算覆盖解析规则；只测解析结果的记录数也不算覆盖回放。发生过数据错误时，至少要有一条从解析结果进入回放的集成回归测试。

## 2. 领域不变量优先于实现细节

测试名应描述用户可观察的业务结论，断言应优先使用下列不变量：

- 未知值必须保持未知。缺失、空白、不可解析不能默认成 `0`、空字符串或合法日期。
- 对有余额证据的成交，期初库存满足 `期初库存 + 成交变动 = 成交后证券余额`。
- A 股及 A 股 ETF 不允许通过回放得到负向持仓。余额与成交量矛盾时必须标记复核/历史不完整，不能解释为空头。
- 显式的证券余额 `0` 与缺失证券余额是两种不同证据：前者可以作为清仓快照，后者不能确认成交前库存。
- 成交数量、价格、费用、现金变动的符号和金额关系必须互相校验；异常行应跳过并留下诊断。
- 交易市场决定 ETF 的归属市场；ETF 内含标的不改变 A股、港股或美股的市场归属。
- 没有可信成本或完整历史时，收益可以不可用，但不能用猜测值补齐。

每条解析规则至少从“正常、缺失、显式零、矛盾、极端量级”中选择适用样例。金融数量和金额使用十进制断言，不使用浮点近似或字符串排序替代数值比较。

## 3. Fixture 编写规则

Fixture 是测试输入契约，不是方便构造对象的默认值集合：

1. 具有业务意义的字段必须显式填写，包括证券余额、成交金额、费用、现金变动和市场。
2. `undefined` 只用于刻意模拟原始 PDF 没有该字段；不能在 fixture helper 中写 `value ?? "0"` 来“补齐”它。
3. 至少分开维护以下样例：余额缺失、余额显式为 0、余额与成交量矛盾、首行卖出、同日多笔成交、跨页表头、非交易流水。
4. 每个样例使用匿名代码、账号和名称；真实 PDF 只通过本地环境变量接入，不提交仓库。
5. Fixture 应保留页码、行号和源顺序，避免测试绕过来源证据直接拼装最终 `TradeExecution`。
6. 重复成交必须用不同源行；不要用去重后的对象掩盖重复导入问题。

## 4. 极端值矩阵

对解析器或重放器新增字段时，至少评估以下矩阵中适用的组合：

| 场景 | 期望结果 |
| --- | --- |
| 首笔买入 + 余额等于成交量 | 期初为 0，期末为成交量 |
| 首笔卖出 + 余额为 0 | 推导为已有多头库存并平仓，不创建空头 |
| 买入 + 余额小于成交量 | 标记不一致和复核，不生成负向期初 |
| 任意成交 + 余额缺失 | 保留成交，历史标记不完整，收益不可盲算 |
| 卖出 + 显式余额为 0 | 作为可信清仓边界保留 |
| 数量/金额为负、零、超大值或非有限值 | 按方向和格式规则拒绝或标记诊断 |
| 同日无时间的买卖和快照 | 使用明确的边界排序规则，不能依赖数组偶然顺序 |

对于每个曾经出现过的生产事故，必须把最小复现样例保留在单元测试中，并同时断言“坏结果不会出现”和“可接受的复核信号会出现”。

## 5. 测试驱动和验收顺序

修复或扩展规则时采用红—绿—重构：

1. 先用最小 fixture 写出旧行为会失败的断言。
2. 只实现让该断言通过所需的规则。
3. 再补同一 invariant 的相邻边界，并运行相关 parser、evidence、episode 测试。
4. 有真实样本时增加可选 corpus 测试；默认未设置环境变量时安全跳过。
5. 最后执行类型检查、构建、全量测试和 `git diff --check`，如有既有失败必须单独记录，不能把它们归入本次通过。

建议命名格式：`<行为结论> when <异常或边界输入>`，例如：

```ts
it("reconstructs a first A-share sell as a long inventory close, not a short", () => {});
```

## 6. 真实 PDF corpus 约定

真实账单测试使用环境变量传入目录，例如：

```bash
CHINA_MERCHANTS_CORPUS_ROOT="/path/to/local/A股" \
  npx vitest run app/lib/import/china-merchants-corpus.test.ts
```

测试只输出文件数、页数、记录数、证据数和复核计数等汇总，不输出账户号、完整文本或逐笔交易。每份文件至少检查格式识别、记录 ID 唯一、数量/价格为正、月结单证据存在，以及 A 股持仓不为负。真实语料测试不能替代匿名 fixture；两者分别承担格式回归和极端值回归。

## 7. 完成检查清单

- [ ] 测试覆盖解析、持仓重建和交易回放三个必要 seam。
- [ ] 缺失值、显式零、矛盾值没有被同一个默认值隐藏。
- [ ] 至少有一个极端值样例能在旧实现上红灯。
- [ ] 失败结果包含可定位的诊断、来源行或复核状态。
- [ ] 金融方向、市场归属和收益可用性均有业务断言。
- [ ] 真实样本测试可选、脱敏且不写入个人路径。
- [ ] 记录聚焦测试结果；既有失败与未执行项明确列出。
