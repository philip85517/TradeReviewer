# 聚焦复盘设计

用户已批准 `docs/research/2026-09-10-product-review.md` 并要求实现。本设计明确其工程边界；采用现有工作台渐进改造，不新增独立交易终端。

## 约束

- 保留原始成交、账户隔离、费用/持仓准确性边界、回放未来信息边界和旧笔记。
- 只包含现有支持的股票和 ETF；不扩大导入资产范围。
- 本地服务使用独立端口和数据库；不修改其他任务的服务。
- 不混算实盘/模拟、不同币种或不同模拟运行；统计必须说明范围和样本。
- 历史未记录的计划不能被自动补成事前计划；过程评价与盈亏分开。
- 兼容现有 JSON 笔记存储；可选扩展字段，旧数据不要求迁移重填。

## 1. 数据与事实

基础总结使用可核对的已平仓回合和费用，不依赖行情。路径统计单独校验回合区间日线；缺日线的路径指标为 null，缺小时线不阻断日线或成交总结。日线估计边界和缺失原因可见。用户观察与规则不依赖行情。
统一交易性质显示且不改变历史 scope/episode ID；左侧成交揭示与图表使用相同的时间精度边界，日精度显示日期及未提供成交时刻。

## 2. 三问与连续复盘

两个笔记入口共用自动保存编辑器。默认三问：关键决策（阶段、依据、可选证据时点）、计划符合度（符合/偏离/无计划/未评估）、下次行动。旧的完整计划、风险、心理、评分、标签在补充分析中可读写。保留旧规则文本，避免复制两份下次行动。
扩展 `EpisodeReviewRecord.review` 可选字段：`keyDecision: string`, `decisionStage: entry|management|exit`, `evidenceAt: string`, `planAdherence: followed|deviated|no-plan|unassessed`, `deferredReason: string`, `ruleStatus: observing|adopted|revised`, `ruleTracking: boolean`, `ruleChecks: Array<{sourceEpisodeId:string; sourceUpdatedAt:string; ruleText:string; result:followed|deviated|not-applicable}>`。`reusableRule` 继续承载下次行动；字段可选。规则快照防止原规则修改篡改历史评价。
完成需要下次行动、关键结论或明确跳过原因；保存成功后才导航，失败停留可重试。提供重新打开复盘。队列按回合、当前过滤范围和时间排序，支持待复盘/已复盘/全部；跳过原因保存在笔记并暂时排出待复盘队列，可从全部重新打开。

## 3. 规则与阶段总结

“追踪这条规则”复用笔记数据，不新增独立规则数据库。阶段总结从记录派生已追踪规则及相关后续检查；可跳回来源回合。在后续复盘中仅显示同市场、同实盘/模拟范围的用户规则，用户明确判断适用性，不自动归因。
阶段总结按全部/最近30天/最近90天或自定义日期筛选，并明确以回合结束日期（未平仓以开始日期）为范围依据；按交易性质及币种分组汇总，展示复盘覆盖率、基础结果、过程评价与来源。支持用户记录阶段“保持/修正/下期重点”，使用现有 UI 偏好持久化存储的独立键并绑定范围，恢复时不覆盖草稿；不自动编造三条结论。
模式洞察仍可展开查看，规则建议默认折叠；标签确认可以从正在复盘的回合处理。计算版本、证据列表默认折叠，“高可信”改为样本分级中性表达。

## 4. 界面

交易库默认待复盘回合入口，保留按标的浏览和高级筛选。导入方式合为一个菜单。默认图表聚焦当前回合附近；完整历史和训练模式明确区分，保留已有下一成交。三问的结束操作容易找到。窄屏可读，不强制完整计划或 R。

## 验证

覆盖：无小时线仍总结、无日线仅路径缺失、异常费用/持仓不进入不可信收益、性质和日精度一致、自动保存失败不跳转、切换回合不串笔记、旧笔记兼容、队列过滤与下一回合、规则快照和关联范围、阶段摘要刷新恢复、实际网页走完短流程。独立测试数据库留存原数据备份，开发后不改变正式成交记录。
