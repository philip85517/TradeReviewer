## Problem Statement

> 2026-09-30 界面增补：[稳定工作台设计](2026-09-30-strategy-stable-workbench-design.md)吸收用户提供的 TradingView 控件参考，补充固定布局与跨状态验收。只调整后续交互/视觉契约，不撤销本文数据、执行、独立资金和真实持久化要求。

用户希望复用交易复盘系统已有的标的与行情集合，站在任意历史时点，用一套完整策略构建 Portfolio，再观察未来一周至一年内的组合表现、调仓与再平衡效果。现有“策略”入口尚未开放；已有复盘主要围绕真实/导入模拟成交，不能替代从选股、仓位决策到模拟成交的新运行。

如果只有筛选表单与最终收益，用户无法理解策略在每一天如何产生决策。如果只遮住图表，却使用今天的市值、后来公布的财报、完整周线或最终存活的证券池，结果也无法代表当时可以做出的决定。

## Solution

建立“策略实验”工作区：选择历史时点、标的集合与一个或多个策略包，各自生成独立 Portfolio，在同一时间轴上逐日模拟，并以一致资金、数据和执行口径比较结果。

用户明确要求：

- **R01 数据复用**：复用整套复盘的底层交易标的与数据集合，不为策略建立另一套抓取/证券身份体系。
- **R02 历史构建**：任意历史时点创建一个或多个策略组合，可隐藏后续走势与财报，模拟当时决策。
- **R03 多期限回测**：一周、一个月、三个月、半年、一年，支持每日市场 bar 逐根展开。
- **R04 调仓与再平衡**：按指定仓位策略调整标的、权重、现金。
- **R05 结果分析**：组合/仓位走势、回测结果、统计，以及多个组合的对比。
- **R06 插件与策略包**：策略可通过插件扩展；“市值 > 200 亿、日交易额 > 2000 万、周线趋势向上、回撤 EMA20”等组合规则以完整策略封装，不以通用条件搭建器为主要交互。

本稿提出的默认设计：首期采用日线决策、下一可交易日开盘执行、单市场单计价币种的多头股票/ETF 组合。不同市场可分别建组合，但不能悄悄把这一范围缩减解释为已完成所有市场数据支持。非交易时点按已完成数据解释；缺失历史可知证据时显示具体能力限制。以下默认方案均可在规格审阅时修改，并非用户已逐项确认。

桌面优先保持“当前时点、主图、推进动作”同屏，持仓和事件为辅助区；默认展示一个所选组合的标的主图，其他组合通过对比净值与切换进入，避免同时堆叠大量 K 线。窄屏按时间控制、图表、持仓、事件顺序组织。未提供参考图，本稿不是像素级视觉批准；实施前须补足各状态画板、布局尺寸与元素契约，不能由组件实现者自行简化。

完整旅程：策略入口 → 新实验 → 历史时点/数据预检 → 选择策略包 → 预览与创建组合 → 下一日揭示真实 K 线及模拟成交 → 自动/逐步调仓 → 暂停保存 → 返回列表并重开 → 运行到期限 → 结果对比 → 点击调仓回看原因。

## User Stories

1. 作为复盘用户，我希望在“策略”入口查看实验与策略库，以便集中管理研究。
2. 作为复盘用户，我希望复用已有证券身份、行情和历史数据，以便避免重复导入和口径不一致。
3. 作为研究者，我希望明确标的集合来自已导入交易、自选集合还是历史证券池，以便理解样本边界。
4. 作为研究者，我希望看到使用事后交易集合选股的提示，以便不把它误认为无幸存者偏差的全市场研究。
5. 作为研究者，我希望选择任意历史日期和时间及其时区，以便重建对应决策环境。
6. 作为研究者，我希望非交易日和盘中选择显示实际可用截止，以便知道使用了哪一根完整日线。
7. 作为研究者，我希望隐藏未来 K 线、财报、统计与成交，以便进行历史盲看。
8. 作为研究者，我希望知道财报首次披露时间和版本，以便避免使用后来修订的信息。
9. 作为研究者，我希望数据缺失、覆盖不足和预热不足有明确原因，以便修复后再运行。
10. 作为策略使用者，我希望选择打包策略，以便不逐个搭建市值、流动性和技术指标条件。
11. 作为策略使用者，我希望阅读策略规则、单位、阈值、版本和示例，以便理解其含义。
12. 作为策略使用者，我希望看到每个标的入选或排除的依据，以便审查规则执行。
13. 作为策略使用者，我希望一个实验选择多个策略，以便在相同历史环境比较组合。
14. 作为策略使用者，我希望每个组合独立使用初始资金和现金，以便比较不会互相影响。
15. 作为策略使用者，我希望预览目标持仓、权重和剩余现金，以便确认策略形成了什么组合。
16. 作为策略使用者，我希望无候选时保留现金并明确提示，以便不被虚构持仓误导。
17. 作为策略使用者，我希望选择持有不动、定期再平衡或策略触发调仓等封装预设，以便比较仓位管理方法。
18. 作为研究者，我希望选择一周、一个月、三个月、半年或一年，以便比较不同观察期限。
19. 作为研究者，我希望看到实际起止交易日期与数据覆盖，以便理解期限落在休市日或超出可用范围的情况。
20. 作为研究者，我希望每次推进一个交易日时真实图表揭示新 bar，以便理解组合当天发生的变化。
21. 作为研究者，我希望控制播放、暂停和运行至终点，以便在过程学习与快速计算之间切换。
22. 作为研究者，我希望逐日运行和一次跑完产生相同结果，以便相信两种模式属于同一模拟。
23. 作为研究者，我希望切换标的、周期和侧栏不会推进历史时点，以便不意外看到未来。
24. 作为研究者，我希望在图表初始窗口之外继续播放仍能看见新增 bar，以便持续跟踪过程。
25. 作为研究者，我希望调仓原因、目标与实际执行分别展示，以便区分策略意图与成交限制。
26. 作为研究者，我希望费用、滑点、整手、现金和交易限制影响模拟执行，以便结果口径透明。
27. 作为研究者，我希望停牌、退市、分红和拆股得到明确处理，以便不因数据缺失产生假收益。
28. 作为研究者，我希望每一天看到持仓市值、现金、净资产和各标的权重，以便理解风险集中度。
29. 作为研究者，我希望区分已平仓回合净盈亏和持仓浮盈亏，以便不把未实现结果当成落袋利润。
30. 作为研究者，我希望看到净值、累计收益、回撤、换手与成本，以便从多个角度评估结果。
31. 作为研究者，我希望结果注明样本区间、指标公式与不可计算原因，以便不被空值或短样本误导。
32. 作为研究者，我希望多个组合在同一游标和比较口径下展示，以便定位策略差异。
33. 作为研究者，我希望可选基准与组合使用相同币种、时间和数据质量口径，以便合理比较。
34. 作为研究者，我希望主动看完整结果后保留“已看后续”记录，以便回到过去时不会伪装首次盲看。
35. 作为研究者，我希望回看历史不覆盖已完成结果，以便安全检查决策。
36. 作为研究者，我希望修改时点、策略或初始配置会创建新运行，以便保留原实验的可复现性。
37. 作为研究者，我希望暂停、返回、刷新和重开能恢复游标、持仓与未执行计划，以便持续研究。
38. 作为研究者，我希望保存失败保留输入，版本冲突可显式恢复，以便不损坏实验。
39. 作为研究者，我希望重复点击、重试和服务重启不产生重复成交，以便账本可靠。
40. 作为研究者，我希望行情刷新或插件升级不改写旧结果，以便重现过去运行。
41. 作为策略开发者，我希望通过稳定插件契约提供选股与仓位策略，以便扩展而不修改工作区主流程。
42. 作为策略开发者，我希望声明数据依赖、适用市场和确定性版本，以便宿主提前检查兼容性。
43. 作为策略开发者，我希望只能访问截止时点内的数据并返回决策意图，以便宿主统一负责执行与审计。
44. 作为系统维护者，我希望某插件失败只阻断所属运行并保留检查点，以便其他实验和真实复盘不受损。
45. 作为复盘用户，我希望策略模拟成交不混入真实交易或其他模拟运行，以便现有统计保持可信。
46. 作为用户，我希望在桌面和窄屏都能完成创建、暂停、保存及查看结果，以便不因布局丢失关键操作。

## Implementation Decisions

### D01 领域对象与数据边界

- **策略包 StrategyPackage（原稿术语）**：具备稳定 ID、不可变版本、说明和能力声明的封装单元。2026-09-30 起，用户层面区分三类“策略模块包”和由它们组装的“完整策略”；实验选择完整策略，运行锁定各包版本。详见增补规格术语表与 LD02/LD04。高级参数仅限包有意公开的命名参数，不引入任意字段的条件搭建器；仓位与再平衡能力保留。
- **策略实验 Experiment**：一组共享历史起点、数据快照、期限和比较设置的研究容器。
- **组合 Portfolio**：有名称、资金口径、策略配置和历史持仓轨迹的逻辑组合；不是用户真实券商账户。
- **模拟运行 SimulationRun**：组合配置的一次不可变执行实例，复用既有“模拟运行”的统计边界。重新运行/修改配置产生新运行 ID，不能按证券或日期把多个运行合并。
- **研究快照 ResearchSnapshot**：引用复用数据的不可变修订、证券集合、日历与口径版本，提供指定时点可知的数据视图。快照是版本引用与必要历史修订保存，不是另建行情抓取体系。
- **决策/订单/成交/持仓检查点**分别持久化，目标权重不等于已成交持仓。交易库既有原始成交保持不变；若后续桥接复盘，必须携带模拟性质与运行来源，不能默认写入实盘统计。
- 新增实验、组合、运行、快照清单、插件版本登记、决策事件、模拟订单/成交与检查点存储。共享 SQLite 与仓库模式，不从浏览器直连另一套业务数据库。

### D02 数据复用与当前缺口

沿用现有统一证券身份、公共行情服务、存储接口、交易日历及可知时间/图表组件。在应用边界新增一个“策略实验服务”，负责创建、预检、推进、暂停、恢复、读取结果；内部分离历史数据视图、插件宿主、执行账本。消费者不能各自实现行情抓取、时间过滤或成交算法。

当前行情公共入口提供同步、覆盖与诊断；现有 ADR 明确它尚不足以保证历史回测无前视。现有日线契约含 OHLCV、来源与抓取时间，不提供通用的历史市值、日成交额、财报版本与历史证券池契约；不能把成交量当成交额，不能默认从价格乘成交量精确获得日成交额。现有可知时间推断和 raw 行情也不等于已审计的历史研究数据。

数据补齐要求：

1. 行情与元数据区分观察/有效时间、公开可知时间、采集时间与修订版本；采集时间不能替代公开时间。历史回溯采集若能证明当时披露内容，允许作为历史证据。
2. 财报保留报告期、首次公开时间与每次修订的公开时间；只有报告期无公开时间的记录不能作为严格历史输入。
3. 市值必须明确总市值/流通市值、币种、股本与价格基准；历史值不可由今天股本直接回算。
4. 证券池记录纳入/移除、上市/退市与历史身份。复用“今天已导入交易的标的集合”可以做指定样本实验，但永久标注事后选样风险，不称作历史全市场选股。
5. 企业行为、交易单位、可交易状态、日历与执行规则必须版本化并声明覆盖；出现影响持仓的未知企业行为、无法解释的价格断裂、退市去向不明时阻断，不能静默丢弃标的。
6. 为每个运行保存数据来源、实际区间、预热区间、缺失项、排除原因和质量结论。源更新生成新修订，原快照不改写。

质量维度分别展示“固定快照可复现”“输入历史可知已核验”“证券池历史覆盖”“交易模型覆盖”。任一维度不足不得以一个绿色“数据完整”替代。缺少策略必需字段时该策略不能运行；部分证券不可评估时先列出缺失清单，由用户显式选择按剩余集合运行并永久标注覆盖偏差，不自动把未知视为规则失败。

### D03 时间与未来信息契约

- 创建时选择绝对时点 T0，显示交易所时区和换算后的截止。日线首期只能使用 T0 以前已经完整结束且可知的 bar；盘中不借用当天收盘数据。休市日不擅自更改用户选择时间，只说明最后可用交易日。
- 初始组合是 T0 的决策意图；首次模拟成交只能发生在 T0 之后的下一可交易日开盘。不得在已知当日收盘后倒填同日开盘成交。
- 独立记录数据可知截止 K、成交事件截止 E、计算检查点 C 与用户查看游标 V。向前推进时按一个日事件事务更新；历史只读回看只改变 V，不能让策略读取 C 之后的数据，也不重做交易。所有展示读取 V 对应的历史投影。
- 一周为 T0 后 7 个自然日；一个月/三个月/半年/一年按日历月 1/3/6/12 个月，月末无同日则取目标月末；终点取该目标时点之前最后可用完整交易日。UI 显示名义终点、实际终点及实际交易日数量。
- 目标超过数据可用末端时不冒充完成整期；提供等待补齐或明确生成“部分区间结果”。不得把剩余时间填成横盘。
- 财报、规则解释、榜单排序、标的卡、搜索结果、图轴范围、成交标记、仓位摘要、指标及下载的数据都受相同截止限制。未来极值不能影响早期图轴。后台可固定未来数据供后续推进，但不能通过策略读取接口或提前返回的浏览器 payload 泄露它。
- 周线信号默认仅用已完成周线；本周形成中数据不能套用最终周收盘。图表若显示部分周线，只聚合已揭示日线并标注“未完成”，不用于该默认策略的周线条件。
- 主动揭示完整结果记录来源、时间和最晚已见时点，返回过去/重新播放/复制实验不清除已有暴露来源；非盲模式同样禁止策略使用未来数据。

### D04 策略包与插件契约

首期选择应用内受信任、经过契约测试的插件注册机制；不建设第三方插件商店或任意脚本上传沙箱。保留兼容版本与能力声明，为未来独立进程执行留接口。

插件声明身份/语义版本、宿主 API 版本、适用市场/资产、必需字段、预热长度、选股与仓位规则、参数 schema/默认值、确定性排序、必要的种子与可序列化状态。插件只接收宿主提供的截止数据视图、当前持仓/现金和自身历史状态，返回候选评分/原因、目标权重或订单意图及状态变更；它不能自行抓取行情、访问完整历史数据库、修改资金账本或直接落地成交。

同一受信任进程的接口约束不是恶意代码安全沙箱。注册审查与测试禁止旁路数据访问；若未来引入不可信插件，必须先有真正隔离执行与资源限制。当前宿主检查非法输出、负权重、超预算、缺数据、失败与取消；错误隔离到运行，保留最近完整检查点，不写半日账本。

原稿把“选股 + 排序 + 组合构建 + 再平衡/退出”统称完整包。2026-09-30 用户将可组装边界明确为标的筛选、买入信号、止盈止损三类模块包，完整命名策略由三者组合并在策略库复用；形态筛选和退出规则支持受信任脚本扩展。排序、组合构建、命名仓位预设与再平衡不删除，归属和冲突语义按增补规格 LD02/LD06 在交互模型与后续执行契约中明确。变更形成独立配置版本，不把回测途中调参覆盖原实验。至少两个不同策略/预设组合应能走同一宿主，证明扩展无需修改页面核心流程。

### D05 示例策略的确定含义（本稿建议值）

用户给出的条件是示例，以下明确公式是可审阅的首个策略包草案，不是已批准的投资规则或有效性结论：

2026-09-30 补充：以下保留为旧示例规则，不能用“不额外推断止损/止盈”省略新完整策略的第三类包；具体退出预设及触发/成交语义由增补规格 LD06 与后续任务确认，不能凭示例自行补数值。

- 名称“高市值·流动性·周线回撤 EMA20”，首个示例适用于人民币计价 A 股普通股票；其他市场使用声明各自币种阈值的独立版本，不隐式把“亿”当美元。
- 市值：截止时点可知的总市值严格大于 200 亿元；日交易额：最新完整交易日的真实成交额严格大于 2000 万元。
- 周线趋势：最近完整周的收盘价高于 EMA20，且本周 EMA20 高于上一完整周 EMA20。
- 回撤：最近完整周最低价 ≤ 同周 EMA20 × 1.02，且 ≥ EMA20 × 0.98，周收盘 ≥ EMA20；它只代表接近均线区域，不代表日内成交在均线上。把“刚好”量化为此区间，不由实现者自由理解。
- EMA 使用完整周收盘，alpha=2/21，前 20 周简单均值为初始值；要求至少 60 个完整周预热。指标序列只处理截至当时已生效的企业行为，不能使用未来企业行为生成的前复权历史；相关数据缺失则不可计算。
- 候选按周收盘距 EMA20 的相对距离升序，平手按稳定证券 ID 排序；最多 10 只，目标总仓位 90%，入选者等权，剩余现金保留。无候选为全现金。10 只和 90% 为包内默认值，不是强加给所有插件的常量。
- 初始按 T0 最近完整周评估；之后每个已完成交易周末重评，下一可交易日开盘执行。移出者目标归零，新入者补入，保留者再平衡。该包不额外推断止损/止盈。
- 同时提供“初始选股后持有不动”仓位预设，用于隔离再平衡的影响；采用同一企业行为/费用/执行口径。

### D06 执行、仓位与资金

首期日线事件顺序：已生效企业行为及可用资金事件 → 开盘执行前一截止产生的订单 → 收盘估值 → 截止内策略决策 → 下一开盘计划。插件不能以当天完整 OHLC 或成交额决定当天开盘订单/成交量。

- 多组合资金互不共享。初始资金必须为正数；无追加/提取本金、无杠杆和卖空；权重非负且总和不超过 100%。不足部分为现金。
- 明确价格单位、币种、数量精度、交易单位、费用、滑点与允许交易条件。执行模型有版本及市场适用范围；费用/税率由可配置且有来源的模型声明，不在规格中假造当前法规数值。
- 基础模型在下一可交易开盘价上施加已配置滑点，按预算、预先可知的流动性上限与整手约束计算数量；不能用当天最终成交额作为开盘可知条件。若缺少价限/停牌等必要证据，不宣称真实可成交。
- 同次再平衡先卖后买；仅使用执行模型认定可用的现金。买入预留费用，现金不足按目标比例缩减并按稳定 ID 分配取整余量，现金不可负。未成交原因保留；默认当次未成交余量失效，下次评估重新出单，不能无限隐式挂单。
- 停牌可按最后可信估值展示但明确陈旧天数，不制造成交；未知交易状态/关键行情缺失导致受影响日阻断。退市不得将仓位悄悄归零。拆股调整数量与成本，现金分红按声明的资格/派发规则入账，不能 raw 价格和复权收益重复计入。
- 到期默认按最后收盘估值，不强制虚构清仓；期末未实现盈亏与未执行计划明确展示。
- 金额与数量在账本采用十进制定点口径；显示舍入不反向影响计算。每个交易日原子提交现金、持仓、成交、插件状态、事件序号和检查点。

### D07 结果与比较

“组合净资产 = 现金 + 各持仓可信市值”，“组合净值 = 净资产 / 初始资金”；在无外部出入金范围内计算累计收益。它不是既有“交易成本收益率”或“本金参考收益率”。已平仓回合净盈亏、持仓浮盈亏分别沿用项目术语。

必需展示：每日净资产/净值曲线、回撤曲线、各标的实际权重/现金占比曲线、目标与实际仓位差、区间累计收益、最大回撤、已实现/未实现盈亏、费用/滑点成本、调仓次数、换手率、闭合回合数量/胜率、标的损益贡献。费用按成交归属，贡献与现金项须与净资产变动对账。

口径：回撤为净值相对截至当天历史峰值的跌幅；最大回撤取区间最大跌幅。每日单边换手率定义为当日买卖成交金额总和除以前一日净资产的两倍，区间值求和；初日用初始资金作分母。胜率仅统计已平仓且可信计算的回合，零个回合显示不可计算而不是 0%。未执行计划不算交易。

年化收益、年化波动、Sharpe 为扩展统计；若展示，必须明示自然日/交易日年化因子、无风险利率和最小样本规则。首期默认不足一年不展示年化收益、不足 60 个有效日收益不展示波动与 Sharpe，无有效分母显示不可计算，不能拿零填充。区间收益不受此限制。

多组合比较默认共享 T0、终点、初始资金、快照、市场/币种、费用模型；差异项突出标注。失败/部分区间组合不能放入完整区间排名，其他组合可以独立继续；同步比较停在共同有效日期，查看更晚单组合结果需显式操作并记录暴露。可选基准只在同期同口径数据可用时展示超额收益，否则明确无基准，不捏造。

### D08 持久化与可复现

运行锁定策略与执行模型版本、参数、数据修订、种子和事件排序规则；同一输入必须生成相同决策、成交与净值。播放速度仅影响呈现。

推进命令带运行版本与幂等标识，重复点击/网络重试不重复成交。采用运行级并发控制，旧版本写入返回冲突且不覆盖新状态。服务中断恢复最近完整日；缺少旧插件时历史结果仍可读，继续执行被明确阻止而非偷偷用新版。用户修改配置创建新运行并保留来源，删除/归档实验不删除共享行情或真实成交。

保存失败保留草稿和最近已保存位置；显式重载后字段、派生指标与保存状态共同恢复，另存产生新实验。图表视野、展示游标与未来暴露记录随实验恢复，不能只保存表单。

## Testing Decisions

### T01 主测试入口与现有先例

优先使用一个新增的高层“策略实验服务”公开行为入口，贯穿创建、推进、读取历史投影、保存重开和结果查询；复用现有行情 repository 与 SQLite 隔离测试边界。测试时可替换外部数据提供者，但保留真实策略宿主、日事件引擎和持久化，不把每个内部 helper 都 mock 掉。

既有先例包括公共行情服务缓存集成测试、SQLite 仓库测试、回放引擎与仓位账本测试、focused review 页面流程和真实图表回放测试。新策略系统不能直接把“回放已存在成交”的引擎当作“产生新模拟成交”的完整实现。

已在当前对话依据 to-spec 发出测试边界核对：以完整用户旅程为主，补充逐根/批量一致性与追加未来不改变过去决策。尚未收到答复时，这是一项明确提出的设计建议，不记成用户确认。

### T02 自动化可观察行为

- 固定小型、可手工核算的历史数据，覆盖首次建仓、涨跌、卖出/补入、费用、取整、现金及期末未平仓；断言公开事件和净资产，逐项核算而不调用被测算法生成期望值。
- 相同配置逐根、播放、批量、中断重启产生相同成交与净值；重复命令不重复成交；不同运行不存在资金与仓位串用。
- 注入仅改变 T 以后 bar、财报/修订、上市/退市或企业行为的反例，T 以前候选、决策、轴范围、摘要和订单必须完全不变。当前财报/总市值不可替代历史值。
- 完整周与未完成周、盘中 T0、休市日、夏令时/半日市、日历月末、预热不足与回测终点超范围均有可读结论。
- 验证严格阈值边界、EMA 初值/预热、候选平手、无候选、未知字段和超预算权重；插件错误不留下半日账本，不读取未来。
- 测试未知交易状态、停牌、企业行为、资金限制和期末未成交，不以虚构成功代替。换手、回撤、贡献、现金、已实现与未实现结果对账。
- 使用真实隔离 SQLite 验证保存→退出→重开与重载，包含保存失败、并发冲突、数据刷新与插件版本变化；真实原始成交内容摘要前后不变。

### T03 独立验收门槛

1. **最小真实图表旅程先接受**：历史预览→建组合→下一日/播放实际揭示新 bar 和成交→调仓解释→回看早期→保存/返回/重开。在超出初始可视窗口后继续推进，必须仍看得见新 bar。先通过这一条，再扩大依赖状态契约的多组合/统计实现。
2. **功能**：完整创建、期限、空状态、错误恢复与多策略对比可达；不以按钮存在或回调触发作为成功。
3. **状态与持久化**：双截止/历史投影不泄漏未来、账本可核算、真实隔离库重开可恢复、原始交易未变。
4. **视觉**：实施前补齐 UI 契约与逐项 DESIGN-COVERAGE；独立于实现者的审查者对照当前批准画板或已记录项目视觉约定，在 1440×900、1280×800、约 390px 与导航展开/长中文等匹配状态截图比较。宽度是本稿建议验收视口，不代表已有设计稿尺寸。
5. 鼠标、键盘、模拟触控与真机触控证据分开。若实施 UI 契约要求真机键盘，缺证据保持 NOT VERIFIED，不以窄屏截图替代。
6. 实施交付需实际浏览器新检查、持续运行的隔离预览 URL 与启动说明。文档交付不启动产品服务，不虚构这些通过记录。

所有实现验收目前均为 NOT VERIFIED；文档本身只检查需求覆盖、术语、链接与一致性。本稿并非接受报告。

## Out of Scope

- 实盘下单、券商自动交易、杠杆、卖空、期货/期权、跨币种混合组合与外部资金流；未来可通过新的执行能力扩展。
- 分钟/tick 级撮合、盘中止损路径推断、订单簿与冲击成本仿真；日线无法证明日内高低点发生顺序。

## Further Notes

### 方案选择与实施顺序

推荐“共享数据层 + 历史快照视图 + 单个日事件引擎 + 插件宿主”。直接在前端筛选缓存虽然少一层，但时间和账本规则会分散且无法可靠复现；另建独立量化平台则会重复证券身份、采集、存储和图表。本方案利用现有基础，新增边界集中在历史研究与模拟执行。

建议纵向交付顺序：

1. 数据能力清单、历史快照与完整 UI 状态契约；先验证示例包所需数据是否真实可得。
2. 一个策略、一个组合、最短区间的真实图表闭环，贯通持久化与无未来泄漏。
3. 自动调仓/再平衡、全部五档期限与执行边界。
4. 多策略同步比较、完整结果统计、第二策略包接入验证扩展契约。

这些是后续拆票依据，不是已经派发的实现计划。具体供应商、数据获取许可/覆盖与执行市场细则需在数据能力票中核验证据，不在本次规格中凭经验承诺。批准设计后再按项目流程建立逐项覆盖矩阵、准确画板引用、纵向任务和独立验收责任，当前不把未分派任务伪装成已有人实施。
