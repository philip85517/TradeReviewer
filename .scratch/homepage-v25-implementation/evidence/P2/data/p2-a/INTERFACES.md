# P2-A F-only draft interfaces

2026-10-23. Performance gate **NOT MET**; this is a reviewable implementation draft, not `implementation-ready` or P2 acceptance. The F3 wrappers retain their prior contract. No series/UI/DB/service wiring exists in this change.

`prepareHomepageV25Source(input)` captures an immutable structured clone of real `TradeLibraryEntry[]`, raw candles, explicit scope/metadata, historical FX observations, independent current FX evidence, lifetime source coverage, and caller revisions. Its opaque handle owns collected original execution lineage, quote/session indexes, fee facts, and memo. The source digest hashes actual content and policy versions; unchanged caller revisions do not hide changed data. Missing nature is still excluded from real live scope.

`projectHomepageV25Boundaries(source, { periodStart, asOf, endpoints, targetCurrency? })` requires a precise ISO `asOf`, valid Shanghai start date and unique endpoint keys. Invalid requests throw `HomepageV25ProjectionInputError` with a stable `code`. The result follows endpoint input order. Future points are null/future with no endpoint replay. Current is independently projected at `asOf`; its cache key excludes selected range.

Each historical point exposes `periodRealized`, `openingUnrealized`, `closingUnrealized`, `unrealizedChange`, `net`, `lifetimeRealizedNet`, `lifetimeNet`, `marketValue`, `unrealizedNet`, `openFees`, and `periodFees`. Tooltip order is market value, net UF, lifetime net realized, lifetime net, selected-period net, actual period fees. All amounts use existing F `HomepageV25Metric`, including native subtotals, coverage, reasons and FX evidence. Native differences are computed before one endpoint conversion. Without inception/through/knowledge evidence, lifetime values are unknown while independent period values can remain known.

`instruments[]` preserves account/instrument/nature/run identity, opening/endpoint canonical/F evidence, separate opening/endpoint quote coverage, FX coverage, fee fact IDs, lifetime coverage, and explicitly named `canonicalKnownFees`. `canonicalKnownFees` is a diagnostic ledger-known cumulative value, never actual period fees. Each point has `plottable` and a state of value/source-missing/future. Per-instrument strict missing-completed-session gates affected MV/UF/net, keeps fallback quote evidence, and does not gate independently known realized or actual period fees. Legal closed/in-progress carry remains usable. Independent current retains the accepted F3 stale fallback policy and publishes its own coverage.

`feeFacts` separates incurred date/precision from amount and attribution knowledge, preserves raw execution/event/source-row lineage, and exposes unknown reasons. Statement principal/refund rows are not negative fees. A Jan8 fee becoming useful to canonical acquisition cost after a Jan20 refund stays a Jan8 actual fee. Unlinked instrument attribution, conflicting fee evidence or unknown incurred boundaries are not guessed. The draft's attached-evidence path retains exact-cursor fee checkpoints, so late knowledge cannot overwrite early snapshots.

Historical FX accepts only same-business-date observations with complete status, positive production pair rates, source evidence, and publication/known/fetched times at or before the endpoint. `currentFxSnapshot` is separate. The batch never manufactures history from latest FX. Same-currency money needs no FX. Current and historical point evidence remain distinct.

The source currently implements `ProjectionMemo` entry/estimated-byte limits and a four-batch cap, but cache retention/LRU validation is incomplete; see `report.md`. Public types are additive only. No consumer should depend on this draft before the performance and retained-memory issues are resolved and root accepts it.
