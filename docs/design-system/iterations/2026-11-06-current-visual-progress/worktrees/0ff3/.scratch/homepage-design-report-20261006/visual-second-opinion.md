# TradeReview 首页截图：独立视觉审查

审查范围：仅直接观察用户提供的截图（2016 × 1244 px）；未检查浏览器行为、代码或业务数据库。本稿供主审整合至 Design Report，不构成功能验收。

证据：`/var/folders/35/254l_pjd3176pndzmz5_2l4m0000gn/T/codex-clipboard-330e5568-92e5-4e3c-89cc-0a88a38b4260.png`

严重性：高＝会妨碍首页核心判断或明显误导阅读；中＝增加理解和操作成本；低＝局部清晰度问题。排序依据是用户首先要判断「资产有多少、变化怎样、这些数能否信任」的任务。

## 发现（按影响排序，最多 8 项）

### V1｜高｜不同币种的识别和数值比较口径不清楚

- **截图可确认：**左卡图例（约 x260–472，y183）中 USD、CNY 都使用近似相同的青绿色，HKD 为紫色；左上单位行并列写 `USD / HKD / CNY`，图内只有同一组纵轴刻度（50.9万、0、-5.2万）。右卡币种切换选中 CNY。
- **用户影响：**用户很难从曲线颜色辨认 USD 和 CNY，也不能仅凭当前画面确定纵轴金额是否已换算；右卡选择 CNY 是否影响左图同样没有直接提示。此处属于呈现歧义，不能据截图认定换算逻辑有误。
- **可验收建议：**在图标题或纵轴旁明确写出「按原币分组」或实际的统一币种口径；若保留多序列，为每个币种同时提供可区分的色彩及非颜色标记/直接标签。明确币种控件的作用范围。任意选中一个图点时，币种、原始金额或换算金额与口径应同时可见。
- **待浏览器验证：**USD/CNY 是否确为不同可见序列；图例能否筛选；提示框的币种/金额/换算口径；左右卡控件的实际联动。

### V2｜高｜诊断明细压过资产结论，暴露大量内部标识

- **截图可确认：**右卡约 y440 起连续显示「全卡缺口」、3 条原因、5 条原因以及「1786 条原因」。约 y875–1160 的可见列表包含 `china-merchants:23cab17a05c851c4:10:241` 等长标识；上方原因还直接包含 `china-merchants/pdf/monthly-v1` 来源规则。相似的「实盘/模拟运行未知」逐条重复。
- **用户影响：**首页将源记录诊断负担交给用户，资产分布卡大半高度被排错文本占据。用户很难先判断当前影响、要采取什么动作，以及哪一类问题最值得处理。截图足以证明内部实现标识进入用户界面，但不足以证明安全泄漏或错误状态。
- **可验收建议：**首页只显示按业务类型去重的原因、受影响记录数量及下一步，例如「运行类型待确认：1786 条交易」；将原始记录标识、来源规则和完整清单放入可明确打开的详情区域。折叠摘要不重复展示同一原因，展开长清单应可筛选/分页并保留返回上下文。
- **待浏览器验证：**截图是否处于用户主动展开的状态；默认首页是否同样展开；长清单是否影响页面性能与键盘阅读；是否已有可执行修复入口。

### V3｜高｜数据完整性信息分散，金额的适用范围难以一次读懂

- **截图可确认：**右卡上方写「可用小计 6/7 个仓位」，圆环中心突出 `CNY 218,865.00`；下方橙色状态另写「全卡覆盖 7/8 个仓位，仍有币种或估值缺口」，并列出负仓差额、缺失估值和多空方向待核对。左卡同时显示「持仓历史正在更新（沿用上次快照）」，右卡用完整 UTC 时间戳显示估值截止。
- **用户影响：**关键限制存在，但位于多个层级，6/7 与 7/8 的分母属于何种范围需要用户自行拼接。最醒目的金额与「部分覆盖」「数据时间」没有形成紧密整体，可能被读作完整且最新的总额。
- **可验收建议：**金额旁固定显示「CNY 可估值小计」及「当前币种 6/7 仓位」；全组合覆盖情况单列并明确范围。将本地可读的估值时间和「更新中／沿用快照」状态靠近受影响金额或图表标题；能在同一视线内回答数值范围、缺失量、时间和可用性四项。
- **待浏览器验证：**6/7 与 7/8 的准确业务定义；左右卡是否使用同一时点；更新完成、失败、部分更新与全量完成时的状态变化。

### V4｜中｜不可用的比例仍采用圆环图外形，制造了图表预期

- **截图可确认：**右卡约 x1390–1600、y201–412 是完整灰色圆环，中心明确写「净市值小计 · 比例暂不可用」，右侧只有 A股 218,865.00 条目；当前圆环未表达可读的份额扇区。
- **用户影响：**大面积圆环吸引视线，却不能回答分布问题；完整的环形也可能被快速扫描成 100% 或已加载的图表，用户需要读中心小字才能修正理解。
- **可验收建议：**比例不可计算时用清楚的「分布比例暂不可用」状态和金额清单承载信息；若保留图形，占位外观需明显区别于有效分布。有效、空数据、部分金额可用但比例不可用三个状态分别截图验收。
- **待浏览器验证：**是否确为不可计算状态；何时比例恢复；占位是否会被辅助技术描述成有效图表。

### V5｜中｜左右卡高度严重失衡，第一屏下半部空间利用失衡

- **截图可确认：**左卡从约 y13 到 y663 结束；右卡持续到 y1177。左侧 y664–1199 出现约 530 px 高的大块空白，下一行卡片直到 y1200 附近才出现。
- **用户影响：**约三分之二页面宽度在这段高度内没有信息，下一部分被右卡诊断文本向下推；用户必须继续滚动，首屏信息密度由排错清单决定。
- **可验收建议：**用收敛后的右卡摘要控制首页高度，并给完整诊断单独空间；在当前相同比较视口下，两卡后方的内容应自然衔接，避免为右栏明细保留大块左侧空白。不要单纯拉高左图填空，应以图表可读性确定其高度。
- **待浏览器验证：**栅格是否按最高卡片等行高；常规未展开状态与窄屏布局；展开/收起是否造成明显跳动。

### V6｜中｜时间、指标与查看方式的控制层级拥挤且分散

- **截图可确认：**左卡顶端同时摆放总市值/未实现盈亏/未实现收益率、近1月/近3月/今年/全部、自定义观察日期、日/周/月；约 y151 插入更新状态。底部另有「历史持仓日期」与「选择日期查看」，而「自定义观察日期」没有与底部选择框形成明确视觉对应。
- **用户影响：**同一区域包含指标、区间、粒度、指定日期四种概念，选中外观又较相似。用户容易把「观察某一天」与「改变曲线区间」混在一起，难以形成稳定操作顺序。
- **可验收建议：**按任务划分三层：指标 → 时间区间与粒度 → 单时点详情；将自定义区间入口放在区间组内，把历史日期定位标为「跳转到某日」并靠近图表交互。当前选中区间、粒度与日期定位应各自有明确语义和可见状态。
- **待浏览器验证：**「自定义观察日期」是按钮、标签还是当前状态；底部日期是否改变图表、仅查看快照或跳转；区间和日期之间是否保留/重置状态。

### V7｜中｜全历史视图里点标记盖过趋势，缺少直接的读图入口

- **截图可确认：**左图从 2015-04-15 到 2026-10-06，绝大部分可见点贴近 0 线，后半段密集散点占据图面；底部提示解释移动查看、左右键、Home/End、Esc 与触屏点选。标题区未显示一个显著的当前总市值数值。
- **用户影响：**此状态主要呈现「很多数据点」，用户需要先理解点、线、断点及数据完整性，才能回答资产趋势或当前值。不能由静态图断言曲线断裂、数据错位或提示框失效。
- **可验收建议：**在选定指标旁提供当前可用值及覆盖状态；在长期区间下调整标记密度或按明确规则聚合，并使线型含义有可发现的简短解释。选中一点后固定显示日期、数值、币种与数据质量，键盘/触屏均可到达同等信息。
- **待浏览器验证：**线段实际连通规则是否符合业务；悬停/选中提示；日周月聚合；极值对纵轴的影响；键盘与触摸的实际可用性。

### V8｜中｜次级文字偏小偏暗，可达性证据不足

- **截图可确认：**右卡时间戳、覆盖说明、诊断文本和查看原因链接在深蓝底上使用较暗的蓝灰色，并明显小于金额；图表图区与图例在序列区分上高度依赖颜色。图中没有正在展示的焦点状态。
- **用户影响：**重要限制条件与可操作入口在视觉上接近辅助说明，阅读和发现成本偏高；截图只能支持可读性风险，不能据此宣称具体对比度比值或键盘失败。
- **可验收建议：**浏览器中测量正文、状态、链接与选中态对比度，常规文本达到 4.5:1；关键质量信息不能只靠颜色表达。直接验收键盘遍历顺序、清晰焦点、图表选点等效操作，并分别记录鼠标、键盘、模拟触屏证据。
- **待浏览器验证：**真实 CSS 字号、缩放与对比度；可聚焦元素名称；展开控件语义；焦点可见性与触控目标尺寸。

## 主审建议

先验证 V1/V3 的口径与状态链，再用 V2/V5 判断首页信息结构；V4/V6/V7 的设计建议需要结合真实交互后定稿。所有发现目前都是截图观察或明确标注的待验证项，不应升级为已证实的业务/持久化缺陷。
