## 已关闭：交易质量明细打开空账户

旧集成路径 `openQualityDataCheck` 以空字符串调用 `openDataCheck(instrumentId, "")`，`StockDataDialog` 因而可能选择空账户并隐藏该标的真实成交。`08-browser-transaction-empty-account.txt` 已实际观察到 MSFT 对话框显示“主账户”、0 笔成交且“补录成交”禁用，无法执行该 issue 给出的修复动作。

当前源码已加入 `defaultAccountIdForInstrument()`，从该标的 imported executions 选择第一个非空 account，并由 `openQualityDataCheck` 传入；对应 helper 测试也已出现。`08-browser-transaction-account-fixed.txt` 复验当前账户有 2 笔成交，补录/编辑按钮可用，故该 P1 已关闭。多账户同标的仍应优先使用 issue 对应回合的 account，而不是任意第一个账户；若模型不暴露完整 account ID，导航层至少要用 episode ID 做映射，避免把补录落到同名账户。

## 已关闭：行情源不支持明细可执行

`quality-details.tsx` 当前对 `source-unsupported`、`open-data-management`、`supplement` 共用分支；此前单看 callback 名称会像是把行情源问题送进交易检查。`08-browser-source-diagnostic.txt` 证明 source 按钮打开的 `StockDataDialog` 明确展示日线/1H 行情状态、覆盖区间与缺口，并提供“更新当前股票行情”，因此在当前没有 provider 管理 UI 的范围内已经是可执行的行情核对路径。`supplement`→`StockDataDialog` 仍是合理的交易补录动作。

现有组件测试可补充该实际路径的回归，但不再阻断本次 source 动作判断。

## 已关闭：holdings 日线与 1H source 状态分离

此前 `buildHoldingsDimension` 将合并标签中的 1H 源状态误用于日线 action。当前 workspace 已传入 `marketDataDailyStatuses`，模型优先使用 daily status；11/11 scope 回归覆盖该组合。`08-browser-daily-retry-fixed.txt` 显示 SPY 过期行情走“重试持仓估值行情”，159919 日线源不支持仍走“查看数据源”；`08-browser-daily-retry-result.txt` 显示 SPY 单条重试后持仓质量从 2/5 变为 3/5，SPY issue 消失。该 P2 已关闭，1H 状态继续作为 StockDataDialog 辅助提示。
