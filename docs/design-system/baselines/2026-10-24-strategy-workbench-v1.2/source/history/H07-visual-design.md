## BT00 · 先知道从哪里进入，以及这张图处于哪一站

当前首页的“策略”入口仍是**禁用、未开放**状态。本册不是生产入口的通过证明；它记录开发原型和目标动线，方便评审者把首页、实验和工作台分开看。

![策略回测台目标进入动线](entry-journey.svg)

图 BT-ENTRY｜目标动线草图，不是首页运行截图。当前可看的开发预览使用合成内存数据，刷新会重置；旧 2.0 首图展示的是某次运行已经展开后的“完整观察”，不是新建实验后的 T0，也不是首页画面。

目标路径是：**首页 → 策略 → 我的实验 → 创建或打开实验 → 回测工作台**。首次从“策略”进入时，推荐先到“我的实验”；这是本版入口建议，与“策略库”并列，尚未被生产实现验收。策略库管理可复用的方法，我的实验管理草稿和运行记录，工作台属于某一次实验内部；不要把工作台当成第三个业务根入口。

| 站点 | 普通说明 | 进入或返回后的可观察状态 |
| --- | --- | --- |
| 首页 → 策略 | 进入策略功能；当前入口仍禁用 | 目标子页为“我的实验”，旁边保留“策略库”；当前真实首页截图和生产接线仍未验证 |
| 我的实验 | 查看草稿和运行记录；新建或打开已有实验 | 新建进入四步创建；打开旧运行回到该运行保存的工作台状态，不另起实验 |
| 四步创建 | 1 设置起点 → 2 选择策略 → 3 预览 → 4 确认 | 确认后进入起点日（T0）/待开始：实际持仓为 0、现金为 100%；目标仓位仍是计划，不能当作已经成交 |
| 已有回测的重开 | 从我的实验打开已保存回测 | 恢复原回测的组合、日期进度、视图和入口来源，保持暂停，不重置为 T0，也不自动播放 |
| 回测工作台 | 在同一实验内看回放观察、阶段结果和组合对比 | 显式返回我的实验；返回是恢复来源，不跳首页、不新建运行 |
| 本册完整观察 | 用于解释已经展开后的工作台画面 | 对应 BT01–BT14；不能冒充首次创建、T0 或生产首页 |

BT00 的目标设计与[策略工作台融合契约](../../../specs/2026-09-30-strategy-workbench-v1-integrated-design.md)一致。生产入口、保存和重开仍归旧任务 10（本地任务路径：`.scratch/strategy-portfolio-backtesting/issues/10-strategy-library-creation-prototype.md`）及其依赖；本册保留这个路径作为查找线索，不将其标记为通过。

## BT02 · 中文说明先讲用途，数字保留完整精度

![文字角色、中文行距与完整金额](../2026-10-11-strategy-backtest-v2/plates/BT-PLATE-01.svg)

图 BT-PLATE-01｜按当前主题参数制作的设计说明样字；不是新的产品运行截图。

顶部的大金额先回答“账户有多少、这次变化多少”；分区标题帮助找到持仓和事件；正文解释为什么调仓、这个判断当时依据什么。操作后的变化要在相邻的中文说明中说清楚，不能只留下数字或图标。金额用于比较，必须保留原币种、原小数位和完整数值；数字列可以用等宽数字，中文正文不能整段变成等宽字体。

金额角色要完整读成：关键金额字号 **24px**、每行高 **32px**、字重 **500（中等）**；次级金额字号 **14px**、每行高 **22px**、字重 **500**。中文正文和控件文字字号 **14px**、每行高 **22px**、字重 **400–500**，主要动作字重 **600**；辅助信息字号 **12px**、每行高 **18px**、字重 **400**。

例如 `¥102,540.84` 要保留 `¥`、逗号和两位小数；如果原数据是 `USD 1,234.567`，就按原数据的币种和精度显示，不为了对齐擅自四舍五入或改成无币种数字。金额列右对齐，长金额不能截断单位；未知值保持“未知”并说明原因，不用 `0` 填空。

## BT08 · 推进一步，看到新增行情；回看只改变当前查看日

![T0到首次建仓，以及回看保留已展开进度](../2026-10-11-strategy-backtest-v2/plates/BT-PLATE-02.svg)

图 BT-PLATE-02｜17→18为同次真实鼠标单步；19→20为同次回看帧的等比例局部。设计说明线不属于原截图。20 的行情和成交边界独立字段均未读取；“已展开至 6/28”来自画面文字，成交边界仅由前后态作限定推断。

单步的意义是“多看完整的一天”：成功后，新 K 线和目标成交标记必须真的出现在主图，右侧实际持仓也随这一天的执行结果更新。图中股票 A 为 44.5%、股票 B 为 45.5%，与计划中的 45.0% / 45.0% 以及现金目标 10.0% 分开显示；计划不是成交事实。

回看早期日期只改变“当前查看日”，不把已经展开的行情和成交进度倒退回去。比如从已展开到 2024-06-28 的运行回到 2024-06-14，当前画面可以回到 T0 的 0 持仓，但仍要明确显示行情已经展开到 6 月 28 日。曾经通过单步、播放、返回最新或结果入口看过后续，都要留下**已看后续记录**；刷新、重开和回看不能把它伪装成当时第一次盲看。

四个日期先用普通话分别读：**当前查看日**是正在回看的哪一天；**行情已展开至**是目前允许查看的行情到哪一天；**成交已展开至**是目前允许查看的执行记录到哪一天；**结果截止**是这次结果计算到哪一天。它们不能互相替代，也不能用计划日期代替实际成交日期。实现层字段对照写入规则详情，正文不使用缩写。没有独立字段证据的内容写“未知（unknown）”，由画面或前后状态推断的内容另标“限定推断”。

## BT15 · 个人评审怎样进入下一版

本章是个人评审的操作说明，不把评论写成生产功能。打开[本版预览](http://127.0.0.1:3072/design-system/baselines/2026-10-11-strategy-backtest-v2.1/visual-spec.html)，选中段落、列表、表格或图注文字后点“评论”；图片不能准确拖选时，点图片旁的“评论这张图”。面板会保留章节、完整原文、版本和图片身份，输入意见后点“保存评论”。只有本机文件写成功才显示已保存；失败、取消或空意见不会制造记录，失败时输入和引用仍可重试。

个人评审使用 `3072` 和 `reviews/strategy-backtest/`。这个目录会随评审产生内容，不能预先假定为空。评审身份中的姓名和角色只是本机声明，不是登录权限，也不会自动执行代码。隔离 QA 使用独立的 `3073` 和 `/tmp/tradereview-document-review-<唯一值>`，两者不能混用；QA 记录不应覆盖个人意见。

保存后的评论按这条链处理：**选文/选图 → 本机保存 → 写评审理由 → 采纳任务、待说明或暂不采用 → 离线生成真正的后续版本 → 读取新版文案和证据 → 非实施者复核 → 必要时重开 → 导出**。评审者打开已有评论，必须写判断理由；“采纳，待修改”还要关联实际存在的项目 Markdown 任务并填写实施者，“待说明”和“暂不采用”只保存理由，不附实施任务。采纳不等于已经修改，待说明和暂不采用也不删除原意见。

实施者从同一份评论记录读取原文、图片身份、理由、任务和证据。生成后续版本时，先复制上一版源目录和 `document-identity.json`，再编辑新的源文档；改写原块前保留明确的 `<!-- stable-id: BTxx-Bnnn -->`，不能靠文本变化或重排猜身份。用 `--source`、`--version`、`--output-dir` 离线生成新的 HTML、manifest 和身份记录，服务只允许从已注册清单读取它。原文、旧图和旧结论继续保留；改写、重复或删除无法唯一对应时进入待定位，不能自动挂到相似文字。

复核者重新读取已注册的新版本、原评论和实际证据，逐段核对原文、新文、图身份、任务完成情况和验证截图/记录。实施者不能自签复核；复核必须填写理由和证据后选择“复核通过，已解决”或退回待修改/待说明。已解决、待说明、暂不采用或待定位的问题需要继续处理时，用“明确重开”，历史和旧引用保留。面板提供 JSON 和 Markdown 导出；两者都来自同一份本机权威记录，不是第二套状态。

评论可引用 BT00–BT14 已有的入口、金额、日期、图表、保存和视觉边界。对于仍标为开发原型、未开放、未知（unknown）或未验证的能力，只能提出任务或保留问题，不能在评论中把它写成已经实现。段落和图片位置来自 `document-manifest.json`；图片身份来自[旧 2.0 的图片身份清单](../2026-10-11-strategy-backtest-v2/image-manifest.json)，二者不混用。

正常评审服务从仓库根目录启动时让服务扫描所有基线清单，不要把单一 `--manifest` 当作后续版本限制：

```sh
python3 tools/document_review/server.py \
  --port 3072 \
  --comments-dir reviews/strategy-backtest \
  --docs-root docs
```

测试或隔离 QA 才使用 `--manifest` 限定临时清单，并改用 `3073` 和 `/tmp/tradereview-document-review-<唯一值>`。服务启动、评论存在或离线生成网页都不等于产品验收；本章只说明文档评论闭环，产品入口、业务保存和真实触控仍按各自验收记录处理。
