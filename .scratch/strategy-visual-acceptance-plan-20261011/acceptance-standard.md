# 验收标准：策略台视觉与图表优先复盘

## 1. 结论语义

每一项只使用 `PASS`、`FAIL`、`NOT VERIFIED` 或有范围理由的 `NOT APPLICABLE`。缺截图、缺真实操作、只读了源码或只跑了 DOM/HTTP 检查，均为 `NOT VERIFIED`。出现可观察不符合时记 `FAIL`，不能由其他维度的得分抵消。

整页必须分别给出三道门槛：

| 门槛 | PASS 需要证明什么 | 不能替代它的证据 |
| --- | --- | --- |
| 功能正确性 | 领域规则、按钮/状态/数据计算符合约定，错误和取消保持安全状态 | 视觉截图、组件快照 |
| 端到端与状态安全 | 真实主图推进、阶段和截止联动、实际保存→返回→刷新/重开；有写入时使用隔离库 | callback 成功、mock fixture、HTTP 200 |
| 视觉还原 | 独立审查者在相同 CSS 视口/状态直接比较参考和渲染，重大差距修复后复核 | DOM 断言、无 overflow、自动化分数、实现者自述 |

纯规划/文档票不强制浏览器或数据库门槛，但必须把后续适用步骤、证据 owner 和 `NOT VERIFIED` 边界写清楚。

## 2. 参考锁定

每张证据截图的文件名或旁注必须包含：版本/提交、URL、CSS viewport、浏览器缩放、DPR、滚动位置、导航是否展开、场景/阶段、数据和文案版本、图表范围、交互状态。归档图仅作为 0.7 视觉参考，最终版本必须在真实浏览器新鲜检查；启动成功不等于视觉通过。

对照集合固定为：

- 策略台：1440×900、1280×800、1280×720、1024/980、760/759、600、390；完整观察、运行中、T0、结果、比较；导航收起和展开；默认、回放中、暂停、选中、焦点、禁用、弹层/长内容。
- RecallWorkspace：1440×900、1280×800、约 390 宽；S0/S1/S2；图表适应全部、Tab 到价格、止损定位、计划/实际、原判断/当前补充/复盘补记、回看早期和未来来源标记；适用时补真实手机软键盘。

## 4. 证据包与职责

每个实现切片至少交付：

1. 一份 `visual-contract.md`（原图尺寸、CSS 视口、DPR/缩放、状态、授权差异）；
2. 一份 `acceptance.md`，按功能、端到端、视觉三道门槛逐项列证据；
3. 真实浏览器截图或录制，含关键宽度和状态；
4. 有写入时的隔离数据库路径、保存/返回/刷新日志和原始数据保护证据；
5. 独立视觉审查者的直接看图结论；实现者不能自签视觉 PASS；
6. 未验证项、失败项和重新打开规则。

整页视觉负责人负责首屏顺序、密度、默认折叠、常驻高度和上下文例外的整合；状态/持久化负责人负责真实链路；协调者亲自检查最终页面和依赖票。

## 5. 版本门禁

- 01 完成后才允许冻结对照图和截图命名。
- 02、03、04 完成后才允许把共享视觉、阶段/截止和响应式合同派发给实现者。
- 05 完成后才允许修改公共 token/组件；未登记的例外阻塞推广。
- 06 完成后才允许生成 07 的实施顺序；关键门槛若仍 `FAIL` 或 `NOT VERIFIED`，只能交付阶段结果。
- 07 后的实现必须先走真实主图回放切片，再扩大到完整 Workbench、响应式和公共组件固化。

## 6. 例外登记

例外记录模板：组件/上下文 → 现状 → 允许理由和用户依据 → 影响 → 适用视口/状态 → owner → 引入版本 → 退出条件 → 证据路径。当前已知例外包括策略 A 最小宽度和横向滚动、RecallWorkspace 的自然文档流与 marker/编辑浮层碰撞、原生 31×36/112×36 命中框、图表 Canvas/导出字体一致性和真实触摸/软键盘未验证。
