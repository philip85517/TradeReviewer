**现有模型能够继续承载项目，但事实写入与首页展示资格需要补齐业务约定。** 本组文档整理当前结构、网页功能依赖、开源参考及三路独立审查；协调者已核对关键证据，使用合成内存库复现四项写入问题。

## 建议阅读顺序

**普通审核人员先看结论，专业人员再查对象与源码。** 两类读者共用同一套证据，避免现状与建议混写。

1. [综合审查意见](REVIEW.md)：核心结论、问题树、优先级及后续决策。建议先读第1–2节。
2. [数据库建模现状](current-model.md)：现在保存什么、支持哪些页面、一笔记录怎样到首页；含术语说明与可展开技术证据。
3. [公开实践与适配](external-practices.md)：Ghostfolio、Portfolio Performance、SQLite官方与Money设计文章；说明借鉴点和不能照搬的部分。
4. [逐表结构附录](schema-reference.md)：46张表的字段、主键、外键、索引与完整建表语句，供按需查询。
5. [数据库模块重设计审查稿](../database-module-design.candidate.md)：用户已选择B方向；具体模块、对象、保存与读取约定待审，不代表问题已经修复。

## 三路独立审查

**三名 GPT 6.1 Sol Ultra Agent 从不同角度审查，协调者负责综合判断。** 每份原报告保留自身证据边界；公开研究没有执行本地反例，反例由协调者另行完成，因此以综合报告判断最终证据级别。

|审查角度|报告|协调者重点核验|
|---|---|---|
|物理结构与逻辑约束|[结构审查](schema-review.md)|身份、去重、修订、语义校验、事务和JSON边界；4项内存反例|
|网页功能与数据生命周期|[功能审查](feature-review.md)|页面到表/对象的对应、完整性影响范围、历史供数、复盘和性能边界|
|公开规范与开源模型|[公开实践](external-practices.md)|固定源码与官方来源、适用性、非目标和验证要求|
