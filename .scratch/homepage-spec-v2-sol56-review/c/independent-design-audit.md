## 严重度发现

### F01 · P1 · C39 的“逐单元可验收”尚未成立

- 预期：11 类控件的每个适用状态都应给真实形态、尺寸、触发、可见反馈、取消/恢复、键盘、异常结果，可直接与实现截图逐项比对。
- 现状：正文 `visual-design.md:303-315` 每控件压缩为一行；状态图生成器 `build-detail-frames.py:133-161` 大量用统一 150×36 占位并复用统一错误文案。DataTable、Popover、ChartTooltip、EmptyState 与其正文尺寸明显不符。
- 影响：实现者仍需自行补全交互与视觉细节，审查者无法按 C39 判定“一致才可”。V2 的“37 条设计 PASS”因此不成立。
- 建议：为 78 个适用状态建立逐格表；至少为 Popover、DataTable、ChartTooltip、EmptyState 单独绘制真实尺寸状态板，逐格记录触发、退出、焦点返回与失败恢复。
- 置信度：高（正文、生成器与浏览器截图三方一致）。

### F02 · P1 · 图标尺寸规范与实际设计图不一致

- 预期：IconButton 为 36×36，内部图标 16（`visual-design.md:305`），同一图标资产可复用并逐像素验收。
- 现状：主页图使用 `build-frames.py:12-15` 的 24 坐标 path 加 `translate(x+6,y+6)`；search 外包络约 14，filter/eye/info 约 18，library 约 16，未统一为 16。状态图 eye 用 `build-detail-frames.py:15`，外包络 16；两套生成器不一致。
- 影响：首页截图、控件规范图和实现无法同时满足“图标 16”，C27/C35/C37/C39 的像素验收会得到相互冲突的基准。
- 建议：冻结 16×16 viewBox 图标集，明确 stroke 是否计入外包络，所有图统一引用同一 path/组件；重新生成主页和控件状态板并做像素比对。
- 置信度：高（path 坐标可直接计算；不是“24 坐标系就等于 24px”的推断）。

### F03 · P1 · 36px 命中区与 Token/Retry 例外定义不闭合

- 预期：`:295,301,339` 多处规定桌面固定 36px 命中区；若 Token 删除区 24、RetryAction 高 32 是视觉尺寸例外，应明确外层 hitbox、焦点环与邻接间距。
- 现状：`:309` 写 Token 高24、删除区24；`:315` 写 Retry 高32。图中 Token 是 104×24 且 `×` 没有独立边界，Retry 是 130×32；没有说明 24/32 是否仍包在 36px hitbox，也没有说明例外授权。
- 影响：实现可能按 24/32 做真实点击区，违反同页“固定36px”；也可能加透明 hitbox，造成视觉/几何验收与重叠规则不确定。
- 建议：把“视觉框尺寸”和“最小交互命中区”分列；画出透明 hitbox/焦点环，并写出 Token 删除区和 Retry 的明确例外或 36px 包裹规则。
- 置信度：高。

### F04 · P1 · D01 被覆盖表和总结错误计为设计 PASS

- 预期：D01 在用户决定前保持待决，任何涉及其去留的复合评论不可整体 PASS。
- 现状：正文 `:126,345` 明确待确认；但 `DESIGN-COVERAGE.md` 对 C18 标“PASS（设计）；D01待决”，总结 `visual-design.md:347` 又称“37 条设计覆盖 PASS”。C28 的评论也含 D01，C31 日历子项亦受影响。
- 影响：精确分母被抬高，可能绕过用户决策并误导实现启动。
- 建议：C18、C28 标 `待决`；C31 标 `部分`；总结改为 29 满足、6 部分、2 待决、2 排除，或在修复其他设计缺口后再重算。
