# 我的交易室界面修正规格

日期：2026-09-22
Status: implemented
范围：交易室界面修正。整合时保留远端 master 已实现的左侧导航、页面状态恢复、行情配置和持仓证据规则。

整合说明：市场分类沿用 master 的 A股/美股/港股归属，ETF 保留为独立资产类型筛选；下文早期按四类显示的描述不覆盖该规则。本金池仍沿用既有配置。本金入口直达数据管理的收益配置页，数据质量入口直达数据质量页。

## Problem Statement

交易员打开“我的交易室”，需要迅速理解选定范围的已平仓表现、持仓中需要复盘的对象以及数据是否可靠。目前图表刻度与图例会干扰读数，自定义日期入口不完整，日历与窄屏金额难以阅读；大量重复说明占据首屏，收益率分母、汇率估算与持仓数据时点不够醒目。用户必须自行拼接散落的信息，才能判断数字的实际含义。

本次审查基于当前代码和独立历史数据副本。副本中的过期行情、负数量只能证明界面需要表达可用性和证据状态，不能作为真实账户异常的结论。

## Solution

保留交易室现有金融口径与一级导航，按“统一范围 → 业绩摘要与趋势/日历 → 当前持仓 → 可折叠收益质量详情”组织内容；把简短数据状态放在摘要附近。压缩无决策价值的标题和重复说明，先修复图表与格式准确性，再提高筛选、日历和持仓比较效率。

本期落地：坐标与图例修正、直接可用的日期选择、完整活动筛选摘要、真实星期日历及窄屏日列表、单价精度、收益率口径披露、可信回合质量指标、紧凑持仓比较与证据标签、汇率与数据时点提示、统一文字及图标语义。

保留默认实盘/全部分类/本月/趋势，保留市场分组与最近成交降序的持仓默认排序。数据管理继续承担本金配置、导入和行情管理；首页只提供上下文入口。本期不建立账户资产或收益率系统。

## User Stories

1. As a 交易员, I want 首屏看到统计范围与关键业绩, so that 我能快速确认当前数字属于哪个交易集合。
2. As a 交易员, I want 趋势刻度与数据点准确对应, so that 我能可靠判断每个时点的累计盈亏。
3. As a 交易员, I want 图例只描述真实绘制的序列, so that 我不会把一条曲线误认为两项指标。
4. As a 交易员, I want 查看日期、期间净盈亏、累计净盈亏和币种, so that 我能追溯曲线变化。
5. As a 交易员, I want 单点、全负值、持平和无样本趋势被正确表达, so that 我不会误读边界情况。
6. As a 交易员, I want 点击自定义期间立即看到日期输入, so that 我不必猜测控件藏在哪里。
7. As a 交易员, I want 无效日期不改变已生效范围, so that 我能安全编辑筛选草稿。
8. As a 交易员, I want 查看全部历史或跳到最近有平仓回合的期间, so that 本月无样本时仍能继续复盘。
9. As a 交易员, I want 始终看见已启用的账户、币种和其他条件, so that 我不会忘记局部筛选。
10. As a 交易员, I want 逐项移除条件或重置范围, so that 我能明确控制统计集合。
11. As a 交易员, I want 切换趋势和日历不改变统计期间, so that 两种视图可以直接对照。
12. As a 交易员, I want 下钻时明确看到新范围并返回上一范围, so that 我不会丢失分析上下文。
13. As a 交易员, I want 日期按真实星期对齐, so that 我能识别交易节律。
14. As a 交易员, I want 区分无平仓样本、数据不可用、持平和未来日期, so that 不会把未知当作零收益。
15. As a 手机用户, I want 日期、金额和正负号完整显示, so that 小屏幕也能准确复盘。
16. As a 键盘用户, I want 操作筛选、访问图表读数与日期详情, so that 核心信息不依赖鼠标悬浮。
17. As a 交易员, I want 单价与金额使用不同格式, so that ETF细小价差不会被金额舍入掩盖。
18. As a 交易员, I want 明确知道收益率名称、分母和适用样本, so that 我不会把成本收益率当作账户回报。
19. As a 交易员, I want 本金缺失时有解释和配置入口, so that 我能理解为何使用交易成本收益率。
20. As a 交易员, I want 同时查看平均盈利、平均亏损、盈亏比和利润因子, so that 我能结合胜率判断回合质量。
21. As a 交易员, I want 小样本与零分母明确提示, so that 极端统计不会被误认为稳定表现。
22. As a 交易员, I want 人民币估算及汇率时间靠近金额展示, so that 我知道历史估算会随当前汇率变化。
23. As a 交易员, I want 汇率缺失时仍看到原币小计, so that 不完整换算不会冒充完整合计。
24. As a 交易员, I want 在紧凑持仓列表比较数量、均价、估值价和浮盈亏, so that 我能减少滚动与来回记忆。
25. As a 交易员, I want 保留市场、账户、资产类型和回合身份, so that 同一证券的不同仓位不会混淆。
26. As a 交易员, I want 看清持仓方向及证据是否充分, so that 负数量不会被自动解释为真实空头。
27. As a 交易员, I want 按最近成交或可比较的浮盈亏排序, so that 我能选择本次复盘顺序。
28. As a 交易员, I want 从持仓行进入准确回合, so that 我不必重新寻找对象。
29. As a 交易员, I want 区分导入覆盖日、估值日和页面查看日, so that 我不会把推导仓位视为券商实时确认。
30. As a 交易员, I want 顶部知道哪些结果不可用并能前往处理, so that 我不会到列表底部才发现限制。
31. As a 交易员, I want 实盘、模拟运行和未知来源保持隔离, so that 财务结果不会被混合。
32. As a 长时间使用者, I want 清晰字号、统一图标和稳定颜色语义, so that 我能低负担地阅读和操作。

## Implementation Decisions

1. **沿用领域边界。** 统计以可信已平仓回合、最后平仓来源交易日、扣费净盈亏为基础；持仓浮盈亏独立。实盘与模拟盘、不同模拟运行保持隔离；ETF本金分类与证券市场身份正交。未列明改变的既有规则继续有效。
2. **一个主要界面测试边界。** 交易室容器接收现有交易库、行情投影、汇率快照、时钟和复盘/数据管理回调；用户在完整页面操作，观察显示与导航结果。复用现有范围、业绩、日历、持仓和质量模型，不新建重复的dashboard状态或第二套金额聚合器。
3. **紧凑信息层级。** 去除重复英文眉题、重复入选计数及趋势区重复累计末值。标题一行，范围工具条可响应式换行；摘要附近保留简短数据状态。1280×720默认折叠状态下应看到主摘要和至少120px趋势绘图区；异常详情不默认占据首屏。
4. **筛选规则。** 保留原快捷顺序和高级筛选默认折叠。账户/币种当前值在工具条摘要可见；标的、复盘状态、ETF市场等启用后成为可移除标签。移除条件不改变交易性质或模拟运行。明确区分“清除附加筛选”和“恢复默认范围”。
5. **日期草稿。** “更多期间”改为直接展开自定义日期与“全部历史”入口；用应用/取消区分草稿与生效值。起始日晚于结束日、日期缺失或越过允许截止日时提示且保留旧范围。本月空样本提供“最近有平仓回合的月份”，尊重当前其他筛选，找不到则解释；首次打开仍为本月。
6. **趋势。** 本期仅绘制累计已平仓回合净盈亏，不新增期间柱状图。图例单条对应实际序列；多原币回退时按币种标识。刻度、点、零线与网格使用相同绘图区坐标；轴标题不参与刻度分布。不能用等距标签冒充不等距采样位置。边缘留出空间，单点可见，缺数据不得伪连为已知路径。
7. **趋势读数。** 悬浮、键盘选点或触控选点提供日期/覆盖范围、期间值、累计值、币种和样本数；继续提供可访问的数据列表。多币种无完整汇率时按原币展示，共用数值尺度必须显式标注且轴不冒用某一币种作为所有序列单位。
8. **日历与范围。** 保留月/年/全部年份的已确认层级与全局期间联动。仅切换趋势/日历不改范围；跨月期间标明“所选期间·按月汇总”，不以选中“月”暗示正在看某月每日明细。月份/年份下钻更新全局期间，显示范围路径和“返回上一范围”；点日仅展开详情。范围或运行变化使旧详情失效时清除，不带回旧金额。
9. **月历布局。** 星期一至星期日七列表头，按真实星期添加月初空位；格内用日号，完整日期进入可访问名称和详情。保留自然日，不把无平仓认定为休市或缺失行情。颜色本期只表示正/负/持平/不可用，提供图例，不暗示收益强度；收益热力强度留待单独设计。
10. **窄屏。** 620px及以下月度每日视图使用可触控日列表，显示完整日期、带符号金额、币种及回合数；年/月汇总可用自适应卡片。禁止页面级横向滚动、正负号换行或金额截断。选择控件可换行，不以窄容器内部滚动挤压选项。
11. **数值格式。** 分离单价、货币金额、比率、数量。单价不加正号，优先使用已有有效报价精度元数据；无精度元数据时保留来源小数有效精度而不是统一截为两位。持仓均价可先显示最多6位小数并提供完整值详情，不改底层数值。金额默认2位，比率默认2位百分数；盈亏保留正负号，未知保持不可用。标签使用“持仓均价”“估值价”，数量标明已有可信单位，未知单位不猜测。
12. **收益率。** 保留本金完整时主卡为本金参考收益率、不完整或局部范围时回退交易成本收益率的既有规则；卡片就近显示明确名称和口径徽标，解释中给出公式、实际分子/分母、币种、纳入/排除数量与原因。本金完整时辅助详情仍有成本收益率。本金配置入口跳数据管理，不在首页新增编辑表单，不计算账户回报或平均分类百分比。
13. **质量指标。** 在默认折叠的收益质量详情中增加平均盈利、平均亏损绝对值、平均盈亏比及利润因子。以同一可信已平仓样本集合为准：平均盈利=正净盈亏之和/盈利回合数；平均亏损=负净盈亏绝对值之和/亏损回合数；平均盈亏比=前两者之比；利润因子=正净盈亏之和/负净盈亏绝对值之和。持平保留在整体样本和胜率分母，不计入胜负均值。无盈利/亏损样本或零分母显示具体原因，不显示Infinity/NaN或伪造0。展示胜/负/平样本数，不自行给出统计显著性或策略稳定性评分。多币种缺汇率时分币种计算，不相加原币。
14. **持仓比较。** 桌面使用紧凑表格/等效对齐列表，小屏用短卡片；保留市场分组、默认最近成交降序与准确回合导航。包含身份、方向/证据状态、数量、均价、估值价及日期、浮盈亏和操作。额外浮盈亏排序仅在同币种可比较行内成立，或者具备同一完整汇率快照时明确标记估算排序；不可用项置后，恢复默认排序可见。不按原币数字跨币种排序。
15. **持仓证据与时间。** 方向只使用现有明确回合/持仓证据，不根据负号直接认定空头；不充分则“方向待核对”。沿用现有可用性判定，不借UI改写数量或成本。持仓不受已平仓业绩日期窗口裁剪；说明“按已导入流水推导”，同时显示查看日与流水覆盖截止，估值行显示行情日期。旧价可保留但必须紧邻标记“过期参考价”，浮盈亏依原有效性规则决定是否可用。
16. **汇率与质量提示。** 主金额就近显示“人民币估算·按最新汇率”；详情可查看原币小计、汇率来源与更新时间。失败沿用旧快照时显示旧日期和更新状态；没有完整快照不显示完整合计。顶部质量摘要分别说明交易统计、持仓估值等受影响数量与分母，并跳转现有数据管理上下文。行内只展示一次短状态，技术时间戳、provider和证据收进详情，不改行情来源或刷新预算。
17. **图标与可访问性。** 使用现有图标库及统一尺寸/描边，导航选中、身份状态、盈亏状态分别使用一致视觉语义；实盘/模拟身份不复用盈亏颜色。主要动作保留文字，纯图标按钮提供可访问名称与焦点；装饰图标对辅助技术隐藏。正文与控件默认至少14px、辅助说明及坐标至少12px，金额用易比较的等宽数字；保留已有红绿/青红偏好。主要触控目标至少44px，不只靠颜色传达盈亏或错误。
18. **接口与存储。** 优先扩充现有只读投影（格式精度、可用性原因、指标样本与分母），维持既有复盘和数据管理动作合约。不新增数据库迁移或外部API；不改变原始成交、财务字段、行情provider、限流和缓存策略。若实现发现数据契约确实不足，先记录缺口，不用猜测数据填充。

## Testing Decisions

- 主测试入口是完整交易室的可观察用户行为：选择范围后各模块是否同步、日期草稿是否安全提交、读数/标签是否一致、导航是否进入正确回合。避免只断言CSS类名、函数调用次数或把实现复制为测试。
- 复用现有交易室容器、趋势日历、持仓组件测试；这些已有模拟运行隔离、统一范围、自定义日期、日历下钻、单点趋势、原币回退与准确回合导航先例。保留有业务意义的断言，更新仅描述旧布局位置的断言。
- 复用既有范围/指标/本金/持仓模型单测核对纯金融边界：费用未知、历史不全、完整回合买入成本、部分本金、跨币种缺汇率、零分母、全胜/全负/持平、明确空头与方向未知。Decimal字符串计算保持不变。
- 日期固定时钟，覆盖跨年、闰年2月、月首不同星期、部分月份、本月截至今日和未来日期。保留来源市场交易日期，不能用UTC截断替代。
- 图表至少用已知正负值与单点样本检查实际坐标、零线及可见标签；文本“纵轴”存在不算坐标验收。截图/实际浏览器检查极值、首末点、边缘裁剪和标签对应。
- 确定性用例覆盖：行情价1.103与1.104能区分；单价无正号而正盈亏有正号；平均盈利200、平均亏损100时盈亏比2；盈利总和400、亏损总和100时利润因子4；无亏损时显示无亏损样本原因而非无限大。
- 浏览器验收至少1280×720与390×844，补320px宽度边界；检查首屏趋势可见、筛选无滚动陷阱、日列表金额完整、键盘焦点、触控及复盘返回状态。不得只依据HTTP 200或组件测试通过宣称UI完成。
- 所有会写入的浏览器流程使用SQLite一致性备份与独立端口；验收前后校验原库成交数量和内容摘要不变。自动加载可能写缓存/复盘草稿，同样不得连接原库。外部行情失败不掩盖已成功主结果。
- 完成后集中运行类型检查、相关测试、构建及适用全量回归；记录已有失败与未运行项。协调者独立真实浏览器验收后保留可用服务，提供可点击URL、数据副本说明与启动方式。
- 测试边界核对已通过异步问题发出，暂未收到答复；按“完整页面+已有领域单测+隔离浏览器验收”的默认方案写入，未声称用户另行确认。若有回复据此更新规格。

## Out of Scope

- 不新增现金余额、持仓市值/账户总资产总览、账户仓位比例、组合风险敞口；此前审查建议保留为未来独立需求，现有已确认规格不支持本期扩展这些能力。
- 不新增账户净值曲线、账户最大回撤、Sharpe、大盘比较、交易建议或自动下单。已平仓累计盈亏不得冒称账户净值。
- 不增加历史汇率库，不改成平仓日汇率，不改变现有本金池、成本收益率样本口径或默认持仓排序。
- 不修正历史成交或仅凭负数量推断/修补缺失流水，不把历史副本的过期行情认定为真实账户故障。
- 不增加期间收益柱状图或收益强度热力编码，不为视觉改造引入新的图表平台或外部服务。
- 不重建数据管理，不在首页展开本金录入/技术诊断面板，不发布远端issue，不推送、合并或部署。

## Further Notes
