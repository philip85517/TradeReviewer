## Question

既然技术拆单不增加回合，系统依据什么证据识别一次人的操作？已有委托标识、人工确认的成交分组与无标识记录如何处理，是否以及在哪里让用户合并/拆分？不能仅凭时间接近自动确认为同一行为。

同一行为的范围是否限制在同账户、同证券、同方向？跨账户操作、缺少开仓、卖出数量超过已知持仓、交易决策分组改变时，如何展示待确认状态并避免产生错误回合数？既有复盘成果如何引用更新后的行为分组？

## Scope

解决由已确认领域定义暴露的行为识别与异常配对设计问题，不重新决定回合按人的操作计数。本票不实施算法、修改数据或迁移历史复盘。

## 验收标准

- [ ] 取得用户对识别证据及无标识记录处理的真实决定。
- [ ] 明确合并/拆分权限、操作入口与原始成交保留规则。
- [ ] 覆盖技术拆单、相邻但独立卖出、不同账户/证券、缺少开仓及分组修订反例。
- [ ] 列出对回合身份、统计和已有复盘成果的影响；未决定的迁移实施不冒充已完成。

## 反例与证据

本票从概念定义票中独立拆出，避免把识别能力当作词汇定义已确认的推论。

2026-10-28 用户确认：历史成交缺少委托编号时标记“待确认”，确认后才计入回合统计。提问同时提出同账户、同标的、相同委托编号可视为一次操作；方向、跨情境等边界、人工确认的入口和分组修订对现有复盘的影响尚须明确，不能仅凭时间相近自行合并。原始成交仍须保留。该决定解决无编号记录的基本处理，并不关闭本票或证明实现、迁移及统计已通过验收。

2026-10-28 [独立逻辑审查](../../trading-library-v20-development/evidence/TL11-D07-independent-rule-review.md)：存档缺号不等于源文件缺号；现有持仓 episode 数与主动平仓回合数并不等价，不能直接替换既有持仓 builder 或移除成交。新增未接线的纯资格门及测试作为局部前置；独立审查发现稀疏数组绕过问题，已交实现者第 1/5 轮修复并待独立复验。实际确认入口、持久化、回合计算和旧复盘关联尚未实现或验收。

后续第 1/5 轮局部复验：修复稀疏数组及无效条目后，独立复验 13 项既有测试与 3 项反例通过；协调者使用固定 Node 独立运行 13 项测试及两文件 ESLint 均通过。该资格门未接生产；它对调用方提供的每个成交执行确认判断，开仓是否应纳入尚未决定，不能将此实现直接视为批准的业务规则或产品验收。独立复验日志见 [记录](../../trading-library-v20-development/evidence/TL11-D07-action-confirmation-independent-retest.log)。
