## 二、时间证据层级建议（研究建议，非产品政策）

建议把“原始证据”与“可推导结果”分开，保留原件路径/页/行或单元格、原墙上文字、精度、原 zone 文字、证据适用范围、规范化 zone/offset、使用的 tzdb 版本、派生 UTC 及推导状态。

1. **同一成交单元格的完整日期时间和明确偏移/区域。** 如 Tiger `GMT+8` 或 `US/Eastern`。固定偏移可直接算 UTC；区域名必须按发生日期查历史规则。保留原始拼写，规范名不替代原文。
2. **同表/章节/整份原件的明确图例。** 按实际适用范围关联到行；同文档不同章节未必相同。“香港时间”可映射 `Asia/Hong_Kong`；“当地市场时间”还依赖可核实的证券/场所身份。
3. **与该券商实体、报表格式、历史有效期匹配的官方说明或逐笔官方回报。** 当前帮助页只证明当前声明，不能自动修补多年前缺图例的 PDF；新旧图例不一致时保留版本边界。
4. **间接一致性检查。** 交易所日历、时段、跨午夜、交收日、相邻已知行和成交回报对应关系，可以提出或否证假设，不能仅因落在盘中就升级为源时区事实。
5. **未知/冲突。** 不能由币种、居住地、设备时区、文件名月份、现有代码默认值补齐。更具体证据一般优先，但证据相互矛盾时应记录冲突；不能机械地覆盖并抹去异常。

时区不等于偏移：`GMT+8` 是固定 `+08:00` 的原件表达；`US/Eastern` 在本地 zoneinfo 可解析，应用代码映射为 `America/New_York`，按日期可能为 -05:00 或 -04:00。即使本批现代日期中香港/上海结果均为 +08:00，也不能把所有 IANA 名永久实现为固定偏移。IANA 维护历史本地时间及政治/DST 变更；缩写还可能歧义，例如 CST。[IANA 数据库说明](https://www.iana.org/time-zones)、[IANA theory](https://www.iana.org/time-zones/theory)。这里没有由“USD”推出纽约时区的步骤。

## 三、五种日期不能互相替代

| 概念 | 含义与证据边界 |
| --- | --- |
| 源墙上日期/时间 | 券商印出的日期和时钟。需和源 zone 一起解释；香港 06-25 凌晨可仍是纽约 06-24。 |
| UTC instant | 唯一时点；只有精度和 zone 足够、转换无歧义时才能确定。UTC 日期只是另一种日历日期。 |
| 市场本地日历日期与交易日 | 把 UTC 转到交易市场只得到本地日历日期；业务交易日还需场所/券商 session 规则、假期及历史有效期。夜盘可能归下一交易日，ATS 归属不宜泛称为所有交易所的统一规则。 |
| 月结单月份 | 原件的账期/归档属性，保留原件标题证据；不是 `UTC.substring(0,7)`，也不是对所有行源日期直接取月。 |
| 交收/结算日期 | 成交后履约或券商展示的结算日期，独立字段；不能倒推唯一成交时刻。原件还明确提醒展示日期与实际发生日期可能不同。 |

富途夜盘的原件证据：`富途/美股/2023-07.pdf` p5 第 6.5 条，及 `富途/综合/2025-06.pdf` p13“其他”5，均说明美东 20:00(T) 至 04:00(T+1) 成交记为 T+1，并展示于相应日结单和月结单。这说明月归属可能受夜盘交易日规则影响。当前[富途夜盘说明第 7 节](https://www.futuhk.com/hans/support/topic2_707)也给出周一晚归周二；[Tiger 官方澳洲站第 6 节](https://www.itiger.com/au/help/detail/15973794?lang=en_US)同样如此，但该站实体/版本不能直接证明本批所有 Tiger 历史 PDF 的账期政策。

交收规则还有历史变化：SEC 记录大多数相关证券由 T+3 改 T+2 于 2017-09-05 实施，再于 2024-05-28 改 T+1。这里的 T+n 是业务规则，不能当 n 个自然日去补交收，更不能拿现行 T+1 改写 2015 年账单。[SEC 2017 实施公告](https://www.sec.gov/newsroom/press-releases/2017-163)、[SEC 2024 实施说明](https://www.sec.gov/newsroom/press-releases/2024-62)。本研究不重建所有交收日历或例外。

### 日期精度与时段边界

- 只有日期的成交证据只支持 date 精度，不能补 `00:00:00`、开盘或收盘制造日内定位。只有分钟同样不能宣称秒级精度。合计行没有时间不等于存在一笔 date-only 成交；先辨别行语义。
- 本次股票/ETF 代表成交行均读到了秒，**没有确认一个独立的 date-only 股票/ETF 成交样本**。date-only 是待覆盖的输入情形，不是已经发现的历史家族。基金/现金日期不用于扩大股票回放范围；例如 `老虎/2024-03.pdf` p2-p3 基金有 `00:00:00, GMT+8`，不能凭字面认定真实日内成交或借此测试股票策略。
- DST 重复小时可能对应两个 UTC，缺失小时没有 UTC。建议输出候选/异常证据，若要用户选 earlier/later 或其他策略应保留选择来源，本研究不代选。仅 `replace(tzinfo=...)` 不会验证缺失小时，需要 UTC 往返校验。[Python zoneinfo 官方文档（fold）](https://docs.python.org/3/library/zoneinfo.html)。
- 当前 [NYSE 官方交易时间](https://www.nyse.com/trade/hours-calendars)列核心交易 ET 09:30-16:00，并列提前收市；这不是所有历史股票成交的合法时段全集。盘前/盘后/夜盘与常规盘分别建证据，不应仅因超出常规盘判为坏时间。
- 历史时段不能固定套用今天的表。[HKEX 2012-03-01 公告](https://www.hkex.com.hk/News/Regulatory-Announcements/2012/120301news?sc_lang=en)明确从 2012-03-05 午后开市由 13:30 改 13:00。该变化早于本批最早港股样本，作为有效期建模的反例，不表示本批有该旧时段成交。夜盘也需历史产品开放、场所和例外证据；本次未穷举首次开放日、暗盘、半日市和临时停市。

| 2024-09-30 20:30:00，New_York（合成） | 2024-10-01T00:30:00Z | 香港 10-01 08:30；按上述富途夜盘归属说明可归 10-01 交易日/月，而纽约日历仍为 09-30；不是已核实的真实月界成交 |

`New_York`、`Hong_Kong` 在表中分别简写 `America/New_York`、`Asia/Hong_Kong`。可复算的核心方法（本次以此方法核验所有区域输入；set 去除正常小时两种 fold 的重复结果）：

```python
from datetime import datetime, timezone
from zoneinfo import ZoneInfo

def candidates(wall, name):
    naive = datetime.fromisoformat(wall)
    zone = ZoneInfo(name)
    result = set()
    for fold in (0, 1):
        utc = naive.replace(tzinfo=zone, fold=fold).astimezone(timezone.utc)
        if utc.astimezone(zone).replace(tzinfo=None) == naive:
            result.add(utc.isoformat())
    return sorted(result)
```
