## Sharp question

在已锁定的整体框架内，哪一组经真实页面测量后的空间预算作为后续实现和视觉放行的绑定目标？需要确认的是剩余的精确阈值和例外处理，不重新讨论“图表优先、左侧入口在左、右侧入口在右、底部执行组居中”这些已经确认的方向。

推荐先以现有基线候选值测量，再由用户只对实际画面的密度、阅读感受和操作清晰度作选择：顶部常驻区不超过当前规范预算；桌面控件视觉高度约 `36px`、粗指针命中 `44px`；左右面板保持现有可读宽度；底部执行图标组以中心线对齐、使用紧凑 icon hit area；主图/轴/侧栏间距和长文滚动以同态截图为准。候选值不能在没有测量时直接冻结。

## Scope / What to build

输出布局预算表和可执行的视觉对照方案，覆盖：顶部阶段/截止与工具行、左侧面板及贴左收缩、右侧计划/笔记及贴右收缩、图表轴、底部居中执行 icon group、导航展开态、面板 open/closed/focus、长中文/长价格/密集标签、`1440×900`、`1280×800`、约 `390px` 两侧断点。

## 验收标准与反例

- [ ] 提供同一数据、同一阶段和同一图表范围的 before/after 截图，并给出顶部、左右面板、图表舞台、价格轴、底部组和页下游的 rect；截图像素尺寸与 CSS 视口分开记录。
- [ ] 左右收缩在对应边缘真实点击、Tab/Enter、Escape 后可逆；开合不推进阶段/截止、不丢选中/滚动、不把按钮移到另一侧；反例是面板回流遮住价格轴或图表被无故压缩。
- [ ] 底部执行控件以 icon 组织，中心线稳定，命中区和焦点可达；不以大块文字按钮牺牲图表高度；反例是控件组漂移、重叠或窄窗口无法触达。
- [ ] 长中文、长价格、密集标签、空/错误状态分别测量；不得通过缩小全页字号、隐藏关键判断/价格、删改固定评论或把桌面窄屏冒充手机键盘解决。
- [ ] 用户只需在实际画面上选择“更紧密/更可读”的候选，选择结果写入 `DESIGN-COVERAGE.md` 和公共组件迁移票；未选择的候选保留为历史参考。

## 验收证据

- 布局预算表：批准值、允许变化、禁止变化、状态、视口、owner、证据。
- before/during/after 几何 JSON 和同态并排/叠图；至少包含面板开合、底部动作 focus、导航展开和断点两侧。
- 鼠标/键盘操作日志；模拟粗指针可辅助，物理触控和系统原生光标保持独立 `NOT VERIFIED`。
- 独立视觉复核者结论：功能动作、空间测量、视觉对照三项分开。

## 派发说明

- 在 HITL 选择完成前只允许新增测量、HTML/截图原型和计划文档；不得把候选预算直接写入全局样式或改变业务布局。
- 选择后实现 owner 以最小垂直切片接入现有主题/组件；不得迁移首页方案 B、替换框架或扩大到未登记页面。
- 共享布局容器由 root 统筹；实现者提交空间变更和状态链说明，独立复核者不得是同一人。
