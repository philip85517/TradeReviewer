## 交付内容

- `QualityDetails` 展示交易、持仓、历史 K 线和人民币估算汇率四个独立维度，分别显示可用/总数、受影响数、影响、原因、更新时间和动作。交易、持仓、FX 的分母单位是“回合”，历史行情是“标的”；空维度不会借用其他维度的分母。
- DataManagement 增加 `qualitySlot`，一级进入数据管理时也能显示当前质量模型，不依赖先从首页点击某个动作。
- workspace 以 dashboard 当前 scope 提供行情、任务、K 线和 FX 快照；dashboard 自己按当前 scope 计算交易/持仓质量。`fxSnapshot`、行情 labels、daily-only status 和质量模型更新均保持稳定引用；质量模型使用完整 JSON 快照比较，issue 标签、原因、账户尾号和动作变化不会被旧明细遮蔽。
- `onRetryDataQuality(dimension, ids)` 保持双参数契约。FX 走 FX refresh；历史/持仓只按有效 imported instrument ids 刷新。空 ids、全为无效 ids 和不支持 retry 的维度均直接 no-op，不会扩大成全库 batch。workspace 另外传入独立日线 status，1H 的 needs-provider 不会误把可重试日线标成 source-unsupported。
- `onOpenDataCheck(dimension, ids, episodeId?)` 会定位到实际标的和问题回合。交易补充和行情源诊断在有 instrument id 时都打开真实 `StockDataDialog`：补充动作可使用“补录成交/为本股补充文件/截图”，行情诊断显示当前日线/1H 状态、provider 返回的 daily/intraday message 和 coverage，不创建假的数据源设置。没有可定位标的时才回退到 `onOpenDataManagement(model)`。
- quality action 打开 dialog 时优先按 issue 的 `episodeId` 找到对应回合账户，再回退到该标的已有成交中的首个非空 `accountId`，避免双账户同标的进入错误账户；`accountIdForQualityCheck` 有回归覆盖。
