## Question

09 选定的模型在完整桌面操作中是否自然，能否从策略库组装/复制完整策略，再回到指定区间的实验并保持正确身份、配置与返回状态？

## Scope / What to build

以 09、11 的真实模型决定及共同框架对齐为前置，细化桌面视觉并制作可点击合成原型。纵向走通“库内建立策略→实验选择”和“实验中就地新建/复制→返回并选中”两条路径，再接入既有预览、待开始与运行入口。不是直接部署生产策略库，不编写真实脚本宿主或真实回测逻辑。

使用包式选择和说明，区分候选、买入触发、退出意图、目标仓位与实际成交。合成场景若展示三类包的作用，必须明确是演示，不证明真实规则计算。

纳入用户追加要求：兼容当前 TradeReview 网页风格；三类包在目录/组装/选择列表/完整策略详情/锁定实验中均可点入说明与细节并原处返回。只读查看与应用选择分离；同一选择面板内浏览详情，不叠加第二层弹窗。

同时覆盖大量包查找与管理：搜索/筛选/排序/分页、标签备注、开发/发布和去重引用统计、置顶、独立整理顺序、单包归档与恢复。按 M12/J4 串成一条完整管理旅程，沿用 M11 返回契约；合成内存原型不冒称个人偏好或库状态已持久化。

修订05补充：完整策略与我的实验列表顶部均有搜索、筛选和排序，按M14/SL17/LD12/LT-O实现组合查询、方向与独立返回状态。卡片密度与动作布局先参考[评估建议](../strategy-library-card-ui-review.md)，待后续画板采纳再固化目标，不擅自按建议尺寸实施。

实验入口全部归“我的实验”：策略库无“用于新实验”，列表→新建→四步创建可达；库内保存只归库，实验内新建保存返回原草稿。遵循M13，不把两策略的F05返回后态接到一策略的F17预览而造成选择丢失。

修订06统一全局元素与用户文案：面包屑、同类输入/按钮、边框和字体颜色遵循[UI06-01–05契约](../strategy-library-wireframes/STYLE-06-CONTRACT.md)，设计说明移出产品区域，保留必要数据/版本/执行限制。对应M15/SL18/LD13/LT-P；不扩展为卡片重构或正式开发。

## 验收标准与反例

- [ ] 09、11 的批准模型及对齐记录、原文/元素/画板与全部状态逐项进入派发前覆盖表，整页视觉与完整数据流各有唯一负责人。反例：照本票摘要自行发明页面或省略组成包。
- [ ] 实际浏览器从空库/已有库完成选择、三类包组装、固定与移动退出预设、历史复制，随后进入实验并预览。反例：只展示独立静态页面或硬编码两个不可编辑策略。
- [ ] 实验已填日期/期限/本金/已选策略时，新建成功选中新策略，取消保留原草稿，失败保留编辑输入；包不兼容与缺数据有原因和恢复路径。反例：返回重置或失败半成品混入可运行选择。
- [ ] 三类包均实际点入说明与细节，显示正确身份/版本/规则/参数及数据范围；从目录、槽位、选择列表、完整策略详情和锁定实验进入，显式返回、浏览器返回/前进和键盘 Escape 分别验来源层级、搜索/筛选/滚动/焦点、待选项、全部草稿字段与运行截止不变。选择列表先返回再明确“使用此包”才替换槽位；历史详情不升级。反例：看详情即选择、统一回首页、第二层模态框陷入或旧实验显示新值。证据：M11/F03/F09、LT-J。
- [ ] 创建两个使用同一策略的不同区间实验，修改复制品不会改来源或旧运行；不同策略的组合不串本金/持仓。反例：策略名称变了但仍共享旧身份或事件。
- [ ] 至少128个合成包、超过两页，三类目录分别搜索/筛选/排序/分页→详情→引用明细→返回原查询及行；标签备注保存不改执行版本，包级当前策略数、版本子集、历史引用去重可核算，未知/失败不当0。反例：只有固定首屏样例、时间字段混淆、置顶突破筛选。证据：LT-K、M12/F10/F12。
- [ ] 置顶→独立整理两组→拖动/键盘上下移动/指定跨页位置→保存/取消/失败/冲突→原查询，首尾及越界可解释；切换派生排序不抹掉手动顺序，个人偏好不改业务定义。反例：取消已经保存、只能拖动、未通过原型刷新边界就宣称持久化。证据：LT-L、F11。
- [ ] 有当前和历史引用的包归档/恢复，分别验证成功、取消、失败、引用统计未知、最后一页清空；旧策略与实验仍保留锁定版本，已有策略可新实验，新增槽位被阻止，活动草稿输入留存，复制归档引用显式确认。恢复同一身份且普通组末尾不置顶。证据：LT-M、F13；正式隔离库刷新和原始快照不变留给01。
- [ ] 从创建交接到真实渲染主图，至少走通开始→下一日可见 bar/事件→暂停→返回→会话内重开；保留 V/M/各组合进度/结果截止与暴露来源。反例：只改游标文本或回调成功。扩展依赖该状态的工作前先独立接受这条最小旅程。
- [ ] 未参与 UI 实现的审查者在 1440×900、1280×800、100% 缩放的匹配状态直接对照 09 模型和现有 TradeReview 风格，覆盖空库、组装、复制、返回选择、错误，以及包详情首屏/长正文末尾/返回后；核对主题色、字体、侧栏、间距、边框、按钮、表单、焦点和固定返回入口。差距分别留证。反例：只凭都是深色判定兼容、测试通过替代视觉、把图 1 像素宽当 CSS 视口。
- [ ] 标注合成数据与会话内存；刷新重置、模拟失败与真实持久化边界清楚。后续正式保存/返回/刷新使用隔离 SQLite，不能由本票豁免。
- [ ] 用户真实试用反馈写入独立 resolution；交付有刚经真实浏览器检查且仍运行的预览 URL、启动方式和技术/视觉结果。反例：技术 PASS 自动等于用户认可。

- [ ] 从业务tab进入我的实验列表，创建、继续草稿、重开原运行/查看结果分别正确；四步主动选择库策略，返回/取消保留原身份与字段；库内新建不产生实验。反例：tab本身新建、库中实验CTA、普通选择冒充新建成功后态、重开生成新运行。证据：SL16/LD11/LT-N、M13。
- [ ] 两页顶部搜索/筛选/排序组合生效，明确字段和方向、结果数与无匹配清除；切tab及详情返回恢复各自查询/分页/滚动，更改查询回第一页，不改变实验运行或策略版本。两档桌面及长记录检查；卡片采用最终获认可画板，不将修订05评估目标冒充已批准。证据：SL17/LD12/LT-O、M14。

- [ ] 全部19板在两档桌面统一导航、控件、线框和文字层级，产品无设计编号/调试说明，数据限制与历史语义保留；独立直接读图，不能用DOM尺寸替代视觉。证据：UI06-01–05、M15、LT-P。
