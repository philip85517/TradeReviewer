# I16 完整交易统计生产接线设计（2026-10-29，只读准备）

## 依据与边界

用户已明确：这批模拟数据为完整交易，不拆单；一文件是一份练习，单账户、单标的。六个真实文件的复核和此前拆单推论更正见同目录 `tradingview-complete-trades-correction-20261029.md`。这一合同支持按本批受支持 TradingView 报表计入完整练习；不把报表编号称为委托号，也不把该结论套用给无相同合同的其他来源。数据本身损坏或金额无法可靠计算仍须明确失败或未知。日期级数据不能确定同日真实成交先后；这影响回放、权益路径，不阻止对完整报表组的已实现净额相加。当前未修改产品、数据库或源文件。

原规范 `docs/design-system/baselines/2026-10-26-trading-library-v2.0/source/visual-design.candidate.md`：第 59–70、72–87 行为信息入口和数值显示；第 176–183 行模拟统计按当前确认练习日期；第 187–200 行按练习而非内部配对、费用一次、含费净额不再扣费；第 202–208 行要求完整有序权益轨迹才能计算最差练习回撤；第 210–216 行规定日/月/年趋势和分布。第 238–245、304–318 行及现行 `DESIGN-COVERAGE.md` 为状态与范围约束。画板为 `docs/design-system/baselines/2026-10-26-trading-library-v2.0/source/images/approved-e-sim-stats-1440.jpg`（1440×1000）：模拟盘、列表/统计、日期/市场/账户筛选、两行四卡、回撤、趋势和分布；画板数字仅是示例，使用规范的练习口径与真实数据。视觉与功能分别由未实现者验收。

## 六文件预期与算法

每个 `交易编号` 是一个报表组，其进场与出场两行重复同一组的净损益及手续费。校验两行角色、方向、数量、金额和费用一致，完整组各取一次。统计使用已含费的 `净损益 CNY`，绝不再次减去手续费；手续费独立按组计一次并求和。使用精确十进制计算，到 UI 边界才按约定格式化。以下为只读 `csv.DictReader`、Python `Decimal` 按组取一行算得；对应第 2 行起的原始数据共 130 行、65 组。日期假设为文件名日期且尚未人工更正；筛选包含所有六份且账户属于当前范围。收益率仅在六份均使用内置默认 100000 CNY 且无已保存全局或练习覆盖时适用，不表示已核实任何实际数据库配置。

默认本金从 100000 改为 200000 时，未单独覆盖的练习收益率减半；覆盖为 50000 的练习使用自身覆盖，其他练习使用新的默认。金额、净盈亏胜负和费用不受本金改变；非正、缺失或损坏本金不能伪造 0、默认或收益率。有效本金优先级为练习覆盖、全局、内置默认，仅在合法的缺省情形使用内置默认；实际非法值按现行合同显示未知/错误。权益回撤不以净额走势替代。

## 可执行纵切及文件所有权

1. **服务端合同单一 owner。** `app/lib/storage/practice-store.ts:166–208` 已在同一读事务校验当前 practice/revision、来源字节 SHA/长度、重新解析的单账户/标的、原始记录和来源，再读取该练习有效本金；`app/lib/storage/practice-statistics-financial.ts:14–85` 将来源映射投影，但第 59–72 行现无条件阻断完整练习净额、费用和残余。根据本次用户确认，在经该受支持来源合同及完整来源重验、全部组有效、无确定矛盾、精度可表达时，令财务结果为已知完整练习净额与完整费用，保留当前 ID/revision 和金额币种关系；其他来源不自动获得该来源合同。投影 `app/lib/trades/tradingview-practice-financial-projection.ts` 的已知闭合组小计可复用，但其本身不证明任意来源的完整练习，避免把无来源上下文的通用函数输出冒称认证。具体响应字段由服务端和客户端 owner 在覆盖矩阵登记；若增添来源合同标识，它应由受支持来源合同产生并与当前 revision 绑定，不能伪造某次人工点击或放宽源完整性检查。现有 `projection.practiceNetPnl` 与 `metrics.netPnl` 必须一致，费用需增加明确的完整范围 known/unknown 合同，不能由客户端从局部小计擅自补全。保持 v1 老接口兼容。
2. **客户端单一 owner。** `app/lib/storage/practice-statistics-v2-client.ts:49–129` 当前明确拒绝全部已知练习净额/收益率，需与服务端一起调整版本化响应校验：仅接受受支持合同、同 ID/revision，完整组计数、行一对一、已含费小计与练习净额一致，费用/本金来源与计算值一致，未知不接受伪造数值；拒绝响应内部不一致，保留现有来源行和超精度验证。客户端格式校验并不能独立认证服务端身份；真实存储来源校验依然是信任边界。
3. **统计页面 owner。** `app/components/library/library-practice-statistics.tsx:75–100` 已按练习聚合金额与收益率样本；第 108、432–435 行的费用文案和值无条件未知，第 493–495 行分布尚不可用。以同一已筛选 v2 快照显示完整费用，并对有未知费用的范围标明未知/完整覆盖数，不把已知小计叫全量；更新 i 文案。利用现有 `app/lib/trades/practice-statistics-distribution.ts` 及既有趋势组件，按规范将分布接线；金额与收益率分别取本指标可计算分母，持平为独立组，不能把未知、缺本金或范围外数据当 0。其五个边界实现为 `<-阈值`、`[-阈值,0)`、`0`、`(0,阈值]`、`>阈值`；阈值目前金额 100、收益率 5%，须同批准原型和当前 DESIGN-COVERAGE 再核验，不以测试实现自证规格。分布下钻属于画板旅程，若本纵切不实现，明确未完成并继续登记，不将页面称为完整。
4. **资本和跨页集成 owner（协调者）。** 数据管理中的 `app/components/data-management/practice-capital-settings.tsx` 通过真实资本路由保存，全局数据管理入口见 `data-management.tsx:253`；统计页由 `trade-review-workspace.tsx:6340–6348` 传入 `practiceRefresh`，其读取 effect 依赖 refreshKey、重试和客户端。不能仅凭组件测试断定本金保存使现有统计自动刷新：真实验证数据管理修改→返回统计→读取→刷新/重开；如保留组件导致数据陈旧，按生命周期增加明确失效/重读，避免静默保留旧资本，不更改账户范围。跨页 owner 同时负责实际浏览器旅程、视觉和共享文件协调。个人练习覆盖目前仅有组件级入口的证据，是否在产品 UI 可达必须实测，不假定。

建议顺序：先冻结服务端/客户端合同及定向测试；随后单一 UI owner 接受合同并做指标、费用、趋势和分布；协调者负责跨页本金刷新与实际端到端。上述 UI 文件均与当前 I12 图表作者文件分离；若实际文件占用变化则重新协调。分支覆盖按当前版本定向测量，不为数字制造空洞测试，保留既有独立 FAIL 及历史限制。

## 真实异常及失败语义

- 空文件、未知来源、损坏字节/hash、关联缺失、不同账户/标的或当前修订不匹配：沿用实际来源/存储错误处理，不能算成零，不能绕过源重验。当前 `readStatisticsInputsSnapshot` 是全量读事务，任一来源损坏导致整次读取失败；本切片不要未经设计悄然变成局部成功，保留明确错误、可重试及可见的上一成功快照标识，当前筛选不得越界。按用户决定，将一般性“可能拆单/持仓”从这些已确认完整且完整验证的练习未知原因中移除。
- 同组缺行、重复行、数量/方向/金额/费用不一致、非数、负费用、明显可证时序倒置、跨组精度溢出：该数据不得输出完整已知值；按现有投影 unknown/错误清晰标示并保留具体原因。既知小计不能称作完整练习，未知练习不进入净额、胜率、分布或收益率分母。真实异常处理粒度及原来 route 503 保持兼容；空范围、无可计算样本、范围无效、加载失败和 0 结果分别显示。
- 正本金无效只影响收益率；同一练习两行重复财务值只计一次。市场/账户交集依现行共享 scope 合同处理，不把无权限或无匹配擅自扩大为全部。对显式筛选使用当前确认日期；日期更正后立即重新归组，不改变练习身份或凭来源日期覆盖人工日期。

## RED→GREEN 与独立验收

- 保留旧报告/FAIL。分别先写公开入口失败反例：源文件→真实预检保存→隔离 SQLite 同快照→真实 v2 route→严格客户端，包含完整多组、非零费、不同正负和持平、原始双行只算一次；重导去重、重开、日期更正、账户及市场过滤、scope 全空/无匹配。测试真实源修订与资本绑定，构造缺组/复制/损坏/非法本金/溢出和 503，在可验证边界保持未知或失败。给定六文件的正式隔离库复算表中每练习和全局数值，不对业务库写入。
- 本金：练习 A 使用全局、B 有独立覆盖，修改全局后 A 变化 B 不变；真实设置路由保存→返回统计→重开，金额和费用不变、收益率及其分母正确；失败、冲突、非法输入保留旧值和提示，不把陈旧快照标为新值。
- UI：按日期/账户/市场筛选及清空、切换列表/统计、刷新失败/重试、全未知和部分未知、费用信息鼠标/键盘、长数字精确值、趋势单点/缺口和分布区间边界；保留焦点和状态契约。不得把纯组件 fixture、进程内 route 或合成数据叫真实浏览器验收。
- 非作者独立审查真实可达的来源完整性、重复手续费、资本覆盖与 v1/v2 兼容，重跑隔离 route/client，再由独立 UI 审查者在显式独占临时 SQLite 和批准视口 1440×1000 的可比数据状态中，直接比较画板截图，鼠标/键盘、保存→返回→重开及刷新均有版本绑定证据。触屏/窄屏依用户当次范围排除；未执行项目标 NOT VERIFIED。该设计不宣称全 I16/I17 或 I12 回放验收。
