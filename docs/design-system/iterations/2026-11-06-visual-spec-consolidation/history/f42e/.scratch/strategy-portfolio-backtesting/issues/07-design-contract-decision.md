## 验收标准与反例

- [ ] 固定布局交接包括所有框架锚点、工具按钮状态、结果/比较/异常切换与两档连续操作证据；明确截图像素与 CSS 视口的区别、批准偏差及主动重排例外。反例：将 TradingView 静态图当作完整像素稿，或只验最终截图。
- [ ] 完整交接包含独立策略库、三类包组装、已有选择/就地新建、历史复制、返回/失败恢复、实验锁定版本和运行结果追溯；未决的包参数、仓位/退出关系与执行语义有明确后续责任，不静默采用旧包默认。反例：只更新实验卡文字就绕过 09/10 关闭地图。

- [ ] 用户走通最终串联原型并给出明确反馈；单页认可不能代替完整动线认可。
- [ ] 逐项记录批准画面、元素、布局/密度、默认状态、错误恢复、两档桌面视口与交互契约；本轮窄屏暂缓，保留旧证据及未确认项，不能假造尺寸批准。
- [ ] 形成需求到原型状态的覆盖表并更新原规格，数据输入/输出需求来自已选场景；尚有关键问题则新增票，不提前关闭地图。
- [ ] 独立记录原型浏览器/视觉证据与用户确认；交接列明真实数据、引擎和持久化尚未实现，不称为功能通过。
- [ ] 用户真实反馈及选定/拒绝理由记录于独立 resolution；反例：原型能运行就自动代表用户同意。
