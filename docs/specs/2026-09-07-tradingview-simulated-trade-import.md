# TradingView 模拟交易 CSV 导入与复盘

状态：已确认，待实现；Issue 使用 `ready-for-agent` 标签。

## Problem Statement

用户希望把 TradingView 的回放模拟交易记录导入 TradeReviewer，使用已有交易库、交易回合、K 线回放和复盘笔记，并始终能够辨认这些记录属于模拟盘。

目前导入支持富途表格、Tiger/招商证券 PDF 和已适配成交截图，没有 TradingView CSV 适配，也没有持久化的模拟盘分类。样本不是普通逐笔成交流水：同一交易编号分别列出进场和出场，整笔交易的盈亏与手续费在两行重复，部分平仓对应多个交易编号。直接按现有格式解析会造成方向、费用、排序或去重错误。

## Solution

增加“导入 TradingView 模拟交易”入口，支持用户提供的中文 CSV 版式。文件在浏览器解析，展示证券、真实交易日期范围、模拟盘标识、成交数量与诊断，确认后进入现有持久化和复盘流程。

来源平台与交易性质分别保存；导入预览、导入历史、交易库和复盘工作区明确显示“TradingView · 模拟盘”。模拟交易使用独立运行范围组织回合、笔记与统计，不与实盘或其他模拟运行合并。行情和证券元数据继续复用已有缓存。

## User Stories

1. 作为复盘用户，我希望从 TradingView 模拟交易入口选择 CSV，以便导入回放练习记录。
2. 作为复盘用户，我希望两份现有示例都能导入，以便复盘不同股票的模拟交易。
3. 作为复盘用户，我希望导入前看到“模拟盘”，以便确认交易性质。
4. 作为复盘用户，我希望从文件名识别交易所和证券代码并核对，以便把无证券列的记录关联到正确股票。
5. 作为复盘用户，我希望文件名无法识别时可以选择证券，以便处理重命名文件。
6. 作为复盘用户，我希望系统自动补全证券名称，以便沿用现有股票展示方式。
7. 作为复盘用户，我希望交易区间取自 CSV 内容，以免把导出日期当成交日期。
8. 作为复盘用户，我希望知道原文件只有日期，以免误以为成交具有准确时刻。
9. 作为复盘用户，我希望预览区分原始行、交易配对、标准化成交和交易回合，以便理解导入数量。
10. 作为复盘用户，我希望多头进出场正确转换，以便复盘买入和卖出。
11. 作为复盘用户，我希望空头进出场正确转换，以便复盘卖出开仓和买入平仓。
12. 作为复盘用户，我希望加仓被保留，以便回顾持仓扩大的过程。
13. 作为复盘用户，我希望分批平仓及其对应入场份额完整保留，以便避免仓位被错误去重。
14. 作为复盘用户，我希望重复列出的手续费只计一次，以便获得正确费用总额。
15. 作为复盘用户，我希望区分源文件报告的盈亏和系统重算结果，以便理解口径或舍入差异。
16. 作为复盘用户，我希望重复导入同一文件不会增加成交或回合，以便安全重试。
17. 作为复盘用户，我希望不同模拟运行相互独立，以免相同股票、日期和价格导致误合并。
18. 作为复盘用户，我希望模拟盘与实盘可以筛选并分别统计，以便辨认练习与真实交易表现。
19. 作为复盘用户，我希望在交易库和复盘工作区持续看到模拟盘标识，以免进入详情后失去来源上下文。
20. 作为复盘用户，我希望使用已有回放控制、成交标记、持仓统计和绘图，以便沿用熟悉的复盘方法。
21. 作为复盘用户，我希望回放尚未结束时隐藏未来成交和最终结果，以便避免被答案影响判断。
22. 作为复盘用户，我希望笔记、标签和绘图在刷新后保留并属于正确回合，以便持续复盘。
23. 作为复盘用户，我希望错误行指出交易编号、行位置和原因，以便修正后重试。
24. 作为复盘用户，我希望取消预览时不产生交易数据，以便放心检查文件。
25. 作为复盘用户，我希望历史行情不可用时得到明确提示，以便理解可用回放周期。
26. 作为已有用户，我希望原有券商和截图导入继续工作，以便继续管理真实交易记录。

## Implementation Decisions

以下为依据现有代码和样本提出的实现约束，并非用户逐项确认的新增需求。

- 复用已有本地解析、证券补全、导入预览、确认入库、交易回合和复盘工作区。增加独立 TradingView 入口及来源适配，不把现有图表组件品牌当作数据来源标识。
- 本期支持两份样本共有的中文表头与 CNY 数据，包括 UTF-8 BOM、引号包围字段、常见换行和末尾无换行。按表头识别格式，不能只依据扩展名接受任意 CSV。
- CSV 没有证券或账户列。文件名中的 SSE 和六位代码作为证券候选，映射到现有上海市场规范；在预览核对或通过现有证券选择能力修正。名称补全遵循现有元数据规则，不要求用户手填名称。
- 文件名日期不参与成交时间计算。样本时间为日期精度，沿用 `date-only` 和上海时区语义，不伪造真实成交时刻；同日无法确定的事件次序明确提示，不能机械沿用“出场在前”的文件行序。
- 按模拟运行、证券与交易编号配对进场和出场；保留原始行号、编号、类型、信号和来源日期作为追溯信息。多头进场/空头出场为买入，多头出场/空头进场为卖出。
- 对每个配对保留两个带份额的标准化成交，再复用“持仓从零开始、回到零结束”的交易回合规则。交易编号是源文件配对编号，不等于应用交易回合编号。同日同价但不同编号的进场份额不能被去重；不推断原始订单 ID。
- 日期升序后，配对内保证进场先于出场；不同配对同日排序遵循可确定的持仓连续性，仍有歧义时阻断该组并说明原因，不猜测盘中先后。
- 数量、价格和费用使用现有十进制字符串。源文件“大小（价值）”可能是入场价值，不能当作出场成交额；系统成交额按对应行价格乘数量计算。
- 同一交易编号两行的手续费是重复的配对级数据，只计一次。由于样本未提供逐次佣金分摊，本期把配对总费用在出场时计入，并在预览/统计说明此规则；不据此声称恢复了真实进场费用。配对内重复统计字段冲突时给出诊断，不能任取一行。
- 源报告净损益、回报、有利/不利波动、累计损益和持续 K 线数是报告指标，不能逐行累加，也不能替代逐步回放的账本。源值按配对单独保留，仅在完整结果可见时展示。系统账本与源报告分别命名；差异不能通过修改成交价格或数量消除。
- 增加显式交易性质（模拟/实盘/未知）和模拟运行标识；来源平台保持 TradingView。已知券商导入按现有来源兼容归类，无法判断的历史来源保留未知，不把所有缺失字段的数据自动称作实盘。系统演示数据继续遵循原有独立边界。
- 本期每份不同内容的 CSV 默认属于独立模拟运行；同一内容重复导入（包括仅改文件名）识别为重复。同内容需归属不同证券时必须识别上下文冲突，不能静默复用；改证券或修正文件后生成不同上下文时仍需明确处理旧批次。不同内容的重叠导出不自动拼接，也不跨运行去重。
- 交易性质和运行范围参与成交对账、回合身份、笔记、绘图及统计隔离；已有实盘回合标识和笔记关联必须保持稳定。证券列表可以共享同一证券，但其回合必须明确分区，汇总不得默认混算实盘和模拟盘。
- SQLite 是唯一业务数据源；扩展结构化成交、批次与相关 API 的校验、保存、读取和兼容升级。不能仅在页面临时添加模拟盘标签。确认前不写成交，确认后采用现有原子导入与重试机制。
- CSV 原文不上传；确认后的必要结构化成交和有限来源信息按现有本机服务边界保存。测试使用最小冻结夹具，原文件不纳入公开 issue 或仓库。
- 配对缺失、重复角色、非法数值、未知类型、退出早于进入或数量不匹配按整组诊断，不能只导入半组造成伪造持仓；其他完整配对允许预览后导入。本期不推断缺失的未平仓交易。
- 导入盘中精度缺失不阻止已有日线复盘；行情失败保留成交与笔记，显示实际可用周期，不生成替代行情。不扩大本期行情供应商或历史分钟覆盖承诺。

## Testing Decisions

- 主要测试边界：用户从工作区选择实际 CSV，经过真实格式识别、解析、预览和确认，进入交易库与回放，保存笔记并重新加载。断言用户可见结果和保存后行为，不测试内部调用次数、私有函数或组件结构。
- 复用已有工作区导入流程测试、导入确认对话框测试、交易回合及回放账本用例。现有工作区测试会替换解析器；新增 CSV 验收用例必须使用真实解析链，仅冻结外部证券和行情响应。
- 另在已有 SQLite 存储 API/仓储边界验证新字段往返、事务失败、重复请求、旧数据兼容以及回合笔记关联；不能仅依赖旧 IndexedDB 测试替身宣称持久化已通过。
- 样本一：34 个数据行、17 个进出场配对，区间 2021-02-19 至 2023-03-23。按持仓归零规则应形成 12 个闭合交易回合；多空方向与分批平仓保留，配对净损益合计 20580 CNY，费用为 0。
- 样本二：24 个数据行、12 个配对，区间 2021-02-19 至 2023-10-16。按持仓归零规则应形成 10 个闭合交易回合；配对费用合计 9.60 CNY，而非重复累加后的 19.20。配对净损益合计 21290.40 CNY，末项源累计损益为 21290.38 CNY，明确保留此差异。
- 验证样本一 2021-04-08 的 7000 与 3000 空头进场份额都存在；样本二 2021-02-19 与 2021-03-16 的两次多头进场构成加仓，2021-04-08 完全平仓。
- 覆盖文件重导与改名重导、独立运行、同证券实盘共存、筛选及汇总、取消预览、错误配对、缺少证券上下文、BOM/换行/引号、来源标签刷新恢复。
- 回放验证未揭示的出场、最终盈亏、源报告有利/不利波动和累计结果不提前显示；日期精度标签存在，行情不足有说明，复盘笔记与绘图只归属当前运行回合。
- 对受影响的现有券商导入、截图导入、回合分组和存储契约运行回归，并执行项目类型检查、lint 与构建。外部实时行情请求不作为确定性验收依赖。

## Out of Scope

- 用户提到的第二个新入口尚未描述，本规格不定义它。
- TradingView 账号登录、API 自动同步、浏览器抓取、实时下单或模拟撮合引擎。
- 未提供样本的其他 TradingView 导出类别、其他语言/币种格式或其他资产类型的全面适配。
- 自动合并不同内容的重叠导出、跨文件恢复同一模拟运行、恢复未提供的原始订单或精确盘中成交时刻。
- 完整复刻 TradingView 策略测试器、保证所有绩效口径一致、推断初始资金/保证金/滑点或缺失未平仓记录。
- 新增行情供应商、扩大历史分钟行情覆盖、上线模式洞察、部署发布或直接实现代码。
