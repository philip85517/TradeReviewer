## Runtime behavior implemented

- The comparison module receives every current portfolio, including failed and excluded portfolios, each portfolio's own capital, draft, ledger, status, and `Mᵢ`. The comparison module reads these projections; it does not advance the runtime clock.
- Comparison owns a separate result cursor `R`. Initial synchronized `R` is clamped to `min(source V or Results R, common Mᵢ)`. Changing `R`, switching to single-portfolio mode, or explicitly revealing the common/single boundary does not change process `V`, global `M`, or a portfolio ledger.
- The synchronized cursor is retained while viewing a later single-portfolio interval. Returning to synchronized mode restores that cursor. Explicit later comparison reveals keep the farthest exposure date and record `组合比较` as the latest source.
- Returning from comparison restores the process context captured at entry, including the original `V`, selected portfolio, chart mode, symbol, holding selection, and viewport. When entry came from Results, the saved process context comes from the Results `resultContext`; Results `R` is never copied into process `V`.
- An event callback carries the portfolio identity and optional symbol. Opening it selects that exact portfolio, sets process `V` to the event date, and opens the event drawer. Returning to the source comparison leaves its controlled `R` and mounted filter, legend, and scroll state intact.
- Comparison and Results hide the workbench. Playback, bulk expansion, and keyboard advance are stopped or guarded while hidden. Checkpoint reload clears stale comparison return state. Restoring a saved process context keeps global `M` monotonic; event navigation uses the live portfolio `Mᵢ`.
- A common boundary at `T0` remains a visible empty comparison when another portfolio has data, so the user can explicitly reveal that portfolio's later interval. The entry is disabled only when fewer than two portfolios exist or every portfolio remains at `T0`, with a nearby reason.
- A pending comparison route can reopen from the experiment list with the same comparison UI state. Process advance, review, a new result entry, or checkpoint reload clears that pending route so an old comparison cannot restore stale runtime state.
