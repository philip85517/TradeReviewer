# 老虎证券已成交股票截图识别设计

日期：2026-08-03
状态：待用户复核

## 背景

当前部署环境能够完整解码并 OCR 处理用户提供的
`截图2.jpg`：图片是 753 × 13,574 的 JPEG，处理完成时显示 8/8 个识别区域。
最终失败发生在 OCR 之后的版式检测阶段，错误为“暂不支持该截图版式，请使用老虎或富途的交易历史截图”。

用户已确认该图片来自老虎证券 App 的“订单 → 已成交 → 股票”页面。该页面使用紧凑的
instrument-first 表格：标题为“订单”，筛选条件包含“状态/已成交”和“类型/股票”，表头依次为
“代码｜名称”“方向”“总量｜价格”“成交时间”。现有老虎版式仅接受“订单历史/交易历史”等标题，
以及“名称/代码”“成交数量”“成交价格”等旧表头，因此正确 OCR 结果仍会被拒绝。

## 目标

- 新增对老虎证券“订单 → 已成交 → 股票”深色紧凑列表的显式支持。
- 从该版式恢复市场、证券代码、证券名称、买卖方向、数量、价格和精确到秒的成交时间原文。
- 支持 US/HK 市场标记与代码被 OCR 为同一文本行或相邻文本行的情况。
- 保留现有人工确认、时区确认、账户输入、去重和持久化流程。
- 保持版式检测 fail closed，不把任意包含“买入/卖出”的列表识别为老虎证券。
- 在当前部署代码基线上发布修复，不回退现有 SQLite 存储和截图校对修复。

## 非目标

- 不增加新的券商。
- 不实现任意券商截图的通用表格解析。
- 不改变 OCR 模型、图片切片尺寸、浏览器本地处理边界或模型资源托管方式。
- 不自动猜测截图时区或账户。
- 不改变其他老虎、富途版式的解析结果。

## 方案选择

采用独立版式版本 `tiger-filled-orders-dark-v1`。

未采用直接放宽 `tiger-instrument-first-dark-v1` 别名的方案，因为新版页面的标题、筛选条件、
表头文案和市场代码表示均构成一组独立契约；混入旧版本会降低检测可解释性，并扩大误识别范围。
未采用通用表格解析器，因为本次只有一个已确认版式，通用化会超出需求并削弱 fail-closed 约束。

## 版式检测

新增版式只有同时满足以下信号时才匹配：

1. 页头区域包含独立的“订单”标题。
2. 首笔成交之前的筛选区域包含“状态”和“已成交”。
3. 首笔成交之前的筛选区域包含“类型”和“股票”。
4. 首笔成交之前存在按横向顺序排列的表头：
   - “代码｜名称”或 OCR 等价形式“代码名称”；
   - “方向”；
   - “总量｜价格”或拆分的“总量”“价格”；
   - “成交时间”。
5. 表头之后至少存在两行结构完整且相互独立的成交记录。每行必须包含：
   - 名称列中纵向排列的证券名称与市场/代码；
   - 方向列中的精确买入或卖出标签；
   - 数量/价格列中的两个数值；
   - 时间列中的日期和秒级时间。

版式不得依赖单个“订单”、单个“买入/卖出”或单行成交完成匹配。若新版与任何现有版式同时达到
匹配阈值，则继续拒绝图片，避免选择不确定的解析器。

## 解析规则

### 行分组

复用现有老虎 instrument-first 的方向锚点和按 OCR 文本框高度计算的局部行窗口。方向列位于图片
中部，名称/代码位于左侧，数量/价格位于右中部，成交时间位于最右侧。每个方向锚点只关联当前
局部窗口中的字段，长图高度不得放大行关联范围。

### 证券身份

名称列第一行作为证券名称。第二行按以下形式解析：

- 同一 OCR 行：`US CTVA`、`HK 06228`；
- 相邻 OCR 行：`US` + `CTVA`、`HK` + `06228`；
- 分隔符允许为空格、连续空格或 OCR 产生的 `|`。

市场仅接受 `US` 和 `HK`。US 代码必须符合现有字母代码规则；HK 代码接受 1–5 位数字，并通过
现有 `canonicalInstrumentSymbol` 规范化。市场和代码共享来源证据；无法同时证明市场和代码时，
两者保持待确认，不从证券名称猜测。

### 数量和价格

数量/价格列中按纵向顺序选择当前行的前两个数值，第一项为数量、第二项为价格。沿用现有十进制
字符串和千位分隔符处理，不使用二进制浮点数。字符修复继续降低置信度并触发人工确认。

### 成交时间

时间列选择当前行中最近的一个日期和一个 `HH:mm:ss` 时间，组合为券商展示的墙上时间原文。
不在解析阶段转换 UTC；用户在校对页确认时区后，继续走现有严格时间转换流程。

### 版式元数据

成功草稿写入：

- `broker: "tiger"`；
- `layoutVersion: "tiger-filled-orders-dark-v1"`；
- 现有图片 ID、批次 ID、捕获顺序、字段证据和原图坐标。

## 错误处理

- 缺少必要版式信号时返回现有“不支持该截图版式”错误。
- 版式匹配但某行字段缺失时保留该行草稿，由人工补全或删除。
- 完整版式匹配但没有产生任何成交草稿时返回现有“未从截图中识别到成交记录”错误。
- 本次不改变 OCR 初始化、取消、重试或资源释放行为。

## 测试策略

### 版式检测测试

- 使用 753 × 13,574 的匿名 OCR 几何夹具，包含新版筛选、表头和至少两笔成交。
- 断言检测结果为老虎证券 `tiger-filled-orders-dark-v1`。
- 删除“已成交”、删除“股票”、破坏表头顺序、只保留一行成交时均必须拒绝。
- 现有富途、老虎旧版和双重匹配负例继续通过。

### 解析测试

- 覆盖组合行 `US CTVA` 和 `HK 06228`。
- 覆盖市场与代码被拆为相邻 OCR 行。
- 断言名称、市场、规范化代码、方向、数量、价格、秒级时间和字段证据。
- 覆盖长图中相邻两行不会串联数量、价格或时间。
- 无法证明市场/代码时生成待确认字段，不猜测。

### 集成和部署验收

- 运行截图版式、老虎解析器、截图导入 Hook 的聚焦 Vitest。
- 运行完整单元测试、类型检查、lint 和生产构建。
- 基于当前部署所使用的代码分支构建新 release。
- 在部署实例上传原始 `截图2.jpg`，验收条件为：
  - 8/8 个识别区域处理完成；
  - 图片不再显示“识别失败”；
  - 校对表产生非零成交记录；
  - 首行至少正确恢复 `US / CTVA / 卖出 / 100 / 88.76 / 2026/07/29 23:01:17`；
  - HK 行至少正确恢复 `HK / 06228 / 卖出 / 200 / 26.380 / 2026/06/26 10:22:37`；
  - 未经用户确认时区和账户前，“确认导入”保持禁用。

## 发布安全

当前部署 release 包含尚未合入 master 的 SQLite 存储和截图校对修复。发布必须以当前部署代码基线
为基础应用本修复，不能直接从较旧 master 重新部署。部署前后记录 active release，并执行健康检查；
若构建或健康检查失败，沿用现有 release 回滚机制，且不修改 SQLite 数据目录。
