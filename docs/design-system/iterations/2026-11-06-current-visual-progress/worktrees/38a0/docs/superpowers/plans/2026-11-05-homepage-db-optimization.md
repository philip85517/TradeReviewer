# 首页数据库优化 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. 每个实现范围独立审查，由协调者最终接受。

**当前状态：** 2026-11-05，部分实现已完成；整体acceptance-failed，性能试改5/5暂停。实际是按需生成后持久复用，尚无写后后台预计算。结果见[最终验收](../../../.scratch/homepage-db-optimization-20261105/FINAL-ACCEPTANCE.md)。

**Goal:** 缩短真实桌面首页完整且正确展示至 1 秒以内，并报告实测而非接口推断。

**Architecture:** 保留原始成交、现有财务规则和缺失状态。服务器按版本提前准备可重建的页面结果，读取仅传页面需要的数据；版本变更使结果失效，发布前核对输入，失败不能发布。首页摆脱完整来源材料与逐证券行情扇出，进入交易库时继续使用原有事实读取合同。

**Tech Stack:** 项目锁定的 Node 26.0.0 / SQLite 3.53.0、TypeScript、React、Vitest、Vinext。

**Spec:** 用户本次实施指令；前工作树 `docs/backend-design/homepage-database-design.candidate.md` 及 `homepage-database-expert-review-2026-11-05.md`；本库 V2.5 `docs/design-system/baselines/2026-10-22-homepage-v2.5/source/visual-design.candidate.md`。

## Global Constraints
- 原数据库只读；测试、迁移、构建和浏览器使用 `.data/homepage-optimization.sqlite` 等显式隔离库。
- 桌面 1440×1000、1280×800，100% 缩放，持仓八行槽、分页、筛选与返回语义保持。
- 缺行情、汇率、来源或性质不得伪造数值；不得以加载骨架、旧值或快速空态宣称完整。
- 实施范围先只移动既有计算和读取；不恢复已暂停的金融规则/Bars 改造。
- 不推送、合并；保留所有既有未跟踪文件。

## Review Focus
1. 同一本账的成交、证券、行情、汇率、复盘变化都必须使依赖结果失效。
2. 构建中输入改变或异常，旧结果不能被标为最新；重启不得丢失可用版本。
3. 页面范围/期间快速变化，旧响应不得覆盖新范围；版本与请求标识不能来自缓存中的旧请求。
4. 无明确实盘性质、缺价或缺汇率时应明确不可用，不能因为性能优化产生“零持仓”的假结论。
5. 首次构建与修订后打开不能藏在计时之外；四类场景单列，完整展示与仅接口速度分开。
