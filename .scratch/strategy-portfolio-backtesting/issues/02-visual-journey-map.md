## Destination

通过用户实际操作可点击视觉原型，确认“策略观察者”的历史组合创建、自动回测观察、调仓解释和结果比较动线，形成可交接的场景、信息架构、关键状态与视觉交互契约。地图结束表示开发前的使用体验决策已清晰，不表示产品已实现。

## Notes

- **2026-09-29 当前桌面范围**：用户要求“窄屏暂不需要修改，其余的生成设计方案”，并确认完整桌面旅程验收。见[桌面设计规格](08-desktop-ux-design-spec.md)。本轮只发布设计输入，不关闭本地图或既有决策票；新布局等待设计反馈。旧窄屏证据保留，当前迭代不安排窄屏改版/专项验收。

- **用户明确要求风格兼容**：当前 A 及后续所有策略原型/页面必须沿用现有 TradeReview 的应用框架与视觉交互语言；A 仅确认分步流程。约束详情以[主导航决策的用户追加约束](../comments/strategy-visual-03/2026-09-29-resolution.md#用户追加约束与现有-tradereview-风格兼容)为准。每轮派发与验收必须引用该约束，并对照现有页面。

- 用户于 2026-09-29 明确要求视觉原型/操作动线先行，随后回复“A”确认策略观察者角色；范围以[规格中的已确认方向](../../../docs/specs/2026-09-29-strategy-portfolio-backtesting.md#已确认的后续方向2026-09-29)为依据。原规格的其他默认值均仍是建议。
- 每次先阅读 wayfinder；处理 UI 决策时使用 prototype 的 UI 分支；需要澄清时使用 grilling 与 domain-modeling，一次一个问题，用户自己作答。已确定方向不反复询问。
- 用完整场景和可点击原型讨论，每票只解决其明确问题；不用逐页孤立截图替代动线，也不用静态净值曲线假装回测已经实现。
- 原型使用明确标注的合成场景数据，无正式库读写，不实现真实撮合/数据采集。可以模拟暂停、返回、恢复和错误供用户判断；模拟恢复不能记为真实持久化验收。
- 先探索信息结构，再逐步提高已选方案的视觉精度。原型提供备选方案，用户实际反馈才是选定证据；沿用现有应用视觉语言，必要变化明确展示。
- 主协调者负责完整动线与整页一致性；进入原型代码工作前按项目流程指定实现者、全页视觉 owner、场景状态流 owner、独立视觉审查者并完成适用覆盖表；默认实现模型遵循项目流程，不在建图阶段派发。
- 有 UI 交付时提供真实浏览器检查过且仍运行的预览与启动方式。原型技术/视觉证据与用户 HITL 决策分开，前者不能替后者作答。
- 已有 [功能规格总票](01-strategy-portfolio-spec.md)保留，产品实施等待本地图完成；本地图不绕过随后真实数据/真实图表/持久化验收。
- frontier 由父子关系和 Blocked by 派生，运行 `python3 .scratch/strategy-portfolio-backtesting/frontier.py`。地图不维护另一份未关闭子票列表。
- 建图阶段不领取或解决子票；后续每次领取一张可领取决策票，结论写入独立 resolution 后再关闭并更新本地图。

## Not yet specified

- 已识别的桌面理解成本、信息过载和路径绕行已形成[桌面设计提案](08-desktop-ux-design-spec.md)，由既有工作台/比较决策票验证；后续实际体验是否还存在未识别问题仍待观察。
- 原型选定的信息结构对页面/共享数据接口的约束：目前不能确定哪些差异需要追加专门决策，待跨场景串联时辨识。

## Out of scope

- 生产页面、回测引擎、行情/财报采集、数据库迁移与插件运行时的正式实现：属于设计之后的开发阶段。
- 人工逐笔决策/手动下单模式：用户选择自动执行的策略观察者角色，本地图不扩展为交易训练台。
- 用演示收益验证策略有效性、宣称历史数据已经完整或无前视。
- 远端发布、推送与合并。

## Scope / What to build

维护决策索引及其子票，产出设计判断与可追溯依据；原型是判断的证据，不是正式产品交付。
