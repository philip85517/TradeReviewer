# 07 组件、设置 Hook 与真实浏览器独立验收

范围：只读复查 `app/components/dashboard/room-principal.tsx` 及其测试、`app/lib/principal/use-principal-settings.ts` 及其测试，并回看 principal model/API 契约和 spec §8、§10、§12；另独立核对 root 保存的 07 真实浏览器证据。重点是异步 config 覆盖、StrictMode 读写竞态、保存失败、币种确认和 live/simulation draft 隔离。未修改产品代码、未重复运行同批测试。

## 结论

**07 通过独立代码与真实浏览器复验。** 先前发现的两个 P1 已由当前实现和新增证据闭合：保存请求期间编辑控件已锁定；live scope 的 mutation 请求强制使用 `runId: null`，模拟盘切回实盘后本金保存/清空均成功。其余已采集的本金、筛选、持久化、回退、币种确认与模拟运行路径证据通过。

## 核对结果

- 异步 config：组件不再用单一 draft 被异步 props 覆盖，而是按 `scopeKey` 保存脏 draft；空 draft 会从新到达的 `config` 显示已保存值，用户已编辑的金额会保留。测试覆盖空 config → live config hydration，以及 live draft → simulation → live 往返。
- scope 隔离：draft、待确认币种和字段错误均按 `scopeKey` 分桶；hook 的 config 由 `principalConfigForScope` 从完整 state 按 `live` / `simulation:<runId>` 取值，不会把另一运行的输入带入当前卡片。
- StrictMode/read-save：初始读取通过 effect cleanup 的 active 标记和 `queueMicrotask` 避免 StrictMode 重复请求；`operationVersionRef` 使保存响应优先于保存前已发出的旧 GET，旧 GET 的结果、错误和 loading 收尾均不会覆盖保存后的 state。现有 StrictMode 回归明确在保存后释放旧 read，配置仍为新值。
- 保存失败：hook 失败时不更新 state，保留当前配置并暴露错误；组件收到 `false` 时保留当前 draft，避免失败后回退成旧值。保存成功才清除 draft，清空失败同样保留编辑内容。
- 输入与币种：四张分类卡片均可编辑；Decimal 正数校验拒绝空值、零和非正数；已填金额改变币种会先显示确认，未确认不能保存，确认只改变币种不自动换算金额。
- 只读呈现：摘要同时显示本金参考收益率、交易成本收益率和“已填本金小计”；fallback 原因由 model 传入，组件不会把成本回退误显示成本金参考收益率。

## 已修复复核：保存中编辑会被成功响应静默清掉

原复现是 `save` 在 `await onSave(category, value)` 前读取一次值，成功响应无条件清理 draft，而请求期间金额和币种仍可编辑；`clear` 也有同一竞态。当前 `room-principal.tsx:175-203` 已对金额、币种和确认/取消控件加 `disabled={saving}`，按钮也保持禁用，因而原竞态不再可由页面输入触发。

最小复现：先在一张卡片输入 `10000` 并点击保存，保持 `onSave` Promise 未 resolve；请求期间把金额改成 `12000`（或发起币种变更并留下确认状态）；让保存成功返回。输入会回到已保存配置/默认值，`12000` 或待确认币种消失，用户没有错误提示。该问题会在慢网络、重试或真实 API 延迟下暴露，属于用户刚输入的数据被成功响应覆盖，不是单纯交互偏好。

修复复核：组件回归新增“saving 时锁定金额、币种和确认控件”覆盖；root 的 07 定向集为 5 files / 28 tests passed。若未来改为允许保存中编辑，应重新引入 revision/value 保护，而不能恢复无条件清理。

## 真实浏览器证据

以下证据由 root 在隔离服务中操作并保存；本报告对页面结果作独立核对。

- `07-browser-global.txt`：默认实盘/全部分类/本月显示完整汇总，原币小计与人民币估算同屏，交易成本收益率为 1%。
- `07-browser-two-percent.txt`：A 股股票筛选下两笔完整回合净盈亏 ¥200、本金 ¥10,000，页面显示本金参考收益率 2% 与交易成本收益率 1%。
- `07-browser-persist-fallback.txt`：保存 ¥20,000 后重开仍保留；细筛缺本金时本金参考收益率回退为不可用，同时成本收益率仍显示，符合缺本金回退契约。
- `07-browser-currency-confirm.txt`：已有金额切换币种先显示“金额不会自动换算”的确认提示，未确认前不提交变更。
- `07-browser-run-a.txt`：选择模拟运行 run-a，ETF 本金 USD 1,000，摘要显示本金参考收益率 1%、交易成本收益率 2.5%。
- `07-browser-run-b.txt`：切换 run-b 后不继承 run-a 的本金；成本收益率为 -2.5%，本金参考收益率不可用并明确提示缺少 ETF 本金。
- `07-browser-live-return-clear-fixed.txt`：从模拟盘返回实盘后清空港股本金成功，摘要为 CNY 92,000，并正确回退为“缺少港股股票”。
- `07-browser-live-return-save-fixed.txt`：随后保存实盘港股本金 ¥10,000 成功，摘要恢复为 CNY 101,200 与本金参考收益率。

## 已修复复核：模拟切回实盘残留 runId，导致本金 API 400

`07-browser-missing-pool.txt` 保留为修复前失败反例：模拟运行切回实盘后旧 `runId` 使本金保存/清空返回 400。当前 `use-principal-settings.ts:111-114` 的 `mutationScope` 在 live 时显式构造 `{ nature: "live", simulationRunId: null }`，并由 `mutate` 传入 API；hook 回归覆盖该请求体边界。新增浏览器证据验证清空和保存均成功，页面没有旧的“本金设置请求无效”错误。

修复复核：live mutation scope 与 UI 返回路径均已覆盖；`07-browser-missing-pool.txt` 仅用于审计修复前行为，不再作为当前版本缺陷。

## 集成验收门槛

组件/hook 通过不等于首页已完成。dashboard 接线后需在隔离 v4 库验证：

1. live 四类金额保存、刷新/重开仍显示；清空后本金缺项提示与成本收益率回退正确。
2. 切换 simulation run-a/run-b 时本金卡、摘要比例和输入 draft 全部隔离；未选择运行时不能套用 live。
3. 异步读取期间编辑金额不会被旧 config 覆盖；保存失败显示错误且保留输入；币种确认不会改变数额。
4. 细筛回退与日期切换沿用本金，摘要/趋势/日历使用同一 scope 和 FX snapshot。

### 预留观察（不阻塞当前预审）

`refresh()` 是公开 hook 方法；若未来在保存请求进行中允许手动 refresh，应补一个“refresh 与 mutate 同时进行”的回归，确保刷新返回的保存前快照不能覆盖成功保存结果。当前页面没有该按钮，现有 StrictMode/旧 GET 回归已覆盖实际启动路径。
