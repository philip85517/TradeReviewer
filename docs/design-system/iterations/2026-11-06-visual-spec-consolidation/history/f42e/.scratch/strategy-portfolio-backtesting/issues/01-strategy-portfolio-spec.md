## 验收标准与反例

- [ ] SL01–SL09：独立策略库、三类包组装、已有策略选择、就地新建返回与历史复制构成完整旅程；正式保存/刷新/重开保留策略与实验的确切版本，旧结果不受新编辑影响。反例：两张固定策略卡冒充策略库，或复制策略改写旧运行。证据须来自后续正式实现。

- [ ] R01：通过统一证券/行情边界复用数据，并用版本固定研究快照；反例：复制另一套抓取器或刷新后旧运行结果变化。证据待后续实现报告。
- [ ] R02：任意历史时点的候选、财报、指标、图表、摘要均遵守可知截止；缺失时明确阻断或标注样本范围。反例：今天股本/未来财报混入历史筛选。
- [ ] R03：全部五档期限、逐日/连续/批量结果一致，新增 bar 在真实主图可见；反例：游标变了但主图未揭示，或一周无结果仍标记完整一年。
- [ ] R04：目标仓位→订单→实际成交→现金与持仓闭环，按所选预设再平衡；反例：直接改权重而无交易或现金变动。
- [ ] R05：曲线与统计可由同一账本核算，独立组合不串资金，部分结果不参与完整期排名；反例：期末浮盈当成已平仓净盈亏。
- [ ] R06：示例完整策略包和第二包/预设接入同一宿主，声明版本及数据能力；反例：每新增策略必须改页面逻辑，或插件直接读取未来行情。
- [ ] S01–S08/T03：真实浏览器完成创建→推进→调仓→保存→返回→重开→结果比较；同状态视觉对照独立通过；反例：仅 mock 回调或 DOM 按钮通过。
- [ ] 保存失败、冲突、重启与幂等重试保持完整日事务；真实交易内容不变；反例：重复成交、旧窗口覆盖或写入正式业务库做测试。
