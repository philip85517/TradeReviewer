# TL11-D07 独立业务逻辑审查

审查时间：2026-10-28；基准 HEAD `d95afc37d30f817edbd6daab41e85f485138de0d`，工作区存在未提交改动，以下判断针对审查时文件内容。静态审查；未访问业务库、未运行服务、未实测 UI、未验证真实文件或历史数据。此报告不是实现或产品验收。

## 决策与事实

- 用户明确确认：历史成交缺少委托编号时标记待确认，确认后才计入回合统计；保留原始成交。决策票仍为 open（`.scratch/trading-library-v11-design-decisions/issues/07-action-identification.md:7,15-17,45`）。该票的“同账户、同标的、相同委托编号可视为一次操作”仅记载为提问中同时提出的建议，不能据此当作用户已批准。
- 业务要求实盘每次主动平仓对应一个回合：先买 100 再买 50，分两次卖 80 和 70，得到两个已完成回合，不必等持仓清零（`docs/design-system/trading-library-design-spec.md:63-79`）。模拟练习汇总按练习计样本，不能未经决定把实盘规则套入模拟（同文档 81-87）；V2 参考也说明生产动作识别未决（`docs/design-system/baselines/2026-10-26-trading-library-v2.0/source/visual-design.candidate.md:148-159`）。
- 富途解析器可以识别编号，但仅多笔成交或有汇总行才生成包含编号的 `executionGroup`；单笔且无汇总的记录即使识别到编号，也可能未保存该字段（`app/lib/import/futu-pdf.ts:123-132,194-199`）。**当前存档字段为空不能证明原文件没有编号**；原始文件有无编号及影响数量均未核验。模拟 `sourceTradeId` 是 TradingView 配对来源，不应自动当券商委托号（`app/lib/import/tradingview-simulation.ts:260-281`）。
- 现有 `buildTradeEpisodes` 按账户/标的等组织持仓，并以持仓归零关闭 episode（`app/lib/trades/episodes.ts:36-46,508-525,573-588`），上述两次卖出形成一个持仓 episode；这一逻辑无待确认判断。列表把 `episodes.length` 作为 episodeCount，页面显示“个回合”（`app/lib/trades/library.ts:151,267-272`；`app/components/library/library-stock-rounds.tsx:425`），不是已证明符合新业务定义的回合数。洞察事实从已关闭的 episode 生成，也未见缺号确认条件（`app/lib/insights/episode-facts.ts:342-360,434-467`）。这属于源码可见差异，不代表已经在真实页面复现每种情形。
- 原有复盘按 `episode.id` 关联（`app/lib/trades/library.ts:190-192`；`app/lib/trades/episodes.ts:103-118`），复盘仓储、未平仓筛选和行情区间也使用现有 builder（`app/lib/recall/server-repository.ts:119`；`app/components/trade-review-workspace.tsx:1611,4787`；`app/lib/market/statement-range.ts:17`）。直接替换该 builder、或先从成交中剔除待确认记录，可能破坏持仓、成本计算和既有复盘关联；影响须单独验证。

## 仍待决定，不能代用户定案

1. 人工确认的对象及操作：逐条确认还是确认一组，是否支持合并/拆分、依据什么认定同一操作，编号在不同账户、证券、方向、日期或来源复用如何处理。不能只凭时间相近合并。
2. 开仓、平仓各有缺号时的状态及配对依赖；待确认如何影响回合以外的持仓、盈亏、列表和复盘展示。用户仅确认回合统计不计入，不能推导删除原始成交或改变其他统计。
3. 确认后数据如何持久化、修改或撤销，既有复盘和标注如何映射，出现并发修改、分组变化与来源异常时如何处理；以及最终确认入口和视觉状态。
4. 对存档缺号但原文件可能有号、来源不支持编号、模拟与历史真实交易的适用范围，需结合可获得的原始证据明确；不得把“未保存”说成“原文件缺号”。

## 可先执行的最小非 UI 工作与反例

先在隔离测试中建立纯函数/数据契约：仅区分“存档中委托编号可用”与“存档中不可用”，将不可用作为**需要人工核查的候选**；保留原始记录，标明并未核实原文件，不写旧库、不自动分组、不生成用户可见的确定性回合，不宣称完成产品功能。可用抽象确认状态做独立统计资格门测试：明确未确认样本不得贡献回合数，确认状态由测试输入提供；是否/如何把实际成交构造成此样本仍待设计。不得为实现资格门而过滤持仓计算输入。

最小反例：编号缺失、空串和空白；源文件有号但现存单笔未保存；仅有模拟 `sourceTradeId`；不同账户/方向或相同编号重用；时间相近的两次独立操作；无号开仓后有号平仓；同一操作多笔技术成交；部分平仓两次；确认重试和修改分组后保留既有复盘。测试中分别断言原始成交未丢、待确认未计回合、持仓与费用不因资格筛选丢失；涉及尚未决定的行为只记录问题，不预设期待结果。
