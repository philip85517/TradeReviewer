# I16 财务来源证据与当前缺口（2026-10-29）

本记录为只读调查；未改产品或业务库。更晚的用户澄清及六份源文件实核见同目录 `tradingview-complete-trades-correction-20261029.md`，其结论优先于本记录最初的条件化担忧：用户明确文件都是完整交易、模拟不拆单，不能将虚构拆单或文件外持仓当成六文件的事实或普遍阻断。

## 已批准口径

V2 原文 `docs/design-system/baselines/2026-10-26-trading-library-v2.0/source/visual-design.candidate.md:183,187–200`：模拟统计以练习为单位；练习净额为已实现毛额加残余浮动毛额减费用一次，来源净额已含费则不二次扣费；无残余不需要终值估值，有残余但结束估值缺失为未知。正的该练习有效本金用于收益率；本金未知或非正时金额可以已知、收益率未知。`:204–206` 的回撤需完整有序权益轨迹，不能将累计盈亏折线冒充权益轨迹。

用户此前确认一份文件对应一份练习、单账户单标的；现在进一步确认提供的都是完整交易且模拟不拆单。这些是本来源应采用的事实合同，不能借其他产品的假设削弱。实际六份每编号均有一进一出、数量方向一致（见更正记录），可据此及用户确认支持每笔完整交易结果，不能仅因假设未平残仓而把所有结果固定未知。若将来实际记录出现缺边、字段冲突，或来源合同不同，应对该实际异常分别处理。

## 数据和现有实现

- `app/lib/import/tradingview-practice-source.ts:42–48` 支持 TradingView 的 17 列：编号、类型、日期时间、价格、数量、报表净额和费用等。编号是报表交易编号，不是委托编号；进出两行的组级净额和费用各只计一次。时间字段不包含来源时区，不可虚构。
- `app/lib/storage/practice-statistics-financial.ts:6–33` 将已验证源字段映射到财务投影；`:59–74` 目前固定让完整练习已实现值、费用范围、残余和权益轨迹未知，即使各闭合组已知。`app/lib/storage/practice-statistics-v2-client.ts:64–72` 还要求完整净额及收益率未知，因此实现真实已知值需要服务端和客户端合同一致更新，不能只改显示。
- `app/lib/trades/tradingview-practice-financial-projection.ts:219–253,285–309,325–415,453–486` 逐交易组核对进出、数量、方向、日期和组内金额，已知组仅累计一次；应基于用户确认的完整交易合同复审如何提升为练习级金额，同时保留实际异常的未知处理。
- `app/lib/storage/practice-store.ts:166–208` 同一 SQLite 读取事务校验练习/版本/来源身份、原文 SHA、重解析内容及本金；`:197–203` 投影同次练习的数据。`app/lib/storage/practice-capital-store.ts:30–32,45–50` 的现行优先级为练习覆盖、全局、内置默认；`practice-capital-contracts.ts:3–22` 内置为 CNY 100000 且合法值为正数。不能把损坏本金变成零，也不能要求已有有效默认必须额外手动输入。
- `app/lib/trades/practice-metrics.ts:155–183` 已有基于确认的费用口径、残余和正本金的金额/收益率计算；`:186–218` 回撤需要轨迹。`app/api/storage/practices/statistics/route.ts:29–41` 为真实版本化统计入口；此处未实跑路由或生产 UI。

## 样本与现有报告冲突

本次只读六份真实文件，130 数据行 / 65 报表组，每组同方向一进一出且数量、净额、手续费一致；按组一次核对的价差减费与净额均在 0.01 CNY 内。此前 `evidence/I16-statistics-snapshot/real-csv-source-semantics-20261028.md:7–17` 也记录该观察。此为具体样本证据，不表示已验证 UI 或所有未来来源。

先前 `production-financial-path-audit-20261029.md:35–40` 倾向将完整文件及闭合组提升到可计算练习；`financial-full-practice-independent-20261029.md:13–15` 对未平残余和跨组费用作更保守的假设，认为不能仅凭组闭合证明完整练习。它们依赖的来源事实边界不同，不能同时无条件成立。用户现明确交易完整、模拟不拆单，且六文件实际无缺边/组内不一致；应以该新证据重新审视之前的阻断，不能继续把假设反例当成真实样本。对于跨组费用，应按实际来源报表净额一次计入而非凭假设二次扣费；若有具体冲突则定位真实字段并处理。

## 最小可靠算例与剩余工作

合成一笔完整多头交易：10 股，进场价 10、出场价 20，进出两行均报告净额 99.4 CNY、费用 0.6 CNY。按交易组只取一次净额为 99.4，不是 198.8 或 98.8；若该练习有效本金为 1000 CNY，则收益率 9.94%。同组两行是报表展示，不构成拆单。真实例子和每文件计数见更正记录。

待决的工程问题（暂不向用户提问）：如何在受信且绑定 practice/revision 的来源合同中表达用户确认，使真实导入、重开、统计路由及客户端一致采用它；异常/不受支持来源如何保持未知；验证金额、币种、金额精度与费用一次计入；收益率使用现有有效本金；如何保留历史结果兼容。日期级同日成交先后和小时柱位置依然未知，不能伪造，回放需独立处理；它不应成为读取报表练习净额的无关阻断。权益回撤仍需完整轨迹。

尚未验证：新合同下的产品修改、隔离数据库到公开路由的完整计算、真实网络和统计 UI/视觉；本调查不声明完整统计通过。
