# Recall 工作台实现验收记录

依据：[功能规格](../specs/2026-09-19-review-workspace.md)。开发分支 `codex/recall-workspace`，起点 `1c6fee0`。实现和独立测试均使用 Luna Max，按领域、图表、集成和导出划分文件责任，交接使用小范围任务说明和报告。

## 实现范围

- 新增 Recall 回合文档、决策分组、多快照、草稿与正式版，以及 SQLite 版本冲突检查。
- 图上多行 Text、自由/锚定定位、样式及宽度控制；图表与标注合成 PNG，并保留可编辑状态。
- 行情与成交双游标、历史快照编辑、回合完成及草稿自动保存。
- 按已留存内容生成 Markdown 和图片，支持 ZIP 与浏览器本地目录导出。

## 已执行的实际浏览器检查

使用独立测试数据库和合成行情，未操作用户交易数据库。测试回合包含同日两次买入、两次卖出，持仓最终归零。

- 首张快照保存后刷新可恢复。
- 回退到首笔成交之前，持仓为零；自动保存和刷新后仍保持该边界，没有提前揭示首笔成交。
- 在第一笔决策输入尚未截图的阶段文字，直接完成回合；刷新并重选该决策后文字可见。SQLite 中草稿和正式版均保留该决策草稿，原有六张决策 PNG 哈希不变，全局图仍仅包含原有三段文字。
- 添加独立第二回合后，浏览器显示零快照且无标注；切回第一回合仍恢复六份决策快照与一份全局图。新回合、跨账户和反向过零另有两项独立回归测试通过。
- 同根 K 线的下一决策使持仓由 100 变为 200，未揭示后续决策详情。
- 展开完整历史后返回，恢复此前行情与成交边界。
- 图上多行文字及自由定位可操作，原始文字随快照保存。
- 修改第一张历史快照后，其它快照和旧正式版的图片保持不变。
- 进入较早决策后刷新，再返回全局，恢复原有三段文字及最后成交边界；阶段编辑状态与全局工作图分别持久化。
- 完成后的普通编辑保留草稿差异，自动保存后仍可明确重新完成。
- 输入文字后直接留存、停留在裁切确认框再确认，快照成功入库；再次完成后草稿与正式版的六张快照一致。
- “数据管理”临时抽屉可访问交易记录导入、截图恢复、导入历史和行情更新，关闭后回到 Recall。
- 导出预览采用首次交易日期的 `YYYYMMDD` 简名，提示缺失快照与草稿状态。生产 ZIP 构建器导出的真实 PNG 包通过 CRC、相对图片引用和 PNG 格式检查。

## 验收限制

当前自动化浏览器不能操作系统原生目录选择器，因此尚未实际验证用户指定目录写入（V10 的目录部分）。目录取消、名称冲突、权限错误和中断通过适配器测试验证；不能据此声称真实目录导出已验收通过。

## 实施裁决与代价

| 裁决 | 理由与可能代价 |
| --- | --- |
| 开发授权允许工程判断，但历史 HITL 待确认项仍保留原状态 | 避免编造用户答复；判断不成立时需要调整架构。 |
| 按文件归属并行开发，先公布共享接口，工作 Agent 不单独提交 | 遵循用户多 Agent 要求；接口冲突需要协调和复验。 |
| 服务端用持久化成交检查清仓；未归属快照阻止完成；统一视野契约 | 防止客户端错误宣告完成或丢失拆分成果；代价是需要先处理不完整归属。 |
| 多轮修复仍保持用户指定的 Luna Max，并用新的独立上下文接手 | 遵循模型偏好；代价是修复速度可能低于更强模型。 |
| 导入和行情管理放入临时抽屉，保留原功能 | 复盘主界面保持简洁；相关操作增加一次打开入口的点击。 |

额外裁决：对于已确认的阶段文字丢失和合法回放状态无法保存，继续进行限定范围修复，不按原定审查轮数提前结束；代价是增加修复与复验时间。
