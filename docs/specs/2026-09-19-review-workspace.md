# 复盘工作区需求规格

状态：v1.0，需求定义完成，可作为设计、实施和验收基线。核心取舍来自逐项确认；第 10–13 节为本轮按用户授权收敛的工程边界与验证要求，不代表用户逐条指定。尚未实施或进行运行时验收。

## 1. 目标与范围

围绕真实历史交易进行回忆复盘（Recall）：明确显示当时买点，用户结合图表，事后补记买卖理由、心态与反思。所有记录在图表上完成，形成可恢复编辑的阶段快照与全局图表，最终导出可阅读、可整理的图文资料。

交易发生在其他软件中，本功能不假设存在实际下单时留下的原始判断记录。不提供重新择时训练或模拟下单流程。

本期包括图上记录、逐笔快照、回合级保存、行情逐步揭示、布局改进、绘图工具与 Markdown＋图片导出。自动内容挖掘、公众号文章改写/排版/发布及 HTML/PDF 导出未纳入本期承诺。

术语见 [CONTEXT.md](../../CONTEXT.md)，逐轮选择见 [访谈决策记录](2026-09-19-review-workspace-decisions.md)。来源为用户提供的 `复盘界面-26-0919.pdf` 及本次需求访谈。

## 2. 复盘对象与边界

| 对象 | 规则 |
| --- | --- |
| 交易回合 | 持仓 0 → 非 0 → 再次 0，是一份复盘的保存与确认完成周期 |
| 交易决策 | 一次实际买入、加仓、减仓或清仓决定，每笔分别记录 |
| 成交明细 | 券商执行事实；同一操作的拆分成交不拆成多份决策复盘 |
| 决策快照 | 一个决策可有多份，例如日线与小时线；每份含图片、文字和可恢复编辑状态 |
| 全局图表 | 沿逐笔复盘持续更新的工作图，最后直接补充全局总结 |

成交归属不确定时，由用户确认合并，并允许拆分误合并的分组。不能仅凭时间接近和方向相同静默合并；原成交事实保留。

已有快照后仍允许调整分组：合并时汇集全部快照，拆分时由用户确认每份快照的决策归属，不要求先删除记录。调整后重新检查每个决策至少一份快照的完整性。已完成回合调整分组后改为“待重新确认”，保留全部内容；用户检查归属与完整性后，一次点击重新保存并完成。

同一回合内继承画线与文字。新回合从空白标注开始，即使股票相同。旧回合成果保留；到达清仓时不能立即抹掉尚待整理的图表。

## 3. 标准使用流程

1. 从紧凑左侧导航选择回合与决策，图表定位真实买点，默认隐藏之后的 K 线。
2. 直接在图上绘图、用 Text 回忆记录理由和心态，编辑过程自动保存草稿。
3. 整理好当前构图，手动点击“留存当前快照”，暂存该决策的图片、文字与图表状态。
4. 可切换周期或构图，为同一决策继续新增快照；也可逐根揭示、跳到下一笔或展开完整行情。
5. 下一决策默认继承当前标注，继续修改并留存其快照。后续编辑不覆盖旧快照。
6. 在导航选中“全局总结”，在同一工作图上补充总结；新增或修改的文字归入全局总结。同样使用“留存当前快照”暂存全局图及文字，供进行中复盘导出，后续可继续更新。
7. 清仓且每个决策至少有一份快照后，一次“保存并完成回合复盘”统一保存并确认完成。
8. 导出 Markdown 与图片，按决策阅读，最后查看全局总结。

逐笔记录不等于逐笔确认完成；不设置“逐笔完成＋全局完成”两层流程。

## 4. 行情揭示与视图

- 当前真实买点明确显示，后续 K 线默认隐藏。显示当前周期的一根完整 K 线：盘中买入时可看完整买入日 K，不承诺成交瞬间的信息还原。
- 支持逐根揭示、跳到下一交易决策、直接展开已有完整行情。任何操作都不要求先写字或留存快照，也不自动确认完成。
- 同一决策的拆分成交跨越多根 K 线时，选择该决策定位首次成交所在 K 线；后续拆分成交随推进揭示，始终归属于同一决策，不要求额外决策快照。
- 后续成交标记到对应时点才出现。未揭示导航项只显示序号及快照状态，点击后定位并揭示具体信息。
- 同一完整 K 线内有多次决策时，仍按决策逐笔揭示。选中上午买入时，仅显示截至该笔的成交标记与持仓；切到下午加仓才推进成交信息，K 线形态可保持不变。行情完整 K 线与成交决策的揭示边界分别管理。
- 持仓与成本只使用已揭示成交，不提前计入后续决策或最终清仓结果。浮动盈亏使用当前可见 K 线的收盘价估值，并明确标注估值价格及时间；这不代表成交瞬间的盈亏。同 K 线多决策时不自动使用该 K 线结束时的全部成交计算持仓。
- 完整行情可包含清仓后走势，用于事后评价，但不混入下一回合成交标记，也不扩大当前回合归属。
- 切换回放与完整历史保持 K 线宽度及有效观察位置；纵轴随当前可见行情调整。展开数据不自动移动到末端或拟合全部。
- 单独提供“适应全部”，回放中仅适应已揭示行情。
- 切换周期沿用标注，按时间、价格映射，不使用 K 线序号硬套位置。旧快照保持独立。

## 5. 图上记录与布局

取消侧边笔记表单，所有理由、心态及评价均通过图上 Text 记录，不重复填写固定字段。

Text 能力：

- 点击图表添加，多行直接编辑；可拖动、调宽，双击再次编辑。
- 选中时显示紧凑工具条，支持字号、文字颜色和背景设置。
- 可自由放置于画布（包括右侧留白），也可关联具体 K 线。
- 关联文字随 K 线移动，自由文字固定画布位置；平移、缩放或切换周期均不改变字号。
- 保存原始文字、位置、宽度及样式，不仅保存含文字的图片。

第一版工具：Text、趋势线、水平线、箭头、矩形区间、平行通道、斐波那契回撤、盈亏比。工具均需保存、恢复编辑并进入截图。

左侧默认显示可收起的紧凑回合/决策导航，显示快照有无，并提供“全局总结”项。选中具体决策时新增或修改的 Text 归入该决策；选中“全局总结”时归入总结。两者编辑同一工作图，不要求逐个 Text 手动设置归属；历史快照仍保持独立。图表占据其余空间。采用带说明及可访问名称的图标入口。导入状态等非复盘信息移出复盘主布局。统计通过图标打开临时面板，默认不占空间，不恢复侧边记录表单。

### 5.1 旧笔记迁移不纳入本期

用户确认尚未记录原有笔记，直接改为图上 Text 记录方式。本期不建设“历史笔记”入口或旧笔记转 Text 流程；此前关于笔记迁移的选择被本次澄清替代。这不代表要求清除成交、行情或已有绘图数据。

## 6. 快照、继承与编辑

### 6.1 留存内容

每份快照保留图片、可读取文字、绘图及可恢复编辑的状态（周期、视野、位置和样式）。截图使用当前图表视野，包含坐标轴、可见成交标记与批注，去掉按钮及编辑工具条；不自动重新缩放或排版。

视野外内容不因未进入截图而从可编辑状态中删除。导出正文包含快照保存的全部 Text，包括截图视野外的文字，并按决策归属去重；图片仍保持原构图。

### 6.2 新增与更新

- 新增快照不替换同一决策已有快照。
- 同一决策内快照默认按留存顺序排列，允许用户拖动调整；界面与导出沿用调整后的顺序。
- 编辑已有快照只更新所选快照；图片、文字与图表状态对应同一次保存。
- 不自动把修改传播到后续快照或全局工作图。
- 第一版不要求同一快照的历史版本选择列表。
- “全局总结”沿用“留存当前快照”动作，暂存全局图表及对应文字，可导出、可继续更新，不代表回合完成。
- 已完成回合的修改先保留为草稿，在回合级保存后更新正式成果。

### 6.3 判断演变

后续阶段修改继承文字，算当前决策的判断更新。例如买入写“突破有效”，减仓改为“突破失败”，买入快照及正文仍保留原判断，减仓图文记录新判断。

回到旧快照编辑，是更新旧记录，与沿工作图产生后续判断分别处理。

## 7. 保存与完成

| 情况 | 行为 |
| --- | --- |
| 编辑中 | 自动保留草稿，可退出后恢复 |
| 留存当前快照 | 暂存阶段记录，不标记本笔或回合完成 |
| 尚未清仓 | 允许记录与留存，保持进行中，不能确认回合完成 |
| 清仓但有决策缺快照 | 完成操作列出缺失决策，补齐前不能完成，草稿保留 |
| 清仓且每个决策至少一份快照 | 用户点击一次统一保存并确认回合完成 |
| 已完成回合调整决策分组 | 改为待重新确认，保留记录，重新检查归属与快照完整性后由用户确认 |
| 保存失败 | 不显示完成成功，不以未保存内容替换正式成果 |

不检查文字字数、是否新增 Text 或固定字段填写量。清仓和自动存草稿均不等于自动完成复盘。

## 8. 图文导出

第一版提供两种导出方式，共用相同内容和目录结构：

- 下载 ZIP：包含 Markdown 文档和图片文件夹。
- 导出到本地目录：用户选择本机目标目录，直接将相当于 ZIP 解压后的复盘文件夹写入该目录，免去手动下载和解压；不要求中途实际生成 ZIP 再解压。

图片引用不依赖应用内部地址，保留相对目录关系后可阅读、整体移动或收入图形库。本地目录指用户所用电脑的目录，不自动解释为部署服务器路径；目录选择、写入授权及运行环境支持按第 11.2 节能力检测与第 13 节浏览器验收落实。不支持直接目录写入时提供 ZIP 下载并明确说明，不能声称已写入本地目录。

导出目录与文档名称的日期部分仅使用首次交易日期，格式为 YYYYMMDD，例如 20260120；不包含结束日期或导出时间戳。完整起止时间、持仓时长及导出时间放入复盘文档内部，跨年信息也在文档内部明确。

重复导出不覆盖此前成果；同名文件夹按 `_02`、`_03` 递增另存。基础名称为 `股票名称_代码_首次交易日期`，例如 `天通股份_600330_20260120/`，内含 `天通股份_600330_20260120_复盘.md` 和 `images/`。冲突序号仅用于外层文件夹/ZIP 名，内部文件名保持稳定。

未清仓或快照未齐全时也允许导出已有草稿内容。文档注明“进行中”，并列出缺少快照的决策；导出不确认完成、不绕过回合完成条件。导出只使用已留存快照及其对应文字，不包含尚未留存的实时编辑。存在未留存修改时提示用户，不自动生成临时快照，不把新文字混入旧快照正文；导出不等于留存或完成确认。

- 按交易决策顺序组织章节；同一决策的多份快照在同一章节，全局图表及总结单列。
- 各图片保留截图视野内的阶段标注，正文按文字归属组织，包含快照保存的全部 Text，包括视野外文字。
- 未改变的继承文字不在后续决策章节重复输出；后续修改作为当前决策的判断更新。
- 同一决策多份快照中，相同的继承文字只列一次；不同判断分别保留并注明所属快照。
- 去重不改变图片或可编辑图表内容，也不依靠截图 OCR 重建原有 Text。
- 同一快照的多段 Text 正文默认按创建顺序排列，可在导出预览中拖动调整顺序；不改变图上位置，不另设文字内容编辑表单。
- 导出保留可编辑文字与可独立使用的图片，为图形库收集和未来文章整理提供素材。

## 9. 核心验收场景

1. 一次买入拆成三条成交，归为一个决策，只需至少一份快照；不确定分组可由用户合并或拆分。
2. 首次买入、加仓、减仓和清仓四个决策，分别留存快照，最终一次确认回合；少任意一笔则列出缺失并阻止完成。
3. 未清仓可保存与恢复草稿；清仓后仍须用户主动确认，不清空正在整理的图表。
4. 下一阶段继承文字和绘图，编辑不改变旧快照；下一回合不继承这些标注。
5. 同一决策留存日线与小时线两份，均可恢复编辑；修改其一不改变另一份或全局图表。
6. 回放可逐根、跳到下一决策或展开；导航、成交标记和统计遵守揭示范围，清仓后行情不混入下一回合成交。
7. 切换回放/完整历史不使 K 线骤然放大；截图保持手动构图，不包含编辑控件。
8. 图上多行 Text 可编辑、拖动、调宽与设置样式；关联和自由文字按各自规则定位。
9. 导出同时包含阶段图与可读文字，继承文字去重，不同周期判断保留归属，全局总结独立。

## 10. 收敛后的交互及状态边界

### 10.1 工作图、阶段编辑与完成

- 首次进入回合定位首次决策；恢复草稿优先恢复上次所选决策、行情游标与视野。导航不因市场行情切换而自动改变 Text 所属决策。
- “下一笔”或选择另一决策明确切换记录归属。仅逐根播放不自动改变正在填写的决策，当前记录对象须始终可见。
- 查看/编辑历史快照进入标明快照名称的独立编辑上下文；退出恢复原工作图，不以旧快照替换全局图。更新所选快照不会创建新快照；在工作图“留存”才新增。
- 全局图保留一个最新留存版本。全局总结下再次留存更新该版本；决策下仍支持新增多快照。
- 点击完成时先提交当前 Text 编辑，并捕获全局工作图，再与各决策已留存快照一并原子保存。无需额外点击一次全局留存，也不自动补齐缺失决策快照。
- 批量跳转至后续决策后再回到较早决策，应恢复该决策最近快照作为编辑起点（没有快照则取此前最近阶段），不把后续文字自动写入较早决策；保留全局工作图供返回。
- 若已留存决策快照还有独立编辑草稿，完成前提示并定位该快照，要求明确更新或保留旧快照；不能静默丢弃编辑或混合新文旧图。
- 已完成回合普通编辑显示“已完成·有草稿修改”，正式版本保持原样；回合级保存后更新正式版本。分组改变、删除某笔最后一份快照或新导入成交改变决策覆盖时，标记“待重新确认”。
- 快照删除可撤销，不能删除原始成交；删除最后一份后立即更新完整性提示。分组拆分保留暂未归属快照，归属未确定前不能完成。
- 新导入使回合边界变化时，不凭索引迁移记录；按原成交稳定标识匹配，不能唯一匹配的内容保留并列为待关联，不自动标记完成。

### 10.2 成交与行情游标

- 保存独立的行情揭示边界和成交揭示边界。选择决策以其首次成交定位；同时间成交按已保存的稳定决策顺序处理，不依赖浮点时间差。
- 点击下一根推进行情至下一根完整 K 线，并揭示截至该根结束的实际成交；可能跨过多个决策，但这些决策仍分别需快照。需要逐决策停留时使用“下一笔”。
- 切换周期只改变行情映射，不推进成交边界。统计估值使用最新已揭示 K 线收盘价，不使用鼠标悬停或平移到的历史 K 线。
- “完整历史”展开已有行情并揭示本回合全部成交；返回回放恢复进入完整历史前的两种边界。横向位置若落入重新隐藏区，保持 K 线宽度并平移至最后已揭示 K 线。
- 只含日期的成交不捏造盘中时间：标注“仅日期”，采用导入明细稳定顺序并允许通过决策分组纠正；禁止宣称精确还原先后心态。
- 找不到对应 K 线时显示成交事实及行情缺失原因，不伪造 K 线或挪动买点。该笔不能生成冒充对应时点的快照；可存草稿，补齐数据后继续。不支持的周期禁用并说明原因。
- 账户、市场、标的及既有交易性质边界保持分离。决策不得跨回合、跨账户合并，不自动把理由相似的多次主动操作合并。既有反向开仓按过零拆分回合，原成交和费用总额不变。

### 10.3 Text、画布与尺寸

- 自由文字保存相对画布位置及 CSS 像素宽度/字号；同尺寸恢复一致，容器变化按相对位置重排，不放大字号。宽度最多为当前画布可用宽度，返回原尺寸恢复原设定宽度。
- 关联文字保存真实时间、价格及文字偏移。切换周期映射到包含该时间的 K 线；目标无覆盖时不吸附到无关 K 线。锚点不可见时文字随其离开视野，内容仍保留。
- 新文字默认 14px、多行、自动换行，行高 1.5；字号提供 12/14/16/18/24/32。支持透明或有色背景。回车换行，Ctrl/Cmd+Enter 结束编辑，Esc 撤销本次尚未提交的输入。
- 输入中文组合文本时，不触发回放、删除绘图或其他图表快捷键。图表撤销/重做与 Text 输入焦点正确隔离。
- 可拖宽但不通过缩小字号强行容纳长文。提供“定位所选文字”，将自由文字临时带回画布或平移至关联锚点；不默默删除溢出部分。
- 留存前若文字与画布边缘相交而被裁切，明确提示“截图文字被裁切”，允许返回调整或按当前视野留存；仍保存完整文字并用于正文导出。
- 右侧分析留白可承载绘图投射和自由文字，不能因没有真实未来 K 线而阻止分析；不得用未来行情填充留白。视野自动纵轴仅依据已显示行情，不受极远的绘图价格强行撑开。

### 10.4 工具细则

趋势线/箭头两点，水平线一点，矩形对角两点，平行通道先画基线两点再定平行宽度，斐波那契两端点（默认 0、0.236、0.382、0.5、0.618、0.786、1），盈亏比分别设置入场/止损/目标。支持选择、移动、锚点调整、删除、撤销/重做、隐藏和锁定；文字样式外的公共样式包含颜色、线宽和透明度。保留现有已支持的垂直线、价格标注及测量能力，无需借本次改版删除。首版不要求扩展全部 TradingView 工具。

## 11. 导出与持久化契约

### 11.1 文件与正文

- 首次交易日期按标的交易所时区取 YYYYMMDD。未知时区则使用已记录来源时区并在文档说明；不悄悄使用访问者电脑时区。
- 文件名保留中文，路径分隔符及平台非法字符替换为 `_`，清除控制字符与尾部点/空格；名称未知用代码。同名冲突递增序号，不覆盖已有文件。
- 图片文件名为 `决策序号_快照序号_周期.png`，例如 `01_01_1D.png`；全局图为 `global.png`。序号按当前导出顺序生成，不作为应用内身份标识。
- PNG 默认按保存时 CSS 画布尺寸的 2 倍像素输出，保持相同比例、字体相对尺寸和构图；不重拟合行情。字体加载和绘图完成后再捕获，合成行情、绘图、Text、成交标记及坐标轴，排除选中框、光标和工具条。
- Markdown 开头包含股票/代码/市场、回合标识、账户显示名、完整起止时间与时区、状态、导出时间、持仓时长、缺失快照清单。持仓时长按经过自然时间计算；未清仓显示“截至本次导出仍持仓”，日期精度不足时不输出伪精确小时数。
- 之后按决策章节列出操作、实际成交明细与图片、文字，最后全局总结。不导出账户凭据或原始文件路径。
- 用 Text 稳定身份、修订和归属去重，不按字符串相同就删除独立写下的判断。仅样式或位置改变不产生新的判断正文；实质文本修改产生当前决策修订。
- 同一文字的同一修订在多个快照重复出现时只展示一次并关联这些快照；不同修订均保留快照归属。删除某阶段的文字不删掉早期已留存版本。
- 默认导出当前回合已留存版本；若存在已完成正式版及修改草稿，预览明确提供“最新已留存草稿”和“上次完成版本”选择，默认最新已留存草稿并标注状态，绝不包含未留存文字。
- 导出预览的排序保存在回合草稿中；导出执行时冻结一份留存内容清单，不让后台编辑改变正在生成的包。未完成/待重新确认/有未留存编辑等状态在预览明确展示，不将未留存正文混入输出。

### 11.2 本地目录写入

直接目录导出走访问者浏览器的目录选择和写入能力，在支持的安全上下文中，由用户点击触发目录选择及浏览器授权；权限取消不改变复盘。执行时检测能力与权限，不依赖浏览器名称猜测。规范依据：[Chrome File System Access 文档](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)、[File System Access 规范](https://wicg.github.io/file-system-access/)。这确认了技术路径，不等于已验证用户当前浏览器可写。

不支持时明确显示原因并提供 ZIP 下载，不能悄悄将目标解释为 Docker 挂载路径。目录导出必须在支持的桌面浏览器作为独立验收项通过，不能只验 ZIP 就声称全部交付。

每次创建唯一新目录，依次写图片再写 Markdown，全部关闭写入流且检查文件数后才提示成功。中断时提示实际路径及“未完成导出”，保留应用草稿；只可清理本次新建文件，不能递归删除用户目录。重试创建新唯一目录，避免将残留包当成功成果。

### 11.3 应用内保存

- 沿用本地服务端 SQLite 的业务存储边界；自动草稿、决策分组、快照、图片和正式回合成果必须持久化，不能仅存在 React 状态或浏览器临时对象 URL 中。
- 输入停止后 1 秒内发起草稿保存，导航切换前提交待保存变更；显示保存中/已保存/失败。页面异常关闭前尚未持久化的输入不声称已保存。
- 图片、文字、状态形成同一快照版本；阶段留存任一项失败就不计入快照数量。回合完成使用一次原子提交，失败保留之前正式版本及草稿。
- 使用版本校验避免异步旧请求或多标签页覆盖新版本；冲突保留本地草稿并提示重新载入，不静默最后写入者覆盖。
- 历史图片不可因行情缓存更新重新生成。可编辑快照保留渲染所需的行情窗口/数据版本和视图参数，使重新打开时能还原保存时图形；主动更新快照才产生新图片。
- 原绘图版本规范化后进入对应回合工作草稿，不自动生成历史决策快照，也不自动完成。无法转换的项保留原数据并提示，不静默丢弃。无需建设旧笔记迁移入口。

### 11.4 最低数据关系

回合草稿/正式版本包含：回合身份、成交归属版本、决策列表、工作图、当前编辑上下文、两类游标、全局留存版本、排序与状态。决策引用稳定成交 ID、首末执行时间及多快照 ID。快照保存稳定 ID、归属、周期、视图、行情窗口、图形对象、Text 身份/修订/归属、图片和留存时间。正式版本与草稿显式分开；删除或编辑一份不能修改其他快照的共享对象。

## 12. 原反馈与方案对应

| 原反馈 | 当前方案 |
| --- | --- |
| 先观察当时形态，再看后来走势 | 标出真实买点，后续默认隐藏，可逐根或展开 |
| 图文与截图记录思考过程 | 每决策多快照＋全局图，均保留可编辑内容 |
| 导入状态占据顶部 | 移出复盘主布局 |
| 按钮过于冗长 | 紧凑图标入口，保留说明 |
| 回放切换缩放突变 | 保持 K 线宽度与有效观察位置 |
| 右侧笔记区难调宽 | 后续明确取消侧边记录，改用图上 Text |
| “关联时点”用途不明 | 决策快照关联阶段，Text 可选关联 K 线 |
