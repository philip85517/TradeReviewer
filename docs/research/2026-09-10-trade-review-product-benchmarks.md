# 交易复盘产品：围绕「完成复盘并形成总结」的官方资料调研

调研日期：2026-09-10。范围：TradeZella、Edgewonk、TraderSync、TradesViz 的官方产品页、帮助文档和官方流程文章。未登录体验付费产品，因此下文“官方事实”指公开文档明确描述的能力；“借鉴建议”是针对本项目的产品判断，不代表竞品现有交互。本文讨论记录与复盘流程，不评价策略收益。

## 结论

最值得借鉴的主线是：**找到值得看的交易 → 看证据并记录过程 → 标记完成 → 汇成少量结论 → 下次检查行动是否落实。** 四家提供了这条主线的不同部件，但不能据此声称它们都具有完整的复盘队列或行动追踪功能。

对于追求精简的产品，先让一轮复盘真的结束，再考虑增加分析图表。建议只保留三个主要入口：待复盘、交易记录、周期总结。规则库先作为复盘表单里的轻量设置，不必成为独立工作台。

## 1. 复盘队列：优先解决“接下来该看哪笔”

**官方事实。** Edgewonk 的交易列表允许星标交易，官方明确列出“稍后复盘”“需要补充信息”“值得以后参考”三个用途，并可用 Basic Filters 中的 Flagged 单独筛选。这里确认的是星标与筛选，没有确认自动优先级、完成状态或下一笔导航。[Edgewonk：Flagging / starring trades](https://edgewonk.zendesk.com/hc/en-us/articles/360013436260-Flagging-starring-trades)

**借鉴建议。** 首页显示“待复盘 8 笔”，直接进入第一笔；每笔提供“保存并完成”“暂存”“稍后处理”，完成后进入下一笔。最初只用确定性条件入队：尚未完成复盘、用户主动标记。不要默认只把亏损交易放进队列，也不要把“有一段笔记”视为“已复盘”。星标与完成状态分开：前者表示值得再次阅读，后者表示本轮工作已结束。

**为何有用。** 列表不再只是查账入口，而能告诉用户今天还剩多少工作，什么时候可以结束。

## 2. 单笔笔记：原地写、模板短、同一份内容多处可见

**官方事实。** TradeZella 将交易笔记和日记同步到 Notebook；交易详情、日视图、日历和 Notebook 可以进入对应笔记，文件夹可设置默认模板。其交易标签与笔记标签不同且不自动同步。[TradeZella：Notebook 管理](https://help.tradezella.com/en/articles/7190696-organizing-and-managing-your-notes-within-your-tradezella-notebook)

**官方事实。** TradesViz 提供 Trade、Day、Misc 三类笔记及相应模板；支持搜索、笔记类型与标签筛选。其官方建议让交易和每日笔记简短，较长文字放在 Misc 笔记；笔记标签与交易/日期标签是独立体系。[TradesViz：Notes complete guide](https://www.tradesviz.com/blog/notes-complete-guide/)

**借鉴建议。** 在交易证据旁固定一个短表单：所用策略、过程评价、问题标签、一句话心得；图片和长文按需展开。初版统一交易问题标签，不复制两套标签体系。周期总结引用原交易与笔记，不再复制一份文字。给出默认提示“当时依据 / 实际偏差 / 下次动作”，用户能删改，避免空白富文本框成为入口。

**为何有用。** 用户不用先决定“写在哪个笔记系统”，同一笔交易的图表、成交和反思始终相邻。

## 3. Playbook：规则应在评估交易时出现

**官方事实。** TradeZella 的 Strategies 支持规则分组，例如入场、离场和市场条件；交易页可以勾选实际遵守的规则，并统计遵守率等结果。规则还可以按交易盈亏条件显示。[TradeZella：Groups and Rules](https://help.tradezella.com/en/articles/6986848-what-are-groups-and-rules-in-strategies)

**官方事实。** 将交易加入策略可在单笔详情完成，也可在 Trade View 选择多笔后用 Bulk Actions 批量关联。[TradeZella：Add Trades to Strategy](https://help.tradezella.com/en/articles/10254425-how-to-add-trades-to-your-strategy-in-tradezella)

**借鉴建议。** 用户选一个策略后，只展示这个策略的三至五条检查项；每项用“遵守 / 未遵守 / 不适用 / 未评估”，不要把未勾选一律计作违规。初版无需规则市场、共享策略和复杂条件显示。重要过程规则对盈利与亏损交易一致呈现，减少结果影响自评。修改规则时保存版本或历史快照，避免新规则悄悄改变旧交易评价。

**为何有用。** “我有没有按计划做”变成可回答、可汇总的问题，不只是写在策略文档里的一句话。

## 4. 过程评价：盈亏与执行质量并列展示

**官方事实。** Edgewonk 的 Tiltmeter 基于入场、离场、交易管理评论；用户预先把评论评为正向、负向或中性，关联交易后仪表随之变化。它不是根据单笔盈利自动计算的质量分。[Edgewonk：The Tiltmeter](https://edgewonk.zendesk.com/hc/en-us/articles/360010150259-The-Tiltmeter)

**借鉴建议。** 交易列表并列显示盈亏和过程评价；初版用“按计划 / 有偏差 / 待评估”就足够。需要细分时再展开入场、管理、离场三项，且显示评分依据。不引入难解释的总分或等级排行榜。总结里允许用户查看“盈利但有偏差”“亏损但按计划”的例子。

**为何有用。** 用户可以区分结果和行为，不会因为赚钱就把未经计划的操作自动认定为好交易。注意：过程评价是用户判断，相关统计不等于证明行为与收益之间的因果关系。

## 5. 周总结：产出三条观察，保留一个下期重点

**官方事实。** Edgewonk 的 Sessions 可按日、周、月复盘，包含 report cards、反思提示及经验记录。[Edgewonk：Trading Psychology，Sessions 部分](https://edgewonk.com/trading-psychology)

**官方流程建议，而非已验证的自动化功能。** TradeZella 官方周复盘文章把输出压缩为三项：做得好的、付出代价的、下一周的一项调整；并建议持续保存观察记录。文章属于厂商的方法建议，不能据此断言产品会自动生成或追踪行动。[TradeZella：Weekly trade review process](https://www.tradezella.com/blog/weekly-trade-review-process)

**借鉴建议。** 生成一个可编辑的总结草稿，包含日期范围、交易数、复盘覆盖率、少量关键结果、重复问题及对应交易链接；最后固定三格“继续保持 / 需要修正 / 下期一个重点”。缺少足够记录时明确提示“证据不足”，不编造模式。下期总结首先展示上期行动，让用户选择“落实 / 部分落实 / 未落实 / 不再适用”并关联证据。总结完成后成为可再次打开的独立记录。

**为何有用。** 总结有明确交付物，下一次复盘有承接点。生成长篇评语或几十张图表不能替代这一闭环。

## 6. 回放：围绕具体问题打开，并回到同一笔复盘

**官方事实。** TraderSync 的单笔交易视图包含交互价格图、入场/离场位置、目标与止损追踪；市场回放模拟器中的练习交易可自动记录到 Analytics。[TraderSync：Trading Journal，Trade Summary Snapshot / Seamless Market Replay Integration](https://tradersync.com/trading-journal/)

**借鉴建议。** 回放入口放在单笔复盘证据区。先明确问题，例如“这笔离场是否符合当时计划”，再打开图表或回放；返回时保留当前复盘草稿，并可把观察关联到时间点。若历史行情和回放能力暂不可靠，优先做好成交时间线、进出标记和截图，不让完整模拟交易平台阻塞核心闭环。将真实交易与模拟练习明确分开，不能混算。

**为何有用。** 回放服务于一条可保存的观察，用户看完能回到复盘并完成记录，而不是进入另一个无终点的分析空间。

## 推荐的最小闭环与验收

以下均为本项目建议，尚未对本地实现作判断。

| 环节 | 用户操作 | 应留下的结果 |
| --- | --- | --- |
| 选交易 | 打开待复盘队列 | 明确当前交易与剩余数量 |
| 看证据 | 查看成交、图表或截图 | 保持同一交易上下文 |
| 做判断 | 选策略，评价过程，标问题，写一句心得 | 可保存、可再编辑的复盘记录 |
| 完成本笔 | 保存并完成，进入下一笔 | 明确的完成状态与时间 |
| 形成总结 | 查看周期证据，写三条观察 | 有交易引用的周期总结 |
| 承接下次 | 确定一个重点，下期回看 | 行动与后续证据关联 |

优先顺序：队列与完成状态 → 单笔短表单 → 周总结及上期行动回看 → 轻量规则检查 → 按需回放。暂缓高级筛选构建器、几十种指标、社交分享、策略市场、复杂模拟器；只有它们解决了真实复盘问题，再增加入口。

验收时用一个具体场景：用户有五笔新交易，完成其中三笔、暂存一笔、稍后一笔；刷新后状态不丢失；生成本周总结时准确显示覆盖率，引用已记录的证据；下周能看到上周留下的一个重点。相比“功能是否齐全”，这更能验证产品是否精简而完整。
