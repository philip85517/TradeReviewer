## 2026-10-29：配对日线的服务端逐步披露实施边界

这是 `TL20-R-NEXT-BAR` 与 `TL20-R-NEXT-DECISION` 的限定实施合同，不代表已实现或 D06、完整回放已验收。依据上表、`visual-design.candidate.md:254–298,375` 与 `evidence/I12/real-chart-next/pair-recall-exposure-minimal-contract-20261029.md`。来源只有日期时，日历日期是事实精度而不是午夜成交时刻；行情日线的完成知识时间不是成交时间。不同日按日期排序；同日仅在来源证明唯一先后关系时分别揭示，不能用行号、报表编号或配对稳定性证明先后。证据不足则动作明确不可用且状态不变，不跳过不确定决策。

2026-10-29 补充：用户确认模拟报表每组是完整的一笔交易且不拆单，同一组的开仓必先于该组平仓，这一业务因果关系可用于同一 BAR 内分次揭示，即使源文件只提供日期。它只证明本组开、平之间的相对顺序，不能证明不同组之间的先后，也不提供具体时刻或已完成的 BAR 数据；不同组顺序仍无法确认时不能臆造。所选配对结束后，继续观察后续行情或已确认的其他交易不得因两个推进入口互相阻挡而停住；各事实的记录归属和结果阶段仍按原合同处理。

服务端在同一数据库事务校验 practice/revision/current version、pairRef 和来源；状态持久化分开记录已完成行情边界、实际已披露成交事实集合及阶段、所选决策、状态版本、先前来源不明标记。首次 GET 仅派生入场前边界且无写入；后续 GET 不扩大持久范围。状态、披露来源和动作幂等收据必须在 `BEGIN IMMEDIATE` 中原子提交；动作由服务端计算，不接受任意客户端截止或未来数据；收据永久去重，不保存完整未来响应，丢响应可使用同 ID/同摘要重试，新旧版本冲突须可恢复。先前详情可能已展示信息，未知历史不冒充未看过；服务端披露记录不能证明人已理解。

逐根只增加下一根真实已完成的同周期行情，缺失/结束明确反馈；对应日期的事实只按已证明顺序及允许知识边界揭示，不能把某根日线收盘当成其成交时刻。下一决策只揭示可证明唯一的下一个来源事实及较其交易日更早的完整行情，未确定当天完成状态时不返回当天高低收等；对应事实的日期锚点不能伪造成秒级成交。若下一状态必须依赖不能证明的日内顺序、跨日线与成交相对时刻、目标行情缺失或当前结构无法在真实图表可见该事实，则返回有原因的不可用并保持原状态，不能宣称下一决策完成。后续显式保存的回看不得清除披露来源或其他阶段草稿；本切片不覆盖 Text、其他阶段恢复或小时数据。

### 日期级决策的真实图表依赖（尚未实现）

决策输入只能来自服务端已披露、身份已核验的来源事实，包含交易日期及 `date-only` 精度、事实 ID、方向和已证明的先后关系；不能把日期投射为午夜、开盘、收盘或任何声称是成交时刻的时间。多个同 BAR 事实必须依服务端有证据的序列逐笔显示；不能证明序列时动作拒绝且不改变状态。真实图表需要可展示交易日位置、但不含该日 OHLC 的日期轴锚点；不能以虚构 K 或提前加载当天完成行情代替。到达同日下一笔后，先前已披露的事实保留，未到达的事实、当天 OHLC、退出和结果不可从轴、tooltip、序列或网络响应泄露。下一根可用完成 K 的披露是独立动作，实际推进须使对应真实 bar 可见。

目前 `chartTimelineData` 对未映射的日期级成交不建立空白点，`executionMarkerFacts` 无当日已知 K 时不生成可见标记；现有壳向图表传空成交。日期级单独锚点及同 BAR 排序是图表的单独依赖，由 root 负责协调；在相同日线状态的真实图表中操作前后、无 OHLC/未来网络数据、鼠标键盘及滚动后实际可见，均需非实现者验收。仅建立空白点或断言 DOM 不足以判定此门槛通过。

### 2026-10-29 用户确认：模拟交易记录完整且不拆单
