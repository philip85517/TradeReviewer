# 策略库、三类策略包与实验：第一轮反馈规格

日期：2026-09-30 · 来源：用户第一轮原型反馈与图 1，以及模型审阅反馈 · 状态：整体模型获认可；修订04纠正实验入口；修订05补齐双列表顶部查询并提出卡片评估建议；修订06统一全局元素与用户文案，仍先交互设计后开发。

本轮交付规格与本地任务。用户明确要求“优先给出交互模型后再设计开发”。下文区分用户确定的产品要求、继承的状态安全约束与供交互模型验证的方案；任务的 `ready-for-agent` 不表示新交互已获认可或可直接实施生产功能。

## Problem Statement

当前页面以“我的策略实验”和“新建实验”为中心，选择策略时仅提供内置完整策略卡片。用户无法独立建立和管理可复用策略，也无法把已有的筛选、买入和止盈止损方案组合起来，再把组合后的策略用于某个时间段的实验。每次实验与可重复使用的策略配置混在一起，缺少实验之前的策略库环节。

用户要先定义“用什么策略”，再定义“在哪段时间运行并收集什么结果”。技术形态、财务筛选和交易规则可能复杂，但用户不希望在界面中逐项搭建原子条件。

## Solution

在策略工作区提供相互可达的**策略库**和**我的实验**。策略库管理可复用完整策略及其三类组成包，保存只归库。**我的实验**提供实验列表和新建入口，在四步创建的策略选择环节选择一个或多个已有完整策略，在指定历史区间内运行、观察并收集结果。需要新策略时可从实验流程进入新建，完成后回到原实验。库内不提供“用于新实验”，切换业务tab也不隐式创建草稿或选择策略。

完整策略由**标的筛选策略包、买入信号包、止盈止损策略包**组合而成。各包封装规则，用户选择包和预设；复杂逻辑在包内实现。创建完整策略支持从零组装，也支持复制历史策略后修改。

### 继承约束与术语

| 术语 | 本轮含义与边界 |
| --- | --- |
| 策略库 | 保存、浏览和复用完整策略及三类组成包的产品区域；具体导航组织由交互模型确认。 |
| 策略模块包 | 封装一种职责的命名规则单元，属于筛选、买入、止盈止损三类之一；不是一条原子条件。 |
| 完整策略 | 三类包及其版本、允许公开的配置构成的可复用策略定义；不携带某次实验的成交、现金或结果。 |
| 策略的组合 | 本轮明确支持三类包组合成完整策略，以及多个完整策略进入同一实验比较；不据此新增共用资金、信号投票或策略嵌套引擎。 |
| 组合 Portfolio | 实验中的资金、持仓和运行观察对象；沿用每个所选策略形成独立本金组合的既有契约，不与策略包组装混称。 |
| 实验 Experiment | 选定完整策略、历史起点和区间及研究条件后组织运行与收集结果的研究容器；未开始时为实验草稿。 |
| 模拟运行 SimulationRun | 某个配置锁定后的一次执行实例，仍是模拟交易和统计的隔离边界。 |

继续保留策略观察者角色、自动执行、A 分步创建、五档期限、独立组合资金、历史可知数据、原运行不可改写、TradeReview 风格与桌面优先。止盈止损不替代既有仓位分配和调仓/再平衡能力；它们之间的交互与执行优先级需在后续契约中显式说明。

## User Stories

1. 作为策略观察者，我希望在策略入口同时找到策略库和我的实验，以便区分可复用规则与运行记录。
2. 作为策略观察者，我希望没有实验时也能进入策略库，以便先准备研究方法。
3. 作为策略观察者，我希望策略库为空时有明确的新建入口，以便知道第一步如何开始。
4. 作为策略观察者，我希望浏览完整策略的名称、说明、组成和版本，以便选择适合本次研究的策略。
5. 作为策略观察者，我希望查看策略的适用市场和数据依赖，以便判断当前数据能否支持运行。
6. 作为策略观察者，我希望新实验优先选择已有策略，以便重复使用已整理的方案。
7. 作为策略观察者，我希望选择多个完整策略进入同一实验，以便在一致历史环境中比较。
8. 作为策略观察者，我希望知道每个策略对应独立本金组合，以便不误以为它们在同一资金池交易。
9. 作为策略观察者，我希望在选择策略时可以新建策略，以便不中断研究思路。
10. 作为策略观察者，我希望新建完成后返回原实验并选中刚创建的策略，以便继续预览和运行。
11. 作为策略观察者，我希望新建过程中取消能够回到原选择状态，以便不会丢失实验日期、期限、本金和已选策略。
12. 作为策略观察者，我希望创建完整策略时清楚看到三类组成包，以便理解策略如何工作。
13. 作为策略观察者，我希望筛选包封装形态、财报和规模等条件，以便不手工拼接原子条件。
14. 作为策略观察者，我希望技术形态筛选可以通过脚本包扩展，以便新增方法无需重做配置界面。
15. 作为策略观察者，我希望查看筛选包的规则摘要和数据要求，以便了解候选来自什么依据。
16. 作为策略观察者，我希望单独选择买入信号包，以便同一筛选范围可以研究不同入场方法。
17. 作为策略观察者，我希望入围但尚未触发买入的标的有明确状态，以便不把候选误认为持仓。
18. 作为策略观察者，我希望按包选用形态或规则型买入信号，以便用一致方式理解不同方法。
19. 作为策略观察者，我希望选择固定止盈止损预设，以便快速组装明确的退出规则。
20. 作为策略观察者，我希望选择移动止盈止损预设，以便研究不同退出方法。
21. 作为策略观察者，我希望止盈止损规则能够通过脚本包扩展，以便不受内置预设数量限制。
22. 作为策略观察者，我希望只面对包和包有意公开的命名参数，以便复杂规则不会挤满创建界面。
23. 作为策略观察者，我希望创建策略时能复制已有历史策略，以便仅替换需要调整的部分。
24. 作为策略观察者，我希望复制后的修改不影响来源策略，以便保留可比较的原方案。
25. 作为策略观察者，我希望复制策略时保留来源标识，以便知道新方案基于哪个历史版本。
26. 作为策略观察者，我希望修改库中策略不会改写历史实验的规则和结果，以便实验可复现。
27. 作为策略观察者，我希望三类包缺失或不兼容时看到具体原因，以便修正配置而不是得到虚假的可运行状态。
28. 作为策略观察者，我希望策略可保存与当前区间可运行分别表达，以便缺少某段数据不会混同于策略定义错误。
29. 作为策略观察者，我希望实验明确记录起点、期限、实际结果区间和所用策略，以便理解结果的适用范围。
30. 作为策略观察者，我希望先预览候选和目标，再开始自动运行，以便区分筛选、信号、计划和成交。
31. 作为策略观察者，我希望运行中能查看筛选、买入、退出和调仓的原因，以便理解策略之间的差异。
32. 作为策略观察者，我希望阶段结果与完整结果明确区分，以便不会把尚未运行的时间当成已有结果。
33. 作为策略观察者，我希望返回列表和重开后仍能核对本次锁定的策略版本，以便继续研究时不选错对象。
34. 作为策略观察者，我希望先用交互模型走通策略库到实验的流程，以便在正式设计开发前修正概念或动线问题。
35. 作为策略开发者，我希望三类包通过统一宿主声明能力和版本，以便扩展不需要增加每种规则专属的页面流程。
36. 作为策略开发者，我希望包只能消费截止时点可知的数据并输出决策意图，以便执行、资金和审计由宿主一致处理。

37. 作为策略观察者，我希望从包目录、组装槽位和包选择列表进入包的说明与细节，以便理解所选版本的规则、有效参数和适用范围。
38. 作为策略观察者，我希望查看详情后回到原页面或面板，并保留搜索、滚动、待选项和未保存草稿，以便继续刚才的操作。
39. 作为策略观察者，我希望从历史实验查看运行锁定包的有效配置，以便不把库中最新版误当成当时使用的规则。
40. 作为策略观察者，我希望新增策略页面沿用现有网页风格，以便在库、实验与工作台之间连续操作。
41. 作为策略库使用者，我希望在很多包中按名称、说明、标签搜索并组合筛选，以便快速缩小范围。
42. 作为策略库使用者，我希望按更新、开发时间、名称、引用数或手动顺序浏览，并在查看详情后回到原页和原行。
43. 作为策略库使用者，我希望给包添加标签和备注，以便记录用途与选用理由而不改变执行版本。
44. 作为策略维护者，我希望区分包被多少个当前策略使用、当前包版本的使用数和历史引用，以便评估整理的影响。
45. 作为策略维护者，我希望看到开发者、首次开发和版本发布时间，资料缺失时明确未知，避免把导入时间当开发时间。
46. 作为策略库使用者，我希望常用包置顶，并通过拖动、键盘上下移动或指定位置调整个人顺序。
47. 作为策略库使用者，我希望在整理时能取消和恢复失败，按引用数排序时仍保留之前的手动顺序。
48. 作为策略维护者，我希望归档不常用包并随时恢复，已有策略和历史实验保持可读、原版本不变。
49. 作为策略使用者，我希望归档发生在草稿编辑期间时有明确提示，并保留我的输入及可恢复路径。

50. 作为策略观察者，我希望在“我的实验”列表中创建实验、选择策略和继续草稿，而策略库只管理方法，避免误把保存策略当成创建实验。
51. 作为策略观察者，我希望无实验来源的策略保存留在库中，有实验来源的保存返回原草稿，取消和查看详情不会改变原选择。

## Implementation Decisions

### LD01 · 本轮交付与下一步

本轮只固化需求、参考和依赖。下一张任务产出领域关系、信息架构、完整用户旅程、关键状态和低保真交互模型；这些输出用于用户反馈，不预先认定具体页签、弹窗、独立页面、卡片样式或步数调整已经获批。随后才做视觉细化与可点击原型。正式开发仍依赖完整动线交接和生产数据/执行能力核验。

### LD02 · 两层复用

策略模块包是复用单元，完整策略是实验选择单元。普通使用者无需进入脚本或内部规则即可从三类包组装策略。暂以每类选择一个命名包作为交互模型的最小候选方案；包内部可封装多条规则。每类是否允许多个包及其合并逻辑尚未由用户指定，不将 AND/OR、信号投票或优先级编辑器写成已确认要求。

筛选负责候选范围，买入信号负责何时提出入场意图，止盈止损负责退出意图；宿主统一处理仓位预算、调仓、成交限制、费用和账本。候选入围不必然立即买入，触发信号不等于已经成交。

### LD03 · 创建实验与就地新建

保留已接受的分步创建骨架，把选择对象从页面内置规则卡提升为策略库中的完整策略。交互模型必须同时覆盖“库内独立保存策略；随后切换我的实验并主动选择”和“从实验选择时新建策略”两条旅程。就地新建成功后返回原实验选择步骤并选中新策略；取消或保存失败保留原草稿与已有选择，失败时保留正在编辑的策略输入。库内单独新建成功不创建实验。要开展实验，切换“我的实验”进入列表，明确新建后在第二步主动选择策略；库中无“用于新实验”入口。

实验起点、标的集合、期限、本金和数据快照属于实验/运行配置，不随“复制策略”复制；策略复制也不继承成交、持仓、结果和播放游标。基于已有实验派生新实验继续保留既有来源与未来暴露约束，不因更名或复制策略清除观察历史。

### LD04 · 复制、版本与历史实验

复制历史策略创建可独立修改的新完整策略，保留来源策略与版本；保存和取消都不能原地修改来源。历史策略至少包括库中已保存策略及实验所引用的历史版本，具体入口由交互模型决定。

沿用原规格不可变运行配置：运行锁定完整策略及三类包的版本和有效参数。修改库中定义只影响后续显式选用的新配置，不回填已有运行；旧包不可执行时，旧结果仍可读，继续执行明确说明限制。策略编辑产生版本的界面方式在交互模型中确定，本稿不提前冻结数据库表或 API。

### LD05 · 包与脚本边界

三类包都声明身份、版本、职责类型、说明、所需数据、市场适用范围和必要预热。技术形态筛选与自定义止盈止损明确支持脚本扩展；买入信号沿统一包契约承载形态/规则逻辑。脚本封装在应用内受信任包机制中，不要求普通用户在创建实验时编写代码。

继续遵守既有插件边界：只读取宿主提供的历史可知视图与运行状态，返回候选、信号、退出意图及解释，不绕过宿主抓取行情、读取未来或写入成交账本。新增包能够沿用同一选择和详情交互。任意第三方脚本上传、安全沙箱与在线脚本 IDE 不在本轮需求中。

### LD06 · 止盈止损与执行模型

固定、移动是必需示例类别，不替用户决定百分比、金额阈值、触发价格或移动基准。交互模型展示规则摘要与触发/执行区别；规则契约随后明确触发截止、移动基准更新、跳空、同日多条件命中、退出与再平衡冲突、未成交和重新入场语义。

原规格的日线、下一可交易开盘执行是既有建议口径，不因加入止盈止损自动变为盘中精确撮合。日线无法证明同日高低点先后，不得把它解释为必然按止损价或止盈价成交。旧示例“不额外推断止盈止损”只能作为旧包边界；新的三类组合必须明确退出包选择，不能沿用旧示例而静默省略第三类。

### LD07 · 兼容性和数据能力

策略定义完整性与某次实验的数据可运行性分开检查。三类包的类型/接口不兼容、配置不完整不能进入可运行状态；历史区间必需数据不足应指出所属包、缺失能力和可用下一步。无候选、没有买入信号、全部现金、未知数据和执行失败分别解释。

复用现有证券身份与公共行情入口。现有行情覆盖不证明历史市值、财报公布版本、证券池和企业行为齐全；不以原型展示脚本包证明脚本宿主或真实数据已实现。

### LD08 · 与旧稿的替代关系

本稿优先细化旧稿的策略库、策略包和创建入口。旧稿把“选股＋排序＋组合构建＋再平衡/退出”统称完整包的表述，在本轮用户层面拆为三类模块包组装的完整策略；排序、仓位和再平衡能力继续保留，归属在交互模型中明确。旧桌面稿的策略卡仍可作为“选择已有完整策略”的参考，不能代替策略库或组装过程。

已有桌面原型技术通过记录按原范围保留。本轮新增需求尚未实现，旧创建页认可和技术验收不能当作新策略库的设计或功能接受。实验内 V、M、各组合进度、结果截止和返回来源等状态安全约束仍适用。

### LD09 · 包详情与风格兼容（模型审阅反馈）

用户对首版模型表示“整体ok”，追加 SL10/SL11。整体组织按模型 A 继续；本轮补充不等于新功能、最终像素或工作台模型已经验收。详见[修订模型 M11](../../.scratch/strategy-portfolio-backtesting/strategy-library-interaction-model.md)和[反馈记录](../../.scratch/strategy-portfolio-backtesting/comments/strategy-visual-09/2026-09-30-feedback-resolution.md)。

完整策略详情可逐一打开三类组成包。包详情统一展示身份/版本、用途、职责、规则摘要、输入输出、命名预设与有效参数（含单位/范围/来源）、数据依赖、市场/预热、兼容性/可执行状态与脚本标记。历史实验读取运行锁定值；资料缺失明确提示，不替换最新版。查看不选择、不保存、不升级。

包目录进入全页详情；组装和策略/实验详情使用只读覆盖面板。包选择列表进入详情时在同一面板内切换，返回列表保留搜索/筛选/排序/滚动及待选项；回列表后才可明确“使用此包”。显式返回、浏览器返回、Escape 遵循同一来源层级，焦点回原触发项；未保存内容和实验/运行上下文不变，运行返回后仍暂停。来源失效给出原因及明确出口。

风格不是仅保留深色：后续复用当前主题 token、字体/字号、侧栏、间距、边框圆角、按钮/表单/详情组件与焦点状态；长正文独立滚动且返回入口常驻。独立对照现有 TradeReview 参考及最终模型画板，覆盖 1440×900 与 1280×800 的首屏、滚动末尾和返回状态。具体尺寸与工作台共享框架仍按 09/11 对齐。

### LD10 · 大量策略包的管理（修订03设计提案）

用户已要求 SL12–SL15；具体操作取舍见[模型 M12/J4 与 F10–F13](../../.scratch/strategy-portfolio-backtesting/strategy-library-interaction-model.md)，尚不代表用户已逐项批准默认值。三类目录统一用一行一个包身份的紧凑列表；历史版本在详情。搜索名称/说明/标签/标识，类型/标签/来源/生命周期分组过滤，默认未归档、最近规则版本发布降序、置顶优先。置顶只作用于匹配结果；筛选后分两组、各组内部按当前排序。查询改变回第一页，详情返回保留原查询/页码/焦点；多页/空库/无匹配/失败分别可解释。

目录“使用策略数”按已保存完整策略的最新版本所引用包身份计不同策略数；当前包版本数是其中子集。历史策略版本数、锁定实验数另外列，实验按身份去重。详情能看引用明细并逐层返回；未保存草稿不计，未知/失败不能显示0。首次开发、最新版本发布时间、导入时间不混用；开发者/来源可靠时展示，否则“未提供”。标签备注属于包身份的管理信息，系统归档/兼容性标记不能编辑成标签；它们和置顶均不生成执行版本，不改变规则版本更新时间。所有画板数字均为设计示例。

置顶和手动顺序是个人偏好，三类目录分开，跨会话保存。独立“整理顺序”模式暂时展示本类型全部未归档包，保存原查询以便返回；置顶/普通组内用拖动、上下移动或本组全局第N位（可跨页）调整，组间通过显式置顶切换、追加组末。改动先留草稿，保存成功回原查询并切手动排序+置顶优先；取消恢复原排序，失败保留布局，冲突不静默覆盖。常规列表单次置顶即时保存，失败回滚。排序是展示偏好，不是包内标的排序或执行顺序。

归档覆盖包身份及全部版本，默认列表和新增包选择隐藏，但可检索已归档并恢复。确认展示引用影响与可选理由；已有策略引用、版本和锁定实验不变。归档是整理动作，不是执行禁用：已有完整策略可继续用于新实验，仍走原可执行性检查。活动未保存草稿中新增引用在提交时重新检查，包已归档则保留输入并要求恢复/替换；复制或编辑已保存策略可显式确认沿用原归档版本。成功返回保留查询并定位相邻行，空末页退最近有效页；失败保留确认态。恢复原身份/版本但置于普通组末尾、不自动置顶，计数重新核对。本轮先做单包闭环，永久删除、批量跨页选择/归档、文件夹及团队权限不纳入。

### LD11 · “我的实验”入口及完整创建流程（修订04）

SL16是用户对原入口设计的纠正，取代旧库列表/历史详情中的“用于新实验”。策略库只提供查看、新建、编辑、复制和包管理；两业务tab正常互达，切换不创建草稿、不隐式预选策略。“我的实验”提供列表、新建、继续草稿、重开原运行、查看结果或失败原因，显示状态/区间/策略组合/更新时间。

从实验列表进入四步创建：设置起点→选择已有完整策略→预览组合→确认并进入待开始工作台。普通选择页与就地新建成功后态分开；创建策略为次动作，带原实验返回上下文。无实验来源保存只归库；实验来源保存成功追加选择并重新预检，取消保留原选择；已有运行不能因返回或库升级被重建。具体状态和静态样例见[模型M13及F14–F19](../../.scratch/strategy-portfolio-backtesting/strategy-library-interaction-model.md)。工作台运行仍属任务11，不在此轮替它实现。

### LD12 · 列表顶部查询工具与卡片效率（修订05）

SL17明确要求我的实验及完整策略列表都有顶部搜索、筛选、排序，布局与状态表达保持一致；具体设计见[模型M14](../../.scratch/strategy-portfolio-backtesting/strategy-library-interaction-model.md)。搜索/筛选/排序组合生效，独立保存各自查询，详情返回恢复来源位置；更改查询回第一页，区分无记录/无匹配/加载失败。排序字段与方向可辨识，不修改实验运行或策略版本。

卡片先做[专业评估](../../.scratch/strategy-portfolio-backtesting/strategy-library-card-ui-review.md)，记录两档桌面真实尺寸和信息冗余；尺寸压缩、字段整理与动作布局属于建议，须形成后续画板，不能把本次“给出建议”当成全部采纳。

### LD13 · 全局视觉元素与文案（修订06）

按[模型M15](../../.scratch/strategy-portfolio-backtesting/strategy-library-interaction-model.md)及[UI06-01–05契约](../../.scratch/strategy-portfolio-backtesting/strategy-library-wireframes/STYLE-06-CONTRACT.md)统一19板：分段面包屑、同类输入/搜索/筛选和按钮尺寸、有限文字层级、中性边框与语义状态色。保留既有框架与卡片结构，不将密度建议顺带实施。

产品说明只表达对象、条件、动作和结果；设计编号、静态操作解释及工程占位迁至默认收起的文档层。合成数据、交易日历未校验、费用与分股假设、历史锁定版本、归档作用域及缺数据原因属于用户决策信息，不能为简化页面而删除。未知数据/参数明确未提供，不伪装真实配置。保存成功页不混入失败设计说明。

## Testing Decisions

### LT01 · 一个主要验收入口

以最高层用户旅程为主：**我的实验列表 → 新建实验 → 设置起点与区间 → 选择已有完整策略（可就地新建／复制、组装三类包后返回原草稿）→ 预览组合 → 确认并进入待开始工作台 → 运行并收集结果 → 返回列表重开原实验**。独立库管理旅程为**策略库 → 新建／复制完整策略 → 组合三类包 → 保存到库并查看策略详情**；随后只有用户主动切换“我的实验”、新建并选择策略才建立实验。两条旅程共享策略定义，不为每个字段或组件新增测试接口。

交互模型阶段用任务走查和状态表核验概念、去向、返回位置及取消行为；可点击原型阶段用真实浏览器验证相同旅程。正式实现时沿既有规格规划的高层策略实验应用服务验证公开行为，把策略库管理接入同一应用边界，复用行情 repository 和隔离 SQLite；该服务是后续建设边界，当前只有原型会话，并非已存在的生产 API。

2026-09-30 已按 to-spec 发出本轮测试边界核对。尚未收到答复时以上边界是建议，不记为用户已确认，也不阻止本轮记录需求和发布后续任务。

### LT02 · 场景、反例与证据

| 场景 | 操作与可观察预期 | 关键反例 |

### LT03 · 既有先例与适用性

复用现有创建原型的会话、草稿、实验派生及返回重开旅程；它目前只保存内存，并使用固定示例策略。原型技术先例是桌面 v2 的完整浏览器旅程与独立截图对照。正式测试先例为公共行情服务集成、SQLite 仓库、仓位账本、focused review 流程和真实图表回放测试；不能把“回放现成成交”当作新策略引擎。

本轮文档只验证需求映射、术语、引用、任务依赖和状态一致性。浏览器、视觉、真实引擎和数据库验收不适用于本轮文档交付；后续功能均为 NOT VERIFIED。
