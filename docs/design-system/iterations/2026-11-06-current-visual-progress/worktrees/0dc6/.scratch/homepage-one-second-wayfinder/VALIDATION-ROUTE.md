# 首页一秒打开：验证路线草案

本文是决策资产。用户已经确认总门槛；数据规模、探针细节、实验方案和正式迭代尚待对应问题解决。建图会话没有运行下面的实验。

## 已确认目标与判定

服务已启动、本地业务数据齐备时，从浏览器导航开始，到与当前范围和数据版本一致的真实首屏财务指标、持仓、设计要求的曲线显示且关键控件可操作，**≤1000ms**。必须覆盖浏览器冷/热、服务重启后首读、导入或修订后首次打开。导航前进程启动、外部行情/FX补齐单列；导航后才发生的编译、连接初始化、内部投影重建不能扣掉。

本地业务输入完整而内部投影缺失/失效不属于外部补数。内部恢复若超时，保留性能FAIL；快速骨架、旧值、错误提示或正确unknown是另外的状态证据，不算完整数据成功。合法空仓可以作为一个场景，但必须有独立非零业务场景。

计时终点须与数据版本、实际图表帧和真实控件行为绑定。HTTP完成、React effect/commit、LCP单项或自报ready标记不能独立证明终点；先用浏览器帧/截图与真实输入验证探针，再用于批量采样。响应错误、金额错误、版本混用或必需内容缺失，即使耗时短也失败。

## 顺序与并行边界

| 关卡 | 本步要得到什么 | 后续如何决策 |
| --- | --- | --- |
| 冻结验收 | 数据规模、非零金样、完整首屏完成判据、设备/桌面视口、逐次采样矩阵 | 形成可执行共同口径；不重复确认已确定的一秒边界 |
| 可比基线 | 同源生产冷/热/重启/写后首开原始结果，真正可随产品变化的端到端反馈回路 | 确认剩余预算与瓶颈，区分环境收益和产品收益 |
| 合同与启动设计 | 读模型字段/来源/失效与发布状态机；首页必要初始化及进入交易库/返回依赖图 | 确定紧凑输出和独立启动是否能保留原设计与金额语义 |
| 实验选择 | 用户选定A/B/C的有限验证路线、假设、授权与暂停内容处理 | 只放行所选实验；不把研究推荐变成正式实现授权 |
| 最小真实纵向实验 | 默认真实范围的财务、真实图表、版本、冷路径、写后读、视觉与逐次速度证据 | 支持扩大、缩小、否定路线，或暴露新的明确问题 |
| 正式优化迭代决策 | 用户依据证据选路线、范围、成本及后续接受关卡 | 路线清楚后另写实施方案；未决问题继续进图，不强行宣布完成 |

基线采集与读模型合同可在验收矩阵冻结后并行；启动边界需要两者。最小实验经过选择与授权后才执行。将来实施可把不重叠的查询优化和入口拆分并行，但发布/消费合同及最小真实旅程先共享、先接受，不能两边各自假设。

实时依赖与可领取问题以[地图](issues/00-map.md)下的 `frontier.py` 查询为准；上表是验证流程，不是第二份任务状态清单。

## 场景矩阵的最低要求

| 条件 | 测量与核验 | 不允许的替代 |
| --- | --- | --- |
| 浏览器冷访问 | 新会话/明确清除相应缓存；记录模块、HTTP、应用缓存各自状态，服务投影状态另列 | 只清React状态却称浏览器冷，或用热模块结果代替 |
| 浏览器热访问 | 同一版本重复导航/返回，记录命中层级 | 只重复调用纯函数memo |
| 服务重启后第一读 | 服务就绪后立刻导航，持久投影/连接/迁移/验证成本均记录；进程启动另列 | 偷做预热请求后称第一读 |
| 导入/修订后首次打开 | 真实隔离写入→提交结果→返回/导航→reload核验；同数量修订、删除/回滚分别覆盖 | 用事务调用成功代替UI持久化闭环，或隐去预计算等待 |
| 内部投影缺失/失效 | 输入完整时测首次构建、算法/schema升级或损坏恢复；无法达标保留FAIL | 归入外部数据未齐备、只测热持久命中 |
| 非零金额与长历史 | 当前代表性真实副本＋可独立核算的多市场业务金样，冻结规模与历史跨度 | 旧漏斗entry/group=0被解释成实际无持仓，或仅与已知错误旧输出一致 |
| 输入缺失/外部更新 | 缺行情/费用/FX、断网/失败、旧数据保留的状态与时间证据；外部补齐成本单列 | unknown补零、插值补齐缺口、readAt伪造新鲜度、快速错误当完整成功 |
| 竞态和恢复 | 构建中写入、迟到旧请求、范围/期间切换、重启、投影损坏，校验版本与取消 | 跨generation拼接成功或新旧来源混用 |

完整组合矩阵及采样数由[验收冻结问题](issues/01-acceptance-matrix.md)确定。研究建议小规模成对试验后做至少30次/状态稳定性观察，尚非用户选定的样本方案。任何必测样本>1000ms保留FAIL；报告每次值、最大值和分位，均值/p95不能抹去失败，也不能承诺对无限数据规模或所有设备的数学上界。

## 单次样本的漏斗

记录同一个导航ID、scope/selection、源revision、投影/算法版本和request/generation，至少包括：

1. navigationStart、TTFB、HTML完成、首页关键模块就绪与财务读取发起。
2. 服务端版本检查、投影命中/失效原因、必要输入查询/SQL、映射、构建、校验、编码；响应请求数/字节数与完整body到达。
3. 浏览器解析、来源/版本校验、主线程long task、React提交、实际图表首帧/财务paint及首个有效输入响应。
4. 金额、持仓、曲线、缺失状态、来源与时间证据的对照结论；不正确时保留失败终态，不只保存超时数字。

父子span不相加，跨线程并行报告关键路径。主测速使用未插桩生产构建，受控profile负责归因且记录开销。原[六段1000ms分配](../homepage-one-second-feasibility-2026-10-24/FEASIBILITY.md:87)只是定位用设计预算，未获阶段承诺，不能据此预测收益。

每次导入/修订还报告：用户操作开始、写入提交、投影发布、导航开始、首屏就绪；给出写入（含阻塞预计算）、首开及总等待，重叠部分按时间线说明。提交是否等投影发布及可接受写入成本由[新鲜度合同问题](issues/03-read-contract.md)决定，不由代理藏入提交定义。

## 四个独立接受门槛

| 门槛 | 必要证据 | 责任 |
| --- | --- | --- |
| 财务功能正确 | 既有正确领域样本＋独立非零业务金样；逐笔金额、费用/FX资格、期初/期末、持仓与曲线对照；真实数据不是占位图 | 完整数据/持久化负责人；协调者独立核算/抽验 |
| 状态与持久化 | 来源revision与原子发布/失效；实际隔离库写入、返回、reload；旧请求、取消、错误/恢复，必要交易库进入/返回 | 同一数据负责人贯通发布与消费；协调者独立浏览器验证 |
| 设计与控件 | V2.5 原图同视口同状态直接比较，密度/层级/默认尺寸、loading/error/expanded；完整受影响控件登记及真实鼠标/键盘旅程 | 一名整页视觉负责人；非实现者独立截图比较与协调者接受 |
| 端到端性能 | 冻结矩阵逐次导航≤1000ms且真实财务完成；冷路径/更新成本/全部原始值，未插桩与profile证据区分 | 协调者独立运行；worker报告只作局部证据 |

原财务核心48控制＋9样本的PASS及64MiB约束可以复用，但其2秒模块门槛不替代整页1秒。现有[历史未接线与暂停项](../homepage-v25-implementation/FINAL-ACCEPTANCE.md)保持原判定；只修快错误显示不能接受为真实财务成功。

设计比较以 **1440×1000、1280×800、100%缩放**为准；旧漏斗1440×900仅是诊断环境，不覆盖批准视口。参考[主页1440](../../docs/design-system/baselines/2026-10-22-homepage-v2.5/source/images/home-1440.svg)、[主页1280](../../docs/design-system/baselines/2026-10-22-homepage-v2.5/source/images/home-1280.svg)、[历史展开1440](../../docs/design-system/baselines/2026-10-22-homepage-v2.5/source/images/home-history-1440.svg)、[历史展开1280](../../docs/design-system/baselines/2026-10-22-homepage-v2.5/source/images/home-history-1280.svg)，以及[正文](../../docs/design-system/baselines/2026-10-22-homepage-v2.5/source/visual-design.candidate.md)。性能目标不授权缩减设计。窄屏/新增触屏设计不在本期；已有受影响行为按实际范围回归，鼠标、键盘、模拟触摸与物理触摸证据不混用。

## 版本、安全与每轮停止规则

运行前固定HEAD＋dirty哈希、算法/合同版本、Node/SQLite固定版本、浏览器、数据计数/哈希和视口。复制数据须WAL一致，显式隔离DB；使用当前[配置优先级](../../conf/README.md)与[开发流程](../../docs/agents/development-workflow.md)。业务库只允许为取得副本进行已授权的一致性备份读取，测试服务和全部测试写操作指向隔离副本，旧3333进程不作为验收操作面。当前建图不启动任何服务，也不访问数据库。

每个实现候选只在批准范围内迭代，主协调者独立接受；最多3轮。记录候选哈希、根因假设、统一修复方案、变化、各门槛结果及证据。先按 systematic-debugging 扫描同根问题、设计统一修复，再实现和回归，不凭单个症状反复打补丁。更改代码后原证据不可直接沿用。

第3轮仍有必需FAIL或NOT VERIFIED，暂停该任务，更新它的issue、功能README和最终接受记录，保存已有进展、未通过原因、未测项及需要的用户决策。不得以改名或换代理获得第四轮。P1/F07、Bars原3/3暂停计数不因本地图重置；[实验选择问题](issues/05-experiment-choice.md)负责具体恢复授权。文档审查不是产品候选轮次。

最小实验仅证明其范围。只有功能、状态/持久化、设计与性能各门槛都有独立证据，才可称该范围成功；反证也应进入后续决策，但不能改成产品PASS。证据不足时保留NOT VERIFIED，新增明确问题；原型失败、超限暂停或停止不能自动释放正式开发。

候选实现身份及轮次在原实现/实验执行票中记录，失败和暂停保持；Wayfinder原型票的接受对象是实验协议完整执行、证据充分及用户真实反馈。全部必需观测已完成而假设被否定时，可以接受负面决策证据，进入停止或取舍讨论，不关闭失败的实现票、不增加修改授权；缺少必需采样、持久化核验或独立视觉审查则原型决策票也继续open/NOT VERIFIED。两种接受对象不互相替代。

## 正式迭代选择所需材料

向用户提供A/B/C实测比较、未验证边界、写入及维护成本、主要风险、建议的下一步和停止条件；分别记录实验授权与正式实现授权。若继续实施，按批准合同拆完整旅程、精确设计元素覆盖、独立文件所有权和每票最多3轮，而非先把任务拆成“写接口/写组件/加缓存”。最终通过产品验收时再提供仍在运行、真实浏览器刚核验过的可点击预览、启动说明及证据。本轮文档规划无产品预览验收。
