## 3. 关键行语义、费用与分页证据

### 主行、成交子行、小计和总计

F3 有直接反例：`富途/美股/2020-01.pdf` p1 中一单補回合计数量 140，下方是 100 和 40 两笔同秒成交；`富途/美股/2022-03.pdf` p1 有同一时刻、相同数量/价格的多条 DDL 子行。不能同时导入合计与子行，亦不能用「时间 + 代码 + 数量 + 价格相同」直接去重。订单聚合均价也不能替代每一笔的实际价格。

F4 的结构在 `富途/综合/2024-11.pdf` p3 目视确认：方向和证券主行数量 10,000，下方成交子行是 6,000 与 4,000，具有同秒时间；费用小计附在整个组之后。合成结构示意（数值非原件）：

```text
主行：卖出平仓 HK:00000，数量 300，均价 10，成交额 3000
子行：SEHK，日期 D，时间 T，交收日 S，100 × 10
子行：SEHK，日期 D，时间 T，交收日 S，200 × 10
费用行：佣金 a，平台费 b，其他 c，小计 a+b+c
```

主行提供身份/方向，子行提供成交锚点；主行不再额外产生 300 股成交。组费用是否可以精确分配到子行，要看该变体是否提供逐笔净额，不能把组费用重复分配给每一笔。此处只列证据需求，不指定产品分配算法。

Tiger `老虎/2020-12.pdf` p4 的「合计 代码」「合计」「合计（基础币种）」是多个汇总层级，不是成交；币种折算总计不适合与原币逐笔金额直接相加。该页的合计行即使有非零数量或金额，也缺少完整成交事实。`老虎/2025-03.pdf` p4 同页先有基金续表和合计，再有股票表；章节边界比日期、数字或买卖字样更强。

### 现金变动不等于成交额，也未必逐笔对应

`富途/美股/2015-04.pdf` p1 的买入成交金额 1,240.20、变动金额 -1,248.20，佣金 5.00、交收费 3.00；这是旧脚本字段错误的直接原件反例。该单确实能用金额差校验费用，但不能推广到所有模板。

`富途/港股/2018-06.pdf` p1 的同组 02382 买入为 100 股 × 151.4 和 100 股 × 151.5，两行各列费用 34.67、19.67；第一行变动金额 -30,344.34，第二行 0.00。两笔总成交额 30,290 加费用 54.34 才对应该现金变动。同页 01347 卖出也出现 1,000/3,000 两笔、现金变动集中在前一行的情形。逐行差值会产生虚假巨大费用，0.00 也不表示免费或没有成交。

富途费用详情与「小計」并存（如 `富途/综合/2024-11.pdf` p3），累加详情后不能再加小计；币种汇总也不是额外费用。Tiger 早期一个费用负数与后期多行标签不同（`老虎/2020-12.pdf` p4；`2022-05.pdf` p4-p6）。费用缺失、明确为零、费用在下一页是三种不同状态，不应统一补零。返还或税费调整的符号语义，本轮没有充分样本验证。

### 页面与文字提取边界

- `富途/综合/2024-11.pdf` p2 最后的 00700 卖出主行，在 p3 页首才有日期/时间、场所、子行金额和费用；p3 末尾的 07552 主行在 p4 继续。不能到页尾即丢上下文，也不能无期限继承上一证券。
- 同件 p2-p4 的 pypdf 输出包含「買賣方向買賣方向」「買入開倉買入開倉」；p3 图像只印一次。应把这视作文本层/绘制重叠证据，不能把全局去重中文字符当通用安全清洗，更不能去重真实同秒成交。
- `老虎/2025-03.pdf` p3 末尾基金名称与日期在前页，p4 页首括号代码、数字与时间续接。该例证明跨页字段碎片存在；它来自基金，不足以单独证明所有股票跨页行都用同样规律。股票表从 p4 延至 p5，费用与名称多行排布需保持列和逻辑组。
- pypdf 文本足以发现候选语义，不能据此给 pdf.js 的坐标分组容差作兼容性认证。本轮仅两处表格裁片目视检查，未完成所有代表页的版面金标准。

## 5. 当前代码对照与旧脚本不可信的具体原因

以下是静态检查结论或明确标明的风险推断，没有运行真实 PDF 导入成功率测试。代码行号基于上述提交；旧脚本行号基于研究时的本地只读文件。

| 位置 | 核实事实 / 对照证据 | 意义 |
| --- | --- | --- |
| `app/lib/import/dispatcher.ts`：`parseBrokerStatement` | 先探测富途 workbook；PDF 只注册 Tiger 和招商检测，不含富途 PDF 分支 | 「应用支持富途导入」不能推广为支持历史富途 PDF |
| `app/lib/import/futu.ts`：`TRADE_SHEET`、`REQUIRED_HEADERS`、`parseFutuWorkbook` | 目标为 XLSX 的「证券-交易流水」，要求成交时间、账户、品类、总费用等列；默认时间为 Asia/Shanghai | 与 F1-F5 均不是同一输入模板，不能直接拿当前列映射证明历史 PDF 支持或统一时区 |
| `app/lib/import/tiger.ts:23`、`detectTigerStatement` | 固定要求 `Tiger Brokers (NZ) Limited` 加股票表；早期样本实际为 `Tiger Brokers Limited` | T1 至少在检测层存在明确不匹配；合法无成交月份也不能仅凭检测不到表归为损坏 PDF |
| `app/lib/import/tiger.ts`：`isExecutionAnchor`、`sideFor` | 行锚点要求非空 direction；数量符号回退只发生在方向标签含开仓/平仓时；T1/T2 样本交易类型格确实可空 | 即使只扩充券商抬头也不足以覆盖早期股票表，空方向可能在候选阶段就漏掉，而非只产生无效行诊断 |

旧 Python 的明确缺陷与风险（路径相对原始资料根为 `提取月结单.py`）：

1. **已核实字段错误，纠正先前报告。** `parse_trade` 第 343 行把「變動金額」读入 `pnl_text`，353 行也可从续行覆盖它，358 行解析为 `realized_pnl`；但 379 行 `gross_amount: amount`，382 行实际为 `cash_change: amount if broker == "富途" else None`。富途的 parsed pnl_text 没有写入 cash_change。故不能声称旧结果保存了原始净现金变化；2015-04 p1 的上述金额就是具体反例。没有更改脚本或输出。
2. **方向词漏项。** 第 246 行 `FUTU_DIRECTIONS` 不含「補回」，而 `富途/美股/2019-06.pdf` p1、`2020-01.pdf` p1 明确存在。结果可能漏行或错误沿用前一个上下文方向；这是代码路径风险，未复跑统计污染范围。
3. **表头识别与取值不一致。** 第 474 行接受 Tiger「成交价格」或「交易价格」，但 `parse_trade` 第 331 行只映射交易价格的简繁体；潜在别名分支不闭合。本轮样本主要见交易价格，不能声称已发现此缺陷造成的真实错单。
4. **金额、费用和续行启发式缺少结构保证。** 第 348-353 行把续行日期后的前四个数固定当数量、价格、成交额、变动额；F3 的成交子行常仅有时间而无完整日期，F4 主行又跨页。第 344 行富途 fee_text 直接为空；第 75-79 行费用以任意数字求和。旧规范化记录不能直接用于准确费用回放。
5. **上下文与资产身份启发式。** 第 483-489 行可能对无表头后续表沿用 active_headers；520-523 行用页面文本最后一个证券上下文覆盖；133-145 行 code_and_name 用宽泛字母/数字正则，未构成证券类型证明。基金、现金章节重置虽存在（495-500 行），仍不能证明不会跨组串单。
6. **快照日期归属风险。** 第 557 行只要整页含「期初」，就给抽到的持仓标为期初。富途确实有期初/期末/资产总览多种名称，需按局部章节定位，不能从整页词命中推断每张表的时点。

旧代码的问题并不意味着原 PDF 错误；旧 JSONL 中有来源路径和页码，也不意味着已解释正确。此票未修正任何历史输出，未给出错误率。

## 6. 可信来源锚点与决策含义

后续要宣称某段历史可以回放，至少需能从一条回放记录回到原 PDF 的具体逻辑组：文件相对路径与指纹、账期正文依据、物理页、章节/表头、主行和子行位置、费用片段、原代码/名称/币种、原方向、原时间及其精度/语义。跨页事件应允许多个源片段；pypdf 行序只是研究定位，不能稳定替代坐标。重复文本片段、重复文件、同单多笔是不同层面的重复，不能使用一种去重规则。

合成最小来源示意：`文件 P / p2 主行 + p3 子行2 + p3 费用行 / 股票分区 / 原代码 C / 日期语义=成交 / 提取版本 V`。现有单页/row source 是起点，不能完整表达这个证据链。账户隔离需要可信内部标识，但本文与研究样本不应暴露账户原号。

这批证据对第一版回放的含义是：识别券商只是第一层；还需证明交易结构、时间可定位、数量和费用不重复、资产类型可解释、起始库存可解释。数量与价格提取成功但起始持仓/辅助事件未覆盖时，可以证明「存在这笔成交」，不能据此证明完整 episode、历史成本或已实现收益准确。期初快照可以证明已有数量，不能制造买入日期或成本；当已有负持仓证据时也不能一律假设历史多仓。

本文不选择新产品行为或计算口径。下一步研究可按以下有限缺口安排，不需要为了首版股票/ETF 回放先补完整账户总账：

- 为 F1、F2、F3、F4/F4a、T1、T2、T3 各建立少量脱敏的版面/字段预期样本，验证当前 pdf.js 提取与 pypdf 调查结论是否一致，尤其是空方向、同秒多笔、跨页身份与费用。
- 对 F2 下单时间与其他富途无印刷时区时间继续找原件说明；日期级证据不能擅自提升为分时图上的准确成交秒。Tiger 已观察到行内时区，不可按市场统一写成固定偏移。
- 对初始持仓、转入、IPO 获配选择少数可闭合案例核对数量；对于成本未知明确保留缺口。拆并股/更名/换股等先补真实事件样本，不从模板条款或市场常识推导个人账户事件。
- 补查 F4a 和最新综合抬头下的活跃月份；需要时再查相邻月份以缩小模板变化区间，仍不宣称券商全局切换日。无交易月份不能作为活跃交易模板测试。
- 已发现的 gross/cash_change 错误单独记录为下游旧数据不可信原因；进入实现阶段后，旧数据纠错需要单独验证，不能把本研究笔记视为数据修复完成。

停止边界：已得到有页码支撑的首轮家族、主从行/费用/跨页反例与代码缺口；未穷举字段组合、未全量逐笔核算、未证实所有转版日期、未对任何家族承诺生产可用。这些限制不妨碍后续以代表样本推进股票/ETF 回放证据验证。

本文档仅记录研究证据，不是运行时规则配置。
