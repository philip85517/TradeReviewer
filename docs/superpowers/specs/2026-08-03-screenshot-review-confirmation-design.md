# 截图交易校对确认阈值与单行放弃设计

日期：2026-08-03  
状态：已确认

## 目标

修复截图交易校对页的两处交互问题：

1. 成交时间不应因为字段类型而被逐行强制确认；达到统一置信度标准且格式有效的时间戳可以自动通过。
2. 其它字段无法可靠确认时，用户可以放弃当前成交行，让同批次其它记录继续导入。

## 已确认的产品规则

- `executedAt` 与市场、代码、方向、数量、价格使用同一 `SCREENSHOT_REVIEW_CONFIDENCE` 阈值（当前为 `0.85`）。
- 字段值有效、存在证据、置信度不低于阈值、未自动修复且未被用户修改时，不产生“需要确认”阻塞。
- 低置信、自动修复、缺少证据或格式无效的成交时间仍需确认、修改或放弃。
- “放弃这条记录”只删除当前截图成交 draft；同批次其它行继续参与导入。
- 放弃使用现有 `deletedDraftIds` 和 `delete-draft` action，不新增持久化状态、诊断类型或导入协议字段。
- 如果所有成交行都被放弃，仍按现有规则阻止空批次导入。

## 数据流与边界

`reviewBlockers` 负责判断活动 draft 是否阻塞完成：`executedAt` 不再有无条件确认特判，沿用其它字段的统一判断条件；时间格式和时区转换校验仍保持不变。

字段证据面板触发已有的 `delete-draft` action。`screenshotReviewReducer` 将 draft ID 加入 `deletedDraftIds`，活动草稿、问题统计、重算 reconciliation 和 `toStatementParseResult` 均继续通过现有过滤逻辑排除该行。OCR 解析器、字段证据结构、最终交易记录结构不变。

## 交互

- 字段证据面板保留“确认识别值”和“保存修改”。
- 面板同时提供“放弃这条记录”，点击后立即关闭该行的校对入口并从成交总表移除。
- 表格原有的行删除按钮继续保留，两个入口都产生同一个 `delete-draft` action。
- 达到阈值的时间戳在表格中显示为“已确认”；低于阈值的时间戳仍显示“待确认”，可打开原图证据。

## 测试策略

- `review-state`：验证时间戳置信度为 `0.85` 且未修复时不产生阻塞；低于 `0.85` 仍产生阻塞；自动修复仍需确认。
- 证据面板/校对对话框：验证“放弃这条记录”触发当前 draft 的 `delete-draft` action。
- reducer 或导入流程：验证被放弃行不再产生字段阻塞，也不会出现在最终待导入记录中；其它行不受影响。
- 保留现有空批次、时区、账户、冲突和重复记录测试。

## 非目标

- 不改变 OCR 模型、截图版式检测、字段置信度计算方式或时区转换算法。
- 不把放弃记录写入导入结果、历史统计或新的持久化表。
- 不调整非截图导入流程。
