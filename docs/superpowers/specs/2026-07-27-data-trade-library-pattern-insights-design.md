# TradeReview 行情数据、交易库与模式洞察设计

日期：2026-07-27  
状态：待用户书面审核

## 1. 背景

TradeReview 已完成富途成交导入、标准化股票聚类、演示行情回放、未来信息遮蔽、图表绘制和本地持久化的第一条纵向切片。当前仍有三个连续缺口：

1. 导入的真实交易没有真实历史行情，无法进入实际回放。
2. “交易库”只有导航占位，用户不能按股票和持仓回合管理历史交易。
3. “模式洞察”只有导航占位，用户不能从多次复盘中识别重复优势和错误。

这三个能力共享同一条数据链路：真实行情先补齐交易上下文，标准化成交和行情再构成交易库，经过用户确认的标签和完整回合最后进入统计洞察。

## 2. 已确认的产品决策

- 产品定位为个人、非商业、无需登录的复盘工具。
- 首期行情覆盖美股、港股和 A 股，只要求日线和周线。
- 行情源不得要求用户注册、配置或保存 API Key。
- 交易、复盘笔记、标签和长期行情只保存在当前浏览器。
- 网页服务端可以代理行情请求、转换格式、限流和做短时公共缓存，但不得持久化用户交易或复盘内容。
- 行情严格采用 Cache First：本地覆盖完整时不得访问外部数据源。
- 交易库采用两层结构：先按股票聚类，再展示该股票的持仓回合。
- 持仓回合从净仓位由零变为非零开始，到重新归零结束。
- 模式洞察首期采用可解释的规则和统计模型，不接入 AI。
- 系统可以自动建议标签，但只有用户确认的标签能进入正式统计。
- AI 归纳、自然语言问答和心理笔记总结属于下一期。

## 3. 范围与非目标

### 3.1 首期范围

- 无 Key 的三市场日线获取。
- 日线的本地长期缓存与周线聚合。
- 行情缺口规划、增量更新、状态和错误恢复。
- 股票聚类的交易库。
- 按持仓回合组织的交易详情。
- 结构化计划、复盘字段和版本化标签。
- 自动标签建议、用户确认和统计洞察。
- 数据导入导出、存储空间提示和模式迁移。

### 3.2 非目标

- 实时行情、盘中监控或交易提醒。
- 分钟线、逐笔行情和盘口。
- 多设备同步、云备份或团队共享。
- 自动交易建议、选股或收益预测。
- 由模型直接解释自由文本。
- 商业化数据展示或市场数据再分发。
- 绕过外部数据源的登录、访问控制、验证码或反自动化限制。

## 4. 总体架构

系统分为六个边界清晰的模块：

1. **Instrument Registry**  
   维护标准化股票 ID、市场、货币、时区、展示名称和各行情源代码映射。

2. **Coverage Planner**  
   根据交易区间、持仓状态和本地覆盖元数据，计算必须补齐的最小日期区间。它不执行网络请求。

3. **Market Data Provider**  
   每个来源实现相同接口，只负责远程请求和来源格式解析，不了解交易、回合、标签或用户笔记。

4. **Market Data Repository**  
   使用 IndexedDB 保存日线、覆盖区间、来源、校验结果、调整方式和同步状态；提供按股票和日期读取、合并和迁移能力。

5. **Trade Library**  
   从不可变的标准化成交派生股票摘要和持仓回合，并关联行情、计划、复盘和标签。

6. **Insight Engine**  
   从合格回合生成可解释指标、候选关联、可信度等级、证据和反例。引擎只读取结构化数据。

依赖方向固定为：

`Imported Executions → Instrument Registry → Coverage Planner → Market Data Repository → Trade Library → Insight Engine`

上游模块不得依赖下游页面或统计结论。

## 5. 行情数据设计

### 5.1 Provider 接口

Provider 的最小接口如下：

```ts
type DailyCandleRequest = {
  instrumentId: string;
  providerSymbol: string;
  market: "US" | "HK" | "CN-SH" | "CN-SZ";
  startDate: string;
  endDate: string;
};

type ProviderDailyCandle = {
  tradingDate: string;
  open: string;
  high: string;
  low: string;
  close: string;
  volume: string;
  adjustedClose?: string;
};

type ProviderResult = {
  provider: string;
  fetchedAt: string;
  candles: ProviderDailyCandle[];
  warnings: string[];
};

interface MarketDataProvider {
  supports(market: string): boolean;
  fetchDaily(request: DailyCandleRequest): Promise<ProviderResult>;
}
```

接口只接收标准化股票、来源代码和缺失日期范围。交易时间、数量、账户和笔记不会传给 Provider。

### 5.2 首期来源

- A 股：以东方财富公开历史行情接口为第一适配器。
- 港股：以 Yahoo Finance 公开历史行情接口为第一适配器。
- 美股：以 Yahoo Finance 公开历史行情接口为第一适配器。

这些来源无需 Key，但不提供稳定性或商业授权保证。产品必须显示真实来源和抓取时间，不得声称数据由交易所授权。遇到拒绝访问或格式变化时停止请求并降级，不能规避来源限制。Provider 接口允许以后加入本地 AKTools 或已授权来源，而不改变交易库和洞察。

### 5.3 同源代理

浏览器向同源接口发送：

```text
market + normalized symbol + start date + end date
```

代理负责：

- 参数白名单和代码格式校验。
- 限制为日线和受支持市场。
- 单次日期跨度上限。
- 每 IP 和全局速率限制。
- 以市场、代码和日期范围为键的短时公共缓存。
- 请求超时、退避和来源错误映射。
- Provider 响应到统一结构的转换。

代理不是通用 URL 转发器，也不接收任何用户交易记录。

### 5.4 本地仓库

IndexedDB 使用版本化 schema，至少包含：

- `instruments`：标准化股票和来源代码映射。
- `dailyCandles`：以 `instrumentId + tradingDate + adjustmentMode` 唯一索引。
- `coverage`：已校验区间、缺失日期、来源、最后抓取时间和状态。
- `executions`：由现有本地存储迁移的标准化成交。
- `episodes`：可重建的持仓回合索引。
- `reviews`：事前计划、事后复盘和评分。
- `tagSuggestions`：规则建议、证据、规则版本和处理状态。
- `confirmedTags`：用户确认或修改后的标签。
- `insightSnapshots`：可重建的统计结果和计算版本。
- `migrations`：schema 与计算版本。

成交和日线以定点十进制字符串保存，不使用浮点数作为持久化事实。

### 5.5 Cache First 与覆盖规划

默认所需上下文为：

- 首笔成交前至少 260 根有效日线。
- 已平仓回合到最后成交后至少 20 根有效日线。
- 开放回合到最近一个完整交易日。

首次规划时先以首笔成交前 400 个自然日和最后成交后 35 个自然日作为请求边界；校验后如果有效日线仍不足，再向前或向后追加请求。同一股票所有回合的所需区间先合并，再减去本地已经校验的覆盖范围，只生成最小缺口请求。跨度过长时按自然年分块，但分块结果仍合并成同一覆盖记录。

系统内置首期四个交易场所的版本化日历：NYSE/NASDAQ 共用美国交易日历，HKEX、SSE 和 SZSE 分别使用各自日历。日历用于识别周末、节假日和最近完整交易日；Provider 返回的停牌日或临时休市缺口单独记录，不能自动填充伪造 K 线。日历随应用版本更新，不在页面打开时额外联网。

只有以下情况允许自动请求：

1. 首次导入且本地不存在该股票行情。
2. 新导入成交扩展了所需区间。
3. 开放持仓的本地最后日期早于最近完整交易日，且距上次尝试不少于 12 小时。
4. 用户主动更新单只股票。

以下操作不得产生行情请求：

- 打开或刷新交易库。
- 切换已经完整缓存的股票。
- 切换交易回合。
- 切换日线和周线。
- 查看模式洞察。
- 浏览器页面重载。

单股“更新行情”默认仍只补缺口。高级操作“重建行情缓存”必须明确提示会重新下载并覆盖该股票的行情缓存。

### 5.6 聚合和调整

- Provider 只写入日线。
- 周线按股票市场时区和交易日历在本地确定性聚合。
- 原始 OHLCV 和调整后价格不得混为同一序列。
- 每个图表和统计结果保存 `adjustmentMode`。
- 成交价格始终保留券商原始价格；若图表使用调整后序列，成交标记必须使用相同调整因子映射。

### 5.7 校验与故障处理

写入前校验：

- 日期严格递增且同一股票无重复交易日。
- `low <= open/close <= high`。
- 价格非负，成交量非负。
- 市场、货币、时区和代码映射一致。
- 返回区间不越过请求区间。

故障行为：

| 故障 | 系统行为 |
|---|---|
| 403、429 或超时 | 保留缓存，指数退避，不循环重试 |
| 来源格式变化 | 整批隔离，不覆盖旧缓存 |
| 部分日期返回 | 写入有效数据，但 coverage 保持 `partial` |
| 浏览器离线 | 只读 IndexedDB |
| 股票代码无法映射 | 要求用户确认市场和代码，不猜测 |
| IndexedDB 配额或迁移失败 | 事务回滚，保留旧版本并提供导出 |

状态至少包括：

`not-requested | syncing | complete | partial | stale | source-unavailable | invalid-response | storage-error`

不完整行情不得进入正式模式统计。

## 6. 两层交易库

### 6.1 第一层：股票库

股票是交易库首页唯一列表对象。同一标准化股票跨导入批次合并，不产生重复卡片或行。

每行显示：

- 股票名称、代码、市场。
- 账户数、成交笔数、持仓回合数。
- 首末成交日期和开放/已平仓状态。
- 净盈亏、收益率和可计算时的累计 R。
- 行情覆盖状态。
- 已确认的主要标签。

支持按股票名/代码搜索，并按市场、账户、年份、标签、开放状态和数据完整性筛选。默认按最近成交时间排序。

### 6.2 第二层：股票详情

进入股票后：

- 左侧按最近优先排列持仓回合。
- 右侧显示当前回合的“行情与买卖点、成交明细、交易计划、复盘结论”。
- 左侧回合项显示区间、买卖笔数、方向、开放状态、净结果和复盘状态。

模式洞察中的证据和反例链接直接打开这个页面并定位对应回合。

### 6.3 持仓回合规则

回合按 `accountId + instrumentId` 独立构建：

1. 成交按执行时间、来源文件指纹和来源行号稳定排序。
2. 净仓位从 0 变为正数时开启多头回合。
3. 净仓位从 0 变为负数时开启空头回合。
4. 净仓位重新归零时关闭回合。
5. 一笔成交穿越零仓位时，按数量拆成关闭旧方向和开启新方向两条 allocation；原始成交保持不可变。
6. 多次买入、加仓和分批卖出都保留在同一回合。
7. 转仓、拆股、分红和费用调整属于独立事件类型，不伪装成买卖成交。

配对和 allocation 是派生结果，可以随算法版本重建；原始标准化成交是事实来源。

### 6.4 回合指标

每个回合计算：

- 总买入/卖出数量和成交笔数。
- 加权平均成本。
- 已实现和未实现盈亏。
- 费用后净盈亏。
- 持仓时长。
- 收益率。
- MFE、MAE 和盈利回吐。
- 计划遵守状态。
- 计划风险存在时的 R 倍数。

没有用户填写的失效价格或计划风险时，R 显示为空，系统不得从最终走势反推止损。

### 6.5 回合记录

每个回合关联：

- 事前计划：买入理由、预期路径、失效条件、目标区间、计划风险。
- 用户可选择的结构化字段：是否计划内、信心等级、情绪、是否遵守止损、执行评分。
- 全部成交和来源信息。
- 行情覆盖、图表绘制和文字标注。
- 事后复盘：决策质量、执行质量、风险管理、心理和可复用规则。
- 自动建议标签和用户确认标签。
- 计算结果与版本。

## 7. 标签建议

### 7.1 生命周期

标签建议状态为：

`suggested | confirmed | rejected | edited`

每条建议保存：

- 标签 ID 和标签字典版本。
- 规则 ID 和规则版本。
- 证据日期、K 线、成交或计划字段。
- 建议时间。
- 用户处理状态和最终标签。

只有 `confirmed` 和 `edited` 的最终标签能进入正式统计。

### 7.2 首期自动建议范围

可由确定性事实建议：

- 20 日区间突破。
- 突破后的首次回踩。
- 入场价格相对 ATR 和近期区间的位置。
- 分批进入、加仓次数和持仓集中度变化。
- 计划外加仓。
- 实际退出相对计划失效价的偏离。
- MFE、MAE、盈利回吐和持仓时间异常。

必须由用户确认或填写：

- Bull Flag、Trading Range 等主观图形结构。
- 恐惧、FOMO、报复交易等心理状态。
- 是否计划内和是否遵守纪律。
- 复盘评分与可复用规则。

系统不得从自由文本中自动推断心理标签。

## 8. 模式洞察

### 8.1 合格样本

正式洞察只使用：

- 已平仓回合。
- 行情覆盖为 `complete`。
- 相关标签已经确认。
- 指标所需字段完整。
- 计算版本兼容。

被排除的回合必须显示原因。

### 8.2 三类洞察

1. **交易条件**  
   市场、方向、持仓周期、波动环境、入场位置、加仓次数与结果的关系。

2. **图形模式**  
   用户确认的突破、回踩、Bull Flag、Trading Range 等模式的结果差异。

3. **执行与心理**  
   计划外加仓、止损偏离、追高、盈利回吐以及用户确认心理标签的结果差异。

首页跨三类选出最显著的 3–5 条，不为每个分类强行生成结论。

### 8.3 指标

- 胜率。
- 净盈亏。
- 中位收益率。
- 期望 R，仅使用存在计划风险的样本。
- 持仓时长。
- MFE、MAE 和盈利回吐。
- 加仓次数。
- 计划遵守率。

胜率不能单独作为排名依据。

### 8.4 可信度

- 3–4 个标签样本：`early-signal`，只显示早期线索，不进入首页排名。
- 5–9 个标签样本：`usable`，可以显示为可用洞察。
- 10 个以上标签样本：`high-confidence`，在数据完整且存在有效基准组时可以标记高可信度。

每个候选还必须有至少 3 个可比较的基准样本，否则只显示描述统计。

候选按以下稳定顺序排名：

1. 可信度等级。
2. 与基准组的中位结果差异。
3. 较小一组的样本数。
4. 最近一个样本的日期。
5. 稳定的候选 ID。

计算优先使用 R；当相关组中不足 80% 的回合拥有计划风险时，改用费用后收益率，并明确显示口径。

### 8.5 可解释性

每条洞察必须显示：

- 结论使用的中性措辞，不声称因果。
- 标签组和基准组。
- 样本数和时间范围。
- 指标口径。
- 证据交易列表。
- 反例列表。
- 排除的交易及原因。
- 规则、标签和计算版本。

用户可以从任何证据或反例进入交易库对应回合。

## 9. 隐私与安全

- 原始对账单继续在浏览器解析。
- 外部行情请求只包含股票、市场和缺失日期范围。
- 服务端不接收账户、成交、计划、笔记、标签或洞察。
- IndexedDB 数据默认不跨设备同步。
- 页面公共可访问，但行情代理实行参数白名单、日期跨度限制、每 IP 限流和短时缓存，避免成为开放代理。
- 数据导出默认脱敏账户号码，并允许排除绝对金额。

## 10. 开发阶段

### Phase 1：无 Key 行情与本地仓库

- IndexedDB schema、迁移和仓库。
- Instrument Registry 和三市场代码映射。
- Coverage Planner。
- 同源代理和 Provider 接口。
- 东方财富 A 股适配器。
- Yahoo 港股、美股适配器。
- 日线校验、合并、状态和周线聚合。
- 单股增量更新和高级缓存重建。

### Phase 2：两层交易库

- 股票索引与筛选。
- 稳定持仓回合与穿越零仓位 allocation。
- 股票详情和回合列表。
- 行情、成交、计划和复盘标签页。
- 回合指标与数据完整性提示。

### Phase 3：标签与统计洞察

- 版本化标签字典。
- 首期建议规则。
- 确认、否决和修改流程。
- 回合指标快照。
- 候选比较、可信度和稳定排名。
- 首页洞察、证据和反例下钻。

### Phase 4：韧性与数据管理

- 来源退避和可替换适配器。
- 缓存与用户数据导入导出。
- 存储配额和迁移恢复。
- 故障模拟和全链路浏览器验收。
- 公共部署和运行状态检查。

## 11. 测试策略

### 11.1 单元与契约测试

- Provider 使用固定响应夹具，测试不得依赖实时第三方网站。
- 美股、港股、沪市和深市代码映射。
- 市场时区、交易日期和周线聚合。
- OHLC 校验、重复日期、部分范围和异常响应。
- Coverage Planner 在缓存完整时产生零请求，在存在缺口时只产生最小请求。
- 持仓回合、多次买卖、做空、穿越零仓位和同时间成交。
- R 缺失、指标计算、标签状态和洞察样本阈值。
- IndexedDB 迁移、配额错误和事务回滚。

### 11.2 端到端测试

- 导入真实格式成交，自动补行情，进入股票库，选择回合并查看洞察。
- 页面刷新、股票切换和日/周切换后，缓存完整的股票产生零行情请求。
- 离线重开后仍能查看缓存股票和完整回合。
- 模拟 403、429、格式错误、部分覆盖和存储失败。
- 真实行情接入后，未来 K 线、未来成交和最终盈亏仍按回放游标遮蔽。

## 12. 首期验收标准

1. XPEV、1810、600519 均能在不配置 Key 的情况下获取真实日线。
2. 三只股票的周线均由本地日线确定性聚合。
3. 完整缓存命中时，页面刷新、股票切换、回合切换和周期切换产生零行情请求。
4. 新导入成交只请求扩展出的日期缺口。
5. 外部来源失败或格式变化不会覆盖已有正确缓存。
6. 离线状态可以查看已缓存股票、持仓回合和既有洞察。
7. 同一股票跨导入批次只出现一次。
8. 分批买卖和穿越零仓位稳定生成相同回合。
9. 未确认标签不会改变正式统计。
10. 每条正式洞察都能查看样本、反例、口径、版本和排除原因。
11. 交易、笔记、标签和长期行情不离开当前浏览器。

## 13. 数据来源风险

首期无 Key 来源适合个人、非商业研究，但可能发生限流、访问拒绝、格式变化或接口下线。该风险通过 Provider 隔离、短时缓存、退避、数据校验、旧缓存保留和真实状态展示来控制，不能被完全消除。
