## 建议的代码设计方向

这是下一步要审定的候选结构，尚未冻结具体文件、函数名或存储格式。按 codebase-design 让调用方跨小 Interface 使用复杂行为，避免把期间算术和状态恢复散落到每个控件。

|候选 Module / Seam|小 Interface 应承担的合同|复用与约束|
|---|---|---|
|首页范围与提交状态|接受市场、账户、附加筛选、当前期间和历史范围动作；输出 draft、pending、完整 applied snapshot 及可恢复错误|首页固定 live；当前期间、最新持仓、历史范围独立；持仓搜索只影响持仓；贡献局部下钻不改顶部市场。不能把共享 scope 全局强制改 live 而破坏模拟盘|
|期间表现与贡献投影|输入账本、行情、FX、asOf 和明确范围；返回逐日已实现/期初期末浮盈/净额、coverage/reasons 和可对账分组|复用 Decimal、账本与历史估值；有缺失即不可计算，保留原币与完整精度。先证明开仓浮盈100→期内实现150且期末0，期间贡献应为50|
|导航与来源恢复|编码/校验目标 URL、解码目标范围、保存/恢复版本化来源快照|URL 决定交易库已应用条件，快照只负责来源恢复；直达无来源时使用明确回退；恢复后重读数据，原对象消失回来源标题|
|首页共享控件 Adapter|使现有真实调用方采用 token、尺寸、键盘、焦点、IME、动效及状态合同|先建立首页局部根与兼容调用方式；不新增无实际变化需求的通用插件框架，不批量改全站样式|

当前不预设新状态管理库、新后端大接口、行情供应商或数据库迁移。是否需要扩展缓存/worker 协议、快照放 sessionStorage 还是其他位置，由状态与导航决策票留下证据后确定。

这些是**初步纵向切片**，还不是可领取的实现票。具体派发前须把对应 [设计覆盖](DESIGN-COVERAGE.md)展开到每个操作、必需状态与真实图稿区域，完成文件所有权及三类验收记录。每片都在本片处理失败、缺失、键盘与视觉，最后一片只做跨片集成收口。

|批次|可演示的完整行为与范围|真实前置条件|接受证据|
|---|---|---|---|
|P0：证据与合同准备|审定财务算例、页面状态与 URL/快照合同；建立隔离样本、批准版本和完整控件登记|从决策 frontier 逐项推进；不是产品实现已完成|期间/贡献逐项输入输出；来源字段表；控制范围与设计引用；派发前编译/测试基线|
|P1：最小真实闭环|实盘市场/账户 → 最新持仓八行槽 → 真实持仓详情 → 普通交易库 → 返回；同时覆盖目标直达/刷新、来源恢复和对象消失回退。共享视觉与页面顺序从第一帧对齐|状态、导航、迁移接入方式明确；当前估值样本可核验；首片旅程审定|两个视口真实点击/键盘；账户市场 URL 与到达数据一致；返回恢复原范围/页/焦点；匹配状态截图。主协调者实际接受后，才扩展依赖此合同的切片|
|P2：期间阅读闭环|本周/月/年/自定义 → 四 KPI＋单日净盈亏曲线 → hover/键盘图点 → 成功/失败/缺口；当前市值与持仓不随期间变|P0 期间投影证明与 P1 相关合同接受|部分平仓/跨年/空头/费用/缺 FX 算例；曲线与 KPI 同快照；图点该日口径、边缘提示框、键盘固定/关闭、超时与旧响应反例|
|P3：查找与持仓操作闭环|全局搜索 → 详情 → 查看交易 → 返回搜索来源；筛选草稿/应用；持仓局部搜索、排序、分页、导出、详情往返|P1 导航/范围；公共控件迁移与搜索集合决定。与 P2 仅在接口冻结、写入范围不重叠时并行|IME 不提交半词；关闭保留查询与焦点；0/1/8/9/50 行、跨币种不可排序原因、CSV 为全部筛选结果、完整金额与来源恢复|
|P4：历史与贡献闭环|历史年/区间与四模式 → 当前/历史唯一贡献区 → 市场/证券下钻 → 详情/交易库 → 原位返回|P1 导航；P2 当前贡献所依赖的期间投影已接受。历史投影准备可先独立进行|年份不改变当前期间/最新持仓；当前贡献全量之和等于期间净盈亏；历史只统计已平仓；多空/打新互斥；混合正负、8 行末页、两模式状态独立记忆|
|P5：整页独立接受|完整首页及必要交易库接线的控制清单、快速连续操作、全局修复、极值、后台更新、保存/返回/重开与视觉比较|各片局部接受；版本和数据固定；未验证/失败必须保留|功能、真实状态/持久化、独立同状态视觉三个结论分别出具；完整页面覆盖分母；影响到的其他页面回归；真实服务与可点击预览仍运行|
