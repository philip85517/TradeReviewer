# 图文视觉设计文档规范 2.0

文档号：**VDF-002**。版本：**2.0**。日期：2026-10-11。状态：**本地迭代版**。维护责任：任务协调者。

本规范用于把产品视觉设计解释清楚，让不熟悉设计术语的读者能够根据画面判断焦点、密度、阅读感受和操作清晰度，同时让实现者找到精确规则。合格文档必须同时满足表达质量、规则准确和证据可追溯；文件齐全或图文没有矛盾不能单独作为完成依据。

本版基于 [VDF-001 原文快照](VDF-001-visual-documentation-v1.0.txt)和策略回测台文档质量诊断修订。VDF-001 是本次新增的归档编号，其原文标准 ID 为 VDF、版本为 1.0；快照正文未改。VDF-002 是可独立采用的完整规范，修订内容见[变更与验证记录](VDF-002-change-record.md)。本版不自动改写历史基线、项目指令或产品已确认契约。

## 1 适用范围与规则优先级

适用于整页设计、公共组件、局部状态、视觉诊断及其图文归档。纯标准修订和索引整理采用文件与内容审查；不要求为此运行产品或写数据库。

具体产品的业务行为、已确认布局与参数由对应功能规格决定。本规范只约束设计如何表达、审查和维护。新任务明确记录采用的文档号；采用本版后，文档表达方式按 VDF-002 执行，不把两个版本的展示要求叠加。用户当前指令优先，项目开发与产品验收流程继续有效。

| 工作类型 | 所需交付 |
| --- | --- |
| 整页基线或视觉重构 | 纯净整页图、范围内专题图版、适用状态过程、规则及验收映射 |
| 局部调整 | 所在整页的有效引用、局部说明图、受影响状态与规则 |
| 现状诊断 | 最新证据、问题区域、实测与推断、用户影响、修改规则和验收方法 |
| 规范或索引维护 | 来源、修订差异、引用和状态一致性检查；不虚构产品验证 |

不以图片数量、章节数量或检查项数量定义质量，不机械要求每次交付整本图册。只有确有值得选择的布局或密度差异时才增加候选。

## 2 三层内容与唯一权威

### 阅读层

`visual-design.md` 或既有 `illustrated-guide.md` 是用户评审入口：先看图，再读作用和取舍，最后查关键规则。网页图册是其派生展示。来源、版本和未决状态以短标签表达；只有影响当前判断的限制进入正文。

### 规则层

优先沿用既有 `visual-baseline.md` 或产品规格中的规则 ID 和权威参数。没有独立规则文件时，完整规则可放在图文文档的附录。主阅读区使用带 ID 的解释视图，不维护第二套冲突结论。

每条完整规则记录：ID、对象与状态、作用域、具体约束与单位、数值分类及依据、例外、验收动作与证据。**字段完整不等于必须在主页面并排展示全部字段。** 这取代 1.0 中容易被理解为每章必须铺开五列的写法。

### 证据层

`images/` 保存图版和必要原始图；`evidence/` 保存测量、录制及审查记录。图片身份、尺寸和指纹在登记表或 `image-manifest.json` 中选一个唯一权威。完整记录从规则 ID 或图 ID 可到达，不在每章重复抄写。

长期内容进入 `docs/design-system/baselines/<日期与功能>/`；实现接受归档进入 `versions/` 或既有有效位置。`.scratch` 仅保存过程记录。必要证据不能只依赖本机服务或临时路径。

## 3 阅读顺序与专题构成

**VDF2-01 首页顺序**：一句话说明用户任务和设计重心 → 纯净整页图 → 简短状态图注 → 章节导航。桌面侧边导航可同时出现。完整元数据放版本页或附录，不把字段大表放在第一张图之前。

**VDF2-02 专题顺序**：说明图 → 普通中文解释 → 精简规则 → 与本章判断有关的未决事项。解释应回答用户在做什么、先看哪里、为何使用这个比例或位置、付出什么取舍。局部图明确来自整页哪个位置。

主阅读区规则表默认三列：**对象及规则 ID / 要求与参数 / 如何判断符合**。必要来源与例外可在单元格简写并链接详情。确有比较需要可增列，但必须在目标视口确认阅读不被破坏；不能直接把验收台账当主页面。

专题按任务组织：整页 → 文字、颜色、空间 → 工作区域和控件 → 操作过程 → 阶段、窄窗和长内容 → 保存、输出及例外。可合并或省略不适用内容，说明范围即可。

“未确认设计”和“未验证实现”分别标注。共同限制集中声明；本章特有的限制留在图旁，不能为简洁隐去影响决策的重要信息。

## 4 图版必须解释设计

**VDF2-03 图版有效性**：在约定的阅读视口和默认缩放下，读者应能直接定位本章对象、辨认所讨论的细节，并把规则对应到图上。点击原图是补充查看能力，不能成为阅读主要参数的必经步骤。

一张图支持多条规则是允许的；只要对象存在就算覆盖是不允许的。无法直接辨认时，应改用局部图、样字、编号、尺寸线或状态并排。无需规定统一放大倍数，实际检查其可读性。

| 专题 | 应展示的内容 | 应判为不合格的表达 |
| --- | --- | --- |
| 整页层级 | 无文档标注的完整产品图；需要时另配区域说明图 | 只有局部，无法理解主工作面与动作位置 |
| 字体与数字 | 中文标题、正文、辅助信息的实际样字；字号/字重/行高对应；数字对齐及完整单位 | 整页缩略图下列字体表，却无法看清对应文字 |
| 颜色 | 实际背景上的色样与角色；选中、焦点、错误等适用状态并排 | 只列十六进制色值，或凭全页颜色猜语义 |
| 尺寸、间距、基线 | 邻接对象及方向，尺寸线或局部标注，说明相对哪个容器 | 只有 4/8/12 等数字，找不到它们的使用位置 |
| 图标与控件 | 图形尺寸与命中边界分别展示；适用描边、文字基线、焦点 | 小图标埋在大截图角落，无法判断视觉重量 |
| 状态与过程 | 同尺度的前态、输入、过程反馈、结果；突出改变与保留的内容 | 堆放数张近似整页图，读者靠记忆寻找变化 |
| 响应式与长内容 | 适用视口的任务顺序、重排和滚动边界；完整中文与关键价格 | 只缩小整张图，或删短内容来适配 |

**VDF2-04 图与证据分离**：原始实拍保持可恢复；允许另存裁切、拼接、标注的派生说明图，保留父图 ID、裁切范围、处理方式和可编辑源。纯净产品图不混入文档箭头。设计示意可呈现尚未实现的状态，但必须标明，不能冒充运行实拍。

重复使用整页图必须有明确作用；若同一整页图承担多个细节专题，应优先提取对应局部，而不是让用户重复浏览整页。新图不能改变关键文字、重要价格或业务事实来美化排版。

## 5 交互和业务约束

**VDF2-05 过程表达**：前态 → 用户动作及输入方式 → 过程反馈 → 完成结果 → 取消、失败与恢复。对适用的普通、悬停、焦点、选中、编辑、拖动、禁用、只读、展开、加载、空、失败及长内容状态逐项决定是否需要图示。同步操作无需虚构加载。

连续动作采用可读的编号分镜；动效有助于解释时增加可重播示意或真实录像，同时提供静态步骤与减少动态效果支持。设计动效与真实录制分别标注，静态截图不证明时长、拖动灵敏度、光标、连续播放或持久化。

图表推进应说明行情与成交截止、未来信息可见性和视野如何变化；实际验收必须看到预期 bar 或成交揭示，按钮状态变化不够。未来信息检查覆盖 Tooltip、列表、摘要、图表缩放及适用输出。

原生复盘以图表和图上批注为主工作面；S0 入场前、S1 持仓中、S2 退出后是同一工作区的阶段。保留原图形与原判断关联，区分新观察、最终结论和复盘补记。策略回测的 T0、查看日、行情/执行/结果截止沿用自身领域定义，不把 S0/S1/S2 直接套入。

使用中文暗色产品环境，沿用当前盈亏配置；计划假设与真实行情成交可区分。复盘不预设栏数或比例，不直接迁移首页 B 布局，不删减关键判断、固定评论或重要价格。候选参数在实际组件完整内容中校准，优先复用主题和组件，不默认更换技术栈。

## 6 网页展示与模板能力

**VDF2-06 参考继承**：用户指定图册时，先记录其阅读视口、章节结构、图版构成、表格表达、颜色和交互方式，再决定复用范围。复用表达方式不等于照搬其业务界面或精确产品尺寸。

本项目暗色图册默认延续参考的暗色阅读环境。采用浅色或其他载体须记录阅读理由并比较实际效果；主题本身不替代图版质量。文档文字默认正文 16px/1.8、主标题 32px/1.3、专题标题 24px/1.5、表格 14px、图注 12px；导航参考桌面 248px、较窄 210px，窄窗转顶部。它们是文档展示起点，不是产品 token 或不可变空间预算。

图片保持比例，可查看原尺寸。表格在自身容器内滚动且键盘可达，整页不能横向溢出；重要图内文字在默认阅读尺度难以辨认时拆图。保持可见焦点、明确链接名称，动效支持暂停或重播及减少动态效果。

模板应支持图注、局部说明、状态并排或分镜、简表与详情链接；若生成器无法表达这些内容，先改生成器或预制图版，不得为适配工具删除设计说明。无需为纯 Markdown 任务新建网站；Markdown 自身仍须可读且资源有效。

## 7 先校准代表章节再扩展

**VDF2-07 制作顺序**：

1. 阅读用户目标、当前产品契约、旧版标准和完整示范；登记本轮范围、参考、视口、已确认方向及允许偏离。
2. 把每条要求映射到计划展示的具体区域和状态；说明图要帮助读者回答哪个问题。映射沿用 `DESIGN-COVERAGE.md`，不复制第二份实现任务表。
3. 整册工作先制作一个基础规范专题和一个适用的交互专题；局部任务只需受影响专题。检查图片有效性、正文层次、规则可读性及与示范的差异。
4. 作者之外的审阅者直接查看渲染结果和参考。代表章节的重大问题修复后再批量扩展。普通制作与可逆修改不要求用户逐步批准；仅有实质审美选择或授权边界时向用户提出具体画面。
5. 完成整册后独立验证表达、规则、资源和展示。实现工作再按项目原流程验证功能、状态安全和视觉，不用文档接受替代。

协调者负责全册一致性和最终结论；工具作者负责派生展示正确；审阅者负责直接检查画面。分工不能把整册阅读质量留成无人负责的事项。

## 8 四项文档验收

**VDF2-08 独立判定**：以下各项分别给出 PASS、FAIL、NOT VERIFIED 或有范围理由的 NOT APPLICABLE。适用必需项存在 FAIL 或 NOT VERIFIED 时不能宣称文档整体完成；不得用平均分抵消重大问题。

| 验收项 | 必须查看或执行 | 阻断示例 |
| --- | --- | --- |
| 表达质量 | 非作者按同等阅读视口直接比较参考与本册；记录章节、画面和差异 | 字体样字看不清；命中边界没展示；状态变化难找；元数据压过主体 |
| 规则准确 | 图示、参数、来源、作用域、例外和业务状态对应 | 当前实测冒充目标；计划混为成交；示意冒充实拍 |
| 资源完整 | 本地链接、图身份、尺寸、指纹、派生一致性及有效版本 | 缺资源、旧图覆盖新状态、多个规则权威冲突 |
| 展示可用 | 有网页时在实际桌面与窄窗检查阅读、目录、原图、表格、焦点和适用动效 | 只验证 HTTP/DOM，没有直接看图；默认比例读不清；页面溢出或操作不可达 |

新网页默认以 1280×720 或指定桌面视口与参考比较，并以 390px 宽检查窄窗阅读；记录实际使用值，按布局增加必要边界。产品截图的 CSS 视口、图像像素和文档阅读视口分别记录。

审阅者应直接回答：不读详细参数能否看出本章重点？不打开原图能否辨认讨论对象？规则能否定位到具体区域？状态变化是否清楚？与参考相比有哪些未解决差距？答案须有章节和画面证据，不能仅写“图文相符”。

**VDF2-09 校验边界**：脚本 PASS 只证明其已执行断言。图片数、哈希数、链接数、无溢出、DOM 元素存在及原图逐张查看，均不能独立证明表达质量。评审必须看实际阅读页面中的比例和组织，而不只看单张原图。

纯规范修订只需内容、引用、继承关系及模板一致性检查；没有新增 UI 或产品行为时，浏览器和数据库验收不适用，必须以范围说明，而非把未测产品标为通过。

## 9 图片记录与数值分类

**VDF2-10 来源可靠性**：图片记录稳定 ID、文件、章节/规则、来源类型、生成或采集时间、作者/来源、源码或原稿版本、可编辑源与生成方式、实际像素和 SHA-256。环境记录 CSS 视口、DPR、缩放、主题、字体链与实际字体证据、浏览器/系统；场景记录固定数据、完整正文、阶段、开合、选择、焦点、编辑、滚动及图表范围和截止。

公共环境只写一次，各图记录差异。裁切、缩放、拼接、标注及父图关系明确登记；多格图版逐格标状态。未知写未知，不从图片尺寸猜 CSS 视口，不从字体加载成功推断实际中文字形。保存必要原始资源与可恢复版本。

| 数值类别 | 使用方式 |
| --- | --- |
| 已确认规则 | 引用用户决定或有效契约，约束适用实现 |
| 候选参数 | 明确待校准，不因画出就成为批准 |
| 当前实测 | 描述现状，可以是缺陷，不自动变为目标 |
| 样本数据 | 用于复现，不能写死为产品默认 |

同态候选固定数据、完整文字、阶段、视口、DPR/缩放与图表范围，单列授权变化。前后动作帧属于时序证据，不能叫同态视觉对比。颜色沿用 token 和用户设置，实际对比度说明背景及透明叠层计算条件。

## 10 版本维护与采用

**VDF2-11 编号与状态**：标准文档号采用 VDF-001、VDF-002 顺序号；正文保留版本、日期和修订依据。产品图 ID 与产品规则 ID 沿用原有体系，不因标准升级改号。历史 VDF01–15 指 1.0 条款，新条款使用 VDF2-01 至 VDF2-11，避免与文档号混淆。

每份产品文档分别记录设计状态（草案/待确认/已确认/已取代）、用户决定范围和运行验收状态。文档格式完成、视觉选择、实施授权与产品验收不是同一个结论。

新任务采用本版时在入口登记文档号。既有图册不批量重写，下一次迭代按影响范围修订；既有规则和原图可复用但须确认有效。质量回归保留原验收记录，追加失败原因和复验，按项目任务跟踪规则重开受影响事项，不能用新版规范抹去历史。

修改后更新相关章节、图、唯一元数据、派生网页和索引，登记差异及验证范围。已接受资源保留可恢复版本；不无痕覆盖。远端提交、合并或发布仍需用户授权。

## 11 开始新文档时的执行入口

使用 [VDF-002 配套模板](../templates/VDF-002-visual-design.template.md)。先填写目标和参考、安排图版，再填写规则与证据；不要先把所有字段铺满后找图装饰。

交付时给出可读入口、主要设计取舍、四项文档验收结论和真正需要用户选择的画面。UI 交付按项目要求提供刚在真实浏览器检查过的可点击预览与启动方式。纯文档规范修订提供本地文件位置和文件检查结果即可。
