## 代码审查与结论边界

实际生成差异只增加隔离缓存支持、替换prepare循环和观测；声明差异反向撤销后与产品公式源逐字一致。全部performance消费者在candidate进程统一路由至同一模块，原position-ledger仍持有自己的WeakMap。ordinaryState与holding facts实际消费复用的canonical；命中后并未调用替换段内的normalize、canonical准备和ordinary费用准备，计数不混入旧值。全库收集、来源资格、费用归集、行情/汇率、索引、页面行和合计每次继续执行。

缓存键保留完整Group及冲突集合内容、模拟身份、规则/代码版本；不缓存全局资格。未证明的外部依赖全部保守纳入键，fallback和冲突组不入缓存；容量只是估算，不能宣称实际堆上限。

**这里还没有可保存到数据库的分组结果。** opaque canonical handle只在同一进程的私有WeakMap内可用，不能JSON保存后恢复；页面行对象仍重新计算。精确Date.now及全局行情/汇率等guard使不同真实请求通常miss，所以固定时点的34对相等不证明实际命中率或性能。分支覆盖率95%工具不可用，明确NOT VERIFIED。后台任务、持久结果、重启、真实库对账和完整首页/交易库≤1秒均未验证，原FAIL保留。
