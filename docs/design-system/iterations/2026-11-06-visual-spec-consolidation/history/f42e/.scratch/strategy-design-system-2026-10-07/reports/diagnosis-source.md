## D01 — 同一上栏的点击外框并未真正统一

- **位置与画面：** 真实复盘页上方搜索、周期、行情数据、图层、设置；`screenshots/current-native-review-1440.jpg`，约 x461–762、y68–104。
- **源码：** `app/globals.css:903–913` 定义 `.icon-button` 为31×31；`app/globals.css:941–950` 定义周期按钮31px最小宽、27px高；`app/components/recall/recall.css:239–263` 调整绘图按钮与图表头部；`:488–492` 定义36px控制高度。`chart-toolbar.tsx:112/147/160/195` 分别使用17/14/17/17px SVG。
- **实测现象：** 外框高度均被复盘规则统一为36px，但搜索、图层、设置宽度仍31px；行情详情只有26px宽。右侧导航/统计为36×36，左侧绘图为36×36。同类独立图标按钮的点击外框不是正方形，宽度相差最高10px（26对36）。
- **用户影响：** 看似同等重要的工具拥有不同可点击范围；密集小图标比右侧按钮更难点中，也形成上栏与绘图区视觉重量差异。不能将其说成手机点击已失败；本轮只有桌面证据。
- **原因判断：** 有实证的 CSS 分工问题：后续规则只统一高度，保留通用组件宽度；“本地数据”通过 `font-size:0` 压缩成图标，外框没有同步归入图标按钮角色。
- **具体规则：** 推荐样板先将此栏独立图标控件校准为36×36px；SVG候选18px、stroke2，并在真实图中检查。信息状态图标允许14px，但其按钮外框仍遵循36px。触控模式目标44×44px，不靠放大图标代替扩大按钮。文字周期可保持内容宽，但最小宽36px。
- **验收：** 同视口测量每个可见外框，width/height均达到所属角色；截图检查中心线；鼠标与键盘逐一激活并检查焦点环是否被容器裁切。触控验收单独记录，不能从桌面DOM推断。

## D02 — 中文文字的用途层级与控件外框比例不一致

- **位置与画面：** 真实复盘头部阶段、回合、导出，计划侧栏标题/标签；策略模式栏和回放栏。两张当前 JPG。
- **源码：** `recall.css:516–528` 标题18与辅助12；`:549–552` 阶段12；`:567–571` 选择器14；`:645–659` 回放13；`:346–352` 计划标题/标签/输入。静态 `workbench-design/index.html:59–77/109/148/293–297` 具有17、16、14、13、12等局部值。
- **实测现象：** 真实阶段12px、回放13px、导出14px在相同36px高控件内共存，高度/字号比分别3.00、2.77、2.57。H1 18/400、H2 16/400与标签14/400字重相同，阶段字比侧栏普通标签更小。策略 body13/normal，而真实正文14/21；两个画面的正文行高机制不同。
- **用户影响：** 当前阶段是复盘的核心上下文，却不如普通表单文字醒目；主要动作和普通动作更多依赖边框、颜色判断。中文连续阅读缺乏稳定节奏，容易把“控件高但字小”感受为比例不协调。
- **原因判断：** 事实是各页面按局部选择器设字号，没有共享文字角色。对层级感的影响为基于当前画面的设计判断；不能仅凭字号数量认定所有差异都应消除。
- **具体规则：** 推荐样板候选：工作区标题18/24、600；分区标题16/24、600；中文正文14/22、400；中文控件13/20、500；当前阶段13/20、600；辅助说明12/18、400。价格/数量使用独立数字角色与 tabular-nums，避免中文说明整段使用等宽字体。候选必须在现有组件中校准，不能只建 token 后宣称完成。
- **验收：** 相同角色在工具栏、计划和回放区 computed 一致；完整多行中文在1440×900与1280×800中读得清楚，标点和英文/数字基线自然；较窄窗口允许换行、滚动或明确展开，不缩小关键判断文字、不删除原文。

## D03 — 中文回退与图表字体没有可验证的一致契约

- **位置与画面：** 中文标题、正文、数字、图表坐标和读数；两张 JPG。截图只能观察视觉差异，不能识别实际字体文件。
- **源码：** `app/layout.tsx:2–14` 使用 next/font 的 Geist/Geist Mono，仅Latin；`app/globals.css:44–47` 的 `var(--font-geist-sans)` 后加中文回退。静态 `workbench-design/index.html:8–9/30` 本地Latin字库与另一套系统栈；`replay-chart.tsx:1015–1019` 未显式设置 Lightweight Charts 的字体。
- **实测现象：** 最新 computed 栈确实不同；真实页面包含位于显式中文字体前的 `sans-serif`，策略包含多个系统/generic项。没有实际字形/字体网络证据。真实canvas CSS为14/21，但不能据此得到坐标字体。
- **用户影响：** 不同环境可能出现中文字重、标点、数字宽度与行高差异；图表和外部工具栏未明确共享字体角色。具体差异程度仍未验证。
- **原因判断：** 字体链有代码事实；“某中文字实际用了PingFang”或“字体没加载造成模糊”均没有证据，不能写为结论。
- **具体规则：** 规范分别定义 Latin、中文系统回退、数字、图表文字的字体链及字号；generic放在有意选择的具体回退之后。复用现有Geist，暂不新增中文Webfont。Chart `layout` 明确fontFamily/fontSize，并与图表读数校准。
- **验收：** 浏览器检查字体资源加载/错误，并使用渲染字体能力检查代表性汉字、数字和英文；没有该能力时标 NOT VERIFIED。使用相同中文测试串检查换行。读取图表API实际options或绘制参数，不使用canvas CSS冒充刻度实测。

## D04 — 策略“播放”普通字号白字对比度实际不足

- **位置与画面：** 策略图下“播放”，`screenshots/current-strategy-1440.jpg`，x842、y823、44×36px。
- **源码：** 静态 `workbench-design/index.html:21/109–111`：蓝 `#2f80ed`，primary白字；对应真实项目通用 `globals.css:1875–1879` 也有该配对，但不能据此认定当前真实复盘primary同样失败。
- **实测现象：** 策略metrics的 `icon-btn primary` 确认fg `rgb(255,255,255)`、bg `rgb(47,128,237)`、13px/400。对比度按sRGB相对亮度计算为 **3.866:1**，低于普通文本4.5:1。真实复盘“下一笔决策/留存当前快照”则是浅蓝字、透明蓝底，**并非此白字蓝底配对**。
- **用户影响：** 主要播放动作的字在发光蓝底上显得细且不稳定；弱视或较低质量屏幕更难识别。
- **原因判断：** 确定的配色问题，不是整个暗色主题都应提亮。当前真实输入正文对比14.789:1、次按钮正文8.895:1、绘图图标5.416:1（依据各自实际或透明底祖先颜色计算），无需统一提高所有文字亮度。
- **具体规则：** 保留蓝色动作语义，给实心primary使用达到白字4.5:1的专用背景；hover、active也逐一核准。选中tab继续用淡蓝底加明确边界/下划线，不全部变成primary。盈亏仍沿用既有绿/红与图表配置。
- **验收：** 从最终样板computed读取前景和实际合成背景，对normal/hover/pressed/focus分别计算。不能将disabled低对比当成普通可用控件失败；本次metrics未记录opacity，disabled最终显示对比未验证。
