# 隔离验收输入与真实控件操作

全部为人工合成，不来自业务库。准备文件不是页面通过证据。只能在 root 拥有的显式隔离 DB/service 运行。不要在浏览器验收中用 API 直接改变页面状态替代以下控件。

## 最小桌面旅程（root 已执行局部 PASS）

`unrelated-E0.json` 经正式 prepare/commit 预置无关成交；保留原币长小数、仅日期、`feeStatus: unknown`。费用文本 `0` 不表示已知零费用。root 已执行后，再从交易库“数据”菜单导入 `synthetic-futu.xlsx`（3 笔/2 标的）→实际预览→确认→返回交易库→reload。证据在上级 `browser-candidate-1-*`。E0 原列原值应不变。该最小记录不等于最终整页/视觉通过。

## 月结真实 PDF 闭环（最终浏览器 NOT VERIFIED）

`generate-monthly.py` 生成四个标有 SYNTHETIC QA ONLY 的 PDF；`monthly-inputs.json` 保存预期，不作页面 mock。四份都已用 pdfjs 真解析；页图 `monthly-0*-render.png` 已检查可读。

1. 导入 `monthly-01-complete.pdf`，经过现有月结摘要/分类步骤，在最终确认框核对 2026-01、合成账户 99991007、AAPL 买入2@10 和卖出1@11。默认“来源材料处理”＝“作为独立材料保存”；确认并返回/reload。若性质为未知，交易库“交易性质”选择“未知”或“全部”，不可误当集合为空。
2. 导入 `monthly-02-missing.pdf`（仅买入）。保持默认时应为独立材料，不得自动把同月同账户当换版。显式在“来源材料处理”选择步骤1的材料（文件/账户/月/指纹摘要）；页面说明“将此文件作为所选材料的新版本”。等待新服务器计划，逐项处理缺行；“保留已存成交”分支另作一次独立隔离旅程。“撤回成交并保留审计”需填写“撤回理由 1”，保存→返回/reload应只剩买入当前事实，来源旧版本/观察/审计保留。尚未选择或缺理由时不能确认。
3. **恢复必须重新上传原始 `monthly-01-complete.pdf`，不是03文件。** 显式选择同一原材料，计划显示“已撤回成交再次出现”；分别验证保持撤回与“恢复为当前成交”＋“恢复理由”。保存/reload后恢复原成交身份；同材料的原 fingerprint 复用自己的历史展示批次，旧 projection 原副本不变。
4. 再上传原始01，**保持默认独立材料**。核对“此文件已有导入记录”及展示批次仅作参考说明。按服务端实际重复/冲突项处理。确认后多一个独立材料/版本/观察，不借用原材料 batch 所有权，不覆写原来源。旧兼容 importHistory 展示批次数可能不增加，正式材料历史必须增加。
5. 上传 `monthly-04-conflict.pdf`，显式选择步骤4的独立材料作为新版本。买入同 order/time 价格变为12，按服务器允许项逐项选择；“使用本次候选”需“替换理由”。其他缺行也必须逐项处理。返回/reload核对 receipt 版本、两个材料的完整历史、原材料旧观察精确不变。冲突选择白名单以实际计划为准，同ID异值不得提供危险的两者保留。

`monthly-03-restore.pdf` 含相同两笔但带不同免责声明，因此有真实不同 fingerprint；可验证“不同文件内容版本”，不能冒充同文件恢复。不得为测试改指纹或伪造 raw/locator。

## 修订、补录与补充

在已导入 AAPL 的交易库/Recall 当前股票点击“检查/修复数据”（对话框可访问名称“检查与修复当前股票数据”）。若有未来信息警告，点“查看完整数据并暂停复盘”。选择明确“当前账户”，依次验证：编辑成交→保留长小数/仅日期与费用未知→填写修订原因→预览修改→服务器全范围变更→确认保存修订→返回/reload；移除此记录同样需理由；“补录成交”选择同账户并填合法数量>0/价格>=0。取消修改保留旧持久化。

“为本股补充文件”可上传原 synthetic-futu.xlsx，页面必须展示仅当前股票/账户范围及排除数量；截图补充须走实际截图识别控件，合成内容可按上述 AAPL 行手工制作截图，不能以 props mock 算浏览器通过。截图受外部识别运行环境影响，目前无单独固定 OCR 截图闭环通过记录。已有确定性截图组件/正式协议测试不替代此项。

## 名称与 Home

名称保存是既有行情查询得到新名称后的自动窄写，产品无新增自由名称编辑器。通过现有“更新当前股票行情”触发；真实上游必须返回与已存不同名称，才可实际验证成功/失败文案。HTTP/SQLite 测试使用人工名称差异并证明仅 name 改动、版本不增；无真实确定性市场响应 fixture 时浏览器该项仍 NOT VERIFIED，不可伪称已点即通过。

从首页/交易库返回与 reload，确认当前 active 集合（含性质未知/账户未知合法事实）未因金融资格或展示编码清空；撤回项不通过 bootstrap 复活。长小数/未知费用/仅日期独立核对。财务、Bars 与完整首屏1秒不在本票恢复范围。
