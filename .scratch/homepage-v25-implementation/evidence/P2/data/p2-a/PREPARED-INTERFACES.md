# Frozen P2-A additive interfaces; not accepted

2026-10-23. Product hashes and verification are in `FREEZE-REPORT.md` and `freeze-manifest.json`. Multi-market performance remains FAIL; no UI/series consumer should treat this freeze as an accepted API handoff.

## Source capture and projection

`prepareHomepageV25Source(input: HomepageV25PrepareInput): HomepageV25PreparedSource` captures a private structured clone of real entries, raw candles, scope/metadata, historical FX observations, independent current FX evidence, lifetime source coverage and four caller revisions. It hashes actual captured content plus explicit finance/fee/calendar/coverage/FX/quote-knowledge policies. Same caller revision with different content gets a different sourceId. Missing real-entry nature is excluded from default live scope. A simulation scope requires simulationRunId.

The handle is opaque and frozen, owns private canonical/index/cache data through WeakMaps, and exposes only sourceId/revisions. The public prepared input requires arrays `fxObservations`/`lifetimeSourceCoverage` and explicit `currentFxSnapshot` (nullable); there is no database/provider lookup or implicit latest retrieval. Quote knowledge policy is explicitly `retrospective-completed-session`: completion is exchange-calendar based, not a claim to possess a historical provider revision archive.

`projectHomepageV25Boundaries(source, {periodStart, asOf, endpoints: [{key,at}], targetCurrency?})` validates the whole request. `asOf` requires an explicit ISO instant; periodStart is a valid Shanghai day; keys are nonempty/unique; endpoints parse as a valid day or ISO instant and may not precede selected start. `HomepageV25ProjectionInputError.code` distinguishes invalid source/asOf/start/key/endpoint. Output follows input order. Day endpoints use the accepted Shanghai natural-day contract; an endpoint on current day is capped to actual asOf, later endpoints are future/null with no historical replay.

Every point has eleven metrics: periodRealized, openingUnrealized, closingUnrealized, unrealizedChange, net, lifetimeRealizedNet, lifetimeNet, marketValue, unrealizedNet, openFees, periodFees. Tooltip order is **marketValue, unrealizedNet, lifetimeRealizedNet, lifetimeNet, net, periodFees**. Amounts use existing F metric shape: value/available/coverage/reasons and money.originalByCurrency/targetCurrency/conversion/fx. Period differences occur in original currency before one endpoint conversion. Lifetime requires one matching complete/inception/through/knownAt/evidence coverage record; otherwise it is unknown without replacing it with selected-period values.

Per-instrument rows preserve identity(account/instrument/nature/run), opening and endpoint canonical/F evidence, independent quote coverages, FX coverage, referenced feeFactIds, lifetime coverage and a separately named **canonicalKnownFees** diagnostic. It is the cumulative fee amount recognized by canonical at that cursor, never actual incurred periodFees. Point state/plottable/reasons reflect dependencies, with foreign native subtotals retained even when target currency cannot be formed.

`current` is projected independently once at actual asOf and cached without selected range in its key. It exposes aggregate and per-instrument currentMarketValue/currentUnrealized/currentOpenFees plus evidence.current, quoteCoverage and fxCoverage. Its finance values use original F3 `quoteFor` directly. P2 strict historical gaps do not change current fallback. There is no periodSummary or UI series adapter in P2-A; later P2-B must use the matching effective endpoint's three period metrics and dependency gates without reimplementing finance.

## Coverage and clocks

QuoteCoverage states: complete, market-closed-carry, session-in-progress-carry, missing-completed-session, quote-missing, quote-invalid, unsupported-market, calendar-unavailable. Selection uses accepted exchange completion/session validity. In P2 history only, a missing required completed session makes dependent nonflat MV/UF/net unknown and keeps fallback quote evidence/missingSessions. Known flat inventory needs no quote. Realized/actual fees and other instruments' native evidence remain independently usable.

HistoricalFxObservation preserves id/source/sourceRevision/businessDate/rates/status, publishedAtByPair, knownAtByPair, fetchedAt and evidenceIds. Same-day, complete, positive production pair rates with all actual knowledge clocks≤endpoint are required. Conflicting observation IDs are unknown in both orders. No latest historical fill or inferred FX holiday carry exists. CurrentFxEvidence separately preserves the actual RoomFxSnapshot id/source/asOf/status, actual fetchedAt, per-pair publication, source revision and evidenceIds. Valid current latest may predate current day; it does not backfill historical rows.

Fee facts retain incurred `{businessDate,at,precision}`, knowledge `{amountKnownAt,attributionKnownAt,availableAt,evidenceIds}`, execution/event/source-row lineage, amount/currency/scope and complete/unknown reasons. Public batch feeFacts are bounded by batch asOf; each historical periodFees selection uses that endpoint's own knowledge. A later refund can resolve canonical cost without changing when an actual fee occurred. Date/attribution/lineage ambiguity is unknown. Exact monthly or coarse-day facts never enter the ordinary numeric prefix shortcut.

## One canonical seam and cache diagnostics

`preparePositionLedger(input)` and `replayPreparedPositionBoundaries(handle, queries)` are additive in the same canonical file. The legacy replay wrapper and prepared path call one evaluator/finalizer. Prepared exposes mode, traversal/storage counters and immutable serialized before/after quantity facts. Private full-precision cost/checkpoints are never public. Only evidence-free unique-ID/unique-time original source uses one sweep; attached/future carrier evidence, ties, duplicate IDs or nonprefix contexts fall back to exact evaluation. Explicit selected IDs beyond cursor retain legacy semantics.

F ordinary checkpoints project the existing fee pool from those canonical quantity facts, not another average-cost calculation. The ordinary actual incurred-fee prefix has separate actual-day and knowledge cutoffs; nonordinary facts retain exact selection. All result/evidence graphs are deep frozen; input mutations do not affect captured sources.

Memo is true access-promoted LRU, at most8192 entries, at most4 retained full batches and estimated64MiB for all results/context caches together. Counts include object identity/refcounts, array capacity and bookkeeping; source/index are separately counted and do not hold hidden query results. `batch.diagnostics` is the immutable build-completion snapshot **before full-result admission**; it is not updated on repeat. Use `inspectHomepageV25PreparedSource(handle)` for actual later cache hits/admission/evictions/counts/bytes/source/index. Oversized public graphs are returned but not retained; the current multi-market MISS shows they may also evict other cache entries. This limitation is part of the pending architecture decision, not hidden behind a stale diagnostic.

No public fields are removed to meet performance. The64MiB value is a conservative retained estimate, not a total JS heap cap. Actual heap and serialization are reported separately. A single prepared ordinary source supports many endpoints without365 legacy builders; attached evidence retains exact-context complexity. Do not implement UI per-day full-builder loops, historical latest-FX fabrication, or P4 lot/category allocation on this API.
