## 公共样式与组件接入

1. 把获选的紧凑规则放到工作区公共样式，以已有 `compactControls` 对应的显式作用域应用。样板与正式入口使用同一契约。不要整体复制样板 CSS 级联，也不要用通配选择器覆盖所有字重、字号和数值。
2. 保留 `headerActions` 槽位。正式页面的数据、股票、返回、检查/修复和专注图表等动作不能被样板的两个链接替代。高频动作常驻，低频动作可进入已有菜单结构；必要返回与保存保护可达。具体密度以正式内容校准。
3. 主题变量继续表达颜色语义；只为确有公共用途的文字角色、命中尺寸、间距、状态新增最少变量。Text、菜单、输入、边缘开关和回放组共用状态规则，图表轴/Canvas 必须单独检查量字和像素结果。
4. Text 卡片、编辑器、锚点和连接线的呈现来自同一布局/市场坐标映射。持久化保留旧对象宽度、字号、比例和 provenance。编辑器的现有最小宽度 220px 与新建卡片的现有 180px 是两种职责，不应强行用一个全局宽度覆盖。
5. 所有工具最终有效确认后，清创建预览、一次历史、activeTool切`cursor`且新对象selected；绘图ICON恢复普通态，箭头ICON选中。当前 `recall-workspace.tsx` 创建命令接缝约1771行仅对Text显式回cursor，未来核对全部工具，不据源码宣称运行已失败或已修复。首点、通道基线、Text框位置不误当最终完成；取消/非法输入/切工具/undo/redo依CB18–22；非空Text草稿先保留编辑缓冲并处理完成/继续/明确放弃，不把取消几何的路径直接用来清正文。把绘图预览、确认、历史与保存的边界继续放在现有绘图命令链中。没有领域需求时不增加 API 或数据库字段；确需字段时先提交兼容迁移与 ADR，再实现。
6. 计划虚线与图外名称/数值统一接到工作图与导出路径。现有 `replay-chart.tsx` 约1600行planPriceLines和约1742行导出snapshot重复使用金色计划标签；两路径一起收敛到CB08/14/27，不能只修实时图。若图表库title进入绘图区，隐藏图内title并用现有DOM/Canvas坐标层实现图外注释；完整名称与价格精度共同量字分配轴区，不更换图表库。保留真实价格、近价引线、同价来源、盈亏设置与既有RR区域；live/export共用格式规则。
7. 正式入口复用首页回合回调、应用壳、headerActions及返回保护；不新增业务路由。instrumentId/episodeId、账户、模拟run与来源队列贯穿工作区，返回合法首页范围/检索/分页；应用壳计入整体视觉预算，见[入口兼容规范](entry-compatibility.md)。
8. 净化仅针对产品外壳和新的展示 fixture；不修改已保存正文、归档截图或业务草稿语义。开发入口的合成来源可以在比较画面之外的验证元数据中明确声明，不能让合成数据冒充真实交易。

## 后续切片与职责

以下是依赖明确的拟实施范围，当前均未领取。root 负责整页视觉一致性和完整持久化流；Luna 是获准执行后默认的有界实现模型，独立复核者不得复核自己实现的 UI。

| 顺序 | 切片 | owner 与边界 | 可独立评审的输出 |
| --- | --- | --- | --- |
| T0 | 验收入口、纯净比较状态与密度确认 | root；只做决策/规范 | 用户选择记录、状态 manifest、获选截图与例外 |
| T1 | 首条真实图表旅程 | root 统筹；单一受控实现 owner | 隔离库真实回合 → 下一根/下一笔 → 锚定 Text → 保存 → 返回/重开/刷新；图上事实和双截止一致 |
| T2 | 公共紧凑外壳 | Luna；仅公共布局、受控入口及必要样板适配 | 同一规则进入正式页面；左右开关贴边、底部图标居中、完整父级动作及来源返回可达，应用壳预算与NAV01–04兼容 |
| T3 | 绘图与 Text 差异收敛 | Luna；仅实际缺口，不重写已经满足的行为 | 全部工具最终确认自动cursor+新对象selected；首点/Text编辑/通道边界及取消/非法输入/历史符合CB15–22，完成后立即反复拖动；保持 T1 状态协议 |

| T5 | 独立整体验收 | 非实现者直接浏览器检查，root 复核证据 | 功能、状态/数据、视觉分别通过，缺陷复验，运行预览链接 |

T1 未接受前，不扩大依赖回放/保存状态的切片。T2–T4 是否可并行由文件所有权和状态接缝决定，不为追求并发拆开同一公共样式或交互 reducer。每次派发前必须把真实缺口、反例和精确参考写入 DESIGN-COVERAGE；历史报告不能代替重读当前代码。

T1还需覆盖只读复核发现的K01完整历史换周期、K02决策工作图viewport丢失风险。二者是未来实际行为复现/排除项，本轮没有浏览器重现或修复；细节见来源记录与本地风险票。既有状态模型能表达目标，部分代码路径仍可能漏接，不能通过缩小验收范围避开。

## 校准方法

- 先在 1440×900 与 1280×800 固定数据/阶段/图表范围比较，再查 1280×720 低高度和断点两侧；同时测完整容器、导航、工具区、主图、轴、计划栏、底部组。
- 顶部 48px 起、样板 48–56px 单行是候选紧凑预算；不是为容纳所有错误、知识边界或手机状态而设的绝对上限。正式入口不能再次新增无任务收益的 58px 说明行。
- 左导航、侧栏宽度、轴标签预留及底部间距依现有候选与完整中文内容校准。方案只提供一个推荐密度，只有实测存在值得选择的差异才另给候选；对照固定所有状态和数据。
- 不以删除文字、隐藏价格、改变图表范围或把字号统一变小取得截图更“紧凑”。

## 数据与发布边界

遵循 `conf/runtime.json` 的共享数据库与端口配置。当前项目默认业务库是该配置中的绝对路径、默认端口 3022；本轮已有 3046 样板服务使用显式隔离库。未来所有写入验收必须显式设置 `TRADEREVIEW_DB_PATH` 指向独立验收库，记录路径及版本；不能创建 worktree-local 的新业务库作为隐式替代。

获选并验收后，可固化范围为公共主题角色、复盘紧凑样式、控件状态、绘图反馈、样板共用契约，以及项目指令中指向本基线的链接。首页和无关模块不自动套用。本轮不更新 AGENTS、不提交、不推送、不发布，也不把计划文件当作执行授权。
