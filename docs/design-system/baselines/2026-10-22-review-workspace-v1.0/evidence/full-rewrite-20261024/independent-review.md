# 独立审查报告：复盘页视觉规范 V1.0 候选

审查范围：`visual-design.candidate.md`（613 行）、12 个 issue 的精确验收标准、`PLAN.md` / `DESIGN-COVERAGE.md`、原 UI 规格、元素规范与 `CONTEXT.md`。本报告只审文档设计包；不把候选规则未获用户确认或业务 UI 未实现本身判为阻塞。

结论：候选稿的总分结构、M/X/D、入场前置与退出后置、同 K 稳定序号、未来信息约束、独立加仓与最近优先配对、冻结 R/毛净费用/MAE/MFE/回撤、评分缺失状态、保存/完成/导出、断点算式和四条评论的迁移意图均有正文覆盖。仍有以下显著缺口，导致“12 项设计任务已完整覆盖/可独立验收”的声明不能成立；候选稿可继续作为候选发布，但应在下一轮定稿或验收记录中补齐。

## Findings

### F1 · 阻塞：旧评论迁移索引缺失，阅读器无法验证评论保留边界

- 证据：候选稿 601–607 行声称保留四条原评论及迁移关系；`evidence/full-rewrite-20261024/scan-and-rewrite.md` 第 49 行明确说映射记录在基线根目录 `comment-migration.json`。但 `docs/design-system/baselines/2026-10-22-review-workspace-v1.0/comment-migration.json` 当前不存在；`review-client.js` 第 34 行会请求该文件，失败时静默使用空 `entries`。
- 反例：阅读器加载正文时，原评论 ID（43d411、008a57、a0b107、2afceb）没有可执行的旧锚点→新章节映射，无法区分“已迁移但 pending-review”和“未迁移/已解决”；这直接违背 issue 11/12 要求的评论锚点、状态与保留边界可验证。
- 最小修订：补齐根目录 `comment-migration.json`，逐条写入四个完整评论 ID、原文/快照指针、旧图引用、新章节或 stable-id、当前状态（至少 `pending-review`）和“不得视为用户确认解决”的说明；在 `acceptance.md` 记录文件存在性与四条逐项读取结果。

### F2 · 显著缺口：TV 13 个绘图槽仍只有通用生命周期，未达到 issue 05 的逐工具合同

- 证据：候选稿 115–128 行逐槽列身份与缺证，300–304 行只给一套所有图形共用的创建/编辑/删除/撤销/重开规则；152 行的 G03 又要求“13 项真实生命周期分别成立”。RV10 第 559 行将该项列为“同条件外观与真实创建/编辑/撤销/重开分验”，但正文没有每个 D01–D13 的创建手势、锚点、属性、取消/删除、撤销重做、重开归属表。
- 反例：D05 矩形、D10 旋转矩形、D11/D12 未知工具都可能有不同点数、手柄和取消语义；套用 301–304 行的“适用的锚点”无法判定其设计合同，也无法核对 issue 05 的逐工具验收。
- 最小修订：增加 D01–D13（以及 H00，如纳入工具合同）逐行合同；未知项保留 `NOT VERIFIED`，但每项至少列“已知/未知、禁止推断、后续证据、保存归属”。不要把静态对照或通用规则记为逐工具通过。

### F3 · 显著缺口：跨批次 Text/形态标注归属仍是二选一可能性，没有可执行默认规则

- 证据：320 行写明节点判断“可以由同一条记录共享给多个相关批次，也可以明确只归属于一个批次”，由用户选择；322 行只要求保存引用关系。issue 06 的验收标准要求 Text、形态标注、锚点、历史快照及跨批次共享/独立归属“清楚”，issue 01 也要求各对象的记录/评分/完成归属明确。
- 反例：一条在加仓前 K 线上创建、随后覆盖两个批次的 Text，若没有明确的默认归属/共享动作、撤销共享、编辑影响范围和导出/评分引用规则，重开或修改该 Text 仍可能串改两个独立交易；“用户选择”不足以保证状态安全。
- 最小修订：在 RV06 增加归属决策表：默认是单批次还是回合共享、显式共享/解除共享入口、共享文本编辑是否生成新版本、批次删除/完成时如何处理引用、M/X/D 与导出/评分如何引用；将该规则标候选并明确待用户决议。

### F4 · 显著缺口：响应状态没有按 issue 10 要求完整登记 active/selected/expanded 等状态

- 证据：issue 10 明确要求登记 `default, hover, active, selected, disabled, expanded, loading, empty, error, saving, conflict, end, longtext, missing`。候选稿 RV08 447–483 行覆盖布局临界值和 loading、empty/missing、invalid、end、saving/conflict、longtext，但没有按控件/区域给出 active、selected、expanded 的可观察表现、焦点/键盘行为和数据承诺；RV03 151 行只把 hover/selected/disabled 留给未来 G02 外观证据。
- 反例：右侧栏“自动展开/手动固定”、工具选中、回放 active/paused、列表选中与菜单 expanded 都是本设计的核心状态；仅写“展开”或“选中不表示正确”不能验收它们的视觉、焦点与是否推进 M/X/D。
- 最小修订：在 RV08 增加逐区域状态矩阵（左列表、工具、右栏、回放、保存/导出），至少为上述 14 个状态列出视觉、可操作性、M/X/D 是否变化、草稿/保存影响；将真实设备/产品验证仍标 `NOT VERIFIED`，但设计合同本身要完整。

### F5 · 显著缺口：独立交易/批次完成规则与 CONTEXT 旧完成规则的差异没有形成明确冲突表

- 证据：RV04 161–183 行把批次聚合、反手、费用分摊和“独立交易全部退出是否才可标记完成”列为候选；RV09 496 行仅重申旧规则（回合清仓、每个交易决策至少一份快照、回合统一确认）。RV10 第 555 行也只写“单笔完成仍待决议”。issue 01 验收明确要求列出与 `CONTEXT.md` 及旧完成规则的冲突；本稿没有逐项写出旧规则、候选变化、受影响状态和决议后的兼容方式。
- 反例：买 100、加 60、卖 80 后，第二个独立交易已清零而第一个余 80；“独立交易完成语境”与“回合完成/决策快照完成”分别是什么，当前只能从多处文字推断，列表状态、导出和关闭门槛无法直接验收。
- 最小修订：在 RV04 或 RV10 增加差异表，至少列回合/决策/独立交易/批次/退出片段的完成条件、允许的列表状态、快照要求、导出可见性，以及与 CONTEXT `已完成复盘` 的冲突/继承关系；每项标 `confirmed/candidate/pending`。

## 未发现的主要问题

候选稿已明确区分候选规则与已确认方向，未将静态 SVG、DOM 状态或原型点击冒充真实回放/持久化证据。M/X 分离、入场前不揭示成交、退出事实后暂停、同 K 稳定序号、回看保留“已看后续”来源、未知不填零、净费用缺失为 null、MAE 与峰值回撤分开、四种评分缺失状态、保存/快照/单笔评价/回合完成/导出分离，以及 1292/1108/1028/844 的宽度算式均有对应正文或算例。上述结论不替代用户对候选规则的决议，也不替代后续浏览器/真实图表/数据库验收。

- **F2（逐工具生命周期）：已解决为设计覆盖。** RV06 已列出 D01–D13/H00 的创建、编辑、取消/删除/撤销/保存/重开边界，并明确每一行 TradingView 实际操作为 `NOT VERIFIED`。D06、D11、D12 等身份未核实工具被明确禁止伪造创建，符合候选设计的证据边界。
- **F3（跨批次 Text/形状归属）：已解决为明确候选默认。** RV06 规定默认当前单批次/节点归属，显式共享、共享编辑、单批次副本、解除共享、快照/评分/导出的版本边界；未把后见信息自动共享或自动重算。

- **F5（旧完成规则差异）：已解决。** RV04 新增差异表，明确回合正式完成仍继承 CONTEXT 规则，独立交易/批次/退出片段仅作为候选导航和计算层，不替代正式完成状态。

RV09 也已补充 Markdown+图片保留，以及 PPTX 离线/可编辑边界；明确 PPTX 文字/表格可编辑、K 线为高分辨率图片，实际生成仍属后续实现。

### 残余边界（不构成新增阻塞）
