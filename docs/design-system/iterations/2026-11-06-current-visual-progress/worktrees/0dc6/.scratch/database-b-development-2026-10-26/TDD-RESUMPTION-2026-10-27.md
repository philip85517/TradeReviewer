# 数据库 B 已暂停问题：有界 TDD 恢复计划

目标：以少量可观察案例修复导入来源校验和测试存储防护，并独立验收桌面导入旅程。用户于本轮明确要求恢复修复，并确认以下三个测试边界；原共同候选 5/5 与此前所有失败、未执行和暂停记录保持不变。

## 边界与计数

1. 成交导入公开接口：正常来源，缺失或不匹配的来源/成交关联，缺失字段的输入错误，以及拒绝后无写入。
2. 浏览器存储测试防护的公开操作：保留合法 UI 设置；禁止读取或枚举旧业务数据键。该项是测试保护问题，不预设生产数据泄漏。
3. 桌面端用户旅程：上传、审核、确认、交易库读取、返回与重新加载；失败或取消时状态不丢失。真实写入只使用显式隔离数据库。

财务 P1/F07 和 Bars 保持暂停；不改原始业务库、不推送、不合并。修复尝试为新授权的有界计数，各问题最多 5 轮；累计历史 5/5 不抹除、不冒充未发生。若同一新问题重复失败超过限制，停止并记录。TDD 红绿循环是案例开发步骤，不自动等于独立候选验收轮次。

## 任务及验收

- [ ] A：导入公开入口。复核现有静态根因；一个反例先观察到预期失败，再做最小修复并复测；逐项覆盖关联缺失、未知关联、必填字段、正常输入以及失败无写入。主要文件：`app/lib/storage/tradingview-import-compatibility.internal.ts`、`app/lib/storage/sqlite-store.ts` 及相关公开接口测试；以实际调用链确定边界，避免重写既有财务规则。独立 Luna 审查，协调者复验。
- [ ] B：存储测试防护。原 `app/lib/storage/storage-boundary.test.tsx` 的防护不允许无条件暴露旧键名，保留真实 Storage 实例及旧键反例；先观察公开操作的失败，再以最小修改实现通过，验证偏好键仍可用。独立 Luna 审查，协调者复验。
- [ ] C：桌面上传和持久化。依赖 A、B；先诊断旧测试替身与新审核协议不一致，再通过当前公开旅程验证，不以旧 merge 调用次数替代结果。关联批准规格、控件登记及实际桌面浏览器：上传→审核→确认→交易库→返回和 reload；隔离库完整读回与错误/取消状态分开记录。由未实施者进行视觉对照与独立验收。
- [ ] D：集成验证：核验必要回归、类型检查与项目检查；逐项记录结果及版本。统计本次相关修改模块的实际分支覆盖率，目标 ≥95%；公开分母和不可覆盖原因，无法测量或不足如实报告，不通过缩小统计范围伪造达标。Vitest 覆盖率插件目前未见安装，需确认可用工具后报告。

每个案例先写测试并运行，确认因目标行为而失败，再进行最小实现并运行通过；不能一次批量先写全部测试，也不修改既有失败记录。每项需保留案例、命令、结果、差异、轮次、独立审核与根因。涉及 UI 的工作适用 `docs/agents/frontend-control-audit.md`，功能、持久化和视觉各自独立判定；原金融和行情工作不能借此解除暂停。
