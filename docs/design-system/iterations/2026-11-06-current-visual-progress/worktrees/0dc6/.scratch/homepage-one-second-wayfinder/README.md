## 优化候选

以下继承[已接受的可行性分析](../homepage-one-second-feasibility-2026-10-24/FEASIBILITY.md)，不是已批准的实现方案。已有 SQLite 行情缓存、FX 缓存及连接复用，不重复做“是否加缓存”的泛研究。

| 候选 | 解决什么 | 必须证伪什么 |
| --- | --- | --- |
| A：窄查询、批量读取、来源复用及首页启动拆分 | 减少全量枚举、重复请求和无关初始化 | 保留大来源传输和浏览器加工后，冷打开是否仍超过1秒 |
| B：请求时生成紧凑首页投影 | 首页只传指标、持仓及所需曲线，复用既有财务算法 | 全部重算转到服务端后，首次构建是否仍超预算 |
| C：持久版本化首页投影＋独立首页启动 | 将可复用计算放到数据更新路径，重启后读取已发布版本 | 失效、原子发布、写后读、重建成本及范围组合能否正确且达标 |

研究推荐以最小真实范围验证紧凑读模型，再决定持久化边界；C最有希望，尚未选定。A中的局部改进可复用，但不能以局部提速证明整页成功。
