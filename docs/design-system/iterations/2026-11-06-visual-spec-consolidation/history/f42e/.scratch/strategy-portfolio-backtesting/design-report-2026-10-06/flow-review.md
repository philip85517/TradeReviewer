## 建议

### FLOW-01｜首步主动作的可见性

- **对应元素/图位置**：`LIB09 / F15`；左侧设置起点表单底部和页面底部动作条。
- **观察**：事实是 F15-1440 首屏只显示到“研究期限”卡片上部，下一步动作不在首屏；F15-1280 也要滚动到 `f15-1280-scrolled.png` 才看到“下一步：选择策略”。风险推断是用户尚未理解起点字段是否完成时，需要额外寻找下一步，且长集合/帮助文案会继续把主动作推下去。
- **建议改法**：保留现有表单与右侧摘要，在步骤页固定一个不遮挡字段的底部动作区，或在右侧摘要底部提供同一“下一步：选择策略”锚点；返回/取消语义不变。
- **优先级**：P1。
- **范围判断**：批准布局内优化，无需改变设计方向。
- **可验证验收**：1440×900、1280×800 及长文本状态下，首屏或固定动作区可发现且键盘可达“下一步”；点击后只进入 F16，已有起点字段与草稿保持不变。

### FLOW-02｜四步创建的状态摘要应成为持续导航

- **对应元素/图位置**：`LIB09 / F15–F18`；顶部四步条及各页右上返回链接。
- **观察**：事实是四页均有四步条，但当前步骤以圆点/勾选和文字表达，页间返回链接分别为“返回我的实验”“返回设置起点”“返回选择策略”“返回预览组合”。风险推断是用户从 F17/F18 回退后，较难一眼确认哪些内容已锁定、哪些仍可编辑，尤其 F18 同时出现“确认并进入待开始工作台”和“返回预览”。
- **建议改法**：在当前步骤下补一行极短的状态摘要（例如“已设置起点 · 已选 1 个策略 · 待确认”），步骤条保留原尺寸；完成步骤可继续点击回看，但只在当前页的明确动作改变草稿。
- **优先级**：P2。
- **范围判断**：批准布局内优化。
- **可验证验收**：在 F15→F16→F17→F18 及回退路径中，当前/已完成/待处理状态始终一致；返回不新建草稿、不清空选择，确认前不产生运行。

### FLOW-03｜F16 的“选策略”应更清楚地承载多组合语义

- **对应元素/图位置**：`LIB09 / F16`；策略卡片左侧复选框、右上“已选 · 1 个独立组合”、底部主按钮。
- **观察**：事实是 F16 用复选框和“1 个独立组合”表达选择，卡片内另有组合预设和每组合本金；未选策略以整块不可用示例显示。风险推断是用户可能把“策略选择”和“组合预设”当成同一对象，也不易预测再选第二个完整策略会新增一个独立本金组合还是覆盖当前项。
- **建议改法**：在选择计数旁加一句固定解释“每选一个完整策略，生成一个独立组合”；将“组合预设/本金”视觉上归入选中结果区，并保留“查看策略详情”作为只读动作。不要增加第四类包或原子条件编辑器。
- **优先级**：P1。
- **范围判断**：批准布局内语义优化。
- **可验证验收**：勾选/取消两个策略时，计数、组合数和本金行同步变化；查看详情不改变勾选；F17/F18 能逐个显示完整策略版本与三类包版本。

### FLOW-04｜F17 需要把候选、信号、成交的阅读顺序再拉开

- **对应元素/图位置**：`LIB09 / F17`；左侧“目标候选”、下方“买入信号”、右侧“目标与成交边界”三块。
- **观察**：事实是页面已有三块内容，并明确“实际成交价格、数量和费用须在运行中执行口径确定”；右侧同时显示目标配置、实际持仓和成交预览。风险推断是首次查看时，用户仍可能把“目标配置 60%”或“候选 12 个”读成已买入，特别是 `实际持仓：尚未成交` 位于同一右栏。
- **建议改法**：在三块标题前增加同一套步骤标识“1 候选 / 2 信号 / 3 成交检查”，并把“尚未成交”提升为右栏状态徽标；保留现有字段和说明，不删掉边界解释。
- **优先级**：P1。
- **范围判断**：批准布局内优化；若要改变卡片顺序或重排为流程图，需用户设计确认。
- **可验证验收**：有候选、无信号、有信号未成交、数据不足四种状态下，候选/信号/成交字段不会互相冒充；F18 仍能显示同一锁定快照。

### FLOW-05｜F18 的预检状态需要把“示例/未接入/已通过”分层

- **对应元素/图位置**：`LIB09 / F18`；“预检状态”卡片、顶部提示、右侧“进入后的状态”。
- **观察**：事实是 F18 同时出现“已检查通过（示例）”“计划终点采用一周合成示例，日历未接入”，顶部又说明确认后进入“待开始”且不会自动运行。风险推断是“检查通过”和“日历未接入”并列时，用户无法判断这是可确认的真实数据、合成预览，还是尚待接线的状态；静态稿不能证明提交后的锁定与失败保留。
- **建议改法**：将预检拆成“可确认条件 / 仅示例说明 / 尚待校验”三行，使用明确状态词；确认按钮在任一必检项未通过时显示原因并停留 F18，成功后才显示“已锁定、待开始”。保留费用、分股和数据截止说明。
- **优先级**：P1。
- **范围判断**：文字与状态层级属于批准布局内优化；若要删掉合成数据或日历说明，需用户设计确认。
- **可验证验收**：覆盖通过、缺数据、版本变化、提交不确定四种结果；成功只创建一个锁定运行并停在待开始，失败保留 F18 全部输入，静态“示例”不被当作业务成功证据。

### FLOW-06｜包目录的高密度列需要保留身份优先级

- **对应元素/图位置**：`LIB07 / F10` 表头与包行；`LIB06/07 / F12` 详情统计卡。
- **观察**：事实是 F10 一屏同时展示包名/版本、目录与标签、使用策略数、首次开发、版本更新时间、开发者/来源、备注/详情操作；F12 又以四张统计卡区分当前完整策略使用、当前版本确认使用、历史版本引用和锁定实验引用。风险推断是包很多时，用户最需要的“当前版本身份、能否新增选择、已有引用影响”会被日期和来源列分散，且四种使用数容易被误读为同一计数。
- **建议改法**：保持三类目录、筛选、排序、置顶与归档能力，把每行第一视觉组固定为“包名 + 版本 + 状态 + 当前可选性”，把开发/来源作为次级元数据；F12 四张统计卡各加短口径副标题，并保持未知不显示为 0。
- **优先级**：P2。
- **范围判断**：列分组和文案属于批准布局内优化；若要删除开发/来源列或改为完全卡片化，需用户设计确认。
- **可验证验收**：1280×800、1299/1301 边界和 1440×900 下，包身份、版本、归档状态和主要动作无需横向猜读；从 F10→F12→返回后搜索/筛选/页码/焦点保留，四种统计口径可被单独解释。

## 值得保留的设计点

1. F01 将“完整策略”置于默认目录，并把标的筛选、买入信号、止盈止损保留为并列目录；单列卡片同时呈现三类包、版本和可用性，符合“先复用完整策略、再深入包”的动线。
2. F15–F18 的四步创建把策略库与我的实验职责分开：F16 明确“查看详情不自动选择”，F17 分开候选/信号/成交边界，F18 明确确认后进入待开始且不会自动运行。这些语义与批准契约一致，值得保留并在真实接线中验证。
