## 3. 剩余两类问题，具体缺什么、为什么会影响判断

**第一类：有下单时间，但没有实际成交顺序。** 例如 CTRP 2019-09（U220/U221）：9/12 下单买 56；9/13 下单卖 56，另有明确“卖空 95、补回 95”。月初/月末都是 0。

- 若买 56 先成交：0 → 56 → 0 → −95 → 0，普通卖出是平多。
- 若前一天的买单延后成交：普通卖 56 → 卖空 95 → 补回 95 → 原买 56，数量为 0 → −56 → −151 → −56 → 0，普通卖出变成开空。

两条数量路径都满足原文明确的卖空/补回标签及月末数量。原件全页没有实际成交日期、成交子行、有效期或可用的具体交收日期来排除后一条；下单日期不能代替执行日期。需要补的是**实际成交日期及顺序，或能同样排除另一条路径的原始成交记录/规则依据**。这不是宣称第二条实际发生；普通“卖出”的开平语义也未获该原件的明确规则定义。

**第二类：获配只有日期，暗盘卖出有时分秒。** 例如 06049 2019-12-18（U226/U227）：股票进出为 IPO 获配 +200；暗盘成交为当日 17:23:23 卖 200，期初、期末均为 0。

- 获配先有效：0 → 200 → 0，卖出减少多头。
- 卖出先有效：0 → −200 → 0，获配抵消负库存。

原件不能确定获配入账生效时间或它与卖出的排序；一般交收备注不足以证明。这里缺的是**获配生效先后依据**，不是外部股票存入确认，也不是再把 IPO 当市场买入。负库存仅为现有数量条件未排除的路径，不等于已证实券商暗盘支持卖空。03347（2020-08-06，100 股）及 02101（2020-09-17，500 股）同类。全部 20 项的原文时间、页、数量、路径与最小补证见[逐项清单](homepage-real-integration-20261114--reports--futu-reconfirmation-detail-20261117.md)。
