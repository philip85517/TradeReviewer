# 全市场行情数据 module 与研究数据基础规格

Status: ready-for-agent

Blocked by: [独立行情数据模块重构决策地图](02-refactor-map.md)中的首期前置决策。用户已于2026-09-21确认推荐方向；2026-09-22按wayfinder请求先完成决策规划，不开始生产实现。

## What to build

形成独立、可诊断、可运维的行情数据 module，先承接 A 股、港股、美股股票与 ETF 的 1D/1H，再支持按证券池扩展；使回忆复盘和未来量化筛选复用可信的数据版本。本文是待选定深化方向后的实施规格，不代表实现已完成。

## Problem Statement

用户无法仅凭刷新成功判断行情是否覆盖完整、口径一致或适合研究。当前获取、补缺、失败判定、缓存和持久化知识分散，任务依赖复盘工作区启动；证券范围主要来自交易记录。全市场采集会放大限流、重启恢复、历史证券身份及质量诊断问题。未来量化插件需要可重现的研究快照，而现有 raw 标签、小时标签与推定可知时间不足以提供这些保证。

## Solution

以行情数据 module 为共同入口，集中管理证券池、获取策略、行情口径、完整性、持久补数和研究快照。复盘调用方与研究调用方只需知道需要哪个数据集、质量是否足够和缺口原因。运维人员可以定位到证券、周期、区间、来源和任务，重试缺口、暂停来源、观察恢复，且保留有效历史数据。

初期采用同仓库独立 module 和独立 worker 入口，复用现有存储 adapter；不提前拆成分布式部署。全市场指可注册市场的证券池驱动能力，第一期实际覆盖仍为现有三个市场及股票/ETF，不宣称全部全球资产已接入。

## User Stories

1. As a 复盘用户, I want 在同一入口读取日线与小时行情, so that 图表不必理解外部来源差异。
2. As a 复盘用户, I want 查看实际数据范围和缺口, so that 成功刷新不会掩盖不完整数据。
3. As a 复盘用户, I want 网络故障时继续使用已验证缓存, so that 已有复盘可以继续。
4. As a 数据管理员, I want 从完整证券池采集行情, so that 范围不依赖个人成交明细。
5. As a 数据管理员, I want 证券池带有效日期与退市状态, so that 历史研究不只包含今天仍上市的股票。
6. As a 数据管理员, I want 每个市场启用来源并集最多三个, so that 运维成本可控。
7. As a 数据管理员, I want 在质量条件内最小化全局来源并集, so that 不为重复覆盖维护额外来源。
8. As a 数据管理员, I want 看到某来源获准用于哪些证券类型和周期, so that 股票可用不被误当成 ETF 可用。
9. As a 数据管理员, I want 固定优先级且明确禁用条件, so that 兜底可解释。
10. As a 数据管理员, I want 不可用来源进入有期限的熔断, so that 故障不会耗尽预算。
11. As a 数据管理员, I want 重试遵守来源配额和总截止时间, so that 批量任务不会冲击交互请求。
12. As a 运维人员, I want 后台任务脱离浏览器运行, so that 关闭复盘页面不终止采集。
13. As a 运维人员, I want 任务可以暂停、取消及续跑, so that 维护时不用重新抓取全部数据。
14. As a 运维人员, I want 重启后恢复已领取任务, so that 进程故障不会永久丢失工作。
15. As a 运维人员, I want 并发 worker 不重复提交同一缺口, so that 数据和覆盖记录一致。
16. As a 运维人员, I want 分开查看超时、限流、无权限、历史边界和格式变化, so that 修复有针对性。
17. As a 运维人员, I want 按来源查看成功率、延迟及有效覆盖率, so that 快速返回的错误数据不会被评为优质。
18. As a 运维人员, I want 查看缺口的具体证券、交易日和时段, so that 可以精确补数。
19. As a 运维人员, I want 先预览补数计划和预计请求数, so that 大范围任务成本可控。
20. As a 数据使用者, I want 明确区分不复权、复权和未知口径, so that 不会混合不同价格尺度。
21. As a 数据使用者, I want 成交量单位得到验证, so that 股数、手数和未知值不混用。
22. As a 数据使用者, I want 小时记录保留实际开始与结束时间, so that 午休、半日市及尾段不会错位。
23. As a 数据使用者, I want 缺失成交量保持未知, so that 数据缺失不会变成真实零成交。
24. As a 数据使用者, I want 查看源记录与转换版本, so that 异常可以追溯。
25. As a 研究者, I want 固定证券池及行情版本, so that 筛选结果能够复现。
26. As a 研究者, I want 区分收盘、发布与抓取时间, so that 不误把事后下载数据当成当时可知数据。
27. As a 研究者, I want 数据不满足要求时明确失败或显式降级, so that 不把缺失股票静默排除。
28. As a 量化插件开发者, I want 批量分页读取研究快照, so that 无需直接访问 provider 或业务数据库。
29. As a 量化插件开发者, I want 结果引用研究快照和参数版本, so that 用户能核验股票入选原因。
30. As a 量化插件开发者, I want 只读访问授权的数据范围, so that 不会修改成交明细和标准行情。
31. As a 数据管理员, I want 新来源通过契约样本后才能启用, so that 新增来源不破坏已有行情口径。
32. As a 数据管理员, I want 旧数据可分批迁移和回滚, so that 时间修正不造成覆盖冲突或数据丢失。

## Implementation Decisions

- 已确认范围：现有市场、股票/ETF、1D/1H、最多三源及尽量减少全局来源；保护成交明细和回忆复盘记录。
- 深化方向已选：先独立行情数据 module；后台采集与研究快照留作后续阶段。具体 interface、来源质量和迁移规则通过决策地图确定，不把方向确认等同于细节已解决。
- 推荐只有一个主要外部测试 seam；复用现有 provider 与存储 adapter 作为内部 seam，不为每个纯函数制造新的公开 interface。
- 每市场来源上限按跨周期、跨股票/ETF 的并集检查。四源仅是原 ADR 的冗余配置，不能宣称数学最小。先剔除不满足质量/权限的来源，再在覆盖、最低备用要求和配额约束下最小化集合；当前证据不足以保证每个组合都有合格备用。
- 现有固定顺序在迁移前保留；未知时区、单位、复权语义的 adapter 不能因排名靠前绕过质量校验。来源选择调整需要更新决策记录。
- 建议将证券身份及符号有效期、证券池版本、获取任务、尝试记录、口径版本、行情修订、完整性诊断和研究快照分别持久化。业务成交记录不依赖外部行情主键重写。
- 1D 使用交易所交易日；1H 使用明确的起止时刻及交易时段。按交易日历生成合法桶，短尾桶保留实际结束时间。仅在对应来源、市场和周期已验证为结束标签时映射回桶起点。
- 保留 BaoStock 已做的起点转换，避免重复减时。百度先归一化 15m，再按 session 聚合，缺少子 bar 不标完整。东财美股时间疑点必须独立验证，不能通过统一减一小时掩盖。
- 区分交易结束时间、来源发布时间、抓取时间和有证据的数据可知时间。历史回填默认不具备严格 point-in-time 证明；研究快照保证数据版本复现，但不自动保证无前视偏差。
- 标准记录明确 adjustment、volume unit、currency、session scope 和转换版本；未知成交量保持缺失。复权研究数据为独立派生版本，不能覆盖 raw。
- 完整性依据证券存续期、交易日历、session、停牌证据与实际 bar 计算。缺失、停牌、未上市、未收盘、超出历史范围分别记录；未知不能归为已覆盖。
- 后台任务采用持久状态、租约、检查点和幂等提交；领取可重试，提交有 fencing 防止过期 worker 回写。bar 与 coverage 在同一事务提交，先写数据再完成任务；崩溃重放不得产生重复有效记录。
- 来源配额集中管理，优先保证交互请求。取消向 HTTP/TCP/子进程传播；总预算覆盖排队与重试。403/权限失败停止自动重试，429 遵守 Retry-After，瞬时故障有限退避。
- 诊断读取已持久化证据，不靠浏览器拼接日志推断状态。保留脱敏错误、attempt、响应摘要或有期限的原始证据；密钥与账户信息不进入诊断输出。
- 未来插件通过只读研究快照消费数据；第一期交付能模拟研究消费的测试调用方，不建立任意插件代码运行环境。
- 迁移使用独立行情数据副本、影子归一化、按范围比较与显式切换；旧口径不能和新口径共用已完成 coverage。失败可切回旧读取路径，原始成交摘要必须不变。

## Testing Decisions

- 验收外部行为：同一需求得到哪些记录、为何缺失、使用哪个版本、是否正确恢复。避免测试内部调用顺序、类名及纯转发函数。
- 主要测试 seam 方向已确认：行情数据 module 的共同入口；具体职责在决策地图中澄清。provider fixture、真实隔离 SQLite adapter、可控时钟作为内部测试设施。
- 复用当前日线/盘中同步、逐日补缺、存储事务、refresh integration、Tiger 子进程取消、BaoStock 协议与来源身份校验测试经验。迁移行为测试而非简单叠加一套重复 mock。
- 覆盖 A 股四个小时桶，港股午休和 11:30–12:00 短桶，美股 15:30–16:00 短桶，夏令时、半日市、停牌、退市、跨日期和来源时区异常。
- 跨来源比较应在同一证券、同一交易时段、相同口径下逐根校验 OHLCV；一个首根收盘价相等不能证明全区间一致或复权一致。
- 验证单位换算、未知量不归零、重复 bar、乱序、部分子 bar、修订版本和响应身份错误的隔离。
- 至少跨三批验证持久调度、配额、取消、任务租约过期、重启恢复、重复请求合并及原子提交失败。
- 验证相同研究快照重复读取一致，后续修订不改变旧快照；没有可知时间证据的数据不得声称严格历史可用。
- 在线 canary 是独立验收，不以 mock 测试通过代替。Tiger 缺配置和 Yahoo 限流均明确报告未验证，历史样本不外推为全市场 SLA。
- 性能以受控证券池规模、1D/1H窗口、并发、冷暖缓存测量吞吐、p95、请求数、写锁等待和内存。先建立基线与部署预算，再确定扩容阈值，不承诺未经测试的全市场容量。

## Out of Scope

本期不实现自动下单、策略收益承诺、完整回测平台、任意第三方插件执行、全部全球市场接入、盘口/实时逐笔数据或提前部署分布式集群。15m 现有兼容行为保留；其全市场能力另行验收。企业行为数据不足时不承诺复权与严格历史可知能力。

## Further Notes

原 ADR 的来源数量最小性、统一减 60m 与可知时间推断存在证据不足，架构报告单独标出重开原因，不静默覆盖旧决策。实施分批推进：口径与证据 → 独立行情 module → 持久采集/诊断 → 研究快照与消费验证。每批由 Luna 实现，协调者独立验收；不能把本规格的发布当作代码交付。
