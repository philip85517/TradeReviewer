# 首页超时：页面区块与读取过程细分

## 先看结论

此前测试分支的桌面首页没有完成真实数据展示：页面提示“读取已超时，新范围未应用”。现有证据表明，首页多个区块共用一条大型数据准备链路；并非已经测出某张卡片单独花了几秒。一次接口探针返回约 **34.3 MB**，而在另一组隔离测量中，完整来源读取及校验的普通样本中位数约 **7.75 秒**。这两组数字测量边界不同，不能相加，也不能代替完整首屏耗时。

这份说明整理历史证据，没有新跑测试或访问数据库。被调查的实验分支为 `codex/home-read-mvp-experiment-20261029`，基点 `0bbf7c4bfeabc325b4987966f93f45ff19f74d1f`；实验工具和证据保存在该隔离工作区。历史结果不代表现在运行在 3333 端口的服务一定使用相同代码或数据。

## 一、用户看到的区块：读什么、做什么、目前测到了什么

这里的“读取时间”分为共用准备时间和区块自身处理时间。下列区块没有各自独立的来源包大小或完成时间记录；不能把 34.3 MB 和 7.75 秒分别算给每个区块，再将它们相加。

| 首页区块 | 实际数据和主要操作 | 已知读取量 / 时间 | 尚未测出 |
| --- | --- | --- | --- |
| 市场、账户与标的搜索 | 基于已读取的交易、账户、标的信息建立可选范围和搜索目录，再根据用户选择过滤 | 依赖共用来源包；来源样本有 1,866 笔成交、236 个标的 | 各目录建立、过滤、渲染及对应数据独立字节数 |
| 当前表现指标 | 从已取得的成交、标的信息、行情与汇率准备财务来源，按当前范围生成期间表现视图，再展示指标 | 来源包共用；汇率请求与来源请求并行；财务来源和指标本身的独立字节数、耗时均未记录 | 等待本地行情、汇率及财务计算各自耗时；真实完成展示时间 |
| 表现曲线 | 与表现指标使用同一期间视图，取时间序列绘图 | 共用来源和期间视图；曲线点数、专属字节数未在本次记录 | 序列计算、绘制与可见完成耗时 |
| 当前持仓、持仓市值和浮盈 | 从已准备的来源和财务事实构造持仓；页面再搜索、排序并切出当前页 | 共用来源包；**每页显示 8 行，不代表只读取 8 条成交**；实际持仓数本次未确认 | 持仓生成、搜索排序、分页、渲染各自耗时及对应字节数 |
| 历史已平仓与贡献 | 当前分支页面明确显示“历史统计与贡献将在后续阶段接入”，历史域状态为 `not-wired` | 无已接入模块的读取时间可报告 | 接线完成后的数据量、计算及展示时间 |
| 交易库入口 | 用当前范围进入交易库；交易库仍依赖大型共用来源读取 | 浏览器验证中进入后也提示读取超时 | 交易库完整首屏和各区块的耗时 |

启动路径也存在先后依赖：代码先读取并校验启动集合，等待标的名称等准备就绪，然后才开始首页全局读取；首页读取中，来源和汇率请求并行，来源回来后再按标的读取本地行情状态。两次大包接口探针可以揭示各自成本，但并非同一次页面追踪，不能把这些探针数值相加当作页面总时间。

逻辑依据：[启动前置读取](../../app/components/trade-review-workspace.tsx)、[工作区统一读取及加工](../../app/components/trade-review-workspace.tsx)、[首页区块和持仓分页](../../app/components/homepage-v25/home-surface.tsx)、[表现指标和曲线共用期间视图](../../app/components/homepage-v25/period-surface.tsx)。

## 二、首页公共数据：每一步花多久

以下来自 2026-10-29 的真实数据**隔离副本**，每次调用既有来源读取入口，再调用既有解析校验入口。普通样本三次：7,745.654、7,409.662、8,467.069 毫秒；中位数 **7,745.654 毫秒**。三次插桩样本仅用于下表细分。插桩会影响运行，机器也有其他负载；三次不足以代表稳定速度。

| 处理步骤 | 插桩样本中位耗时 | 系统在做什么 |
| --- | ---: | --- |
| 原始行取出 | 28 毫秒 | 通过该入口查询数据库并取出原始行。**这不是全部数据库查询时间。** |
| 原有启动集合读取与整理 | 152 毫秒 | 读取并整理成交、标的等多类数据；其中成交读取和整理约 122 毫秒，已包含在 152 毫秒内。 |
| 两个内部页的快照整理 | 958 毫秒 | 按每页最多 1,000 笔构造两页，整理来源材料、证据与快照摘要。内部材料上下文约 381 毫秒、快照摘要约 499 毫秒，已包含在本行。 |
| 两个内部页编码和摘要 | 649 毫秒 | 将每页内容编码并生成校验摘要。 |
| 完整包编码和摘要 | 1,037 毫秒 | 将整个来源集合再次编码并计算摘要。 |
| 来源结构与一致性检查 | 332 毫秒 | 检查分页关系与交易内容是否一致。 |
| 解析时规范化和复制整包 | 1,111 毫秒 | 将完整数据规范化编码、解析成独立对象；包含内部编码，不能再把内部编码时间加上。 |
| 解析时再次检查结构 | 347 毫秒 | 再检查集合、分页与交易内容之间的一致性。 |
| 完整包绑定摘要校验 | 1,113 毫秒 | 编码、转为字节并校验绑定摘要；不是纯粹的摘要算法运行时间。 |
| 两个内部页的合同解析 | 1,466 毫秒 | 使用既有解析规则逐页校验；内部步骤没有进一步计时。 |

表中部分步骤是其他步骤的组成部分；另外各行中位数可能来自不同样本。**不要把表中数字相加推导总时间或各区块占比。** 上述整个“来源读取与整理”插桩中位数为 3,216 毫秒，“解析与校验”插桩中位数为 4,411 毫秒；这两个中位数也不能相加作为总中位数。只统计产品函数调用，不含 HTTP、页面计算、浏览器渲染、服务启动或实验的文件复制等准备。

详细数据、范围及独立复核见[来源准备分段报告](../source-preparation-profile/reports/approved-01-plain-report.md)和[独立复核](../source-preparation-profile/reports/INDEPENDENT-RESULT-REVIEW-APPROVED-01.md)。

## 三、34 MB 里面装的是什么

下表来自 **10 月 28 日另一份隔离副本**的单次接口字段统计，返回 34,332,057 字节；这份副本比上述样本多一笔先前测试成交，因此数量及字节不能与 10 月 29 日的 1,866 笔、34,315,599 字节样本混为同一次测量。MB 使用十进制，约数按原报告保留。

| 响应中的内容 | 数量及大小 | 含义 |
| --- | --- | --- |
| 启动集合 | 约 6.33 MB | 包括 1,867 笔成交约 3.24 MB、236 个行情任务约 2.68 MB，以及标的、导入历史等。 |
| 两个内部成交页 | 合计约 28.00 MB | 包括成交事实、页面展示信息、来源材料和校验信息；两页最后仍合在同一个响应。 |
| 来源材料现状 | 两页各约 4.34 MB | 两页中的内容相同，各出现一次。 |
| 材料沿革 | 两页各约 4.37 MB | 两页中的内容相同；与“材料现状”是不同信息。 |
| 来源诊断 | 两页各约 0.11 MB | 两页中的内容相同。 |
| 成交事实中的原始与解析证据 | 两页合计约 5.48 MB | 文本形式的原始证据及解析后的对象均出现；用途与保留粒度仍需逐项核查。 |

以上有父子包含关系，不能纵向相加。例如“来源材料现状”已经包含在“两页”之中。仅就这个样本，第二页重复的材料现状、沿革和诊断约 8.82 MB；这不等于可以直接删掉，必须先确保核验和追溯能力仍正确。完整字段统计见[协议审查](../home-trades-recovery-diagnosis-2026-10-28/PROTOCOL-REVIEW.md)和[字段大小原始统计](../home-trades-recovery-diagnosis-2026-10-28/protocol-fields.json)。

## 四、从打开到超时：已知和未知

1. 桌面 1440×900 打开首页，实际出现超时提示，页面上的“0 条持仓”不能视作真实持仓为零。
2. 另一次隔离副本接口探针中，来源接口两次分别 **4.106 秒**和 **8.154 秒**，每次返回 **34,315,599 字节**；另一个启动接口同样返回该大小。它们是独立请求样本，不是同一次页面各阶段。首次启动接口 12.404 秒还包含开发服务编译。
3. 页面逻辑设有约 **15 秒的请求期限**，并在超时后拒绝迟到结果；这是代码期限，不是已测出的从点击到提示的准确耗时。
4. 目前没有记录完整页面中各请求的开始和结束、数据解析、每个财务区块完成及浏览器绘制的关联时间，因此不能说 15 秒具体由某几个步骤各占多少。

证据：[桌面实测及四次接口探针](real-baseline-2026-10-29.md)、[超时期限实现](../../app/components/homepage-v25/use-homepage-host.ts)。

## 五、下一次补测应输出什么

若要真正得到“每个组件读取时间 / 数据量 / 操作”的精确账单，需要对同一次桌面请求建立关联记录，而不是把共用包切分猜给各个组件。应记录：

1. 页面导航开始、页面请求开始、每个响应首字节及完成、数据解析结束；分别计响应总字节和有需要的字段字节。
2. 来源构造、各标的行情读取、汇率读取、交易集合整理、财务来源准备、持仓构建、期间视图和曲线序列的起止时间、输入和输出条数；共享步骤单列，父子和并行区间标识清楚。
3. 指标卡、曲线、持仓表以及历史区块的真实数据就绪和可见完成时刻；未接线、失败、超时、被取消分别报告，不能用零代替。
4. 同一代码版本与隔离数据库副本，在浏览器冷／热访问、服务重启首读和数据更新后首读分别比较 1 秒完整展示目标；外部行情／汇率补齐单列，敏感成交明细不写入报告。

该补测是诊断，不恢复此前暂停的财务、Bars 或并发优化开发任务，也不代表优化已经通过。应保留原始失败和样本、记录实际测量开销，避免新增探针改变结论。
