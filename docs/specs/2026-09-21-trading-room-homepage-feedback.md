# 交易室首页反馈修复规格

状态：ready-for-agent  
日期：2026-09-21  
功能编号：`trading-room-homepage-feedback-20260921`  
设计原则：简约、聚焦、清晰；先修正信息层级和可读性，再考虑扩展能力。

## Problem Statement

第二版首页 review 反馈表明，当前“我的交易室”虽然已经具备统一统计范围、收益摘要、趋势/日历和当前持仓，但这些内容在视觉和交互上仍没有形成一条稳定的判断路径：

- “交易性质”被做成与分类、期间并列的大框，和右上角已有的“实盘”身份标记重复。实盘、模拟盘和当前持仓入口没有被放在用户最容易理解的位置。
- “统计期间”和“更多期间”与其他筛选项的布局方式不一致；“更多期间”点击后没有立即出现可编辑的日期控件，用户无法判断操作是否生效。
- “分类”命名不够准确，来源未知等诊断信息混在主筛选中，增加了用户对统计范围的理解成本。
- 净盈亏卡片的辅助文字过密，原币金额、日期、汇率和来源信息挤在小卡片中，主结论反而不突出。
- 收益概览和累计盈亏趋势分成两个视觉模块，重复展示区间和累计值；趋势图的比例、坐标、标签和点值不够易读，用户不能快速回答“哪个期间发生了多少变化”。
- 盈亏日历在年或全部年份视图下主要只显示金额和回合数，未充分利用已有胜负和样本信息；颜色、月份和收益文字的层级不足。
- 当前持仓中的负持仓、行情不可用、行情过期、行情早于最近交易或币种不匹配等状态没有被清晰地区分。用户无法判断这是合法空头、交易证据问题、行情源问题，还是应用计算问题，也缺少直接的处理入口。

本次目标不是重做交易室业务模型，而是把现有数据和计算结果组织成可读、可操作、可诊断的首页。

## Solution

将首页收敛为一个主路径：

`右上角范围/视图切换 → 紧凑筛选条 → 收益概览与趋势大块 → 盈亏日历 → 当前持仓与数据处理入口`

### 1. 顶部范围与视图控制

- 移除筛选区内独立的“交易性质”大框，以及右上角重复的单一“实盘”身份标记。
- 在“收益概览”标题区域右上角放置紧凑的三段式控件：`实盘`、`模拟盘`、`当前持仓`。
  - `实盘`和`模拟盘`切换统计范围；默认仍为实盘。
  - 选择模拟盘后继续要求选择一个明确的模拟运行，不能跨运行合并结果。
  - `当前持仓`作为当前状态视图入口或定位入口，不伪装成第三种交易性质；它保留当前统计范围，并将用户带到同页持仓区域或聚焦持仓区域。
- 将“分类”改名为“市场分类”，主筛选只保留全部市场、A股股票、美股股票、港股股票和 ETF 等可理解的市场/资产分类。
- 不在主筛选中展示“来源未知”选项。未知资产和来源未知回合仍保留在数据状态或质量提示中，不得静默计入四类市场合计，也不得通过删除选项丢失诊断信息。
- 将 `本月`、`近3个自然月`、`今年至今`作为紧邻收益概览标题的主要期间快捷切换，保持默认本月和明确的实际日期范围。
- `更多期间`必须有可见结果：点击后在同一范围控制区域展开起止日期输入；应用后显示自定义日期范围，取消或无效输入不改变当前已生效期间，并提供明确的校验提示。不得要求用户猜测控件是否成功。
- 保持模拟运行、账户、标的、币种、复盘状态等低频筛选在“更多筛选”中；展开状态、焦点顺序和选中状态要清晰。

### 2. 收益概览与趋势合并

- 将收益摘要和 `RoomPerformance` 视觉上合并为一个“收益概览”大块；共享同一份交易室范围、日期范围、FX 快照和可信样本口径。
- 保留四个核心结论，但压缩卡片内容：
  - 已平仓回合净盈亏；
  - 可信已平仓回合及胜/负/持平；
  - 合计胜率及样本分母；
  - 在分母有效时显示本金参考收益率，否则显示交易成本收益率和简短回退原因。
- 净盈亏卡片只在首屏显示主金额、期间和一条短的币种/口径说明。原币分项、汇率状态、证据说明等详细信息放入已有的可展开详情或数据管理入口，不把长文本压缩进小字号卡片。
- 延续未知值语义：暂无样本、数据不足、无法合计和部分可用必须区分，不能用 0 或一串不可读的解释代替。
- 用户可见金额、数量、百分比最多保留两位小数；底层 Decimal 计算和财务口径不改变。

### 3. 趋势图可读性与点详情

- 趋势图保留日、周、月分桶，但分桶只影响图表，不改变顶部范围或收益卡片统计口径。
- 图表使用稳定的绘图区比例和明确的内边距，不能因为 SVG 拉伸导致折线陡升、文字变形或点位贴边。
- 明确绘制横轴时间标签、纵轴金额刻度和零基线。金额刻度遵守两位小数规则，并根据当前是人民币合计还是单一原币显示对应币种。
- 每个有效点都提供期间收益和累计收益；桌面端支持悬停/点击，键盘聚焦也能打开同样的点详情；窄屏下提供紧凑的选中点详情区域，避免依赖悬停。
- 点详情至少包含：期间标签、期间净盈亏、累计净盈亏、可信回合数、胜负数量和覆盖日期。数据不足或多币种无法合计时，直接显示原因和原币小计，不伪造人民币累计值。
- 不再把完整点明细默认挤在图下方；保留可访问的详情列表作为辅助入口，默认展示当前选中点或摘要信息。

### 4. 盈亏日历信息层级

- 趋势与日历继续使用同一“收益概览”大块内的二级视图切换，不新增独立页面。
- 月视图、年视图和全部年份视图保持现有层级与翻页/下钻能力；切换视图和下钻时继续同步全局期间、摘要和趋势。
- 日历单元格在可计算时展示净盈亏和样本数，并补充已有模型可以可靠提供的胜率、胜/负/持平信息；金额、胜率和样本数按可读优先级排列。
- 收益率只在对应成本或本金分母有效时显示；如果分母缺失、样本不足或多币种不能合计，显示明确的不可用原因。不得为了填充日历而新造一套收益率算法。
- “赔率”不作为本次临时新增的金融口径；若现有模型没有稳定的盈利/亏损金额分子分母，则不展示伪造的赔率值，并记录为后续独立指标需求。
- 正负颜色、月份文字、金额文字和辅助文字使用一致的对比度和字号；不以颜色作为唯一信息，负值和不可用状态同时有文字/符号说明。

### 5. 当前持仓与行情问题诊断

- 保留当前持仓的市场分组、最近成交排序和进入回合复盘能力；持仓不因业绩期间快捷切换而被错误隐藏。
- 对负持仓明确区分：
  - 如果方向和持仓证据明确，显示为空头/负数量，这是有效状态，不自动改成正数；
  - 如果方向、数量或成本证据不完整，显示“持仓证据待核对”，并指向数据管理/数据检查。
- 将“行情不可用”拆成用户能理解的原因标签：缺少行情、行情已过期、行情早于最近交易、行情日期晚于统计截点、行情价格无效、行情币种与结算币种不一致、数据源未连接/不支持等。
- 持仓行首屏只显示状态摘要和一个明确动作；完整的最近交易日、行情日期、采集时间、提供方、证据原因和影响范围放入行内详情或数据管理入口，避免再次形成密集长句。
- 对可重试的行情问题提供“重试行情”或“打开数据管理”；对源不支持、币种不匹配或证据缺失提供“查看数据源/查看数据”的动作。动作必须沿用现有数据管理能力，不在首页新增另一套修复流程。
- 任何行情不可用都不能用零价格或零浮盈亏代替；状态、原因和当前可用字段必须保持分离。

### 6. 对齐、响应式和验收约束

- 同一筛选组统一使用“标签在上、控件在下”的布局；同级标签顶部偏差不超过 2px，同级控件起始线偏差不超过 2px。
- 桌面端不出现控件互相遮挡、按钮脱离所属组或右侧控件被截断；“更多期间”展开后的日期输入仍在当前面板内完成。
- 390px 和 320px 窄屏下，顶部三段式控件和期间快捷项可以横向滚动或换行，但页面整体不得横向溢出；趋势点详情必须可读。
- 保持现有一级左侧导航和模块职责，不新增全局顶栏、面包屑、独立路由或装饰性卡片。

## User Stories

1. 作为交易者，我希望在收益概览右上角直接切换实盘和模拟盘，以便快速改变统计范围。
2. 作为交易者，我希望默认进入实盘，以便模拟结果不会误混入首屏判断。
3. 作为模拟盘用户，我希望选择模拟盘后明确选择一个模拟运行，以便不同运行不会被静默合并。
4. 作为交易者，我希望从右上角进入或定位当前持仓，以便不用在长页面中寻找持仓区域。
5. 作为交易者，我希望主筛选写成市场分类，以便理解它筛选的是市场/资产类别，而不是数据来源。
6. 作为交易者，我希望来源未知不混在主分类选项中，以便主筛选保持简单，同时仍能在数据状态中发现未知数据。
7. 作为交易者，我希望本月、近3个自然月和今年至今直接可选，以便快速切换最常用的观察期间。
8. 作为交易者，我希望点击更多期间后马上看到日期输入，以便知道操作已经产生了可编辑的结果。
9. 作为交易者，我希望无效日期不会悄悄改变当前范围，以便不会误读错误期间的收益。
10. 作为交易者，我希望摘要和趋势属于同一个收益概览大块，以便一次理解数字和变化方向。
11. 作为交易者，我希望净盈亏卡片只突出金额、期间和简短口径，以便不会被密集说明文字干扰。
12. 作为交易者，我希望看到可信回合数、胜负数和胜率分母，以便判断收益结论的证据量。
13. 作为交易者，我希望本金参考收益率和交易成本收益率有明确标签，以便不会把不同分母的比例混为一谈。
14. 作为交易者，我希望暂无样本、数据不足和无法合计分别显示，以便知道下一步是导入数据、补证据还是补汇率。
15. 作为交易者，我希望趋势图有时间轴、金额轴和零基线，以便不用猜测折线的位置代表什么。
16. 作为交易者，我希望点击或聚焦任意趋势点就能看到期间收益和累计收益，以便解释每个拐点。
17. 作为窄屏用户，我希望趋势点详情不依赖鼠标悬停，以便在手机或窄窗口中仍能查看金额。
18. 作为交易者，我希望趋势图的日期、点值和累计值使用稳定比例展示，以便折线不会因为容器伸缩而变形。
19. 作为交易者，我希望盈亏日历显示金额、样本和可可靠计算的胜率，以便比较不同月份或年份。
20. 作为交易者，我希望日历在缺少分母时明确显示不可用，而不是显示看似精确的收益率。
21. 作为交易者，我希望正负收益既有颜色也有文字/符号，以便在不同对比度或色觉条件下仍能理解。
22. 作为交易者，我希望负持仓被明确标识为空头或待核对，以便区分合法交易状态和数据问题。
23. 作为交易者，我希望知道行情不可用的具体原因，以便判断应该重试行情、补充交易证据还是检查币种。
24. 作为交易者，我希望持仓行能直接打开对应的数据管理动作，以便不需要离开当前上下文重新查找问题。
25. 作为交易者，我希望行情不可用时不被显示成零价格或零浮盈亏，以便不被错误数字误导。
26. 作为交易者，我希望期间切换不会把当前持仓误过滤掉，以便持仓仍代表当前状态。
27. 作为交易者，我希望页面在桌面和窄屏下同样对齐、不遮挡、不横向溢出，以便可以连续使用。
28. 作为产品验收者，我希望每次修改都能通过真实浏览器的视觉几何检查，以便单元测试通过不再被误认为视觉验收通过。

## Implementation Decisions

- 复用现有交易室统一范围对象作为唯一状态源。范围、摘要、趋势、日历、持仓和数据质量不得各自维护一套期间或交易性质。
- 保留现有左侧一级导航和数据管理入口；本次只调整交易室首页内部的控制层级和模块组合。
- 以现有 dashboard、performance/calendar、holdings 和 quality 组件作为实现边界。允许调整它们的展示契约和组合关系，但不建立新的通用页面框架。
- 顶部三段式控件的实盘/模拟盘状态继续映射到现有交易性质和模拟运行筛选；当前持仓只负责同页定位/聚焦或视图状态，不引入第三种财务性质。
- 主分类隐藏来源未知选项，但数据模型仍保留 unknown 分类以及质量提示，保证未知数据可追踪、不可静默合计。
- 更多期间使用现有自定义期间状态和日期范围模型，改为同区展开并提供应用/取消/校验反馈，不新增持久化格式。
- 摘要和趋势在视觉上合并，但保留较高层的组件 seam：摘要继续消费交易室模型，趋势/日历继续消费现有日历模型，避免复制财务计算。
- 趋势点详情优先消费现有 `TradingRoomTrendPoint` 的期间金额、累计金额、胜负和日期字段；只有现有字段无法可靠计算的指标才显示不可用，不在 UI 层推导新的金融口径。
- 日历扩展只使用现有可信回合、胜负、样本、金额和排除状态。赔率或新收益率算法作为后续独立规格，不在本次为了满足视觉反馈临时添加。
- 持仓诊断沿用现有持仓模型的 `quantityStatus`、`costStatus`、`quoteStatus`、`unrealizedPnlStatus` 和 `statusReason`，补充稳定的用户文案和动作映射。负数量不被格式化层改写。
- 行情修复动作继续调用现有数据管理/行情更新入口；不在交易室新增 provider、缓存或自动修复逻辑。
- 所有用户可见金额和百分比使用统一的最多两位小数展示函数，底层金额和汇率精度不变。
- 覆盖色彩、文字和边框的最小视觉调整，重点修复层级、间距、对齐、可读性和状态表达，不进行全站换肤。

## Testing Decisions

测试以用户可观察行为为边界，不测试 CSS 类名或内部实现细节；视觉几何是本次明确的外部行为，因此需要真实浏览器验收，不只依赖单元测试。

1. 在交易室 dashboard 组件 seam 验证默认实盘、模拟盘运行选择、当前持仓入口、市场分类、期间快捷项、更多期间展开/取消/校验和摘要同步。
2. 在 performance/calendar 组件 seam 验证趋势与日历共享范围，点选/聚焦趋势点可得到期间金额与累计金额，日历切换/翻页/下钻仍同步摘要和趋势。
3. 在 trading-room-calendar 模型 seam 验证空样本、排除样本、多币种不可合计、正负状态、胜负样本和日期边界；不为未定义的赔率编造断言。
4. 在 trading-room-holdings 模型和持仓组件 seam 验证负数量、方向未知、成本证据缺失、缺少行情、过期行情、行情早于最近交易、币种不匹配和无效价格的原因分类与展示动作。
5. 复用现有 dashboard、room-performance、trading-room-calendar、trading-room-holdings 和 quality 的测试夹具，优先增加外部文案、状态、交互和数据保持断言。
6. 真实浏览器验收至少覆盖 1280px、1440px、390px 和 320px：检查同级标签/控件对齐、无重叠、无页面横向溢出、更多期间确实展开、图表坐标/点详情可读、当前持仓状态和动作可达。
7. 浏览器几何验收使用明确阈值：同级标签顶部差不超过 2px，同级控件顶部差不超过 2px；截图复核同时覆盖有数据和空/不可用数据。
8. 浏览器写入或触发重试时使用独立 SQLite 副本，验收前后核对原始交易数量和内容摘要不变。
9. 完成定向测试后执行类型检查、构建和相关回归；记录已知警告、未运行项目和任何外部行情限制，不以测试全绿替代视觉验收。

## Out of Scope

- 不新增交易数据导入格式、解析器、行情 provider、汇率源或缓存策略。
- 不自动修正负持仓、不把负数强行显示为正数，也不把未知行情替换成零。
- 不新增账户总资产、基准指数比较、夏普比率或另一套收益率算法。
- 不在本次临时定义赔率口径；赔率需要独立确认盈利/亏损金额、样本和币种边界后再设计。
- 不新增一级导航、URL 路由、面包屑、操作审计或独立持仓页面。
- 不把收益概览、趋势、日历和当前持仓拆成更多二级页面。
