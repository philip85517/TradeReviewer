## What to build

以[完整 UI 与数据规格](REQUIREMENTS.md)和[七页设计草案](demo/index.html)为开发依据，实现主图优先工作区、三阶段快照组织、可查询的计划／执行数据和三图一表演示导出。用户已确认阶段拆分；以 v1.0 最终需求和[元素规范](UI-ELEMENTS.md)为准。本票供后续启动产品开发，当前仅完成设计交付包。

## Blocked by

无前置任务。后续实现先核对规格及现有工作区版本，并按项目协调者＋Luna 工作方式拆分有明确文件所有权的实施任务。

## Acceptance criteria

- [ ] 沿用现有深蓝灰/蓝色交互主题、Geist/Lucide 和用户图表设置，按元素规范验收。
- [ ] 主图优先，顶部和底部压缩，结构记录使用按阶段嵌入的侧栏。
- [ ] 买入前录入价格／仓位计划，持仓侧栏只读原计划，执行评价仅在事后复盘逐次填写。
- [ ] 侧栏展开时图表与价格轴仍可见，价格标签与右栏不重叠；关闭／切换保留草稿。
- [ ] 窄屏将侧栏下置，并保留紧凑价格上下文，不使用遮图全屏表单。
- [ ] 支持逐根揭示及图上 Text；输入法和图表快捷键互不干扰。
- [ ] 三阶段不替代逐笔交易决策与快照，旧快照保持独立。
- [ ] 计划／实际、仓位／资金基数、费用／净盈亏和计划 R／实际 R 口径明确。
- [ ] 支持部分退出、提前退出三态及原因、计划修订，保留原始成交。
- [ ] 结构化字段服务端持久化，可查询，具备修订与来源。
- [ ] 四页演示导出为三张阶段图＋可编辑汇总表，缺失阶段不伪造。
- [ ] 样例净盈亏为 6,760 CNY、实际 R 为 1.69，空值不能作为零。
- [ ] 通过完整用户路径、数值边界、保存恢复／冲突及导出验收。
- [ ] 写入验收使用独立数据库；协调者完成浏览器验收并提供运行中的预览入口。
