# 交易库 V1.0 评论诊断与修复方案

诊断日期：2026-10-24（Asia/Shanghai）。评论基线：revision 6。范围是设计文档与图稿，未验证交易库产品实现。

## 结论

4 条新评论可归为 5 个问题。主要根因是：独立出来的交易库规范继续使用历史局部图稿，正文中的共享规则、完整旅程和业务口径没有一致地落实到各张图中。当前图稿缺少共同的整页框架、统一的视图切换，以及跨章一致的样例数据和连续分镜。

证据链为：评论指纹 → 当前正文与原始 SVG → 真实浏览器显示 → 公共规范对照 → 历史文件比较。涉及的 5 张 SVG 与 HEAD、冻结 V2.4.2 中的对应图片字节一致；这说明本轮看到的图稿问题是沿用内容中的缺口。此前行文修订明确保留 20 张图片和 5 个分镜块，因此不能把那次正文接受理解为整页视觉接受，也没有证据将这些图稿问题归因于行文修改。

## 分层根因与排除结果

1. **图稿层：局部图被用于表达整页，且独立手写坐标和状态。** 整页宿主缺失、工具条偏移和切换条有无不一都能在 SVG 源文件与浏览器中直接复现。公共规范引用本身不能保证每张图使用相同规格。
2. **样例层：图与图之间没有一致的校验结果。** 单点趋势不足以验收普通趋势效果；同一练习回合数冲突是更直接的样例一致性失败。未发现可据此证明产品统计计算错误的证据。
3. **分镜层：按题材收集画面，没有逐步覆盖用户动作后的状态。** 第六章的帧序与正文规定的普通到达路径不连续，空间位置和状态变化只能靠读者猜测。
4. **交付范围层：正文完善与图稿完善分开进行，但当前文档承担了完整页面设计的阅读预期。** 这是从范围记录与当前产物作出的流程判断，不是对历史作者动机的推断。已有行文验收的“不改图”证据继续有效；后续必须增加整页视觉与跨帧数据验收。

已排除或限定：

- 模拟盘图不是资源丢失：“下一步”可显示该图，原尺寸弹窗也可打开及关闭。
- 窄侧栏确实放大了阅读困难：当前319×694视口中，1440px宽图片缩到249px；但已有100%原尺寸入口。它是可发现性与缩略图阅读的次要因素，不能解释源图没有导航或仅有一个点。建议显式显示“查看原尺寸”和状态名称，属于后续优化，不将其误报为预览加载故障。
- 单点可能对应只有一天有有效样本；本轮确认的是“普通趋势设计示例不足”，没有证明原样例为何只有一天，也没有检查产品计算或业务数据库。
- 首页参考为1440px宽长页面；本次只比较公共导航、页头、层级与位置表达，不把首页模块顺序和整页高度强加给交易库。

## 修复顺序与交付方式

1. **先补第二章整页契约。** 一张完整母版连同公共规范映射，固定全局导航、页头、视角、来源、条件区及内容区；明确1440/1280下的尺寸、信息顺序、局部图使用方式。先让第三章的普通到达状态成立。
2. **统一列表与统计的公共区域。** 一次修正工具栏对齐和视角切换，再同步第三、四、五章；不要各图分别补同一个按钮。
3. **建立贯穿各章的样例。** 从练习、成交与回合推导趋势和分布，用多日期普通样例与边界样例分开表达，修正A练习2/3回合矛盾。
4. **按用户动作重排第六章。** 普通路径完整连续，待复盘为独立分支；图外说明保持简短，避免把操作流程说明画成产品界面。
5. **独立复验后再处理评论。** 同状态、同尺度比较整页截图；核对样例一致性与所有受影响分镜；重新生成文档并验证评论定位。实现人不能独自签署视觉通过。

上述为修复方案，本轮没有执行。正文和图稿尚有5项开放问题，不能据此声称设计已修复或产品已通过验收。
