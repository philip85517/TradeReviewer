# 首页和交易库继续排查：来源读取拆分

## 结论

当前隔离副本中的历史成交能够通过来源协议读取，但两页未通过完整展示；交易库打开后重现“目标交易集合读取超时”，返回首页后也重现“读取已超时”。不能把首页显示的“0 条”当作真实持仓结果。来源接口本身在两次 1 秒 HTTP 探测中均未返回首字节，因此在当前开发服务和数据条件下，无需等待后续页面计算即可判定该链路不满足 1 秒完整首屏的必要条件。这不是生产构建或所有场景的验收。

## 环境和边界

沿用 [前次诊断](DIAGNOSIS.md) 的 worktree、服务 3333、隔离副本与用户排除范围；前次的 1440×900 浏览器证据和源文件内容指纹见该报告。本轮服务进程仍监听 3333，数据库检测与服务端分段使用 `.data/tradereview-test.sqlite`，分段数据库连接以只读方式打开；服务本身可能进行后台写入。副本含先前验收加入的一笔合成成交。期间未更改应用代码和共享业务数据库，没有恢复暂停的财务、Bars 或重复导入任务。

本轮浏览器范围仅交易库直接进入及返回首页，观察来源加载与失败状态；不是全部控件、设计视觉对照或写入链验收。页面验证用 Codex 内置浏览器实际导航及按钮，默认过滤实盘、全部市场、全部账户、全部时间。手动页面观察无精确 1 秒计时；本轮未重测浏览器 CSS 视口，桌面 1440×900 证据以原报告为准。一次点击使用过期 AX 索引失败，刷新状态后按按钮名称点击成功。未完成独立视觉审查。


服务端分项测试运行 3 次全部通过，记录 [第一次](server-breakdown-first.json)、[第二次](server-breakdown-second.json)、[第三次](server-breakdown.json)；客户端分项探针运行 2 次全部通过，记录 [第一次](contract-breakdown-first.json)、[第二次](contract-breakdown.json)。这里的“通过”只指探针运行和内部合同断言通过，**不代表产品或性能验收通过**。

HTTP 测试输出两次均为 `curl: (28) Operation timed out after 1010 milliseconds with 0 bytes received`，`status=000`，时间分别 `1.010383s` 和 `1.010256s`；该结果是预期的失败信号，仅覆盖实际来源请求，不是完整页面的自动验收。
