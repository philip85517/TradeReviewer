## Problem Statement

用户要用 TradeReview 页面导入用户指定本地“A股”目录的招商证券 PDF，并逐条核对导入记录与外部账单。目录有 9 份 PDF、45 页；历史本地探查找到 445 条明确买卖行：A 股 154、ETF 224、港股通 55、可转债 12。跨文件完整签名重复 67 条，得到 378 条候选独立记录（140/191/35/12）。目录名不能当筛选条件，所有原始行都必须说明去向。

2026-09-09 本地探查报告记录：当时招商适配器对这批文件全部 `blocked`，原因是表头、日期和市场在 PDF 文本层是分离项。当前成交模型还未独立保存成交金额、分项费用、资金变动、余额和结算币种；账单也只有日期、没有成交时刻或成交编号。因此不能声称当前结果与外部记录完整一致，也不能进行港股通混合币种盈亏核算。普通交易的 `executionCandidateKey` 未含账户，可能错误合并两个账户。

## Solution

扩展现有页面导入流程，逐份选择 PDF，在浏览器本地用 PDF.js 文字坐标重建“流水明细”表，支持分离/合并表头、续页和重复表头，精确读取 17 个账单列。只将“证券买入/证券卖出”作为成交候选；回购、申购、配号、资金流水、公司行动、可转债及未知行分类统计并保留来源，不静默丢失。

每行保留标准成交和本地源证据（脱敏账户、日期、市场、代码、名称、方向、数量、价格、金额、各项费用、余额、币种、文件指纹、页/行位置）。预览显示逐行状态、外部值与标准化值，状态包括可导入、重复、冲突、排除、未识别、无效和“核心模型未表示”。普通实盘候选键必须含稳定账户；跨账户绝不去重。同账户重叠文件按完整证据和出现次数核对，同文件相同行仍保留多笔。

范围为指定目录内的股票、ETF和港股通买卖记录。用户明确要求不导入可转债；可转债仅记录排除去向，不作为待完成或阻塞项。其他无法正确表示的范围内资产列为阻塞项，不能静默排除后宣布全部完成。使用页面确认导入并核验持久化成功，重载可恢复；本地逐行核对报告保留来源与系统记录的对应关系。PDF 不上传，元数据请求只带市场和代码；行情失败不回滚已保存成交。

## User Stories

1. As a 个人投资者, I want 从页面逐份选择招商 PDF, so that 我能导入全部账单。
2. As a 个人投资者, I want 内容识别格式, so that 重命名不改变结果。
3. As a 个人投资者, I want 看到账户、页数、日期和原始行数, so that 我能确认文件。
4. As a 个人投资者, I want 只读取流水章节, so that 其他章节不会造出成交。
5. As a 个人投资者, I want 分离表头和续页正确解析, so that 不漏行、不翻倍。
6. As a 个人投资者, I want 每行有页码、行号和指纹, so that 我能回查外部证据。
7. As a 个人投资者, I want 看到 A 股、ETF、港股通和转债分类, so that 混合资产不被隐藏。
8. As a 个人投资者, I want 全部原始买卖行都有去向, so that 统计可守恒。
9. As a 个人投资者, I want 核对日期、市场、代码、名称、方向、数量和价格, so that 核心字段可验证。
10. As a 个人投资者, I want 核对成交金额、佣金、印花税、其他费、变动金额、余额和币种, so that 不把局部相等冒充完整一致。
11. As a 个人投资者, I want date-only 和同日来源顺序被标明, so that 不误解虚构时刻。
12. As a 个人投资者, I want 缺失字段显示未表示, so that 系统不会猜值。
13. As a 个人投资者, I want 未识别标的可重试, so that 其他完整行仍可导入。
14. As a 个人投资者, I want 同账户重叠文件显示重复候选, so that 我能审查去重。
15. As a 个人投资者, I want 同文件相同成交保留其次数, so that 合法重复不丢失。
16. As a 个人投资者, I want 两账户相同交易各自保留, so that 账户不会串账。
17. As a 个人投资者, I want 金额/费用冲突进入待处理, so that 我能决定取舍。
18. As a 个人投资者, I want 港股通逐条得到核对结论、可转债按要求排除, so that 范围内记录不遗漏且转债不入库。
19. As a 个人投资者, I want 预览显示新增、重复、冲突、排除和未表示计数, so that 我能解释结果。
20. As a 个人投资者, I want 问题未处理时确认禁用且重载后可复查, so that 不完整记录不入库且结果可审计。

## Implementation Decisions

- 复用页面导入、招商适配器、PDF.js/PDF 布局、导入预览、元数据补全、执行对账和 SQLite；本批文本 PDF 不引入 OCR。
- 解析以坐标列重建和章节状态机为核心；坏行诊断，必要结构缺失则阻断。
- 数值用十进制字符串；数量为正、方向独立；日期精度为 `date-only`，`sourceOrder` 只排序。
- 本地证据保存 17 列及字段级核对状态；未进入核心成交模型的字段必须显式标为未表示，不能声称一致。
- 普通实盘候选键加入账户；重复比较账户、标的、日期、方向、数量、价格及可用金额/费用证据；跨账户永不匹配，重复按来源多重集合保留。
- 使用现有页面完成导入，不通过脚本或直接写库代替页面操作。逐行报告可保留在本地，不预设必须新增产品内报告或证据存储功能。任何必要产品修复先形成最小变更，再重新运行页面验收。
- 原始 PDF 只在浏览器读取；日志和协作产物脱敏，元数据接口只接收市场和代码。

## Testing Decisions

- 最高接缝采用现有页面级导入流程：上传→解析→逐行预览→确认→SQLite→重载；以现有 TradeReviewWorkspace 导入流程测试为先例。该验收边界已获用户确认。
- 招商解析测试覆盖分离表头、续页、重复表头、两账户前导零、同日多笔、股票/ETF/港股通/转债、非交易章节、缺列、无效日期和 17 列保真。
- 逐行黄金夹具要求原始行数等于所有最终状态之和；比较字段使用十进制、日期精度和现金校验，不用浮点近似掩盖差异。
- 执行对账测试覆盖跨文件重复、同文件合法重复、金额/费用冲突和跨账户同交易不得去重；沿用现有 reconciliation 测试先例。
- 页面、预览、SQLite 测试覆盖元数据失败可重试、问题阻断、取消不变、事务回滚、证据 round-trip、重载恢复和行情失败隔离；网络断言确认 PDF 未上传。
- 本地真实目录只做回归 sanity check：核对 9/45/445、154/224/55/12、67/378 历史基线及逐行差异；基线不替代当前验收。

## Out of Scope

- 用户明确要求不导入可转债；本批12条可转债记录按要求排除，不属于未完成项。

- 本规格不扩展为全功能账本重构，不要求新增通用自动对账产品。执行目标仍是完成真实页面导入及逐条核对。
- 不支持扫描/OCR、任意券商、自动文件夹导入、基金/外汇/回购/资金流水/公司行动作为普通成交。
- 不承诺成交编号、精确撮合时间、逐笔唯一性、缺失期初持仓或完整历史盈亏；不输出未经支持的港股通混合币种收益。
