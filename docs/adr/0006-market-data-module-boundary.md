# ADR 0006：独立行情同步模块的首期边界

日期：2026-09-22。状态：首期已实施；供应商策略与口径治理仍待后续落地。

## 问题

交易复盘页面直接并发调用日线和分时同步器，并自行读取覆盖状态、判断取消、处理失败和保留旧行情。其他消费者若复用行情层，必须再次实现这些规则，容易出现一个周期失败覆盖另一个周期成功、旧 15 分钟数据被空小时线清空等差异。

## 决定

在现有 `app/lib/market` 内建立单个公共应用入口 `market-data-service.ts`，负责一个证券的日线/小时线同步。它不依赖 React，不操作页面任务队列或证券元数据，通过 `MarketDataRepository` 使用现有原子提交能力。低层日线/分时同步器及 provider 路由继续作为模块内部协作组件。

消费者提供证券身份、各周期所需区间、已有行情快照、存储接口及取消信号；入口返回各周期的数据、覆盖、状态和结构化刷新诊断。刷新结果与当前保留的数据分别表达，不能把失败后的缓存展示解释为本次请求成功。

公共函数为 `refreshMarketData(request)`。返回 `daily` 和 `hourly`：`interval` 是实际返回数据周期，`retainedPrevious` 表示是否保留调用方旧数据；`error` 是低层同步返回部分结果时的错误，`refreshError` / `refreshErrorSource` 表示同步异常或后续覆盖读取异常。失败区间通过 `failedRanges` / `failedCount` 保留。

为兼容当前消费者，`status` 并非通用质量结论：日线拒绝后有缓存时按旧覆盖计算，小时线保留旧 15m 时仍反映本次 1H 尝试状态；`source` 也不能替代 `retainedPrevious` 判断返回数据来自何处。后续 worker/研究消费者必须同时读取诊断字段，不能只用 `status === complete` 判断本次采集成功。

| 职责 | 所属 |
| --- | --- |
| 所需证券/区间与任务触发 | 复盘消费者；未来由其他消费者提供 |
| 日线/小时线并行、异常隔离、覆盖读取、保留旧数据 | 独立行情入口 |
| 缺口规划、provider 请求、原子写入 | 现有低层同步器 |
| 来源顺序、供应商报文解析 | 现有路由与 provider adapter |
| 中文展示消息、元数据刷新、任务状态持久化 | 当前复盘页面 |
| 后台租约、重试调度、不可变数据版本、研究快照 | 后续阶段 |

## 不变量

- 任一周期失败不能丢弃另一周期的可用结果。失败刷新保留已有数据。
- 空的小时线结果不能清空已有可用 15 分钟数据；返回数据必须保留实际周期标签。
- 取消作为取消传播，不转换为来源失败或成功刷新。已发生的底层原子提交不假装回滚。
- 日线获取完成但覆盖读取失败时保留新行情和旧覆盖，明确标记存储错误。
- 覆盖 complete 只表示当前同步规则的区间覆盖，不表示时间戳、复权、成交量、历史可知时间已核验。
- 不更改交易数据、历史行情、数据库 schema 或未经证实的供应商转换规则。

## 扩展路径与限制

本期入口沿用 `SupportedMarket` 的 US/HK/CN-SH/CN-SZ；这是面向现有已支持市场的可复用模块，并不意味着已接入全部全球市场。新市场仍需要证券身份、交易日历、供应商能力与口径证据。

本期继续使用原来源路由；“每市场最多三源、全局尽量少”的目标尚未落地，仍由决策地图约束后续策略实施。没有把旧 ADR 中四源最小性、统一减一小时或全局成交量倍数当作结论。

后续采集 worker 可以调用同一入口；量化研究消费必须在版本化存储、企业行为与可知时间证据具备后建立研究快照。入口当前返回的覆盖和诊断不足以支持无前视偏差的历史回测。
