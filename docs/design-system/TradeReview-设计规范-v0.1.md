# TradeReview 设计规范草案 v0.1

日期：2026-10-07。状态：**候选规范，尚未通过真实页面视觉验收**。负责人：root。适用范围：首页的文字与控件基础，以及复盘工作区的共用规则；本轮只新增可逆样板，不把候选值直接覆盖全站。

本规范以中文阅读、金融信息的可信表达和图表操作为中心。推荐方向是克制的暗色工作台：减少重复轮廓，让重要数值、当前阶段和主要动作自然突出。参考 TradingView 的操作分组与图表优先原则，不照搬品牌色、字体或未经测量的尺寸。[官方 Supercharts 说明](https://www.tradingview.com/support/solutions/43000746464-getting-started-with-supercharts/)将周期、图表操作和绘图工具按任务分组；下述尺寸是 TradeReview 的候选值，并非 TradingView 的设计参数。

2026-10-08 首页方案调整：用户要求按正式 master 拉齐，首页推荐改为复用完整工作区，详见 [首页候选 v0.2](TradeReview-首页拉齐-v0.2.md)。本文件后文中的合成首页仅为历史组件校准，保留在 `/design-preview/component-sample`；复盘阶段及基础规则仍有效。新首页不是固定内存样板，使用严格隔离的业务副本。

## 推荐方向与信息层级

首页帮助用户先确认范围和数据状态，再阅读资产数值与趋势，最后进入待复盘交易。范围字段与辅助操作在同一密度层级；数据缺口在指标旁给简明完整的解释，长明细按任务展开。已知部分必须称“小计”并说明覆盖，未知不可当作 0。没有可用比例时用说明或列表承载，不把空圆环当作有效资产分布。

复盘工作区帮助用户在图上理解当时的判断与实际行情。阶段和可知截止靠近图表；图表与批注是主工作面，原文与当前补充紧邻其上下文。辅助内容按完整中文的阅读长度与可用空间布局。本规范不预设复盘栏数、比例或固定侧栏宽度，首页方案 B 的布局不能直接迁入复盘。

容器只在分组必要处使用边框；层级主要由位置、间距、文字角色和少量底色建立。同一模块避免三层相似圆角大框。标题不承担所有强调；重要数值使用独立角色，缺失原因仍需可读。

## 文字角色与中文字体

候选 UI 字族为 `"Geist", "PingFang SC", "Microsoft YaHei", system-ui, sans-serif`，generic 放最后。当前 Geist loader 调用声明 `subsets: ["latin"]`；实际下载和命中字族仍待浏览器核对。字体 loader 的 fallback 必须显式核对，不能在 CSS 变量中先插入 generic，再附中文候选。不得声称 macOS 与 Windows 已使用相同字体。

| 角色 | 字号 / 行高候选 | 字重候选 | 使用规则 |
| --- | --- | --- | --- |
| 页面标题 | 20 / 28px | 600 | 页面身份；不与每张卡片等权 |
| 模块标题 | 16 / 24px | 600 | 资产、历史、原判断等模块 |
| 正文 / 控件值 | 14 / 22px | 400 / 500 | 中文正文与操作；控件值不继承 label 的 650 |
| 多行批注 / 原文 | 14 / 24px | 400 | 原句完整，按段换行，不用固定高度截断 |
| 说明 / 数据元信息 | 12 / 18px | 400 | 日期、币种、覆盖；关键风险说明不能仅靠小字 |
| 金融重点数值 | 20 / 28px 起试 | 500 | 与 label 拉开层级；真实页面再校准，不能挤掉币种与精度 |
| 图表轴与图上文字 | 轴沿现有 SDK；Text 初试 14px | 按现有绘制契约 | 需与 DOM 同屏比较；不声称 scoped CSS 已改变 Canvas |

仅用 400、500、600 建立首轮角色，避免无依据的 550/650/800 混用。视觉上的字重差异必须结合实际 rendered font 判定。数字优先使用 `font-variant-numeric: tabular-nums`；正文中文不用等宽字体。价格保留业务需要的小数位、币种与正负号，缺失值使用“暂不可用”及原因。

DOM、文字编辑框、图上 Text 的测量和绘制应引用同一经验证字族。SDK 轴标签必须由图表配置显式传入；现有 ReplayChart 没有字族透传接口，本轮样板保留该限制。统一前先比较编辑中、完成后、重开与导出的行宽与折行，不能让字体修改破坏已有 Text 锚点和原字号。

## 语义颜色与对比度

沿用现有暗色基底：page `#0b1220`、surface `#111a2b`、raised `#182337`、正文 `#e7edf6`、辅助文字 `#adbbcf`。链接/选中线候选保留 `#2f80ed`；白字主动作填充候选复用已有 `#2169cc`，先解决对比度，再校准视觉重量。

颜色应按用途命名：`text-primary/secondary`、`surface/canvas/raised`、`divider/control-border`、`action-primary-fill`、`selection-bg/border`、`focus-ring`、`state-info/success/warning/danger`、`market-gain/loss`。分隔线与识别控件的边界不是同一角色。错误、未读、成功和警告不能使用 `market-gain/loss`；盈亏与蜡烛继续服从用户现有设置。

计划与假设保留金色 `#f3ba2f`、虚线和“计划”文字；实际成交使用独立成交标记和数量/价格；不能只凭颜色区分。状态同时有文字或图标，色觉差异不应阻断理解。

| 色值组合 | 静态比值 | 结论与边界 |
| --- | --- | --- |
| `#e7edf6` / `#0b1220` | 15.91:1 | 当前正文配色不是普遍偏暗的证据 |
| `#adbbcf` / `#111a2b` | 8.94:1 | 仍须检查透明度与最终背景 |
| 白字 / `#2f80ed` | 3.87:1 | 小字号普通文本低于 4.5:1；不靠加粗补救 |
| 白字 / `#2169cc` | 5.31:1 | 主动作填充候选；hover/pressed 另测 |
| `#34445b` / `#111a2b` | 1.76:1 | 若轮廓是唯一识别控件的线索，需另验证非文本对比；装饰分隔不自动判失败 |

上述数值按标准 sRGB 计算，不是截图采样。普通文字目标至少 4.5:1；符合大字定义的文字至少 3:1，交互识别必需的非文本信息通常需 3:1。[WCAG 文字对比解释](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[非文本对比解释](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)应结合实际用途使用，不能把所有边线都按同一阈值处理。

## 尺寸、间距与图标

桌面标准控件候选高 36px，主动作高 40px；窄窗口或粗指针命中区至少 44×44px。视觉图标可保持小，命中区单独规定。44px 是产品触摸目标，不应误称 WCAG 2.2 AA 的一律要求；[WCAG 最小目标尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)的基准为 24px 并含适用例外。

控件左右内边距候选 12px，图标与文字间距 8px。间距以 4、8、12、16、24px 建立规则：4 是紧密相关内容，8 是同控件元素，12/16 是行与分组，24 是大模块。控件圆角 6px、面板 8px。不要为挤进一行缩中文字号；长标签换行或重新分组。

延续 Lucide。字段/导航图标候选 18px，绘图工具候选 20px，描边先试 1.75；是否使用固定绝对笔画须在 1×/2×截图校准。图标与文字统一 flex 对齐，不能通过逐个 margin-top 修基线。品牌图形可有独立角色，需记录光学例外。通知中的 `! / ~ / ↗` 应替换成语义明确的 Lucide 图标或正式定义的文字徽标。

按钮保持边框占位，hover/selected 不改变总尺寸。只含图标的动作有中文可访问名称，Tooltip 补充含义，不能承担唯一命名。搜索清除、弹出层关闭也要测命中区，不能只保证工具栏主按钮。

## 公共组件与交互状态

首轮优先复用 ScopeChoiceGroup、ScopeSelect、现有 ChartToolbar、DrawingToolbar、ReplayChart 和首页卡片/历史组件。当前没有完整通用 Button/Input；规范不把它们假设为已经存在。

| 组件 / 状态 | 规则 | 验收重点 |
| --- | --- | --- |
| Button：primary/secondary/text/icon/danger | 使用明确语义、统一文字与尺寸；一处工作流一个主要动作 | hover/pressed 不跳动；原因可读；危险动作不能借用盈亏色 |
| Field / Select / Search | label、值、hint/error 分层；值统一 14px/500 起试 | 长中文、无选项、原生键盘操作、输入法、焦点、错误恢复 |
| selected | 淡蓝底 + 边框 + aria 状态 | 与 hover、focus 独立，可同时存在 |
| focus | 候选 2px `#9ecaff` 外描边，offset 2px | 真实 Tab 焦点，不用假框代替；边缘及弹层不裁切 |
| disabled | 禁止动作并给原因；保留解释的可读性 | 鼠标/键盘均不触发；不能只降低 opacity |
| loading | 不阻断其它工作，明确任务与进度，避免重复触发 | 默认异步补齐；人工触发；aria-live 与 reduced-motion |
| readonly | 内容可读、可复制，禁止编辑原判断 | 不等同 disabled；原文始终可对照 |
| error / empty / partial | 原因与下一步；已知小计保留覆盖 | 不显示假 0、假比例或假“成功” |
| Tabs / segmented | 真正页面页签与单值选择区分 | tabs 的箭头/Home/End、roving focus 与 panel 关联独立验收 |

Scope 现有 API 尚未覆盖 disabled/error/loading，tabs 分支也缺完整键盘导航。本轮不通过外部假样式宣布公共组件已具备这些能力。样板仅可诚实展示已有能力；后续公共组件迁移需要补接口和真实操作证据。

## 复盘阶段、证据与未来信息

S0 入场前、S1 持仓中、S2 退出后是同一复盘空间的状态。阶段与“行情截止 / 成交截止”并列说明；单一“日期”不足以解释已知范围。样板以合成 D69 持仓中开场，原计划 56 / 52 / 68、初始 1,000 股；已经揭示的减仓后持仓为 400 股。初始 S1 不出现最终净盈亏或未来退出。

| 动作 / 阶段 | 可知边界 | 图表与原文规则 |
| --- | --- | --- |
| S0 原判断 | 已完成行情与未揭示成交分开说明 | 显示原图形、原文与计划，实际买入未揭示 |
| 揭示入场 → S1 | 显式推进成交前缀与相应知识截止 | 买入标记与数量价格可见，原计划保留 |
| 下一根已完成 K | 推进行情截止；成交截止不会暗中前进 | 真实新 K 在视口内可见；Tooltip、摘要与图层同步过滤 |
| 显式展开退出 → S2 | 允许展示已揭示退出与结果 | 原判断仍可对照，新结论注明形成阶段 |
| S2 返回早期 | 恢复早期双截止 | 不沿用未来价格轴和事实；见过后续的来源信息持续保留 |

调用 ReplayChart 前先过滤完整数据；`cursor` 属性本身不等于安全过滤。K 线同时按时间与 knowledgeAt，成交按稳定前缀与知识截止，批注按形成阶段与 createdAtCursor 过滤。同一过滤结果用于 Tooltip、成交列表、OHLC 摘要、数据弹层、图层和图表范围。

原判断有稳定 ID、只读原稿与图上锚点，阶段推进不能改写或删除它。当前补充分阶段存放；已形成的旧阶段补记在后续阶段只读，新观察另记在当前阶段，不能把旧内容的形成阶段或时点改成当前阶段。在事后回填历史观察时标“复盘补记”，保留已看后续信息的来源状态。图形选中能定位原文，原文能定位图形。多行中文完整展示，不删关键句、不把固定评论改短来适配排版。

样板采用过滤数据 + 阶段切换重建图表来避免未来轴状态残留；这是可逆演示方案，不是生产 viewport 恢复或数据库持久化验收。生产保存必须在隔离数据库完成写入、返回导航、刷新及重开验证；本轮内存样板不能显示“已保存至复盘”等承诺。

样板阶段按钮切到固定代表状态：S0 为 D60 已完成行情且首次成交未揭示，S1 为 D69 买入及减仓已揭示，S2 为 D80 完整结果。S0→S1 的代表状态跳转不是首次入场逐步回放的已验收证据；下一根揭示另在真实图表检查。

## 样板、比较与验收

推荐样板路径为 `/design-preview`。首页与复盘分别检验同一组基础规则；基线/推荐切换共用组件、fixture、全文、阶段和当前图表范围。基线是当前组件风格的同数据对照，不冒充当前业务首页的完整截图。只做一个推荐方向；出现真实可选择的密度差异后才追加候选。

比较视口：首页1440×1000、1280×720；复盘1440×900、1280×800；两者另查1024×768、390×844、320×740，记录 DPR、导航/弹层、内容宽度及 pointer 类型。另查内容断点两侧和宽屏粗指针，不能只按手机宽度验收。固定数据与状态后，独立审阅者直接比较原图、基线与推荐截图；功能、未来信息安全、视觉三个结论分开记录。

必须检查：主图实际面积；中文 rendered font 与字体加载失败；所有文字的字号/行高/字重；同角色控件 bbox/padding/gap；图标图形与命中区；真实焦点及选中并存；有效颜色与对比度；完整长文、重要价格和窄窗；S0→S1→下一根→S2→S0 的真实图表旅程。鼠标、键盘、emulated touch、physical touch 分别记录，不混称通过。

本轮静态类型、构建、源码边界与 HTTP 可用性可以独立验证，但不能替代以上浏览器证据。截图缺失时保留 **NOT VERIFIED**，不以分数或“无溢出”判断补足。

## 样板选定后的固化范围

1. 在 `app/globals.css` 建立文字、字体、语义颜色、密度、间距和焦点 token，清理重复晚段覆盖；`app/layout.tsx` 明确字体 loader fallback。逐页迁移，保留批准例外。
2. Scope 公共组件明确 size 语义，补状态 API 与 tabs 键盘行为；新增薄 Button/Field/IconButton 时延续 React、CSS Module、Lucide，不更换框架或组件库。
3. 首页页头、范围条、全局工具、指标卡、历史与诊断使用同角色 token；错误通知脱离盈亏配置。原有异步补齐和人工触发行为继续保留。
4. ChartToolbar、DrawingToolbar、绘图编辑器与 ReplayChart 接入共享字体/图标角色；SDK 字族作为显式配置，按阶段和轴安全单独验收。不得为密度修改删减关键复盘内容。
5. 在 `AGENTS.md` 与 `docs/agents/ui-task-templates.md` 引用本规范的批准版本、例外登记、匹配状态截图和独立验收要求；更新 DESIGN-COVERAGE 与功能 README。**选定前不改项目指令、不全站铺开候选。**

例外需记录页面、角色、具体偏差、业务理由、参考状态、证据、负责人和复查时机。合法例外包括品牌图形、特殊图表数字精度、已有原稿字号与宽表格局部滚动；“为了放进一屏”不足以授权截断判断或隐藏价格。

版本推进：v0.1 为有证据边界的候选；取得启动包与真实截图/测量后修订；用户只需选择画面的焦点、密度、阅读感受和操作清晰度，再把选定规则固化为 v1.0。
