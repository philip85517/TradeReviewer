## 当前性能判断

25db 在 **50 份合成练习 × 每份 50 对交易**的内存库里，真实列表指标读取三次为 **1.42–1.49 秒、301 次 SQL get/all**；分段诊断发现一次列表触发 **2,500 次分组 CSV 解析**。单练习原始详情自身可按 ID 读取，但详情财务消费者另走全库统计，使单对象需求受无关练习数量放大。

38a0 既有隔离发布的真实处理器“就绪 → 第一页 → 严格解析”三次为 **3.71–4.18 秒**，尚未包含 socket、浏览器和 React。就绪和分页两个请求分别重读并验证约 **25.4 MB** 的详情／证据 JSON。已有预计算与 worker 没有消除这条热读成本。

这些证据支持重新组织读取边界，同时保留来源、unknown、费用、版本、CAS、幂等与完整性规则。它们不能证明 SQLite 本身不适合，也不能当作真实业务库的生产延迟或容量结论。两项性能诊断断言仍为 **FAIL**；55 条窄范围保护测试通过不能抵销性能失败。
