# 项目拆票标准

本标准补充 [开发流程](development-workflow.md) 和 [本地任务跟踪](issue-tracker.md)，适用于功能拆解、修复和 UI 派发。沿用当前用户指定模型及项目默认实现模型；模型选择不能替代验收。只在已授权范围内执行，不因使用通用拆票技能重复索取批准。

前端测试/检查等同义请求及影响前端交互、布局或状态接线的开发，默认接入[前端控件与视觉空间诊断规范](frontend-control-audit.md)。拆票时把控件登记、功能与状态检查、点击前中后的空间对照和独立复核分派到具体 owner；不将它们留为无人负责的开发后备注。整页或全部控件请求覆盖完整登记范围，局部开发记录受影响范围，均不得以控件存在或组件票通过代替实际交互验收。

## 先建立契约，再划分实现

- 读取已确认需求、元素规格、准确画板和现有实现。票保留规格路径、章节/原文行号、elementID 与参考图准确路径；通用 `to-tickets` 的“避免文件路径”不适用于这些设计依据。实现文件所有权写在派发说明中，避免把猜测的实现文件冻结成产品需求。
- 在 `.scratch/<feature-slug>/DESIGN-COVERAGE.md` 建立逐项矩阵。每个在范围内的需求、元素、必需状态和旅程都有行，不能只覆盖组件名称。多个状态或参考图不得用一个模糊的“符合设计”合并。
- 每行包含下表字段；不适用项写明规格依据，设计变更记录用户决策依据。删减原约束不能由票摘要或实现者判断代替。
- 涉及前端时，将控件/操作及必需状态 ID 映射到矩阵行，注明完整登记清单或局部影响面、视觉空间预算及验证表证据位置；条件出现、展开后的入口和数据驱动实例纳入登记。不得只给组件名，遗漏状态与上下游旅程。

| 需求 ID / 规格与原文行号 | elementID | 准确画板 / 图片路径 | 阶段与状态 | owner / 任务 | 交付组件 | 浏览器操作 | 可观察预期与反例 | 证据路径 | pass / fail / unverified |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 按本次已确认规格填写 | 无元素时注明不适用依据 | 指向具体图及区域 | 含错误、空值等适用状态 | 单一责任人与集成负责人 | 仅作交付映射 | 从可重现入口开始 | 包含应不可见的内容 | 验收后填写 | 初始 unverified |

例如主图复盘使用 [需求规格](../specs/2026-09-25-chart-first-review-ui.md)、[E01–E22 元素规格](../specs/2026-09-25-chart-first-review-ui-elements.md) 和对应的 [主图画板](../designs/2026-09-25-chart-first-review/02-chart-workspace.png)、[持仓画板](../designs/2026-09-25-chart-first-review/04-holding-stage.png)、[事后画板](../designs/2026-09-25-chart-first-review/05-final-review.png)。新功能使用自己的已确认来源，不能机械套用这些元素或图片。

## 纵向切片与依赖

每票交付一个可演示、可独立验证的完整用户行为，贯穿所需数据、接口、主图、交互和验证；不要按“底栏 / 侧栏 / 统计 / 导出组件”横切后直接并行。切片应能在一个新上下文内完成；机械广泛重构可按 expand–migrate–contract 分批，并明确最终集成门槛。

涉及回放的第一条切片必须走通真实主图 → 下一根 / 播放 / 下一决策 → Text → 回看早期状态 → 保存/重开。协调者实际验证图表和同状态视觉对照并接受该切片后，才扩大依赖其状态、图表和布局契约的并行实现。可独立的研究、准备工作不必人为阻塞。共享文件唯一负责人只解决编辑冲突，协调者仍负责侧栏顺序、首屏动作、默认折叠、常驻高度及跨组件语义的集成。

`Blocked by` 只表达真实前置契约或验收依赖，使用编号、标题和链接。状态契约或早期视觉门槛就是有效依赖，不能为提高并行度删除；不因优先级或共享文件本身添加虚假产品依赖。并行派发时另列允许写入范围、接口、禁止项和报告路径。

## 状态转移必须可验收

回放相关拆票前维护转移表：起始阶段、动作、行情可知截止、成交可知截止、目标阶段、可见/不可见字段、Text 归属、未来暴露标记与来源、视野策略、持久化及重开结果。注明独立值及必须原子更新的组合。至少覆盖：

- 区分 next bar、播放/暂停、next decision、阶段恢复、查看完整历史、重新开始回放；覆盖首次成交前、未完成 K、同 K 多决策、缺失行情和末尾。不可用一个恢复规则替代全部动作。
- 行情与成交独立截止；主动看结果或未来快照后回看早期，不能提前显示买入事实、退出、最终盈亏或利用未来高低点定轴。所有揭示入口记录未来暴露来源，切阶段、刷新、关闭重开不得清除来源或伪装盲态记录。
- 切周期、侧栏开合和刷新不隐式推进任一游标；选择决策按明确契约跳转，不借另一阶段旧游标越界。重开恢复已保存的所选状态。
- 推进后新增 K 线、目标成交和时间轴在真实主图可见，包括超出初始视野的推进；刷新与 resize 保留用户视野。末尾、无行情有原因与可用下一步，不能留下无反馈按钮。
- 逐笔点选成交与恢复该决策的工作进度分别定义；已有更晚草稿、完整历史和编辑快照时的入口行为都要覆盖。视野有多个写入方时，注明主动导航、阶段恢复与尺寸变化的优先级，验证末尾提示/侧栏导致尺寸变化的同帧场景。
- Text、输入和 IME 焦点阻止回放；Text 锚点、长文折叠与历史快照独立。未平仓事后状态保留可计算的已实现/浮动拆分。
- 保存异常的切片必须覆盖恢复动作：失败或版本冲突时保留本地输入；用户显式重新载入后，字段值、派生指标和保存状态必须共同反映服务器版本，再次编辑可正常保存。行情刷新保留本地草稿与显式重新载入是不同动作，不能只验错误提示出现或消失。

## 每票的验收与证据

每条验收写清起始条件、浏览器操作、可观察结果、至少一个相关反例及证据位置。自动化、领域口径、真实图表、视觉分别给结论，不能用测试通过或游标数值变化替代实际图表播放与视觉验收。无 UI 的票可注明浏览器/视觉不适用及原因。

第一张完整阶段画面出现即比对，新增侧栏模块或底栏入口后复核。对照保持相同视口、阶段、侧栏/应用导航状态和近似文本密度，保存并排截图或叠图及必要尺寸；差异映射 elementID。按各功能批准的规格选择视口；主图复盘记录 1440×900、1280×800、约 390px、导航展开态及真实手机软件键盘状态，桌面窄屏不能冒充手机键盘测试。测试写入使用显式隔离数据库，证据不暴露业务明细。

票的 `accepted` 只证明该 Scope 被接受；feature accepted 仍需协调者独立走通完整核心旅程、状态安全及设计对照。必需检查 unverified 或仍在范围内的失败均阻止整体完成。完整规则见 [开发流程](development-workflow.md)。

## 可复用票模板

以下是模板，不是实际产品任务；按 [生命周期规则](issue-tracker.md) 更新字段。

```markdown
# <NN> — <用户行为标题>

ID: <稳定 ID>
State: open
Status: ready-for-agent
Assignee: unassigned
集成负责人: <协调者>

## Scope / What to build
<本票可演示的端到端行为、范围边界；局部接受不代表功能接受>

## Refs
- <已确认规格准确路径、章节/原文行号、elementID>
- <准确参考画板/图片路径、对应阶段与状态>
- <DESIGN-COVERAGE.md 对应行、状态转移契约>

## Blocked by
- <NN — 标题及相对链接；无依赖写 None>

## 验收标准与反例
- [ ] <起始状态 → 操作 → 可观察结果；相关反例；证据链接>
- [ ] <前端控件检查触发依据、完整/局部范围、控件/状态登记与覆盖分母；非前端注明不适用依据>
- [ ] <点击前中后空间、作用域和上下游状态链符合契约；规范中的验证表/问题表及独立复核证据>

## 验收证据
- 自动化 / 领域 / 浏览器真实主图 / 同状态视觉：<各自结果与报告；不适用说明>
- <代码版本、服务/端口、隔离数据库、浏览器路径、视口与设备状态、时间>
- 未验证或失败项：<说明及后续责任人>
- 协调者接受：<人、时间、Scope、证据；未接受留空>

## 派发说明
- <允许写入范围、共享文件唯一 owner、输入/输出接口及真实调用方、禁止项、报告路径>
- <跨组件事件从哪个入口触发、由谁接入、最终改变什么可观察行为；不适用注明>

## 历史
- <时间、状态转移、依据；回归保留旧验收并追加失效原因>
```

## 拆票前与派发前检查

- [ ] 已读原需求、元素规格和图片；准确路径有效，未用摘要替代原约束。
- [ ] 逐项反查需求与元素全集：矩阵无遗漏、无无主项；每个必需状态、动作和反例均有票及证据计划。对主图复盘逐一核对 E01–E22。
- [ ] 切片可独立演示；第一条真实主图旅程有验收负责人，下游依赖保留早期验收门槛。
- [ ] 涉及回放时，双截止与转移契约、未来信息防漏及来源持久化覆盖完整，跨组件接口一致；不适用写明依据。
- [ ] 每票都有可观察验收、反例、Refs、owner、集成负责人；未把自动化等同于视觉或真实图表通过。
- [ ] 前端任务已读取控件诊断规范，登记控件/状态范围及检查 owner，空间变化预算和独立视觉复核有证据计划；局部覆盖不冒称全页，用户排除逐项有依据。
- [ ] 文件所有权仅放派发说明；依赖链接有效且无环；全部票创建后再复核依赖与矩阵覆盖。
- [ ] README、票与最终验收使用同一生命周期语义；预留证据与回归重开记录，未把 ready-for-agent 当完成。
