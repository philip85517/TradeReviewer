# 历史成交时间缺失或无效：用户确认

2026-10-26，用户真实答复。本记录属于“练习名称与日期口径”的部分决策；其他未决问题保持 open。

## 用户依据

问题：“如果文件中的历史成交时间缺失或无效，是否在导入确认页列出问题原行并阻止完成导入，修正源文件后重试？这样不会丢弃坏行，也不会用其余有效行冒充完整历史交易区间。这是原日期决策票尚未确定的异常规则。”

答复：“阻止导入并定位问题原行（推荐）”。

## 已确认规则与验收

历史成交时间缺失或无效时，导入确认页列出问题对应的源文件原行并阻止完成导入。用户修正源文件后重试；不能丢弃坏行、只保存有效子集、用导入时间或练习日期补造历史成交时间，也不能以有效子集的最早/最晚时间冒充完整历史交易区间。

校验覆盖文件全部源交易记录，包含未配对及未被既有 parser 接受的记录。成功的历史区间取全部完整、有效源交易记录的最早/最晚日期，保存原时间精度及来源时区；date-only 来源不虚构精确时刻。诊断须映射回原文件行号，不以配对后序号代替。

反例：三行中间一行日期无效→列出该原行、无保存；最早一行未配对但时间有效→仍参与最早日期；只有一条有效历史日期→起止为同日；缺失/无效行多处→全部列出，不因首条错误短路隐藏其他行。实际隔离库应验证失败/取消不写入，修正后完整导入并返回/reload重读。

这是业务决策，尚未实现真实导入、原行 UI、文件 adapter 或持久化。纯日期区间校验只可接受明确声明完整的所有源记录；其通过不能证明调用方没有漏行，也不能验证原时间字符串的时区/精度转换。上述产品旅程仍 **NOT VERIFIED**。
