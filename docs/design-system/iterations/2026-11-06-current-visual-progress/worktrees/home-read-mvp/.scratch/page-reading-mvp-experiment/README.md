# 交易摘要与分页：一次性隔离实验

本实验只回答一个问题：**把有限交易展示结果预先准备并落入 SQLite，能否减少后续反复读取和编码原始材料的工作，并显式识别旧版本？** 它不是正式接口实现、产品性能基线、真实财务算法或完整页面一秒验收。

当前状态：合成实验通过协调者独立复跑与独立代码审查，详见 [独立验收记录](INDEPENDENT-ACCEPTANCE.md)。原 wayfinder `03-mvp` 保持原有状态与依赖；本实验不填写用户判断、不生成该票 Resolution、不宣称完整 MVP 被接受。

## 数据与精确口径

两组固定、可重建合成样本：1,867 笔／236 标的，以及 20,000 笔／1,200 标的，均为 3 个虚构账户。每个标的跨账户出现，执行日期刻意重复，稳定排序为 `executed_at DESC, id ASC`，每页 8 笔。成交、标的、账户按不同键计数，绝不把笔数解释为持仓数或回合数。

每笔带 3,264 字节重复合成 padding 及少量 JSON；**这不复刻既有 34.33 MB 响应、材料沿革结构、来源资格检查或产品内部重复映射次数。** 1,867／236 仅匹配已知诊断的记录规模，不能称为“同数据”或代表正式库。

日期只采用合成成交日期，含上下边界。账户与市场用集合筛选，空账户集合明确返回零条；搜索按合成 `symbol` 子串，全范围筛选后才计数、排序和分页。排序不含估值，不涉及真实持仓时点、平仓日期、练习保存日期或时区归属。

`amount_cents` 是人工输入的展示金额，不由数量、价格、成本或费用计算；每 17 笔置缺失。缺失保留事实，金额为 `null`、状态 `unknown`、原因 `synthetic-amount-basis-missing`；摘要单列已知小计 `knownSubtotalCents`，存在缺失时完整金额 `amountCents=null`。这是状态传输反例，不验证财务金额可计算资格。

## 三条主读取路线

|名称|每次做什么|回答的问题|
|---|---|---|
|`repeatedFullSimulation`|全表读取，逐笔解析和检查合成 evidence，JS 全范围筛选／排序／摘要，编码全部原始行加当前页|反复读取并发送大来源包的一个简化模拟|
|`narrowResponseOnRequestSimulation`|同样全表读取和准备，仅编码摘要和当前页|只缩小响应，是否还保留反复准备开销|
|`preparedRead`|提前全量解析与校验一次，持久化轻量交易行及 all／单账户／单市场摘要；请求只取版本、摘要和当前页|把工作移到准备阶段的读取收益与成本|

附加 `filteredPreparedRead` 用单账户＋期间＋搜索组合；它从完整轻量结果计算摘要，仍要扫描适用行，未预存所有筛选组合。SQL 页使用 OFFSET；深页并非恒定成本。原始证据留在 raw 表，轻量行存原始 ID 引用和 SHA256；详情按引用读取，不随每页传输。

所有响应计时包括同步 DB／计算、JSON 编码和本地 Node JSON 解析；分别保存阶段时间。字节量为本地未压缩 UTF-8 JSON，不含 HTTP 压缩或协议开销。**没有 HTTP、网络、浏览器、React、图表、曲线、用户可交互或完整页面计时。** 三路共享同一合成库和预热的操作系统缓存。首次准备、准备后首次读、合成更新、准备重建、新进程首读另记。

## 版本、发布与故障

版本由合成 dataset／trade／review／rule 组成；成交与复盘版本分开，rule 只是失效测试标识。本实验没有行情／汇率版本，不假设它们跟随成交更新。

游标绑定完整版本、筛选、排序、页大小；使用“发现变化后明确拒绝并刷新”的策略，不保留可读取的历史快照。原始合成变更与版本递增同事务。结果全量准备在一个写事务中替换轻量行、摘要和发布指针。读请求事务内核对版本；来源变更但未准备时 `PREPARED_STALE`，旧游标为 `VERSION_CHANGED`。不会把旧摘要配上新版列表后当成同一份结果。

故障注入在发布指针更新前抛错，事务回滚；旧准备行与指针保留，但因为来源版本已变化而拒绝当作当前结果读取。重建后恢复。此模型暂时阻塞写者，尚未做非阻塞后台准备、增量准备、多进程并发、历史快照保留、并发竞争或失败重试调度。

重启是新建 Node 进程打开同一个合成库；验证读出的版本、摘要、分页响应摘要值和父进程一致，没有重新准备。进程启动＋打开＋读取＋退出与进程内首次读分开报告。它仍不是断电恢复或操作系统冷缓存测试。
