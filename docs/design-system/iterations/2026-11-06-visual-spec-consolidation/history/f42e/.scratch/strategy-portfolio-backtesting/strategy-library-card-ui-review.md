# 策略库与我的实验：列表卡片 UI 审视

2026-09-30，修订05。用户要求两页顶部均有搜索/筛选/排序，并从专业 UI 视角检查卡片。root 负责浏览器实测与综合建议；entry_visual_review 未参与画板实现，独立直接读图提出意见。本报告是设计评估，不是已批准的卡片重构方案。

结论：现有深蓝框架、名称/状态层级、全宽单列方向合理；实验卡片的信息效率偏低，优先去重并缩短。策略卡片的三类包对齐有价值，宜保留并小幅收紧。两者不必强行采用相同内部结构。

## 建议与优先级

| 优先级 | 现象及影响 | 建议 |
| --- | --- | --- |
| 先落实 | F01缺少排序；筛选是一段弱化文字。F14搜索很宽，过滤/排序的表达与F01不一致 | 两页统一顶部搜索、带标签的筛选、排序字段与方向、结果数。默认最近更新；有条件时显示清除条件。排序依赖的时间应在列表内有对应位置，便于理解先后 |
| 高 | 实验状态在标题徽标和元数据列重复；暂停/完成/失败又将起点重复放进研究区间。四列含义随卡片状态变化，不利于纵向扫描 | 所有状态固定“名称+状态 → 研究区间（含起点和期限） → 策略/组合数 → 更新时间”的顺序；缺值写未设置。卡片只保留实际进度或失败原因；通用说明移入详情/帮助。草稿可显示待完成步骤，不能为了齐整伪造日期 |
| 高 | 实验每张约195px，说明、四列元数据、动作各占一层，右侧大片空白。现有列表难以快速浏览十几个实验 | 建议试做120–150px的常规横向卡片：左侧名称/状态和核心摘要，右侧稳定动作区，次要时间弱化显示。保持正文12–13px、主要动作至少36px，长名和异常原因允许自然增高。此范围为试稿目标，不是硬截断高度或已验证容量 |
| 中 | 策略三类包对照明确，但“定义完整”与“可用于实验选择”重复；摘要/来源位置不统一，缺更新时间导致最近更新排序难解释 | 保留三列包及版本，名称可进入详情；缩小分区间隔，合并可用性提示，统一底部数据需求/来源/更新时间。试做112–136px常规卡。仍明确区分定义完整和区间数据覆盖，缺失包及修复入口不可折叠隐藏；包使用数与开发日期继续在包目录按M12口径显示，不混成实验收益 |
| 中 | 草稿主动作突出，暂停的配置与打开工作台却同级；大量卡片重复按钮和边框增加视觉噪声 | 每张固定一个语义主动作：草稿继续设置、待开始/暂停进入工作台、完成查看结果、失败查看原因。配置/复制/删除降为次级或更多；不要为每张卡再增加蓝色实心块。库保持查看/编辑/复制，不出现新建实验。减少重复竖线，保留对齐、间距和状态颜色+文字 |

建议优先做单列紧凑行式卡，不做双列或三列磁贴。两类列表都需要跨记录对比时间、组成与状态，多列磁贴会使扫视路线、日期和操作位置分散。暂无必要一开始就同时维护“卡片/表格/磁贴”三套视图。

## 大量数据与下一轮检查

若采纳卡片优化，先用每页30条合成记录、多页、五种实验状态、长中文名称、长包名、缺字段和异常原因绘制代表性状态。检验相同字段纵向对齐、全文可查、控件不挤出、详情回退恢复查询与滚动。匹配数量和分页/每页条数作为规模管理反馈呈现；检索和详情返回由任务10实际操作验证。

卡高目标不靠缩小全部文字实现，也不固定容器裁掉名称或失败原因。两档首屏条数作为比较指标而非唯一目标，保持当前侧栏、导航和配色兼容。生产中是否固定查询栏、引入密度开关，待长列表试稿后再定，不在本轮暗中增加交互。
