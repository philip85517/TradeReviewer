# 完全相同文件拦截实施计划

目标：成功导入的完全相同文件在确认前拦截；保存边界也保护；未成功的重试可用。技术：TypeScript、React、SQLite、Vitest。规格与控件见 DESIGN-COVERAGE.md。

约束：保留工作区现有全部改动，真实库不写；不同文件中的成交重叠保持原规则；文件名不是内容身份证据；已有记录缺少可用指纹时不得凭猜测声称成功导入；不能修改财务/Bars；现有已暂停问题的旧证据不重置；不提交远端或自行 commit。用户此前批准的测试接缝为导入公开接口及桌面上传→审核→确认→重新读取。

## 关键反例
1. 同文件重命名；2. 同文件先取消/失败再导入；3. 同文件已成功但重试并发或页面被绕过；4. 文件名相同而内容不同、不同文件部分重叠；5. 旧数据缺可靠文件证据；6. 原确认页面日期精度/账户脱敏回归。

## 单一纵向实现任务
- [ ] 明确真正的成功导入凭据、内容指纹、竞态和已使用版本，不能仅以“存在材料”推断全部成交成功；识别各来源适用性，无法证明时报告缺口。
- [ ] 写一条公共接口/页面首个 RED：成功导入文件后再次上传（包含改名）应阻止，确认不写入；记录真实预期失败。
- [ ] 仅针对根因实现足够的前端和服务端行为；重跑 GREEN。
- [ ] 继续用精简 public-seam 案例覆盖未成功重试、不同内容及绕过/并发；保留原始证据和日期/脱敏要求。
- [ ] 命名源文件与接口、记录所有 RED/GREEN 日志、设计局限和完整 diff，交独立审查。
- [ ] root 在隔离库执行真实桌面旅程、确认数据库变化与返回/刷新；独立非实现者视觉同状态比较，完成受影响控件登记。
- [ ] 复验相关测试与类型检查；记录失败、未验证及第几轮，按照最多 5 轮处理同一问题，超过则停止并记录。
