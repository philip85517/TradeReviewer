## Implemented

- Added the named `ResultsPrototype` export with the contract props, including optional `portfolioName`. The chart, KPIs, contribution table, and event list are calculated from the selected `ledger` prefix; initial capital comes from `ledger[0].equity`. `R` is clamped to both `maxCursor` and the available ledger length. Selecting an already-expanded date after entry calls `onRevealResult`; events call `onEvent(event, firstTradeSymbol)`; the return action calls `onReturnProcess`.
- The view state is keyed by `entryId`: a new entry starts at `initialCursor` with the net-value tab and all-events filter, while an event return with the same ID retains R, chart mode, event filter, and component scroll. The root has a unique React `useId` range-input ID per mounted instance. The component exposes `hidden` so the caller can keep each result view mounted. Charts use responsive inline SVG paths from the ledger and need no hidden-canvas resize callback.
- Added ledger-derived net-value, drawdown, and daily actual-allocation charts. The allocation series includes cash at every date. Core metrics include cumulative return, maximum drawdown as a positive magnitude, period-end assets, rebalances excluding initial construction, and DD12 “组合当日收益” amount/rate using the prior snapshot as denominator. T0 shows no daily return, no analyzable drawdown, and no completed-round win rate.
- FIFO lot accounting separates closed symbol rounds, realized reductions in still-open rounds, and remaining-position unrealized P&L. Cash earns zero in this prototype; fees and slippage are shown as zero with that limitation stated. Turnover is explicitly `双边总成交额 ÷ 初始本金` (no divide-by-two adjustment). The disclosure sits beside the contribution totals because the approved spec does not mandate FIFO; the coordinator's independent reference uses moving-average matching. Both methods must reconcile total P&L even when later realized/unrealized splits differ.
- Added scenario-specific sample coverage text for complete, partial, missing-market-cap, and empty-candidate cases. Partial-coverage text distinguishes EMA's turnover-volume dependency from quality's first-report-disclosure dependency; a full time horizon is separate from sample completeness. Empty candidates are identified as all-cash, not as a strategy return result.
- Visual hierarchy follows the accepted workbench palette, Chinese section titles, 20–22px page title, compact metadata, blue selected tabs/action, neutral assets/cash, sign-colored P&L, 6–8px surfaces, and 36px primary controls. “交互原型 · 合成数据 · 刷新重置” makes the refresh boundary visible. Benchmark excess return and unsupported annualized/Sharpe measures are explicitly omitted.
